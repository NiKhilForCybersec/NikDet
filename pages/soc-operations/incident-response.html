Incident Response

A comprehensive guide to handling security incidents from detection through recovery.

The NIST Incident Response Lifecycle

The NIST SP 800-61 framework defines four phases of incident response:

1. Preparation

Build capability before incidents

2. Detection & Analysis

Identify and investigate

3. Containment, Eradication, Recovery

Stop and remove threat

4. Post-Incident Activity

Learn and improve

Phase 1: Preparation

Preparation happens before an incident. You cannot build the fire department during the fire.

IR Team Structure

RoleResponsibilities
Incident CommanderOverall leadership, decision authority, executive communication
Technical LeadDirect technical investigation and response activities
Communications LeadInternal/external communications, stakeholder updates
ScribeDocument all actions, decisions, and timeline
AnalystsPerform investigation, containment, evidence collection

Preparation Checklist

  • ☐ IR plan documented and approved by leadership
  • ☐ Contact list current (internal team, executives, legal, PR, vendors)
  • ☐ IR retainer contract in place (if using external help)
  • ☐ Communication templates ready (stakeholder updates, breach notifications)
  • ☐ Tools tested and ready (forensic tools, IR platform, war room)
  • ☐ Playbooks created for common incident types
  • ☐ Evidence preservation procedures documented
  • ☐ Tabletop exercises conducted quarterly
  • ☐ Team trained on procedures and tools
  • ☐ Backup communication channels established (if email compromised)

Phase 2: Detection & Analysis

This phase bridges SOC monitoring and formal incident response.

Detection Sources

  • Internal: SIEM alerts, EDR detections, user reports, network monitoring
  • External: Threat intelligence, law enforcement, vendor notifications, customer reports

Initial Assessment Questions

Key Questions to Answer
  1. What happened? What type of attack/incident is this?
  2. When did it start? Timeline of earliest known activity?
  3. What is the scope? How many systems/users affected?
  4. Is it still active? Is the attack ongoing?
  5. What data is at risk? Sensitive data potentially accessed?
  6. Business impact? What business functions are affected?

Incident Classification

SeverityCriteriaResponseExample
Critical (P1) Active attack, major business impact, data breach in progress All-hands response, executive notification, potential retainer activation Active ransomware, APT, major data exfiltration
High (P2) Confirmed compromise, contained but serious IR team engaged, management notification Malware on servers, credential theft, limited breach
Medium (P3) Suspicious activity, investigation needed SOC investigation with IR oversight Phishing success, single compromised endpoint
Low (P4) Minor issue, limited impact SOC handles within normal operations Blocked malware, policy violation

Analysis Activities

1
Collect Evidence
  • Preserve volatile data first (memory, running processes)
  • Capture disk images of affected systems
  • Export relevant logs from SIEM
  • Capture network traffic if attack ongoing
  • Document chain of custody
2
Build Timeline
  • Establish earliest known malicious activity
  • Map attack progression through systems
  • Identify initial access vector
  • Document lateral movement
  • Track data access and exfiltration
3
Determine Scope
  • Identify all compromised accounts
  • List all affected systems
  • Determine data at risk
  • Map attacker infrastructure (C2, domains)
  • Identify persistence mechanisms

Phase 3: Containment, Eradication, Recovery

Containment Strategies

TypeDescriptionWhen to UseRisks
Network Isolation Disconnect system from network Active malware, C2 communication May lose volatile evidence, business disruption
EDR Isolation Isolate via EDR while maintaining telemetry Need to continue monitoring Attacker may detect and accelerate
Account Disable Disable compromised accounts Credential theft confirmed Business impact, attacker may have other access
Block IOCs Block malicious IPs/domains at firewall Known C2 infrastructure Attacker may have backup channels
Segment Network Isolate affected segment Widespread compromise Major business disruption
Containment Considerations
  • Don't tip off the attacker: Hasty containment may cause attacker to accelerate or destroy evidence
  • Preserve evidence: Capture memory and disk before major changes
  • Coordinate timing: Execute containment actions simultaneously across affected systems
  • Document everything: Record all actions with timestamps

Eradication

Remove attacker presence completely:

  • Remove malware from all affected systems
  • Eliminate all persistence mechanisms (registry, scheduled tasks, services)
  • Reset compromised credentials (all accounts accessed by attacker)
  • Patch exploited vulnerabilities
  • Block attacker infrastructure (C2, domains, IPs)
  • Revoke stolen certificates or tokens

Recovery

1
Restore Systems
  • Restore from known-good backups (pre-compromise)
  • Rebuild from clean images if needed
  • Apply all security patches before reconnection
  • Implement additional security controls
2
Validate Eradication
  • Scan all systems for IOCs
  • Verify persistence mechanisms removed
  • Monitor for re-compromise indicators
  • Test that vulnerabilities are patched
3
Return to Production
  • Gradual reconnection with monitoring
  • Validate business functions restored
  • Enhanced monitoring for 30-90 days
  • Document recovery completion

Phase 4: Post-Incident Activity

Learn from every incident to improve future response.

Post-Incident Review (PIR)

Conduct within 1-2 weeks of incident closure:

QuestionPurpose
What happened?Establish facts of the incident
How was it detected?Evaluate detection capabilities
How long before detection?Measure dwell time
What worked well?Identify successful practices to repeat
What could improve?Identify gaps without blame
What should we do differently?Actionable improvements

Documentation Requirements

INCIDENT REPORT STRUCTURE

1. EXECUTIVE SUMMARY
- What happened (1-2 paragraphs)
- Business impact
- Current status

2. INCIDENT DETAILS
- Detection date/time
- Incident type
- Severity
- Attack vector

3. TIMELINE
- Chronological events

4. SCOPE
- Systems affected
- Accounts affected
- Data at risk

5. RESPONSE ACTIONS
- Containment actions
- Eradication steps
- Recovery activities

6. ROOT CAUSE
- Initial access method
- Contributing factors

7. LESSONS LEARNED
- What worked
- What to improve

8. RECOMMENDATIONS
- Short-term actions
- Long-term improvements

Improvement Actions

  • Detection: Create new detections for observed TTPs
  • Prevention: Patch vulnerabilities, improve controls
  • Process: Update playbooks based on lessons
  • Training: Train team on gaps identified
  • Tools: Acquire tools to address capability gaps

Incident Response Quick Actions

Immediate Actions for Major Incidents
  1. Activate IR team - Get people on the call/war room
  2. Preserve evidence - Capture memory before rebooting anything
  3. Assess scope - How big is this? Is it still active?
  4. Contain (carefully) - Isolate affected systems if safe to do so
  5. Document everything - Start the timeline immediately
  6. Notify stakeholders - Management, legal, communications
  7. Consider external help - Activate IR retainer if needed
