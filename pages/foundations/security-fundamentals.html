Security Fundamentals

Core security concepts every SOC analyst must understand. These principles underpin everything you'll do in security operations.

The CIA Triad

The three pillars of information security. Every security control exists to protect one or more of these:

PrincipleMeaningThreat ExampleProtection Example
ConfidentialityOnly authorized people can access informationData breach exposes customer recordsEncryption, access controls, DLP
IntegrityInformation hasn't been tampered withAttacker modifies financial recordsHashing, digital signatures, audit logs
AvailabilitySystems and data are accessible when neededDDoS attack takes website offlineRedundancy, backups, DDoS protection

Authentication vs Authorization

These are commonly confused but fundamentally different:

ConceptQuestion It AnswersExample
Authentication"Who are you?"Entering username and password to prove you're John Smith
Authorization"What are you allowed to do?"John Smith can read files but not delete them

Authentication Factors

FactorTypeExamplesStrength
Something you knowKnowledgePassword, PIN, security questionWeak (can be guessed, phished, stolen)
Something you havePossessionPhone, security key, smart cardMedium (can be stolen, but harder)
Something you areInherenceFingerprint, face, irisStrong (hard to fake, but not impossible)
Somewhere you areLocationGPS, IP address, networkSupplemental (easy to spoof)

Multi-Factor Authentication (MFA)

MFA requires two or more different factors. This is crucial because:

  • If password is stolen, attacker still needs your phone
  • If phone is stolen, attacker still needs your password
  • Dramatically reduces successful account compromises (by 99%+ according to Microsoft)
MFA Bypass Techniques

Attackers can still bypass MFA through: SIM swapping (stealing phone number), real-time phishing (Evilginx, Modlishka), MFA fatigue (spamming push notifications), session hijacking (stealing cookies after MFA). SOC analysts must understand these to detect them.

Defense in Depth

Never rely on a single security control. Layer multiple defenses so if one fails, others still protect you:

LayerExamplesWhat It Stops
PerimeterFirewall, WAF, email gatewayAttacks from outside the network
NetworkSegmentation, IDS/IPS, NACLateral movement, internal attacks
EndpointEDR, antivirus, host firewallMalware, unauthorized software

Least Privilege Principle

Users should only have the minimum access required to do their job. Nothing more.

Bad PracticeGood PracticeWhy It Matters
All users are local adminsUsers have standard accounts; admins use separate admin accountsMalware can't install without admin rights
Shared admin passwordsUnique credentials per person, per systemCompromised password affects only one account
Permanent access to everythingJust-in-time access, time-limitedReduces window for abuse
Service accounts with domain adminService accounts with minimal required permissionsCompromised service account can't take over domain

Encryption Basics

Encryption transforms readable data into unreadable data using a key.

Types of Encryption

TypeHow It WorksUse CasesExamples
SymmetricSame key encrypts and decryptsBulk data encryption (fast)AES, ChaCha20
AsymmetricPublic key encrypts, private key decrypts (or vice versa)Key exchange, digital signaturesRSA, ECC
HashingOne-way transformation (can't reverse)Password storage, integrity verificationSHA-256, bcrypt

Encryption in Practice

  • HTTPS: Uses TLS to encrypt web traffic (asymmetric for key exchange, symmetric for data)
  • Disk encryption: BitLocker, FileVault encrypt entire drives
  • Email encryption: S/MIME, PGP encrypt email content
  • VPN: Creates encrypted tunnel for all traffic

Logging and Monitoring

If you don't have logs, you can't detect attacks. Period.

Log SourceWhat It RecordsWhy SOC Needs It

Firewall logsAllowed/blocked network connectionsDetect C2 communication, port scanning
Endpoint logsProcess execution, file changes, registryDetect malware, persistence, lateral movement
Application logsApplication-specific eventsDetect application attacks, misuse
Cloud logsCloud resource changes, accessDetect cloud misconfigurations, unauthorized access

Vulnerability vs Threat vs Risk

TermDefinitionExample
VulnerabilityA weakness that could be exploitedUnpatched server with known CVE
ThreatSomething that could exploit a vulnerabilityRansomware group scanning for that CVE
RiskLikelihood × Impact of threat exploiting vulnerabilityHigh risk if server is internet-facing and has sensitive data

Risk = Threat × Vulnerability × Impact
