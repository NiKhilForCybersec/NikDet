Vulnerability Scanning

Techniques and tools for discovering vulnerabilities across your environment.

Scanning Types

TypeDescriptionUse Case
Network Scanning Scans hosts over the network for vulnerabilities General infrastructure assessment
Authenticated Scanning Logs into systems for deeper inspection Comprehensive assessment (recommended)
Agent-Based Local agent reports vulnerabilities Continuous monitoring, remote workers
Web Application Tests web apps for OWASP vulnerabilities Web application security
Container Scanning Scans container images for vulnerabilities DevSecOps, CI/CD pipelines
Cloud Configuration Checks cloud misconfigurations (CSPM) Cloud security posture

Authenticated vs. Unauthenticated

AspectUnauthenticatedAuthenticated
VisibilityNetwork-visible services onlyFull system including local apps
AccuracyHigher false positivesMore accurate results
Coverage~30% of vulnerabilities~90%+ of vulnerabilities
SetupSimpleRequires credentials
RiskLowCredential management needed
Best Practice

Always use authenticated scanning when possible. Unauthenticated scans miss a significant portion of vulnerabilities.

Scanning Frequency

Asset TypeRecommended FrequencyRationale
Internet-FacingWeekly or continuousHigh exposure, prime target
Critical InternalWeeklyHigh business impact
Standard InternalMonthlyBalance of coverage and resources
Development/TestBefore deploymentCatch before production
Container ImagesOn build + continuousDevSecOps integration

Scanner Configuration

Nessus Example

# Nessus CLI scan
nessuscli scan --policy "Advanced Network Scan" \
  --targets 192.168.1.0/24 \
  --credentials windows:admin:P@ssw0rd \
  --output results.nessus

# Key scan policies:
- Basic Network Scan: Quick unauthenticated scan
- Advanced Scan: Customizable, recommended
- Credentialed Patch Audit: Best for patch compliance
- Web Application Tests: OWASP vulnerabilities

OpenVAS Example

# OpenVAS scan with GVM
gvm-cli --gmp-username admin --gmp-password secret \
  socket --xml "Network
  192.168.1.0/24"

# Create task and start scan
gvm-cli ... --xml "
  Weekly Scan
  
  
"

Container Scanning

# Trivy - scan container image
trivy image nginx:latest

# Trivy - scan with severity filter
trivy image --severity HIGH,CRITICAL nginx:latest

# Trivy - scan filesystem/IaC
trivy fs --security-checks vuln,config /path/to/project

# Grype - scan image
grype nginx:latest

# Scan in CI/CD pipeline
trivy image --exit-code 1 --severity CRITICAL $IMAGE_NAME

Nuclei Example

# Update templates
nuclei -update-templates

# Scan with all templates
nuclei -u https://target.com

# Scan with specific severity
nuclei -u https://target.com -severity critical,high

# Scan multiple targets
nuclei -l targets.txt -severity critical,high -o results.txt

# Scan for specific CVEs
nuclei -u https://target.com -tags cve

Scan Results Management

  • Deduplicate: Remove duplicate findings across scans
  • Enrich: Add context (asset owner, criticality, EPSS)
  • Correlate: Link to threat intel (KEV, exploit availability)
  • Prioritize: Apply risk-based scoring
  • Track: Monitor remediation progress

False Positive Management

ActionWhen to Use
Accept RiskVulnerability exists but compensating controls in place
Mark False PositiveScanner incorrectly identified vulnerability
DeferCannot remediate now, schedule for later
ExceptionBusiness justification to not remediate
