Threat Hunting Reality

Let's be honest about what threat hunting actually looks like:

What Threat Hunting ISN'T

  • ❌ Running a saved query once a week and calling it "hunting"
  • ❌ Waiting for alerts and investigating them
  • ❌ Always finding APTs and nation-states
  • ❌ Magic that only elite analysts can do

What Threat Hunting IS

  • ✓ Proactively looking for threats that bypass existing detections
  • ✓ Forming hypotheses and testing them with data
  • ✓ Often finding NOTHING (that's okay - it means defenses are working)
  • ✓ Sometimes finding misconfigurations, policy violations, shadow IT
  • ✓ Occasionally finding actual malicious activity
  • ✓ Always learning about your environment

Realistic Hunt Outcomes

OutcomeFrequencyValue
Nothing found ~60% Validates defenses, builds environmental knowledge
Misconfigurations found ~20% Security improvements, better hygiene
Policy violations found ~10% Training needs, process improvements
Shadow IT / unauthorized software ~7% Risk reduction, asset inventory improvement
Actual malicious activity ~3% Incident prevented, detection gap found

Hunt Process (Practical)

Step 1: Form a Hypothesis 15-30 min

A hypothesis is a testable statement about threat activity. Good hypotheses come from:

  • Threat intelligence: "APT group X is targeting our industry using technique Y"
  • Recent incidents: "We got phished last month - are there other compromises?"
  • Coverage gaps: "We don't have a detection for living-off-the-land techniques"
  • Environmental changes: "New VPN deployed - is it being abused?"

Example Hypotheses

  • "Attackers are using LOLBins (certutil, bitsadmin) to download malware"
  • "Compromised accounts are being used to access SharePoint from unusual locations"
  • "Persistence mechanisms exist via scheduled tasks we don't know about"
  • "Data is being exfiltrated to cloud storage services"

Step 2: Identify Data Sources 10 min

Hypothesis: "LOLBins downloading malware"

Data sources needed:
✓ Process execution logs (DeviceProcessEvents, Sysmon 1)
✓ Network connections (DeviceNetworkEvents, Sysmon 3)
✓ File creation (DeviceFileEvents, Sysmon 11)
? Command line logging - is it enabled? CHECK FIRST

Step 3: Build and Run Queries 1-4 hours

Start broad, then narrow based on results.

Step 4: Analyze Results 1-2 hours

This is where experience matters. For each result, determine:

  • Is this expected/legitimate activity?
  • Is this suspicious but not necessarily malicious?
  • Is this definitely malicious?

Step 5: Document and Act 30 min - 2 hours

  • If nothing found: Document what you checked, update hypothesis
  • If misconfiguration found: Report to relevant team
  • If malicious activity found: Escalate to incident response
  • Always: Consider creating detection rule for future

Real Hunt Scenarios

Hunt 1: LOLBin Abuse 2-3 hours

Hypothesis: Attackers are using legitimate Windows tools (certutil, bitsadmin, mshta) to download malicious payloads.

Query:

DeviceProcessEvents
| where TimeGenerated > ago(7d)
| where FileName in ("certutil.exe", "bitsadmin.exe", "mshta.exe", "regsvr32.exe")
| where ProcessCommandLine contains "http" or ProcessCommandLine contains "ftp"
| project TimeGenerated, DeviceName, AccountName, FileName, ProcessCommandLine, 
    InitiatingProcessFileName, InitiatingProcessCommandLine
| order by TimeGenerated desc

Results (47 events):

Benign (42 events): certutil -urlcache used by SCCM for certificate updates. Expected, from SCCM server.
Suspicious (4 events): bitsadmin downloading from internal SharePoint. User is IT admin - probably legitimate but unusual method. Follow up with user.
MALICIOUS (1 event): mshta.exe executing script from hxxp://pastebin[.]com on WKSTN-045. User is in Finance. ESCALATE IMMEDIATELY.

Hunt Outcomes

  • 1 active compromise found → Incident response initiated
  • Created detection rule for non-SCCM LOLBin downloads
  • Documented SCCM as known legitimate source

Hunt 2: Unusual Authentication Patterns 2-4 hours

Hypothesis: Compromised accounts are being used to access resources from unusual locations or at unusual times.

Query:

SigninLogs
| where TimeGenerated > ago(14d)
| where ResultType == 0  // Successful logins only
| extend Hour = datetime_part("hour", TimeGenerated)
| extend DayOfWeek = dayofweek(TimeGenerated)
| summarize 
    LoginCount = count(),
    UniqueIPs = dcount(IPAddress),
    Locations = make_set(Location),
    OffHoursLogins = countif(Hour < 6 or Hour > 22),
    WeekendLogins = countif(DayOfWeek == 0 or DayOfWeek == 6)
    by UserPrincipalName
| where UniqueIPs > 5 or OffHoursLogins > 10 or WeekendLogins > 5
| order by UniqueIPs desc

Results (23 users flagged):

Benign (18 users): Sales team - travel frequently, VPN from hotels explains multiple IPs/locations.
Benign (3 users): IT on-call staff - off-hours access is expected for their role.
SUSPICIOUS (2 users): Finance users with logins from countries they don't travel to. Contacted users - one confirmed travel (benign), one did NOT travel to Singapore. Investigating further.

Hunt Outcomes

  • 1 account potentially compromised → Password reset, MFA review
  • Identified need for better travel tracking integration
  • Created baseline of normal travel patterns for Sales team

Hunt 3: Scheduled Task Persistence 2-3 hours

Hypothesis: Attackers have established persistence via scheduled tasks that we're not aware of.

Query:

DeviceProcessEvents
| where TimeGenerated > ago(30d)
| where FileName == "schtasks.exe"
| where ProcessCommandLine contains "/create"
| project TimeGenerated, DeviceName, AccountName, ProcessCommandLine
| extend TaskName = extract(@'/tn\s+"?([^"\s]+)"?', 1, ProcessCommandLine)
| extend TaskAction = extract(@'/tr\s+"?([^"]+)"?', 1, ProcessCommandLine)
| where TaskAction !contains "Microsoft" and TaskAction !contains "Windows"
| summarize FirstSeen=min(TimeGenerated), LastSeen=max(TimeGenerated), 
    Hosts=make_set(DeviceName) by TaskName, TaskAction, AccountName

Results (34 unique tasks):

Benign (28 tasks): Known software: backup agents, update checkers, monitoring tools.
Suspicious (5 tasks): IT admin scripts - not documented. Need to verify and document.
SUSPICIOUS (1 task): Task "WindowsUpdate" running PowerShell from C:\Users\Public\. That's NOT how Windows Update works. INVESTIGATE.

Hunt Outcomes

  • Fake "WindowsUpdate" task found → likely persistence mechanism, investigating host
  • 5 undocumented IT scripts identified → created documentation
  • Created allowlist of legitimate scheduled tasks

Common Hunt Findings

Here's what you'll actually find most often during hunts:

Finding TypeExampleAction

Policy violations Users sharing credentials, disabling security tools User training, enforce controls
Misconfigurations Services running as admin, open shares, weak permissions Remediate, add to hardening checklist
Old/forgotten systems Test servers still running, decommissioned systems online Asset inventory update, decommission
Detection gaps Activity that should alert but doesn't Create new detection rule
