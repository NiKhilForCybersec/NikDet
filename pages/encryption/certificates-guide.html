Creating Certificates

CERTIFICATE CREATION WORKFLOW ═══════════════════════════════════════════════════════════════════════════════ STEP 1: GENERATE PRIVATE KEY ───────────────────────────────────────────────────────────────────────────── Choose algorithm and key size: RSA (traditional, widely compatible): ┌─────────────────────────────────────────────────────────────────────────┐ │ openssl genrsa -out private.key 2048 # Minimum acceptable │ │ openssl genrsa -out private.key 4096 # Better security │ └─────────────────────────────────────────────────────────────────────────┘ ECDSA (modern, smaller, faster): ┌─────────────────────────────────────────────────────────────────────────┐ │ openssl ecparam -genkey -name prime256v1 -out private.key │ │ openssl ecparam -genkey -name secp384r1 -out private.key # Stronger │ └─────────────────────────────────────────────────────────────────────────┘ ⚠️ PROTECT THIS KEY! Anyone with it can impersonate your server. Set permissions: chmod 600 private.key STEP 2: CREATE CERTIFICATE SIGNING REQUEST (CSR) ───────────────────────────────────────────────────────────────────────────── CSR contains: Your public key + Information about you/your organization CSR is signed by: Your private key (proves you have it) ┌─────────────────────────────────────────────────────────────────────────┐ │ openssl req -new -key private.key -out request.csr │ │ │ │ You will be prompted for: │ │ Country Name (2 letter code) []:US │ │ State or Province Name []:California │ │ Locality Name (city) []:San Francisco │ │ Organization Name []:My Company Inc │ │ Organizational Unit Name []:IT Department │ │ Common Name []:www.example.com ◄── YOUR DOMAIN NAME │ │ Email Address []:admin@example.com │ └─────────────────────────────────────────────────────────────────────────┘ For multiple domains (SAN), use config file: ┌─────────────────────────────────────────────────────────────────────────┐ │ # san.cnf │ │ [req] │ │ distinguished_name = req_distinguished_name │ │ req_extensions = v3_req │ │ │ │ [req_distinguished_name] │ │ CN = www.example.com │ │ │ │ [v3_req] │ │ subjectAltName = @alt_names │ │ │ │ [alt_names] │ │ DNS.1 = www.example.com │ │ DNS.2 = example.com │ │ DNS.3 = api.example.com │ │ DNS.4 = *.staging.example.com │ └─────────────────────────────────────────────────────────────────────────┘ openssl req -new -key private.key -out request.csr -config san.cnf STEP 3: SUBMIT CSR TO CERTIFICATE AUTHORITY ───────────────────────────────────────────────────────────────────────────── For PUBLIC CA (DigiCert, Sectigo, etc.): 1. Certificate Monitoring

Certificate Expiration Monitoring

Set up alerts at least 30-60 days before expiration to avoid outages.

# Bash script for certificate expiration monitoring
#!/bin/bash

DOMAINS="example.com api.example.com www.example.com"
WARN_DAYS=30
CRIT_DAYS=7

for domain in $DOMAINS; do
    expiry=$(echo | openssl s_client -connect $domain:443 2>/dev/null | \
             openssl x509 -noout -enddate | cut -d= -f2)
    expiry_epoch=$(date -d "$expiry" +%s)
    now_epoch=$(date +%s)
    days_left=$(( ($expiry_epoch - $now_epoch) / 86400 ))
    
    if [ $days_left -lt $CRIT_DAYS ]; then
        echo "CRITICAL: $domain expires in $days_left days!"
    elif [ $days_left -lt $WARN_DAYS ]; then
        echo "WARNING: $domain expires in $days_left days"
    else
        echo "OK: $domain expires in $days_left days"
    fi
done

Best Practices

Certificate Security Best Practices

Key ProtectionStore private keys encrypted, use HSMs for high-value certs, restrict file permissions (600)
Key SizeRSA: minimum 2048-bit, prefer 4096. ECDSA: P-256 or P-384
Validity Period1 year maximum for public certs (industry standard since 2020)
AutomationUse Let's Encrypt + certbot for automatic renewal. Use ACME protocol
MonitoringAlert 60, 30, 14, 7, 3, 1 days before expiration
TLS ConfigurationTLS 1.2 minimum, prefer TLS 1.3, disable weak ciphers
HSTSEnable Strict-Transport-Security header, consider preload list
Certificate TransparencyMonitor CT logs for unauthorized certificates for your domains
