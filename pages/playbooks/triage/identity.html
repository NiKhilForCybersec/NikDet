Identity Security Alert Triage

Comprehensive triage procedure for identity and access management alerts including privileged account changes, service account anomalies, group modifications, and identity protection alerts.

TierL1 / L2
Time5-15 min
ToolsAzure AD, AD, SIEM

Triage Decision Flow

1
Identify the Change Type
Change TypeRisk LevelImmediate Concern
Global Admin assignedCriticalHighest privilege in tenant
Domain Admin addedCriticalFull domain control
Service account interactive loginHighShould not happen
New user with admin roleHighPersistence mechanism
OAuth app with mail accessHighData access risk
Standard group changeLowNormal operations
2
Verify the Actor
  • Who made the change? - Check if authorized admin
  • From where? - IP address, location expected?
  • When? - Business hours or off-hours?
  • Change ticket? - Approved change request?
  • Normal behavior? - Does this admin typically make such changes?
3
Assess the Target
Target TypeRisk FactorCheck
New accountHighIs account creation legitimate?
Existing userMediumIs role change appropriate?
Service accountHighAny change is suspicious
Guest/ExternalHighVerify business need
Admin accountCriticalExtra scrutiny required
4
Make Triage Decision
ScenarioDecisionAction
Authorized change with ticketCloseDocument, verify complete
Admin doing normal workCloseDocument
Unknown admin activityInvestigateContact admin, verify
Service account anomalyEscalateInvestigate immediately
Unauthorized privilege changeEscalateRevert, investigate

Identity Triage Queries

// KQL - Azure AD privileged role assignments
AuditLogs
| where TimeGenerated > ago(24h)
| where OperationName has_any ("Add member to role", 
    "Add eligible member to role", "Add scoped member to role")
| extend TargetUser = tostring(TargetResources[0].displayName)
| extend Role = tostring(TargetResources[0].modifiedProperties[1].newValue)
| extend Actor = tostring(InitiatedBy.user.userPrincipalName)
| project TimeGenerated, Actor, OperationName, TargetUser, Role

// KQL - AD privileged group changes
SecurityEvent
| where TimeGenerated > ago(24h)
| where EventID in (4728, 4732, 4756) // Member added to group
| where TargetUserName has_any ("Domain Admins", "Enterprise Admins",
    "Schema Admins", "Administrators", "Account Operators")
| project TimeGenerated, SubjectUserName, MemberName, TargetUserName

// KQL - Service account interactive logins
SigninLogs
| where TimeGenerated > ago(24h)
| where UserPrincipalName has_any ("svc_", "service_", "_svc")
| where ResultType == "0"
| where AppDisplayName != "Windows Sign-In" // Interactive
| project TimeGenerated, UserPrincipalName, AppDisplayName,
    IPAddress, Location

// KQL - OAuth app consent grants
AuditLogs
| where TimeGenerated > ago(7d)
| where OperationName == "Consent to application"
| extend AppName = tostring(TargetResources[0].displayName)
| extend Permissions = tostring(TargetResources[0].modifiedProperties)
| extend User = tostring(InitiatedBy.user.userPrincipalName)
| project TimeGenerated, User, AppName, Permissions

// KQL - New user accounts created
AuditLogs
| where TimeGenerated > ago(24h)
| where OperationName == "Add user"
| extend NewUser = tostring(TargetResources[0].userPrincipalName)
| extend Creator = tostring(InitiatedBy.user.userPrincipalName)
| project TimeGenerated, Creator, NewUser, OperationName

// KQL - Password resets by admins
AuditLogs
| where OperationName == "Reset password (by admin)"
| extend TargetUser = tostring(TargetResources[0].userPrincipalName)
| extend Admin = tostring(InitiatedBy.user.userPrincipalName)
| project TimeGenerated, Admin, TargetUser

// SPL - AD privileged group changes
index=wineventlog EventCode IN (4728, 4732, 4756)
| search TargetUserName="Domain Admins" OR TargetUserName="Enterprise Admins"
| table _time, SubjectUserName, MemberName, TargetUserName

Escalation Criteria

Escalate Immediately If:
  • Global/Domain Admin role assigned without ticket
  • Service account interactive login detected
  • Unknown user granted privileged role
  • OAuth app with mail/files access consented
  • Bulk user creation outside HR process
  • Admin account created outside normal process
  • Privileged group modified by non-admin
  • Conditional Access policy disabled/modified
