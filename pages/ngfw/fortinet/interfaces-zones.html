FortiGate Interfaces & Zones

Complete guide to interface configuration including physical ports, VLANs, zones, VDOMs, and link aggregation.

Understanding Interfaces vs Zones

Interface = A physical or logical port (like a door in your building)
Zone = A grouping of interfaces with the same trust level (like "employee entrance" vs "visitor entrance")

You configure physical connectivity on interfaces, but write security policies based on zones.

Physical Interface Configuration

View Current Interfaces

# List all interfaces
get system interface

# Detailed view of specific interface
get system interface port1

# Show interface status (up/down, speed, duplex)
get hardware nic port1
diagnose hardware deviceinfo nic port1

Configure WAN Interface (Internet)

# Static IP configuration
config system interface
    edit "wan1"
        set vdom "root"
        set mode static
        set ip 203.0.113.10 255.255.255.248
        set allowaccess ping
        set type physical
        set alias "Internet-Primary"
        set role wan
        set snmp-index 1
    next
end

# DHCP configuration (for cable/DSL)
config system interface
    edit "wan1"
        set mode dhcp
        set allowaccess ping
        set role wan
        set defaultgw enable
        set dns-server-override disable  # Use manually configured DNS
    next
end

# PPPoE configuration (DSL with auth)
config system interface
    edit "wan1"
        set mode pppoe
        set username "user@isp.com"
        set password your-password
        set allowaccess ping
        set role wan
    next
end

Configure LAN Interface (Internal Network)

config system interface
    edit "port2"
        set vdom "root"
        set mode static
        set ip 10.1.1.1 255.255.255.0
        set allowaccess ping https ssh
        set type physical
        set alias "LAN-Users"
        set role lan
        set device-identification enable  # Identify connected devices
    next
end

# Enable DHCP server on LAN interface
config system dhcp server
    edit 1
        set dns-service default
        set default-gateway 10.1.1.1
        set netmask 255.255.255.0
        set interface "port2"
        config ip-range
            edit 1
                set start-ip 10.1.1.100
                set end-ip 10.1.1.200
            next
        end
        set lease-time 86400
        set dns-server1 10.1.1.10  # Internal DNS
        set dns-server2 8.8.8.8
        set domain "company.local"
        set ntp-server1 10.1.1.1
    next
end

Configure DMZ Interface

config system interface
    edit "port3"
        set vdom "root"
        set mode static
        set ip 172.16.1.1 255.255.255.0
        set allowaccess ping
        set type physical
        set alias "DMZ-Servers"
        set role dmz
    next
end

VLAN Configuration

Why VLANs?

VLANs let you create multiple logical networks on a single physical interface. This is essential for:

  • Segmenting user departments (HR, Finance, Engineering)
  • Separating voice and data traffic
  • Creating guest networks
  • When you have more networks than physical ports

Create VLAN Interfaces

# Create VLAN 100 for Users on port2
config system interface
    edit "VLAN100-Users"
        set vdom "root"
        set type vlan
        set vlanid 100
        set interface "port2"
        set ip 10.100.1.1 255.255.255.0
        set allowaccess ping https ssh
        set alias "Users-VLAN"
        set role lan
        set device-identification enable
    next
end

# Create VLAN 200 for Servers
config system interface
    edit "VLAN200-Servers"
        set vdom "root"
        set type vlan
        set vlanid 200
        set interface "port2"
        set ip 10.200.1.1 255.255.255.0
        set allowaccess ping
        set alias "Servers-VLAN"
        set role lan
    next
end

# Create VLAN 300 for Voice
config system interface
    edit "VLAN300-Voice"
        set vdom "root"
        set type vlan
        set vlanid 300
        set interface "port2"
        set ip 10.300.1.1 255.255.255.0
        set allowaccess ping
        set alias "Voice-VLAN"
        set role lan
    next
end

# Create VLAN 999 for Guest WiFi
config system interface
    edit "VLAN999-Guest"
        set vdom "root"
        set type vlan
        set vlanid 999
        set interface "port2"
        set ip 192.168.99.1 255.255.255.0
        set allowaccess ping
        set alias "Guest-WiFi"
        set role lan
    next
end

Switch Configuration Required

The switch port connected to the FortiGate must be configured as a trunk port carrying all necessary VLANs:

# Cisco switch example
interface GigabitEthernet0/1
  description "To FortiGate port2"
  switchport mode trunk
  switchport trunk allowed vlan 100,200,300,999
  switchport trunk native vlan 1

Zones

Understanding Zones

Zones group interfaces that should be treated the same way in firewall policies.

Create Zones

# Create Trust zone (internal networks)
config system zone
    edit "Trust"
        set description "Internal trusted networks"
        set interface "VLAN100-Users" "VLAN200-Servers" "VLAN300-Voice"
    next
end

# Create Untrust zone (internet-facing)
config system zone
    edit "Untrust"
        set description "Internet connections"
        set interface "wan1" "wan2"
    next
end

# Create DMZ zone
config system zone
    edit "DMZ"
        set description "Public-facing servers"
        set interface "port3"
    next
end

# Create Guest zone
config system zone
    edit "Guest"
        set description "Guest and BYOD networks"
        set interface "VLAN999-Guest"
    next
end

Zone Behavior

Intra-zone traffic: By default, traffic between interfaces in the same zone is allowed without a policy.
Inter-zone traffic: Requires explicit firewall policy.

To control intra-zone traffic, use interface-based policies instead of zone-based.

Link Aggregation (LAG/802.3ad)

Why Link Aggregation?

  • Bandwidth: Combine multiple links for higher throughput
  • Redundancy: If one link fails, traffic continues on others
  • Common uses: Core switch connections, server farm connections

Configure LAG (Aggregate Interface)

# Create aggregate interface with port5 and port6
config system interface
    edit "agg1"
        set vdom "root"
        set type aggregate
        set member "port5" "port6"
        set ip 10.10.10.1 255.255.255.0
        set allowaccess ping https ssh
        set alias "LAG-to-CoreSwitch"
        
        # LACP mode (recommended)
        set lacp-mode active
        set lacp-speed slow  # or fast
        
        # Minimum number of links for LAG to be "up"
        set min-links 1
    next
end

# Static LAG (no LACP - not recommended)
config system interface
    edit "agg2"
        set type aggregate
        set member "port7" "port8"
        set lacp-mode static
        set ip 10.20.20.1 255.255.255.0
    next
end

Switch Must Match

The switch must also be configured for LACP on corresponding ports:

# Cisco switch example
interface Port-channel1
  description "To FortiGate LAG"
  switchport mode trunk

interface range GigabitEthernet0/5-6
  description "To FortiGate agg1"
  channel-group 1 mode active

Virtual Domains (VDOMs)

What are VDOMs?

VDOMs are virtual FortiGates within a single physical device. Each VDOM has its own:

  • Interfaces and routing tables
  • Firewall policies
  • Security profiles
  • Administrator accounts

Use Cases

  • Multi-tenant: MSPs hosting multiple customers
  • Separation: Isolate business units or compliance zones
  • Lab/Production: Separate environments on same hardware

Enable VDOMs

# Enable VDOM mode (requires reboot)
config system global
    set vdom-mode multi-vdom
end

# Reboot to apply
execute reboot

Create VDOMs

# Create a new VDOM
config vdom
    edit "CustomerA"
    next
    edit "CustomerB"
    next
end

# Assign interfaces to VDOMs
config global
config system interface
    edit "port5"
        set vdom "CustomerA"
    next
    edit "port6"
        set vdom "CustomerB"
    next
end
end

# Switch to VDOM to configure it
config vdom
edit "CustomerA"
    # Now configure as if it's a standalone FortiGate
    config system interface
        edit "port5"
            set mode static
            set ip 10.50.1.1 255.255.255.0
        next
    end
    # ... firewall policies, etc.
end

Inter-VDOM Links

To allow traffic between VDOMs, create virtual links:

config global
config system vdom-link
    edit "CustomerA-to-root"
        set type ethernet
    next
end

# This creates two virtual interfaces:
# CustomerA-to-root0 in VDOM CustomerA
# CustomerA-to-root1 in VDOM root

# Configure IPs and routing in each VDOM
config vdom
edit "CustomerA"
    config system interface
        edit "CustomerA-to-root0"
            set ip 10.255.1.1 255.255.255.252
            set allowaccess ping
        next
    end
end
end

config vdom
edit "root"
    config system interface
        edit "CustomerA-to-root1"
            set ip 10.255.1.2 255.255.255.252
            set allowaccess ping
        next
    end
end
end

Software Switch / Hardware Switch

What is a Software Switch?

Groups multiple physical interfaces into a single logical switch. All ports share the same IP and act as a layer 2 switch.

Create Software Switch

config system switch-interface
    edit "LAN-Switch"
        set vdom "root"
        set member "port2" "port3" "port4"
        set type switch
        set intra-switch-policy implicit
    next
end

# Now configure IP on the switch interface
config system interface
    edit "LAN-Switch"
        set ip 10.1.1.1 255.255.255.0
        set allowaccess ping https ssh
        set role lan
    next
end

Software vs Hardware Switch

Hardware Switch: Uses dedicated switch chip - better performance, limited features
Software Switch: Uses CPU - more flexible, may impact performance

Desktop models often have built-in hardware switches. Check your model's documentation.
