Real Event Examples

Event 4624: Successful Logon - What to Look For

Normal User Logon (Interactive)
An account was successfully logged on. Subject: Security ID: SYSTEM Account Name: WORKSTATION$ Account Domain: CORP Logon Information: Logon Type: 2 ← Interactive (keyboard login) New Logon: Security ID: CORP\john.smith Account Name: john.smith Account Domain: CORP Network Information: Workstation Name: WORKSTATION Source Network Address: - ← Local logon, no network address Source Port: - Logon Process: User32 Authentication Package: Negotiate

Analysis: Normal user logging in at their workstation. Logon Type 2 = interactive. No concerns.

Suspicious: Network Logon to Workstation
An account was successfully logged on. Logon Information: Logon Type: 3 ← Network logon (remote) New Logon: Security ID: CORP\admin_svc Account Name: admin_svc ← Service account Network Information: Workstation Name: WKSTN-FIN-023 Source Network Address: 10.1.50.201 ← Different subnet Source Port: 49847

Analysis: Service account doing network logon to workstation from different subnet. Why is a service account logging into a workstation remotely? Investigate!

MALICIOUS: Pass-the-Hash Pattern
An account was successfully logged on. Logon Information: Logon Type: 9 ← NewCredentials (runas /netonly) New Logon: Security ID: CORP\domain_admin Account Name: domain_admin Network Information: Source Network Address: 10.1.10.55 ← Workstation IP Logon Process: seclogo Authentication Package: Negotiate

Analysis: Logon Type 9 from a workstation for domain admin = Pass-the-Hash attack. Attacker using stolen admin credentials. ESCALATE IMMEDIATELY.

Event 4688: Process Creation - What to Look For

Normal: User Opens Notepad
A new process has been created. Creator Subject: Account Name: john.smith Process Information: New Process Name: C:\Windows\System32\notepad.exe Creator Process Name: C:\Windows\explorer.exe Process Command Line: "C:\Windows\System32\notepad.exe"

Analysis: User opened Notepad from Explorer. Normal activity.

MALICIOUS: Encoded PowerShell from Word
A new process has been created. Creator Subject: Account Name: jane.finance Process Information: New Process Name: C:\Windows\System32\WindowsPowerShell\v1.0\powershell.exe Creator Process Name: C:\Program Files\Microsoft Office\root\Office16\WINWORD.EXE Process Command Line: powershell.exe -nop -w hidden -enc SQBFAFgAIAAoAE4AZ...

Analysis: Word spawning hidden PowerShell with encoded command = macro malware! Classic phishing attack. The user opened a malicious document.

MALICIOUS: LSASS Access (Credential Dumping)
A new process has been created. Process Information: New Process Name: C:\Users\Public\procdump64.exe Creator Process Name: C:\Windows\System32\cmd.exe Process Command Line: procdump64.exe -ma lsass.exe lsass.dmp

Analysis: Procdump targeting LSASS = credential dumping attempt. Attacker trying to extract passwords from memory.

Attack Patterns in Logs

Pattern: Brute Force Attack

What you see:

Multiple 4625 events in short period: 4625 - Logon Failure - john.smith - Status: 0xC000006D (Bad password) 4625 - Logon Failure - john.smith - Status: 0xC000006D (Bad password) 4625 - Logon Failure - john.smith - Status: 0xC000006D (Bad password) ... (50+ more failures) 4624 - Logon Success - john.smith ← They guessed it!

Detection query:

SecurityEvent | where EventID == 4625 | summarize FailedAttempts=count(), SuccessAfter=countif(EventID==4624) by TargetUserName, IpAddress, bin(TimeGenerated, 5m) | where FailedAttempts > 10

Pattern: Lateral Movement via PsExec

What you see (on target):

Event 4624: Network logon (Type 3) - admin account from workstation IP Event 4688: cmd.exe spawned by PSEXESVC.exe Event 4688: attacker_commands.exe spawned by cmd.exe Event 7045 (System): New service installed "PSEXESVC"

Detection query:

SecurityEvent | where EventID == 4688 | where ParentProcessName contains "PSEXE" or NewProcessName contains "PSEXE" | project TimeGenerated, Computer, Account, NewProcessName, CommandLine

Pattern: DCSync Attack

What you see (on Domain Controller):

Event 4662: Object access Operation: {1131f6aa-9c07-11d1-f79f-00c04fc2dcd2} ← DS-Replication-Get-Changes Event 4662: Object access Operation: {1131f6ad-9c07-11d1-f79f-00c04fc2dcd2} ← DS-Replication-Get-Changes-All Subject: CORP\compromised_admin Source: 10.1.10.55 ← NOT a domain controller!

Why it's bad: Replication requests should only come from other DCs. If a workstation or server is requesting replication, someone is stealing the AD database (including all password hashes).

Investigation Scenarios

Scenario: "User Says They Didn't Log In"

User reports: "I got an email about a login from Russia but I wasn't there."

Investigation steps:

  1. Find the logon events:
SecurityEvent | where EventID == 4624 | where TargetUserName == "suspicious_user" | where TimeGenerated > ago(7d) | project TimeGenerated, LogonType, IpAddress, WorkstationName, AuthenticationPackageName | order by TimeGenerated desc
  1. Check what they did after logging in:
// Look for actions after the suspicious logon time SecurityEvent | where TimeGenerated between (datetime(2025-01-04 03:00) .. datetime(2025-01-04 04:00)) | where TargetUserName == "suspicious_user" or SubjectUserName == "suspicious_user" | project TimeGenerated, EventID, Activity, Computer | order by TimeGenerated
  1. Check for impossible travel:
// Find logins from different locations close in time SigninLogs | where UserPrincipalName == "user@company.com" | where TimeGenerated > ago(24h) | project TimeGenerated, Location, IPAddress, AppDisplayName | order by TimeGenerated

Scenario: "Malware Alert on Host - What Happened?"

Alert: Malware detected on WKSTN-045

Investigation steps:

  1. What processes ran around the detection time:
SecurityEvent | where Computer == "WKSTN-045" | where EventID == 4688 | where TimeGenerated between (datetime(2025-01-04 14:00) .. datetime(2025-01-04 14:30)) | project TimeGenerated, Account, NewProcessName, CommandLine, ParentProcessName | order by TimeGenerated
  1. Who logged in before the malware ran:
SecurityEvent | where Computer == "WKSTN-045" | where EventID == 4624 | where TimeGenerated > ago(24h) | project TimeGenerated, TargetUserName, LogonType, IpAddress | order by TimeGenerated desc
  1. Build the process tree (what spawned what):
// Look for suspicious parent-child relationships SecurityEvent | where Computer == "WKSTN-045" | where EventID == 4688 | where TimeGenerated > ago(1h) | where ParentProcessName contains "outlook" or ParentProcessName contains "winword" or ParentProcessName contains "excel" | project TimeGenerated, ParentProcessName, NewProcessName, CommandLine
