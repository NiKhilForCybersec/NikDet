Endpoint Isolation Playbook

Procedures for isolating compromised endpoints using EDR, network controls, and manual methods.

When to Isolate

ScenarioIsolation PriorityMethod
Active ransomwareImmediateEDR isolation or network disconnect
Confirmed C2 communicationImmediateEDR isolation
Credential theft detectedHigh (within minutes)EDR isolation
Lateral movement sourceImmediateEDR isolation + network block
Malware execution (contained)Medium (within 30 min)EDR isolation for investigation
Suspicious but unconfirmedLow (after triage)Consider impact before isolating

Isolation Methods by EDR Platform

Microsoft Defender for Endpoint

// Isolate via Portal
Security Center > Devices > [Device] > Response Actions > Isolate device

// Isolate via API (PowerShell)
$DeviceId = "device-id-here"
$Body = @{
    Comment = "SOC-2025-001: Ransomware investigation"
    IsolationType = "Full"  # or "Selective" (allows Outlook/Teams)
} | ConvertTo-Json

Invoke-RestMethod -Uri "https://api.security.microsoft.com/api/machines/$DeviceId/isolate" `
    -Method Post -Headers $Headers -Body $Body

// Release isolation
Invoke-RestMethod -Uri "https://api.security.microsoft.com/api/machines/$DeviceId/unisolate" `
    -Method Post -Headers $Headers -Body @{Comment="Cleared for release"} | ConvertTo-Json

// Check isolation status
DeviceInfo
| where DeviceName == "WORKSTATION01"
| project DeviceName, DeviceId, MachineGroup, HealthStatus, RiskScore, ExposureLevel

CrowdStrike Falcon

// Contain via Falcon Console
Host Management > Hosts > [Select Host] > Network Containment > Contain

// Contain via API
POST /devices/entities/devices-actions/v2?action_name=contain
{
    "ids": ["device-id-here"]
}

// Lift containment via API
POST /devices/entities/devices-actions/v2?action_name=lift_containment
{
    "ids": ["device-id-here"]
}

// Real-Time Response for investigation
Hosts > [Host] > Real Time Response
Commands: ps, netstat, reg query, get [file], kill [pid]

Cortex XDR

// Isolate via Console
Endpoints > [Endpoint] > Actions > Isolate Endpoint

// Isolate via API
POST /public_api/v1/endpoints/isolate
{
    "request_data": {
        "endpoint_id": "endpoint-id-here"
    }
}

// Live Terminal for investigation
Endpoints > [Endpoint] > Actions > Live Terminal

SentinelOne

// Network Quarantine via Console
Sentinels > [Agent] > Actions > Network Quarantine

// Disconnect from Network via API
POST /web/api/v2.1/agents/actions/disconnect
{
    "filter": {
        "ids": ["agent-id-here"]
    }
}

// Remote Shell for investigation
Sentinels > [Agent] > Actions > Remote Shell

Network-Level Isolation

When EDR isolation is unavailable or additional containment needed:

MethodImplementationProsCons
Switch port disableNetwork team disables portImmediate, completeManual, requires NOC
VLAN quarantineMove to isolated VLANControlled accessRequires NAC/switch config
Firewall blockBlock IP at perimeter/internal FWFlexibleMay affect legitimate traffic
802.1X reauthenticationForce re-auth to quarantine VLANAutomatedRequires 802.1X deployment
Physical disconnectUnplug network cableGuaranteedRequires physical access

Firewall Isolation Rules

// Palo Alto - Block all traffic from/to IP
set security-rule Quarantine-Host source any destination 10.1.2.50 action deny
set security-rule Quarantine-Host source 10.1.2.50 destination any action deny
commit

// Windows Firewall - Block all network (PowerShell on endpoint)
New-NetFirewallRule -DisplayName "Quarantine-Block-All" -Direction Outbound -Action Block
New-NetFirewallRule -DisplayName "Quarantine-Block-All-In" -Direction Inbound -Action Block

// Allow only EDR communication
New-NetFirewallRule -DisplayName "Allow-EDR" -Direction Outbound `
    -RemoteAddress "edr-cloud-ips" -Action Allow

Pre-Isolation Checklist

  • ☐ Document current device state (running processes, network connections)
  • ☐ Identify device owner and their role (VIP? Critical function?)
  • ☐ Check if device hosts critical services
  • ☐ Notify IR lead of isolation decision
  • ☐ Prepare user communication (if applicable)
  • ☐ Ensure EDR agent is responsive
  • ☐ Document ticket number for isolation comment

Investigation While Isolated

EDR live response commands for remote investigation:

// Process listing
processes

// Network connections (if available)
netstat -an

// Scheduled tasks
schtasks /query /fo LIST /v

// Services
sc query state= all

// Autorun locations
reg query "HKLM\SOFTWARE\Microsoft\Windows\CurrentVersion\Run"
reg query "HKCU\SOFTWARE\Microsoft\Windows\CurrentVersion\Run"

// Collect suspicious files
getfile "C:\Users\Public\malware.exe"

// Memory dump (if supported)
memdump

Release from Isolation

Release Criteria

  • ✅ Malware removed and verified clean
  • ✅ No persistence mechanisms found (or all removed)
  • ✅ User credentials reset
  • ✅ System reimaged (if severe compromise)
  • ✅ IR lead approval for release
  • ✅ Enhanced monitoring configured

Post-Release Monitoring

// Monitor released device for 7 days
DeviceProcessEvents
| where TimeGenerated > ago(7d)
| where DeviceName == "RELEASED-DEVICE"
| where FileName in~ ("powershell.exe", "cmd.exe", "wscript.exe")
| where ProcessCommandLine has_any ("-enc", "downloadstring", "invoke-expression")
| project TimeGenerated, FileName, ProcessCommandLine, AccountName
