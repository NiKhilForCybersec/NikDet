DLP Alert Triage

Procedures for triaging Data Loss Prevention alerts to identify true data exfiltration attempts.

Common DLP Alert Types

Alert TypeData CategorySeverity
PII DetectionSSN, DOB, addressesMedium-High
Financial DataCredit cards, bank accountsHigh
Source CodeProprietary code, scriptsMedium
Confidential DocumentsClassified, internal-onlyMedium-High
Healthcare Data (PHI)Medical records, diagnosesHigh
Bulk Data TransferLarge volume any typeMedium

Step 1: Initial Assessment

QuestionWhere to Look
What data type was detected?DLP alert details, policy name
What action occurred?Email, upload, print, USB copy
Was it blocked or allowed?Alert action status
Who was the user?User ID, role, department
Where was it going?Destination email, URL, device
Is this user a repeat offender?Historical DLP alerts

Step 2: Context Gathering

// User's DLP history (Sentinel/M365)
DLPRuleMatch
| where UserId == "user@company.com"
| where TimeGenerated > ago(90d)
| summarize TotalAlerts=count(), Blocked=countif(ActionType=="Block"), Allowed=countif(ActionType=="Allow") by PolicyName

// What data types has this user triggered?
DLPRuleMatch
| where UserId == "user@company.com"
| summarize count() by SensitiveInfoType, DestinationType
| sort by count_ desc

Step 3: Decision Tree

QuestionIf YESIf NO
Was transfer blocked?Data protected; review for patternAssess impact → Continue
Is there business justification?Document; may need policy exceptionContinue investigation
Is user a repeat offender?Escalate to management/HRFirst-time → Education
Does pattern suggest intentional exfil?Escalate as insider threatAccidental → User education

Red Flags for Intentional Exfiltration

  • Large volume transfers over short period
  • Transfers to personal email or cloud storage
  • After-hours or weekend activity
  • User recently gave notice or is on PIP
  • Multiple data types being exfiltrated
  • Attempts to bypass controls (renaming, archiving)
  • Activity spike before announced departure

Common False Positives

ScenarioWhy It's FPResolution
Test data with fake SSNsNon-production environmentTune policy, exclude test systems
Approved vendor sharingLegitimate business partnerAdd exception, document approval
Marketing materialsPublic-facing contentAdjust classification
HR/Legal legitimate transfersRole-appropriate accessDocument and close

Escalation Criteria

  • Large volume sensitive data transferred externally
  • Transfer to personal email/cloud without approval
  • Departing employee with unusual data access
  • Highly sensitive data (trade secrets, M&A, executive)
  • Repeated violations after warning
  • Pattern consistent with data theft
