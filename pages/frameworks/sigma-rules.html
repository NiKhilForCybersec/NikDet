Sigma Rules

Generic signature format for SIEM systems - write once, convert to any platform.

What is Sigma?

Sigma is an open-source, generic signature format for log events. Write detection rules once in YAML format, then convert them to Splunk SPL, Microsoft Sentinel KQL, Elastic Query DSL, and 30+ other platforms.

Sigma Rule Structure

title: Suspicious PowerShell Download Cradle
id: 3b6ab547-8ec2-4991-b9d2-2b06702a48d7
status: experimental
description: Detects PowerShell download cradle patterns commonly used by malware
author: SOC Team
date: 2025/01/03
references:
    - https://attack.mitre.org/techniques/T1059/001/
tags:
    - attack.execution
    - attack.t1059.001
logsource:
    category: process_creation
    product: windows
detection:
    selection_powershell:
        Image|endswith:
            - '\powershell.exe'
            - '\pwsh.exe'
    selection_download:
        CommandLine|contains:
            - 'DownloadString'
            - 'DownloadFile'
            - 'DownloadData'
            - 'WebRequest'
            - 'Invoke-WebRequest'
            - 'IWR'
            - 'wget'
            - 'curl'
            - 'Net.WebClient'
    condition: selection_powershell and selection_download
falsepositives:
    - Legitimate administrative scripts
    - Software installers
level: medium

allAll values must matchCommandLine|contains|all: ['net', 'user']

Convert Sigma to SIEM Queries

Using sigma-cli

# Install sigma-cli
pip install sigma-cli

# Convert to Microsoft Sentinel (KQL)
sigma convert -t microsoft365defender -p microsoft365defender rule.yml

# Convert to Splunk
sigma convert -t splunk -p splunk_windows rule.yml

# Convert to Elastic
sigma convert -t elasticsearch -p ecs_windows rule.yml

# Convert to QRadar
sigma convert -t qradar -p qradar rule.yml

Example Output (KQL)

DeviceProcessEvents
| where (ProcessVersionInfoOriginalFileName =~ "PowerShell.EXE" or InitiatingProcessVersionInfoOriginalFileName =~ "PowerShell.EXE")
| where ProcessCommandLine contains "DownloadString" or ProcessCommandLine contains "DownloadFile" 
    or ProcessCommandLine contains "WebRequest" or ProcessCommandLine contains "Invoke-WebRequest"

Best Practices

  • Always include MITRE ATT&CK tags for mapping
  • Document known false positives
  • Use specific log sources (not generic)
  • Test rules before deploying to production
  • Include references to threat intel or research
  • Use UUIDs for rule tracking
  • Version control your rules in Git
