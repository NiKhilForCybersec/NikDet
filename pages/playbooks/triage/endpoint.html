Endpoint Alert Triage

Quick triage guide for endpoint security alerts - determine severity and next steps in minutes.

Why Proper Triage Matters

The Triage Dilemma
If You Triage Too Slow...If You Triage Too Fast...
Real threats progress while you analyzeYou miss context that identifies true positives
Alert queue backs upYou close real incidents as false positives
Time-sensitive containment delayedAttackers remain active

Goal: Make accurate severity decision in 5-10 minutes, not 5-10 seconds or 5-10 hours.

Rapid Triage Decision Tree

5-Minute Triage Flow

Q1: Is this a known false positive pattern?

├─ YES → Close as FP, document pattern if not already

└─ NO / UNSURE → Continue

Q2: Was the threat BLOCKED or EXECUTED?

├─ BLOCKED → Lower severity. Check source, verify block, consider closing.

└─ EXECUTED → Higher severity. Continue to Q3.

Q3: Is there network activity (C2, exfil, lateral movement)?

├─ YES → ESCALATE IMMEDIATELY. Active threat.

└─ NO → Continue to Q4.

Q4: Is this a high-value target (admin, exec, server)?

├─ YES → Escalate to L2, investigate thoroughly

└─ NO → Standard investigation, may be able to handle at L1

Quick Queries

// KQL - Quick process tree view
DeviceProcessEvents
| where Timestamp > ago(1h)
| where DeviceName == "DEVICE-NAME"
| where SHA256 == "suspicious-hash" or FileName =~ "suspicious-file.exe"
| project Timestamp, FileName, ProcessCommandLine, 
    InitiatingProcessFileName, InitiatingProcessCommandLine, AccountName

// KQL - Did process make network connections?
DeviceNetworkEvents
| where Timestamp > ago(1h)
| where DeviceName == "DEVICE-NAME"
| where InitiatingProcessFileName =~ "suspicious-file.exe"
| project Timestamp, RemoteIP, RemotePort, RemoteUrl

// KQL - Is this alert pattern common (potential FP)?
AlertEvidence
| where Timestamp > ago(30d)
| where Title has "ALERT-NAME"
| summarize Count = count(), Devices = dcount(DeviceName) by Title

Common False Positives

Suspicious script execution Developer activity, build tools Check user role, verify with manager Document as expected for dev users

When to Escalate

Escalate to L2 Immediately If:

  • C2 communication detected
  • Credential theft tool executed
  • Ransomware indicators
  • Server or domain controller affected
  • Admin or executive endpoint
  • Lateral movement indicators
  • Multiple related alerts on same/different systems
  • You're unsure and it could be serious

Close as FP (L1) If:

  • Matches documented FP pattern
  • Threat was blocked and source is not suspicious
  • Verified legitimate IT/admin activity
  • User-installed known software (policy issue, not security)
