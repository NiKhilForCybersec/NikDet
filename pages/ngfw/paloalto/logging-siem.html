Configure Log Settings

Enable Logging on Security Rules

> configure

# Enable logging for a security rule
# set rulebase security rules  log-start yes
# set rulebase security rules  log-end yes
# set rulebase security rules  log-setting default

# Example
# set rulebase security rules Allow-Users-Internet log-start yes
# set rulebase security rules Allow-Users-Internet log-end yes

# commit

# Create log forwarding profile
# set shared log-settings profiles My-Log-Profile match-list Traffic-Logs log-type traffic

Microsoft Sentinel Integration

Option 1: CEF over Syslog (Recommended)

Prerequisites

  • Azure Log Analytics workspace
  • Linux VM as syslog forwarder with Log Analytics agent
  • Palo Alto configured for CEF syslog

Step 1: Deploy Syslog Forwarder

# On Linux VM (Ubuntu)
# Install Azure Monitor Agent or Log Analytics agent
wget https://raw.githubusercontent.com/Microsoft/OMS-Agent-for-Linux/master/installer/scripts/onboard_agent.sh
sudo sh onboard_agent.sh -w <workspace-id> -s <shared-key> -d opinsights.azure.com

# Configure rsyslog for CEF
sudo nano /etc/rsyslog.d/security-config-omsagent.conf

# Add:
if $rawmsg contains "CEF:" then @@127.0.0.1:25226

# Restart rsyslog
sudo systemctl restart rsyslog

# Open firewall
sudo ufw allow 514/udp
sudo ufw allow 514/tcp

Step 2: Configure Palo Alto for CEF

> configure

# Create syslog profile for Sentinel
# set shared log-settings syslog Sentinel server Linux-Forwarder server 10.1.1.150
# set shared log-settings syslog Sentinel server Linux-Forwarder transport UDP
# set shared log-settings syslog Sentinel server Linux-Forwarder port 514
# set shared log-settings syslog Sentinel server Linux-Forwarder format CEF
# set shared log-settings syslog Sentinel server Linux-Forwarder facility LOG_USER

# Create log forwarding profile
# set shared log-settings profiles Sentinel-Forward match-list All-Traffic log-type traffic
# set shared log-settings profiles Sentinel-Forward match-list All-Traffic filter "All Logs"
# set shared log-settings profiles Sentinel-Forward match-list All-Traffic send-syslog Sentinel

# set shared log-settings profiles Sentinel-Forward match-list All-Threats log-type threat  
# set shared log-settings profiles Sentinel-Forward match-list All-Threats filter "All Logs"
# set shared log-settings profiles Sentinel-Forward match-list All-Threats send-syslog Sentinel

# Apply to security rules
# set rulebase security rules  log-setting Sentinel-Forward

# commit

Step 3: Enable Sentinel Connector

  1. Azure Portal → Microsoft Sentinel → Data connectors
  2. Search "Palo Alto" → Select connector
  3. Follow configuration steps
  4. Verify data in: CommonSecurityLog table

Sentinel KQL Queries

// All Palo Alto logs
CommonSecurityLog
| where DeviceVendor == "Palo Alto Networks"
| take 100

// Blocked traffic
CommonSecurityLog
| where DeviceVendor == "Palo Alto Networks"
| where DeviceAction == "deny" or DeviceAction == "drop"
| summarize count() by SourceIP, DestinationIP, DestinationPort
| top 10 by count_

// Threat detections
CommonSecurityLog
| where DeviceVendor == "Palo Alto Networks"
| where Activity == "THREAT"
| project TimeGenerated, SourceIP, DestinationIP, 
          ThreatName=DeviceCustomString1, 
          Severity=LogSeverity,
          Action=DeviceAction

// Application usage
CommonSecurityLog
| where DeviceVendor == "Palo Alto Networks"
| where Activity == "TRAFFIC"
| summarize TotalBytes = sum(SentBytes + ReceivedBytes) by ApplicationProtocol
| top 10 by TotalBytes

// Failed GlobalProtect logins
CommonSecurityLog
| where DeviceVendor == "Palo Alto Networks"
| where Activity == "GLOBALPROTECT"
| where DeviceAction contains "fail"
| project TimeGenerated, SourceIP, SourceUserName, Message

// WildFire malware detections
CommonSecurityLog
| where DeviceVendor == "Palo Alto Networks"
| where DeviceEventClassID == "wildfire"
| where DeviceCustomString2 == "malware"
| project TimeGenerated, SourceIP, DestinationIP, FileName, FileHash

Splunk Integration

Option 1: Syslog to Splunk

# On Splunk:
# 1. Settings → Data Inputs → UDP → New Local UDP
# 2. Port: 514
# 3. Source type: pan:log (use Palo Alto Add-on)
# 4. Index: pan_logs

# On Palo Alto - configure syslog server pointing to Splunk
> configure
# set shared log-settings syslog Splunk server Splunk-Server server splunk.company.com
# set shared log-settings syslog Splunk server Splunk-Server transport UDP
# set shared log-settings syslog Splunk server Splunk-Server port 514
# set shared log-settings syslog Splunk server Splunk-Server format BSD

# commit

Option 2: Palo Alto Add-on for Splunk

Install from Splunkbase for pre-built dashboards and field extractions.

Splunk Searches

# All Palo Alto traffic
index=pan_logs sourcetype=pan:traffic

# Blocked sessions
index=pan_logs sourcetype=pan:traffic action=deny OR action=drop
| stats count by src_ip, dest_ip, dest_port
| sort -count

# Threat events
index=pan_logs sourcetype=pan:threat
| table _time, src_ip, dest_ip, threat_name, severity, action

# Top applications by bandwidth
index=pan_logs sourcetype=pan:traffic
| stats sum(bytes) as total_bytes by app
| sort -total_bytes
| head 20

# User activity
index=pan_logs sourcetype=pan:traffic src_user=*
| stats count, sum(bytes_sent) as sent, sum(bytes_received) as received by src_user
| sort -count

# GlobalProtect connections
index=pan_logs sourcetype=pan:globalprotect
| stats count by portal_user, public_ip, login_duration

Cortex Data Lake

What is Cortex Data Lake?

Palo Alto's cloud-based log storage and analytics platform. Benefits:

  • No on-premises log storage infrastructure
  • Integrated with Cortex XSOAR for automation
  • Machine learning analytics
  • Long-term retention

Enable Cortex Data Lake

> configure

# Configure Cortex Data Lake connection
# set deviceconfig system log-settings cortex-data-lake region americas
# set deviceconfig system log-settings cortex-data-lake enable-log-compression yes

# Enable log types to forward
# set deviceconfig system log-settings cortex-data-lake log-type-traffic yes
# set deviceconfig system log-settings cortex-data-lake log-type-threat yes
# set deviceconfig system log-settings cortex-data-lake log-type-url yes
# set deviceconfig system log-settings cortex-data-lake log-type-data yes
# set deviceconfig system log-settings cortex-data-lake log-type-wildfire yes
# set deviceconfig system log-settings cortex-data-lake log-type-auth yes
# set deviceconfig system log-settings cortex-data-lake log-type-globalprotect yes

# commit

Query in Cortex XDR

// XQL query for threat events
dataset = panw_ngfw_threat_raw
| filter action != "allow"
| fields timestamp, src_ip, dst_ip, threat_name, severity, action

// Traffic analysis
dataset = panw_ngfw_traffic_raw
| filter bytes > 1000000
| stats sum(bytes) as total_bytes by app
| sort desc total_bytes
| limit 20

> show logging-status

# Check disk space for local logs
> show system disk-space
