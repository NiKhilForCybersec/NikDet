Log Collection

How to get logs from sources to your SIEM reliably and efficiently.

Log Collection End-to-End (Interview-Ready)

This section provides complete, senior-level explanations of log collection architecture. Understanding these flows is critical for interviews and real-world implementation.

RATE LIMITS • Cloud APIs have rate limits (requests/minute) • Must handle 429 Too Many Requests errors • Design polling interval to stay within limits 2. AUTHENTICATION • OAuth 2.0 (most modern APIs) • API Keys (simpler but less secure) • Certificate-based (high security) 3. PAGINATION • APIs return results in pages • Must handle pagination correctly • Track "cursor" or "next page" tokens 4. STATE MANAGEMENT • Must track "last polled timestamp" • Avoid duplicate or missed events • Handle restarts/failures gracefully INTERVIEW POINT: "API-based collection requires careful handling of rate limits, pagination, and state management. I use a checkpoint mechanism to track the last successfully processed event, so I can resume from that point after failures without duplicates." ═══════════════════════════════════════════════════════════════════════════════ PATTERN 4: NATIVE CONNECTORS (MANAGED) ═══════════════════════════════════════════════════════════════════════════════ HOW IT WORKS: ───────────────────────────────────────────────────────────────────────────── [Microsoft Service] [Sentinel] │ │ │ ════ Native Integration ═════►│ (Microsoft manages this) │ (No user configuration) │ │ │ This is a SPECIAL CASE for cloud-native SIEMs where the SIEM vendor manages the integration completely. For Microsoft environments, I'd consider Azure Monitor Agent with Data Collection Rules, managed via Azure Policy for automatic deployment to new VMs." Q: "We're losing firewall logs. What would you check?" ───────────────────────────────────────────────────────────────────────────── A: "First, I'd verify if they're using UDP or TCP syslog. UDP drops packets under load. I'd switch to TCP. Then I'd check the syslog collector's queue metrics, disk space, and whether the SIEM's ingestion rate is keeping up. I'd also verify the firewall's logging configuration and that no network ACLs are blocking traffic." Q: "What's the difference between agent-based and agentless collection?" ───────────────────────────────────────────────────────────────────────────── A: "Agent-based uses installed software that buffers and forwards logs - more reliable, but requires deployment. Agentless uses syslog or API polling - no installation needed, but syslog over UDP can lose data, and API polling adds latency and requires state management. I use agent-based for servers I control, syslog for network devices, and API polling for cloud/SaaS services." Q: "How do you ensure log integrity and no data loss?" ───────────────────────────────────────────────────────────────────────────── A: "Multiple layers: TCP instead of UDP for syslog, agents with persistent queues that survive restarts, acknowledgment-based forwarding in Splunk, monitoring of ingestion health dashboards, alerting on silent sources when expected volume drops. For compliance, I'd also implement TLS encryption and log signing."

Syslog Collection

Syslog Server Configuration (rsyslog)

# /etc/rsyslog.conf - Enable TCP syslog listener

# Load modules
module(load="imtcp")
input(type="imtcp" port="514")

# For TLS (recommended for security)
module(load="imtcp" StreamDriver.Name="gtls" 
       StreamDriver.Mode="1" 
       StreamDriver.AuthMode="x509/name")

# Write logs to files by source
template(name="RemoteLogs" type="string"
         string="/var/log/remote/%HOSTNAME%/%PROGRAMNAME%.log")

if $fromhost-ip != '127.0.0.1' then {
    action(type="omfile" dynaFile="RemoteLogs")
}

# Forward to SIEM
*.* action(type="omfwd" target="siem.company.com" port="514" protocol="tcp")

Network Device Syslog Configuration

# Cisco ASA
logging enable
logging host inside 10.0.0.50 UDP/514
logging trap informational
logging facility 20

# Palo Alto
set deviceconfig system log-settings syslog syslog-server siem-server server 10.0.0.50
set deviceconfig system log-settings syslog syslog-server siem-server transport UDP
set deviceconfig system log-settings syslog syslog-server siem-server port 514
set deviceconfig system log-settings syslog syslog-server siem-server format BSD

# Fortinet FortiGate
config log syslogd setting
  set status enable
  set server 10.0.0.50
  set port 514
end

Collection Best Practices

PracticeWhy It Matters

Implement bufferingPrevents log loss during SIEM outages
Monitor collection healthDetect gaps in log coverage immediately
Normalize timestampsEnsure all logs use UTC for correlation
Document source configsEasier troubleshooting and onboarding
Test failoverVerify logs still flow when primary collector fails

Troubleshooting Collection Issues

SymptomPossible CauseSolution

Intermittent gapsNetwork congestion, UDP dropsSwitch to TCP/TLS, add buffering
Delayed logsCollection queue backlogScale collectors, increase throughput
