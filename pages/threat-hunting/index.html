Threat Hunting

Proactively search for threats that evade automated detection.

What is Threat Hunting?

Threat hunting is the proactive, human-driven search for threats that have evaded existing security controls and automated detection. Unlike reactive incident response, hunting assumes the adversary is already inside and actively seeks to find them.

Proactive

Hunt before alerts fire. Don't wait for detections to trigger.

Hypothesis-Driven

Start with a theory about attacker behavior, then test it.

Human-Led

Analyst creativity and intuition drive the search.

Iterative

Refine hypotheses based on findings. Each hunt informs the next.

The Hunting Loop

1. Hypothesis
2. Collect
3. Analyze
4. Document
5. Automate

Loop Steps Explained

1
Form Hypothesis

Develop a testable theory about attacker presence or behavior based on threat intelligence, attack trends, or gaps in detection coverage.

Example: "Attackers are using certutil.exe to download malware from external URLs in our environment."

2
Collect Data

Identify data sources needed to test the hypothesis. Query SIEM, EDR, or other tools to gather relevant events.

Example: Query for all certutil.exe executions with "-urlcache" in command line over last 30 days.

3
Analyze

Examine the data for anomalies, patterns, or evidence of malicious activity. Pivot on findings to expand scope.

Example: Found 3 instances from marketing workstations downloading from suspicious domains.

4
Document

Record methodology, queries, findings, and conclusions. Document both successful and unsuccessful hunts.

Example: Create hunt report with timeline, affected hosts, IOCs, and recommendations.

5
Automate

If hunt reveals detection gap, create automated detection rule. Convert successful hunt queries into production alerts.

Example: Deploy new detection: "Certutil External URL Download" based on hunt findings.

Types of Hunts

TypeDescriptionExample
Hypothesis-Driven Start with theory about attacker TTPs "Hunt for LOLBin abuse in engineering department"
Intelligence-Driven Based on specific threat intel or IOCs "Hunt for TTPs from recent APT report"
Anomaly-Driven Look for statistical outliers "Find users with unusual login times"
Asset-Focused Focus on high-value targets "Hunt for threats on domain controllers"
Technique-Focused Based on ATT&CK technique "Hunt for T1003 Credential Dumping"

Hypothesis Examples

Strong Hypothesis Characteristics
  • Specific: Clearly defines what you're looking for
  • Testable: Can be validated with available data
  • Threat-based: Grounded in real attacker behaviors
  • Scoped: Reasonable timeframe and data volume

Getting Started

  1. Start small: Begin with 1-2 hunts per month
  2. Use ATT&CK: Pick techniques relevant to your threat model
  3. Leverage existing queries: Build on KQL/SPL library
  4. Document everything: Even "no findings" is valuable
  5. Create detections: Turn successful hunts into automated rules
  6. Build a program: Develop repeatable methodology and playbooks
