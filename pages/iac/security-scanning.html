IaC Security Scanning

Learn how to automatically find security issues in your Terraform, CloudFormation, and other IaC code before deployment.

What is IaC Security Scanning?

IaC Security Scanning means using automated tools to check your infrastructure code for security problems BEFORE you deploy it. Think of it like a spell-checker for security.

What it catches:

  • Storage buckets set to public
  • Databases without encryption
  • Security groups open to the internet
  • Hardcoded passwords in code
  • Missing logging configuration
  • Overprivileged IAM roles

When it runs:

  • In your IDE as you type (immediate feedback)
  • In CI/CD pipeline before merge (blocks bad code)
  • Pre-deployment check (last line of defense)

Why Scan IaC Code?

Without ScanningWith Scanning
Developer accidentally makes S3 bucket public Scanner blocks PR: "ERROR: S3 bucket has public access"
Security finds issue weeks later in production Issue caught in seconds, before code merges
Data breach, incident response, customer notification No breach, just a quick code fix
Cost: $$$$$$ (breach, fines, reputation) Cost: 5 minutes to fix the code

Popular Scanning Tools

Checkov (Recommended for Beginners)

What it is: Free, open-source scanner by Bridgecrew/Palo Alto. Supports Terraform, CloudFormation, Kubernetes, and more.

Quick Start:

# Install
pip install checkov

# Scan a directory
checkov -d ./terraform/

# Scan a single file  
checkov -f main.tf

# Output as JSON (for CI/CD)
checkov -d ./terraform/ -o json

Example Output:

Check: CKV_AWS_19: "Ensure all data stored in the S3 bucket is encrypted"
  FAILED for resource: aws_s3_bucket.data
  File: /main.tf:15-25
  Guide: https://docs.bridgecrew.io/docs/s3_14-data-encrypted-at-rest

Check: CKV_AWS_20: "Ensure S3 bucket has block public access enabled"
  FAILED for resource: aws_s3_bucket.data  
  File: /main.tf:15-25

Strengths: Free, great documentation, 1000+ built-in checks, easy to use

tfsec

What it is: Fast, Terraform-focused scanner. Now part of Trivy.

Quick Start:

# Install (macOS)
brew install tfsec

# Scan
tfsec ./terraform/

# Soft fail (don't block CI on warnings)
tfsec --soft-fail ./terraform/

Strengths: Very fast, Terraform-specific, good IDE integration

Snyk IaC

What it is: Commercial tool (free tier available) with broad language support and remediation guidance.

Quick Start:

# Install
npm install -g snyk

# Authenticate
snyk auth

# Scan IaC
snyk iac test ./terraform/

Strengths: Great remediation advice, integrates with other Snyk products, good reporting

Common Issues Scanners Catch

IssueWhat Scanner SaysSeverityFix
Public S3 Bucket "S3 bucket has public access enabled" CRITICAL Add block_public_access { ... }
Unencrypted Storage "S3 bucket not encrypted at rest" HIGH Add server_side_encryption_configuration
Open Security Group "Security group allows 0.0.0.0/0 to port 22" CRITICAL Restrict cidr_blocks to specific IPs
No Logging "S3 bucket access logging not enabled" MEDIUM Add logging { ... } block
Hardcoded Secret "Hardcoded AWS access key detected" CRITICAL Use variables or secrets manager
Overprivileged IAM "IAM policy allows * actions" HIGH Use least-privilege permissions

Adding to CI/CD Pipeline

The real power comes from blocking bad code automatically. Here's how:

How It Works in Practice:

1
Developer pushes code - Creates PR with Terraform changes
2
CI pipeline starts - GitHub Actions/Jenkins/etc triggers
3
Scanner runs - Checkov/tfsec checks the code
4
Results:
  • ✅ All checks pass → PR can be merged
  • ❌ Critical issues found → PR blocked until fixed

GitHub Actions Example:

# .github/workflows/iac-security.yml
name: IaC Security Scan

on:
  pull_request:
    paths:
      - 'terraform/**'

jobs:
  checkov:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v3
      
      - name: Run Checkov
        uses: bridgecrewio/checkov-action@master
        with:
          directory: terraform/
          framework: terraform
          soft_fail: false  # Block PR on failures
          output_format: sarif
          
      - name: Upload SARIF
        uses: github/codeql-action/upload-sarif@v2
        with:
          sarif_file: results.sarif

Handling False Positives

Sometimes scanners flag things that are intentionally configured that way. Here's how to handle it:

Option 1: Inline Skip (Use Sparingly)

# Terraform - Skip specific check with comment
resource "aws_s3_bucket" "public_website" {
  #checkov:skip=CKV_AWS_20:This bucket intentionally hosts public website
  bucket = "my-public-website"
}

Option 2: Config File (Better for Patterns)

# .checkov.yaml
skip-check:
  - CKV_AWS_20  # Public bucket check - we have public websites
  
soft-fail-on:
  - CKV_AWS_18  # Logging - working on enabling
Warning

Every skip should have a documented reason. If you're skipping lots of checks, your security posture has problems - don't just suppress the symptoms!

Best Practices

Recommendations
  1. Start with soft-fail: Let developers see issues without blocking them initially
  2. Fix existing issues first: Don't enable hard-fail with 500 existing violations
  3. Block only CRITICAL/HIGH: Let medium/low through initially
  4. Document all skips: Every exception needs justification
  5. Review skips periodically: Are they still needed?
  6. Use pre-commit hooks: Catch issues before code even gets pushed
