Security Controls Decision Guide

When to implement what, why it matters, common questions answered, and decision frameworks for every major security control.

Multi-Factor Authentication (MFA)

Should I Implement MFA?

QuestionAnswerExplanation
Do I need MFA?YES, AlwaysPasswords alone are compromised constantly via phishing, breaches, and guessing. MFA stops 99.9% of account compromise attacks.
Is MFA enough by itself?No, but criticalMFA is essential but not complete protection. You still need monitoring, conditional access, and endpoint security.
Will users complain?Initially, yesUsers adapt within 2-4 weeks. Modern authenticator apps with push notifications are low-friction. The alternative (breach) is far worse.
What about service accounts?Different approachService accounts can't do interactive MFA. Use managed identities, certificates, or vault-stored credentials with strict IP restrictions instead.
Can attackers bypass MFA?SometimesMFA fatigue attacks, SIM swapping, and real-time phishing proxies exist. Use phishing-resistant MFA (FIDO2) for high-value accounts.

MFA Method Selection Decision Tree

Which MFA Method Should I Use?

START: Is this for privileged/admin accounts?

├─ YES → Use FIDO2 security keys (phishing-resistant, hardware-bound)

└─ NO → Is this for Windows devices with TPM?

├─ YES → Use Windows Hello for Business (phishing-resistant, seamless)

└─ NO → Can users install apps on their phones?

├─ YES → Use Microsoft Authenticator with number matching

└─ NO → Are these external users/guests?

├─ YES → Use Email OTP or SMS (better than nothing)

└─ NO → Use Hardware OATH tokens (for special cases)

Common MFA Questions

QuestionAnswer
Why not SMS for everyone?SMS can be intercepted via SIM swapping, SS7 attacks, or social engineering the carrier. It's the weakest MFA method. Use only as last resort.
Why is FIDO2 better?FIDO2 is cryptographically bound to the legitimate site. Even if a user clicks a phishing link, the key won't authenticate to the fake site. It's impossible to phish.
What's MFA fatigue?Attackers spam MFA push notifications hoping the user accidentally approves. Mitigate with number matching (user must type a number shown on screen).
Should I exclude anyone from MFA?Only break-glass emergency accounts. Everyone else, including executives, must use MFA. Executives are actually higher targets.
What if someone loses their phone?Have backup methods registered (security key, backup codes). Use self-service password reset with identity verification. IT helpdesk as last resort with strong verification.
How often should MFA be required?Every sign-in for sensitive apps. Can reduce frequency for low-risk apps from compliant devices. Never set "remember MFA" longer than 30 days.

Encryption

Encryption Decision Matrix

ScenarioEncrypt?Why / Why NotHow
Laptop hard drivesYESLaptops get lost/stolen constantly. Without encryption, all data is exposed. It's also often a compliance requirement.BitLocker (Windows), FileVault (Mac), LUKS (Linux). Use TPM for key storage.
Database at restYESProtects against stolen backups, decommissioned disks, and unauthorized file access.TDE (Transparent Data Encryption) for SQL, or storage-level encryption.
Internal network trafficIt dependsTraditional "internal = trusted" is outdated (Zero Trust). Encrypt sensitive internal traffic, especially between zones.TLS for apps, IPsec for network-to-network, mTLS for microservices.
BackupsYESBackups often have weaker access controls and are stored longer. Unencrypted backups are a major breach vector.Backup software encryption + separate key management (not stored with backups).
Email internalUsually noMost internal email doesn't need encryption. It adds complexity and breaks features like search and DLP scanning.Only encrypt specific sensitive emails using S/MIME or sensitivity labels.
Email to external with PIIYESEmail passes through multiple servers you don't control. PII exposure creates compliance and legal risk.Microsoft Message Encryption, Virtru, or portal-based encryption.
Cloud storage (M365, etc.)Provider encryptsMicrosoft/Google already encrypt at rest. Additional encryption needed only for highest sensitivity data or regulatory requirements.Sensitivity labels with encryption, or BYOK/HYOK for keys you control.

Common Encryption Questions

QuestionAnswer
Does HTTPS mean my data is safe?HTTPS encrypts data in transit between browser and server. It does NOT protect data at rest, on the server, or from the server itself being compromised.
If I encrypt everything, am I secure?No. Encryption protects confidentiality, not integrity or availability. Ransomware encrypts your data against you. You still need access controls, monitoring, backups.
TLS 1.2 or TLS 1.3?TLS 1.3 is faster and more secure. Use 1.3 where possible. TLS 1.2 is acceptable minimum. Disable TLS 1.0 and 1.1 (vulnerable).
What about key management?Keys are the critical part. Store in HSM or cloud key vault (Azure Key Vault, AWS KMS). Never store keys with encrypted data. Have key rotation and backup procedures.
Does encryption slow things down?Modern CPUs have AES acceleration. Encryption overhead is typically <5%. The security benefit far outweighs the minimal performance impact.
Can encrypted data be searched?Traditional encryption: No, you must decrypt first. This is why email encryption can break search. Searchable encryption exists but is complex and limited.
What's the difference between CMK and BYOK?CMK (Customer Managed Key): You control the key but it's stored in provider's key vault. BYOK (Bring Your Own Key): You generate and can escrow the key externally. BYOK gives more control but more responsibility.

Network Segmentation

Do I Need Network Segmentation?

QuestionAnswerExplanation
Is flat network okay?NOA flat network means one compromised device can reach everything. Attackers move laterally freely. Ransomware spreads instantly to all systems.
Can't my firewall protect me?Only at the edgePerimeter firewalls only see traffic entering/leaving the network. They're blind to east-west (internal) traffic where most attacks happen.
Is VLAN segmentation enough?It helpsVLANs provide layer 2 separation but attackers can still route between VLANs unless you add firewall rules between them. VLANs alone are not security controls.
Do I need microsegmentation?For critical assetsMicrosegmentation (per-workload firewalls) is ideal for data centers and critical systems. It's overkill for general corporate networks. Start with zone-based segmentation.

Common Segmentation Questions

QuestionAnswer
Won't segmentation break things?Yes, initially. That's why you implement in phases: 1) Monitor mode first to see traffic patterns, 2) Create rules based on legitimate traffic, 3) Enable blocking, 4) Handle exceptions as they arise.
How do I know what traffic is legitimate?Use network monitoring tools to baseline traffic for 2-4 weeks. Work with application owners. Document all approved flows. Unknown traffic should be investigated, not just allowed.
What about cloud workloads?Use cloud-native security groups (AWS SGs, Azure NSGs). Apply same principles: default deny, explicit allow only required traffic, different rules per tier.
Is Zero Trust the same as segmentation?Zero Trust includes segmentation but goes further. ZT assumes breach, verifies every access request based on identity + device + context. Segmentation is one component of ZT.

Data Loss Prevention (DLP)

DLP Implementation Decisions

QuestionAnswerExplanation
Should I start with blocking or monitoring?MONITORINGAlways start with audit/monitor mode. Blocking without understanding your data flows will disrupt business and create DLP fatigue.
How long to monitor before blocking?2-4 weeks minimumNeed enough time to see all business processes, monthly activities, edge cases. Review every alert to understand false positive patterns.
Should I block or warn?Depends on dataBlock for high-sensitivity (SSN, credit cards, credentials). Warn for medium sensitivity (allows override with justification). Audit-only for general monitoring.
Will DLP stop all data theft?NODetermined insiders can find ways around DLP (photos of screen, retyping, encrypted containers). DLP stops accidental exposure and opportunistic theft.
Do I need endpoint DLP?YESNetwork/cloud DLP misses USB, printing, local saves. Endpoint DLP covers the last mile where data actually leaves.

DLP Rule Design Framework

DLP Rule Best Practices
DoDon'tWhy
Start with specific, high-confidence patterns (SSN, credit cards)Try to catch everything at onceHigh-confidence rules have low false positives, build trust in the system
Use context (keywords + patterns together)Match patterns alone"123-45-6789" could be SSN or phone number. "SSN: 123-45-6789" is clearly sensitive
Create business process exceptionsIgnore all false positivesLegitimate FPs (HR sending SSN to payroll) need documented exceptions, not disabled rules
Require justification for overridesAllow silent overridesOverride justifications create audit trail and deter abuse
Review and tune weekly initiallySet and forgetBusiness processes change. False positives cause alert fatigue. Rules need maintenance.

Common DLP Questions

QuestionAnswer
What about encrypted files?DLP can't inspect encrypted content. Options: 1) Block encrypted attachments to external, 2) Use endpoint DLP that sees before encryption, 3) Accept the gap and monitor for anomalies.
Should I inspect HTTPS?For DLP to see cloud uploads, you need TLS inspection. This requires deploying certificates to endpoints and has privacy implications. Many organizations inspect with exclusions for banking/healthcare sites.
How do I handle departing employees?Enable enhanced monitoring for departing users (often a DLP policy group). Alert on any sensitive data movement in their last 30 days. Work with HR for coordinated offboarding.
What's the biggest DLP mistake?Blocking too aggressively too early. This causes business disruption, users finding workarounds, and eventually DLP being disabled. Start with detection, build accurate rules, then gradually enable prevention.
Do I need to classify all data first?Ideal but not required. You can start with auto-classification (pattern matching) and content inspection. Manual classification can run in parallel or come later.

Endpoint Detection & Response (EDR)

EDR Decisions

QuestionAnswerExplanation
Is antivirus enough?NOTraditional AV only catches known malware by signature. Modern attacks use fileless malware, living-off-the-land, and zero-days. EDR detects behaviors, not just signatures.
EDR or XDR?DependsEDR = endpoint only. XDR = correlates endpoint + network + cloud + email. If you have good SIEM integration, EDR is fine. XDR simplifies correlation for smaller teams.
Should I enable automated response?YES, for high confidenceAuto-isolate for confirmed ransomware. Auto-block for known malware. Manual review for suspicious activities to avoid disrupting legitimate work.
What about servers?YESServers are high-value targets. Same EDR or server-specific agent. May need different policies (servers have different baseline behavior).
What about Linux/Mac?YESAttackers target all platforms. Ensure your EDR has full coverage. Some vendors have weaker non-Windows support.

EDR Alert Triage Framework

How to Triage EDR Alerts

Question 1: Is this a known false positive pattern?

├─ YES → Document, add to exclusion list if recurrent, close as FP

└─ NO → Continue investigation

Question 2: Was the activity blocked/prevented?

├─ YES → Still investigate source, but lower urgency

└─ NO (executed) → Higher urgency, may need containment

Question 3: Is the user/system high-value target?

├─ YES (exec, admin, finance) → Escalate priority

└─ NO → Standard priority

Question 4: Is there follow-on activity?

├─ YES (persistence, lateral movement) → Active incident, escalate immediately

└─ NO (isolated event) → Investigate but may be contained
