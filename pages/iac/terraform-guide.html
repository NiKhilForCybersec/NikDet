Terraform - Complete Beginner's Guide

Learn Terraform from scratch: what it is, how it works, and how to use it securely.

What is Terraform?

Terraform is a tool that lets you create cloud infrastructure (VMs, networks, databases, etc.) by writing simple text files instead of clicking through cloud consoles.

You write this:

resource "aws_instance" "web" {
  ami           = "ami-12345678"
  instance_type = "t2.micro"
}

Terraform does this:

  • Logs into AWS using your credentials
  • Creates an EC2 instance with the specified settings
  • Records what it created so it can manage it later
Real-World Analogy

Terraform is like a recipe book for infrastructure:

  • Recipe (Terraform code) = Lists ingredients and steps
  • Kitchen (Cloud Provider) = Where cooking happens (AWS, Azure, GCP)
  • Chef (Terraform) = Reads recipe, does the cooking
  • Meal (Infrastructure) = The end result (VMs, networks, etc.)

Same recipe always produces same meal. Change the recipe, Terraform updates the meal to match.

Core Concepts (Explained Simply)

1. Provider - "Which Cloud?"

provider "aws" {
  region = "us-east-1"
}

provider "azurerm" {
  features {}
}
What this means: A provider tells Terraform which cloud service to talk to. It's like telling your GPS which country's maps to use. You can use multiple providers in the same project.

2. Resource - "What to Create"

resource "aws_instance" "my_server" {
  ami           = "ami-0c55b159cbfafe1f0"
  instance_type = "t2.micro"
  
  tags = {
    Name = "WebServer"
  }
}
What this means:
  • resource = "I want to create something"
  • "aws_instance" = The type of thing (an EC2 VM)
  • "my_server" = Your nickname for it (used to reference it elsewhere)
  • The stuff inside {} = Settings for this resource

3. Variable - "Changeable Values"

# Define a variable
variable "environment" {
  description = "Deployment environment"
  type        = string
  default     = "dev"
}

# Use the variable
resource "aws_instance" "web" {
  instance_type = var.environment == "prod" ? "t2.large" : "t2.micro"
  
  tags = {
    Environment = var.environment
  }
}
What this means: Variables let you change values without editing the main code. Set environment = "prod" and you get a larger instance. Great for using same code across dev/staging/prod.

4. State - "Terraform's Memory"

Understanding State (Critical Concept)

When Terraform creates something, it writes down what it created in a state file (terraform.tfstate). This is how Terraform:

  • Knows what it already created
  • Figures out what needs to change
  • Knows what to destroy when you remove code
Security Warning

State files contain sensitive data (passwords, IPs, resource IDs). Never commit state to Git! Store it in remote backend (S3, Azure Blob, Terraform Cloud).

Complete Example: Create a Web Server

Let's walk through creating an AWS web server step by step:

# main.tf - Create a simple web server

# Step 1: Tell Terraform we're using AWS
provider "aws" {
  region = "us-east-1"
}

# Step 2: Create a security group (firewall rules)
resource "aws_security_group" "web_sg" {
  name        = "web-server-sg"
  description = "Allow HTTP and SSH"
  
  # Allow HTTP from anywhere
  ingress {
    from_port   = 80
    to_port     = 80
    protocol    = "tcp"
    cidr_blocks = ["0.0.0.0/0"]
  }
  
  # Allow SSH from my IP only (SECURITY!)
  ingress {
    from_port   = 22
    to_port     = 22
    protocol    = "tcp"
    cidr_blocks = ["10.0.0.0/8"]  # Only internal network
  }
  
  # Allow all outbound
  egress {
    from_port   = 0
    to_port     = 0
    protocol    = "-1"
    cidr_blocks = ["0.0.0.0/0"]
  }
}

# Step 3: Create the EC2 instance
resource "aws_instance" "web_server" {
  ami           = "ami-0c55b159cbfafe1f0"
  instance_type = "t2.micro"
  
  vpc_security_group_ids = [aws_security_group.web_sg.id]
  
  # Enable encryption on root volume
  root_block_device {
    encrypted = true
  }
  
  tags = {
    Name        = "WebServer"
    Environment = "Production"
    ManagedBy   = "Terraform"
  }
}

# Step 4: Output the public IP
output "web_server_ip" {
  value       = aws_instance.web_server.public_ip
  description = "Public IP of the web server"
}
What each part does:
  1. Provider: Connect to AWS in us-east-1 region
  2. Security Group: Firewall allowing HTTP (port 80) and restricted SSH
  3. Instance: The actual VM with encrypted storage
  4. Output: Show the IP address after creation

Security Best Practices

❌ Bad vs ✓ Good Examples

❌ Hardcoded Credentials

provider "aws" {
  access_key = "AKIAIOSFODNN7EXAMPLE"
  secret_key = "wJalrXUtnFEMI/K7MDENG"
}

Credentials in code = leaked when code is shared

✓ Environment Variables

provider "aws" {
  # Uses AWS_ACCESS_KEY_ID and
  # AWS_SECRET_ACCESS_KEY from environment
}

Credentials never touch your code

❌ Open Security Groups

ingress {
  from_port   = 22
  to_port     = 22
  protocol    = "tcp"
  cidr_blocks = ["0.0.0.0/0"]  # WHOLE INTERNET!
}

SSH open to the entire internet

✓ Restricted Access

ingress {
  from_port   = 22
  to_port     = 22
  protocol    = "tcp"
  cidr_blocks = ["10.0.0.0/8"]  # Internal only
}

SSH only from internal network

❌ Local State File

# State stored locally
# terraform.tfstate in same directory
# Easy to lose, can't collaborate

State file lost if laptop dies

✓ Remote State Backend

terraform {
  backend "s3" {
    bucket = "my-terraform-state"
    key    = "prod/terraform.tfstate"
    encrypt = true
  }
}

State encrypted, backed up, team accessible

Modules - Reusable Code

What Are Modules?

Modules are like functions in programming - reusable blocks of Terraform code. Instead of copy-pasting the same security group config everywhere, you create a module once and reuse it.

# Using a module
module "web_server" {
  source = "./modules/ec2-instance"
  
  instance_type = "t2.micro"
  environment   = "production"
  enable_ssh    = false
}

# The module handles all the security settings internally
Benefits:
  • Security settings baked in - can't be accidentally skipped
  • Update module once, all uses get the fix
  • Easier code review - just check the module
