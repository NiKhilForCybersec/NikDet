Certificate Revocation

CERTIFICATE REVOCATION METHODS ═══════════════════════════════════════════════════════════════════════════════ WHY REVOKE? ───────────────────────────────────────────────────────────────────────────── • Private key compromised (stolen, leaked) • Employee left company (for client certs) • Certificate issued incorrectly • Domain ownership changed • CA compromise CRL (Certificate Revocation List): ───────────────────────────────────────────────────────────────────────────── ┌─────────────────────────────────────────────────────────────────────────┐ │ │ │ CA periodically publishes list of revoked certificates │ │ │ │ ┌──────────────────────────────────────────────────────────┐ │ │ │ CRL - Certificate Revocation List │ │ │ │ │ │ │ │ Issuer: DigiCert TLS CA │ │ │ │ This Update: 2024-06-15 00:00:00 │ │ │ │ Next Update: 2024-06-16 00:00:00 │ │ │ │ │ │ │ │ Revoked Certificates: │ │ │ │ Serial: 0x1234ABCD Revoked: 2024-06-10 Reason: keyCompromise │ │ Serial: 0x5678EFGH Revoked: 2024-06-12 Reason: cessationOfOperation │ │ Serial: 0x9ABCIJKL Revoked: 2024-06-14 Reason: affiliationChanged │ │ ... │ │ │ └──────────────────────────────────────────────────────────┘ │ │ │ │ PROS: CONS: │ │ • Works offline (cached) • Can be large (megabytes) │ │ • Simple implementation • Update delay (hours/days) │ │ • Privacy concern (reveals access) │ │ │ └─────────────────────────────────────────────────────────────────────────┘ OCSP (Online Certificate Status Protocol): ───────────────────────────────────────────────────────────────────────────── ┌─────────────────────────────────────────────────────────────────────────┐ │ │ │ Client ────────────► OCSP Responder ◄──────────── CA │ │ │ │ 1. Client: "Is certificate serial 0x1234ABCD revoked?" │ │ │ │ 2. OCSP Responder: "Certificate status: GOOD" │ │ or "Certificate status: REVOKED" │ │ or "Certificate status: UNKNOWN" │ │ │ │ PROS: CONS: │ │ • Real-time status • Requires online access │ │ • Small response size • Privacy (CA sees what you access) │ │ • Up-to-date info • Extra latency (network request) │ │ │ └─────────────────────────────────────────────────────────────────────────┘ OCSP STAPLING (OCSP Must-Staple): ───────────────────────────────────────────────────────────────────────────── ┌─────────────────────────────────────────────────────────────────────────┐ │ │ │ Server periodically fetches OCSP response from CA │ │ Server includes ("staples") OCSP response in TLS handshake │ │ │ │ │ │ Server ───► OCSP Responder: "What's my cert status?" │ │ ◄─── Response: "Status: GOOD, valid for 7 days" │ │ │ │ (Server caches this response) │ │ │ │ Client ───► Server: TLS handshake │ │ ◄─── Server: Certificate + Stapled OCSP response │ │ │ │ Client validates OCSP response signature (from CA) │ │ No need to contact OCSP responder directly! │ │ │ │ PROS: │ │ • Privacy preserved (CA doesn't see client access) │ │ • Faster (no extra network request) │ │ • Server bears the cost, not client │ │ │ └─────────────────────────────────────────────────────────────────────────┘ CERTIFICATE TRANSPARENCY (CT): ═══════════════════════════════════════════════════════════════════════════════ ┌─────────────────────────────────────────────────────────────────────────┐ │ │ │ Public, append-only logs of ALL issued certificates │ │ │ │ CA issues cert ───► Must submit to CT logs ───► Anyone can search │ │ │ │ Purpose: │ │ • Detect mis-issued certificates │ │ • Detect CA compromise │ │ • Monitor your domains for unauthorized certs │ │ │ │ Search CT logs: https://crt.sh/?q=%.example.com │ │ │ │ Chrome requires CT for all public certificates since 2018 │ │ │ └─────────────────────────────────────────────────────────────────────────┘

PKI Commands

# ═══════════════════════════════════════════════════════════════════════════
# VIEW AND VERIFY CERTIFICATES
# ═══════════════════════════════════════════════════════════════════════════

# View certificate details
openssl x509 -in cert.pem -text -noout

# View certificate chain from website
openssl s_client -connect example.com:443 -showcerts

# Verify certificate against CA
openssl verify -CAfile ca-bundle.crt certificate.crt

# Check certificate expiration
openssl x509 -in cert.pem -noout -enddate

# Extract public key from certificate
openssl x509 -in cert.pem -pubkey -noout > pubkey.pem

# ═══════════════════════════════════════════════════════════════════════════
# CERTIFICATE REVOCATION
# ═══════════════════════════════════════════════════════════════════════════

# Check OCSP status
openssl ocsp -issuer intermediate.crt -cert server.crt \
    -url http://ocsp.digicert.com -resp_text

# Download and check CRL
curl -O http://crl.digicert.com/DigiCertTLSRSASHA2562020CA1.crl
openssl crl -in DigiCertTLSRSASHA2562020CA1.crl -text -noout

# ═══════════════════════════════════════════════════════════════════════════
# INTERNAL CA SETUP (OpenSSL)
# ═══════════════════════════════════════════════════════════════════════════

# Create Root CA
openssl genrsa -aes256 -out root-ca.key 4096
openssl req -x509 -new -nodes -key root-ca.key -sha256 -days 7300 \
    -out root-ca.crt -subj "/C=US/O=MyCompany/CN=MyCompany Root CA"

# Create Intermediate CA
openssl genrsa -aes256 -out intermediate-ca.key 4096
openssl req -new -key intermediate-ca.key \
    -out intermediate-ca.csr \
    -subj "/C=US/O=MyCompany/CN=MyCompany Issuing CA"

# Sign Intermediate with Root
openssl x509 -req -in intermediate-ca.csr -CA root-ca.crt -CAkey root-ca.key \
    -CAcreateserial -out intermediate-ca.crt -days 3650 -sha256

# Issue server certificate
openssl genrsa -out server.key 2048
openssl req -new -key server.key -out server.csr \
    -subj "/C=US/O=MyCompany/CN=server.example.com"
openssl x509 -req -in server.csr -CA intermediate-ca.crt -CAkey intermediate-ca.key \
    -CAcreateserial -out server.crt -days 365 -sha256
