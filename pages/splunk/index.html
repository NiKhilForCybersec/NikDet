What is Splunk?

Splunk is a data platform that indexes logs and lets you search them with SPL (Search Processing Language). For security, Splunk Enterprise Security (ES) adds SIEM capabilities.

Key concepts:

  • Index = Where data is stored (like a database table)
  • Sourcetype = Tells Splunk how to parse the data (WinEventLog, syslog, etc.)
  • Source = Where the data came from (file path, input)
  • Host = The machine that generated the event
  • SPL = Splunk's query language

How Splunk Organizes Data

Understanding how data is organized is key to searching effectively:

ConceptWhat It IsExample
Index Container where events are stored index=main, index=security, index=firewall
Sourcetype Defines how data is parsed and what fields exist WinEventLog:Security, pan:traffic, syslog
Source File or input that provided the data /var/log/messages, WinEventLog:Security
Host Machine that generated the event DC01.company.com, webserver-prod-01 
// Basic search structure
index=security sourcetype=WinEventLog:Security EventCode=4625
| fields _time, host, Account_Name, Source_Network_Address
What this means:
  • index=security - Look in the "security" index
  • sourcetype=WinEventLog:Security - Only Windows Security events
  • EventCode=4625 - Only failed login events
  • | fields - Show only these columns in results

Common Sourcetypes You'll Use

Windows Events

WinEventLog:Security

What it contains: Windows Security Event Log

Key fields: EventCode, Account_Name, ComputerName, Logon_Type, Source_Network_Address

Use for: Authentication (4624/4625), process creation (4688), privilege use

// Find failed Windows logins
index=* sourcetype=WinEventLog:Security EventCode=4625
| stats count by Account_Name, Source_Network_Address
| sort -count

WinEventLog:System

What it contains: Windows System Event Log

Key fields: EventCode, ComputerName, SourceName, Message

Use for: Service changes, system errors, driver issues

XmlWinEventLog:Microsoft-Windows-Sysmon/Operational

What it contains: Sysmon detailed endpoint telemetry

Key fields: EventID, Image, CommandLine, ParentImage, Hashes

Use for: Process execution, network connections, file creation

// Find PowerShell with encoded commands (Sysmon Event 1)
index=* sourcetype="XmlWinEventLog:Microsoft-Windows-Sysmon/Operational" EventID=1
| search Image="*powershell.exe" CommandLine="*-enc*"
| table _time, ComputerName, User, CommandLine

Network & Firewall

pan:traffic (Palo Alto)

What it contains: Palo Alto firewall traffic logs

Key fields: src_ip, dest_ip, dest_port, action, app, rule

Use for: Network traffic analysis, blocked connections

// Find blocked traffic to unusual ports
index=firewall sourcetype="pan:traffic" action=denied
| stats count by dest_port
| sort -count
| head 20

cisco:asa / cisco:ftd

What it contains: Cisco ASA/Firepower logs

Key fields: src_ip, dest_ip, action, protocol

Use for: Firewall analysis, VPN connections

Linux & Unix

linux_secure / linux_audit

What it contains: Linux authentication and audit logs

Key fields: user, src_ip, action, process

Use for: SSH logins, sudo usage, authentication

// Find SSH login failures
index=* sourcetype=linux_secure "Failed password"
| rex "Failed password for (?\S+) from (?\d+\.\d+\.\d+\.\d+)"
| stats count by user, src_ip
| sort -count

Web & Proxy

access_combined / access_common

What it contains: Web server access logs (Apache, Nginx)

Key fields: clientip, uri_path, status, method, bytes

Use for: Web attacks, access analysis

bluecoat:proxysg:access:syslog

What it contains: Web proxy logs

Key fields: src_ip, url, category, user, action

Use for: Web filtering, data exfil, malware callbacks

How to Find What Data You Have

// List all sourcetypes with event counts
| metadata type=sourcetypes index=*
| sort -totalCount
| table sourcetype, totalCount, lastTime
What this does: Shows you all sourcetypes in your Splunk environment with how many events each has. Great for discovering what data is available. 
// See sample events from a sourcetype
index=* sourcetype=WinEventLog:Security
| head 10
// List all indexes
| eventcount summarize=false index=*
| table index, count

Understanding Field Extraction

Splunk automatically extracts some fields, but you often need to extract more:

Automatic Fields (Always Available)

FieldDescription
_timeEvent timestamp
_rawOriginal raw event text
hostMachine that generated event
sourceInput/file path
sourcetypeData format type
indexIndex where event is stored

Extracting Fields with rex

// Extract IP and username from a log message
index=* sourcetype=syslog "Failed password"
| rex "Failed password for (?\S+) from (?\d+\.\d+\.\d+\.\d+)"
| table _time, host, username, src_ip
The rex command: Uses regex to extract values into named fields. (?<fieldname>pattern) captures the pattern into that field name.

Quick Reference Queries

Check if data is flowing

index=* earliest=-15m | stats count by index, sourcetype

Find events containing a keyword

index=* "password" OR "failed" OR "denied"
| head 100

Count by field

index=security sourcetype=WinEventLog:Security EventCode=4625
| stats count by Account_Name
| sort -count

Time-based analysis

index=firewall sourcetype="pan:traffic" action=denied
| timechart span=1h count by dest_port
Pro Tips for Splunk Users
  • Always specify index and sourcetype - Makes searches much faster
  • Use time pickers - Searching "All Time" is slow and expensive
  • Click on fields - The field sidebar shows values and lets you add to search
  • Use | head 10 first - See sample data before complex queries
  • Pipe commands sequentially - Each | passes results to next command
