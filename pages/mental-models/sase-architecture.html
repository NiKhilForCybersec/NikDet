SASE & Modern Security Architecture

SASE (Secure Access Service Edge) is the convergence of networking and security into a unified, cloud-delivered service.

SASE in One Sentence

SASE = Network + Security, delivered from the cloud, applied based on identity and context.
Instead of backhauling traffic to a central datacenter for inspection, security controls are applied at the edge, closest to the user.

Traffic Flows: How Each Works

Flow 1: User Opens Website (SWG)

  1. User Action: Types https://example-news.com
  2. Agent Intercepts: SASE Agent on endpoint intercepts HTTP/HTTPS traffic
  3. Tunnel to PoP: Agent → TLS tunnel → Nearest SASE PoP (~5-15ms latency)
  4. SWG Processing:
    • URL Categorization: "News" category → ALLOW
    • Reputation Check: Domain history, threat intel → CLEAN
    • SSL Inspection: Decrypt → Inspect → Re-encrypt
    • Malware Scan: Check response content
  5. Forward to Destination: PoP → Internet → website
  6. Response: Website → PoP (inspection) → Agent → Browser

What Gets Logged: URL, category, action, user identity, bytes transferred, threat verdicts

Flow 2: User Opens Microsoft 365 (CASB)

  1. Agent Recognizes SaaS: Destination matches "Microsoft 365" in catalog
  2. CASB Processing:
    • Tenant Check: Corporate M365 or personal? → Corporate ✓
    • Session Controls: Device managed? Location allowed? → Full access
    • Activity Monitoring: Track uploads, downloads, shares
    • DLP Inspection: Scan for PII, credit cards, SSN patterns
  3. Unmanaged Device? → Block downloads, view-only, watermark docs

Two CASB Modes:

  • Inline (Proxy): Traffic flows through CASB → Real-time blocking
  • API-based: CASB connects to SaaS APIs → Near real-time visibility

Flow 3: User Opens Internal App (ZTNA)

  1. Agent Intercepts: Internal app detected (hr.internal.company.com)
  2. Identity & Device Check (BEFORE connection):
    • User authenticated via SSO (Entra ID) ✓
    • MFA completed ✓
    • Device registered in Intune ✓
    • EDR running and healthy ✓
    • Disk encrypted ✓
    • Location: Allowed country ✓
  3. ZTNA Broker Creates Connection: Inside-out model — app never exposed to internet
  4. Micro-Tunnel: User Agent ↔ SASE Cloud ↔ App Connector ↔ HR App

ZTNA vs VPN:

VPNZTNA
Network-level access (full subnet)Application-level access (specific app only)
Connect first, authenticate laterAuthenticate first, connect only if allowed
App exposed to internet (VPN gateway)App never exposed (inside-out connection)
Lateral movement possibleNo lateral movement by design

Flow 4: Branch Office Traffic (SD-WAN)

Traffic Classification:

Traffic TypeRouting Decision
Microsoft 365Direct breakout → Internet (no backhaul)
Salesforce, ZoomDirect breakout with SWG/CASB inspection
Internal ERPTunnel → Datacenter (IPsec/GRE)
Voice/VideoQoS priority → Best path (low latency)
General WebTunnel → SASE PoP → SWG inspection

Key Benefits: Direct Internet Access (no backhaul latency), link aggregation, application-aware routing, automatic failover

SWG Policy Configuration Example

SWG POLICY RULES (processed top-to-bottom)

RULE 1: Block Malicious Content
├── Categories: Malware, Phishing, Botnets, Cryptomining
├── Action: BLOCK
└── Apply to: All Users

RULE 2: Block High-Risk Categories
├── Categories: Adult, Gambling, Weapons, Drugs
├── Action: BLOCK
└── Apply to: All Users

RULE 3: Warn on Streaming (Bandwidth)
├── Categories: Streaming Media
├── Action: WARN (user can proceed with acknowledgment)
└── Apply to: All Users (except Marketing team)

RULE 4: Allow Sanctioned SaaS
├── Apps: Microsoft 365, Salesforce, Workday, Zoom
├── Action: ALLOW + Apply CASB policies
└── SSL Inspection: Enabled

RULE 5: Block Unsanctioned Cloud Storage
├── Apps: Personal Dropbox, Personal Google Drive, WeTransfer
├── Action: BLOCK
└── Message: "Use company OneDrive instead"

RULE 6: Default Allow (with inspection)
├── Categories: All others
├── Action: ALLOW
└── SSL Inspection: Enabled, Malware Scan: Enabled

SSL INSPECTION EXCEPTIONS:
├── Healthcare sites (HIPAA concerns)
├── Banking/Financial (certificate pinning)
└── Specific domains: *.gov, healthcare-app.com

SASE vs Traditional Architecture

❌ Traditional (Hub & Spoke)

  • All traffic through datacenter
  • High latency for remote users
  • Single point of failure
  • Expensive MPLS links
  • Hardware bottlenecks

✅ SASE (Cloud-Delivered)

  • Direct to nearest edge PoP
  • Low latency everywhere
  • Global redundancy
  • OpEx model (no hardware)
  • Infinite scale

Zero Trust Principles in SASE

PrincipleHow SASE Implements It
Never Trust, Always VerifyEvery request authenticated, no implicit trust based on network location, continuous validation
Least Privilege AccessAccess granted per-app not network-wide, just-in-time access, no lateral movement
Assume BreachMicrosegmentation limits blast radius, all traffic inspected, continuous monitoring
