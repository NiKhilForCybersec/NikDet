Real Incident Scenarios

🚨 Incident: Malware Outbreak via Email

Initial Alert (9:15 AM):

Alert: Malware Detected
Host: WKSTN-FIN-023
User: jane.doe (Finance)
Threat: Emotet (trojan)
Action: Quarantined
Source: Email attachment "Invoice_12847.xlsm"

What Actually Happens:

9:15 - MDE alerts on Emotet. L1 sees alert, starts triage.

9:18 - L1 checks: "Quarantined" - considers closing. But waits...

9:22 - Two more alerts: WKSTN-FIN-019, WKSTN-HR-007. Same malware.

9:25 - L1 escalates: "Multiple hosts, same malware, escalating to L2."

9:30 - L2 declares incident. Starts bridge call.

9:35 - Check email: Same phishing email sent to 47 recipients.

9:40 - Block sender domain, delete email from all mailboxes.

9:45 - 8 users clicked. 3 had malware execute before quarantine.

10:00 - Isolate 3 compromised hosts for investigation.

10:30 - Investigation shows no lateral movement, no persistence.

11:00 - Reimage 3 hosts, user awareness reminder sent.

12:00 - Incident closed. Total time: 2h 45m.

⚡ Key Decisions Made

  1. Don't just close "quarantined" alerts - check for spread first
  2. Declare incident early - when pattern emerges (3+ hosts)
  3. Block at source - email before investigating all endpoints
  4. Isolate first, investigate second - for active malware

🚨 Incident: Compromised Admin Account

Initial Alert (2:30 AM - overnight):

Alert: Suspicious Sign-in Activity
Account: admin_svc_backup (service account)
Location: Russia
Risk Level: High
Action: Sign-in succeeded (no MFA on service account)

What Actually Happens:

2:30 AM - Alert fires. Night shift L1 is handling other tickets.

2:45 AM - L1 sees alert. "Service account from Russia... that's weird."

2:50 AM - L1 checks: No VPN for this account. Escalates immediately.

3:00 AM - On-call L2 paged. Reviews alert.

3:05 AM - L2 disables account, revokes sessions. Containment in 35 min.

3:15 AM - What did attacker do? Queries show...

// Attacker activity found:
2:32 AM - Logged in from 185.xx.xx.xx (Russia)
2:33 AM - Accessed Azure Portal
2:35 AM - Listed all storage accounts
2:38 AM - Downloaded blob from "backups" container
2:41 AM - Attempted to create new admin user (BLOCKED - PIM required)
2:45 AM - Attempted to access Key Vault (BLOCKED - no permission)
3:05 AM - Account disabled by IR team

3:30 AM - Manager notified. Data in "backups" container = DB backups with PII.

4:00 AM - Legal and CISO looped in. Potential breach.

8:00 AM - Investigation: Password was in code repository (leaked)

💡 Lessons Learned

  • Service accounts need MFA or conditional access
  • Credentials in code = instant compromise
  • 35-minute response prevented worse damage
  • PIM blocking admin creation was critical control

Common IR Mistakes

❌ Mistake 1: Not Preserving Evidence Before Containment

What happens: Attacker on server. Admin immediately reimages it. Now you have no evidence of what attacker did, what they accessed, or how they got in.

Real example: Ransomware on file server. IT reimages it within 1 hour. Investigation can't determine if data was exfiltrated. Company must assume breach and notify all customers.

✓ Correct: Isolate First, Preserve, Then Contain

  1. Network isolate (prevents spread)
  2. Capture memory dump (volatile evidence)
  3. Disk image or triage collection
  4. THEN reimage/rebuild

❌ Mistake 2: Tipping Off the Attacker

What happens: Attacker has access to email. IR team sends email: "We've detected an intrusion, please reset all passwords." Attacker sees email, accelerates attack, deploys ransomware.

✓ Correct: Assume Attacker Can See Communications

  • Use out-of-band communication (phone, Signal, separate email)
  • Don't discuss IR in company Slack/Teams if compromise is unknown
  • Coordinate simultaneous containment before attacker notices

❌ Mistake 3: Partial Containment

What happens: Find compromised user account, reset password. But attacker already created backdoor account. Attacker returns next day.

✓ Correct: Full Scope Before Eradication

  • Find ALL compromised accounts
  • Find ALL persistence mechanisms
  • Find ALL affected systems
  • Eradicate everything simultaneously

❌ Mistake 4: No Communication Plan

What happens: Major incident in progress. CEO walks into SOC asking "What's going on?" No one knows who should talk to executives. Chaos.

✓ Correct: Define Roles Before Incidents

  • Incident Commander: Overall coordination
  • Technical Lead: Investigation direction
  • Communications Lead: Talks to executives, legal, external
  • Scribe: Documents everything

Containment Playbooks

Malware Containment Checklist

  • Isolate affected host(s) from network
  • Identify source (email, USB, download, lateral movement)
  • Block source at perimeter (email sender, URL, IP)
  • Check for spread to other hosts
  • Preserve evidence (memory dump, disk image if needed)
  • Scan all hosts for same indicators
  • Remove malware / reimage system
  • Verify clean before returning to network

Compromised Account Checklist

  • Reset password immediately
  • Revoke all active sessions
  • Check for mailbox rules (forwarding, deletion)
  • Review account activity for last 30 days
  • Check for new MFA devices added
  • Look for OAuth app consents
  • Review data access (files downloaded, emails read)
  • Check for persistence (new accounts created, permissions changed)
  • Enable MFA if not already
  • Notify user and require security awareness

Ransomware Containment Checklist

  • ISOLATE EVERYTHING - network segment, affected hosts
  • DO NOT REBOOT (may trigger more encryption)
  • Disable accounts used by ransomware
  • Block C2 communications
  • Preserve encrypted samples and ransom note
  • Check backup integrity (are backups affected?)
  • Identify ransomware variant (for decryptor possibility)
  • Engage leadership for business decisions
  • Contact cyber insurance if applicable
  • Report to FBI IC3 / CISA

====================
Incident: INC-2025-0104-001 - Emotet Malware Outbreak
Date of Incident: January 4, 2025
PIR Date: January 6, 2025
Attendees: SOC Team, IT Security, Email Admin, Finance Manager

INCIDENT TIMELINE:
09:15 - First malware alert
09:25 - Pattern identified, escalated
09:30 - Incident declared
09:40 - Email blocked and purged
10:00 - Affected hosts isolated
11:00 - Reimaging complete
12:00 - Incident closed

WHAT WENT WELL:
✓ Detection was fast (within minutes of execution)
✓ L1 correctly identified pattern and escalated quickly
✓ Email containment executed within 30 minutes
✓ No lateral movement or data loss

WHAT COULD BE IMPROVED:
✗ Phishing email bypassed email security (new variant)
✗ 3 users still clicked despite training
✗ Macro-enabled files are still allowed from external senders
✗ Took 45 min to get IT to help with reimaging

ROOT CAUSE ANALYSIS:
- Email filtering did not catch zero-day variant
- Users trained 6 months ago, need refresher
- No policy blocking macro-enabled files from external

ACTION ITEMS:
| Action                                    | Owner       | Due Date   |
|-------------------------------------------|-------------|------------|
| Review email filtering with vendor        | Email Admin | Jan 10     |
| Block macro files from external senders   | IT Security | Jan 8      |
| Schedule Finance dept security training   | HR/Security | Jan 15     |
| Create runbook for faster IT coordination | SOC Lead    | Jan 12     |
| Add detection for Emotet variant IOCs     | Detection   | Jan 7      |

METRICS:
- Time to Detect: 3 minutes
- Time to Contain: 85 minutes
- Time to Eradicate: 165 minutes
- Business Impact: 6 person-hours lost, 2-hour Finance delay
