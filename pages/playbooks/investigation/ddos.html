Investigation Steps

Step 1: Confirm DDoS vs Other Outage

First 5 Minutes - Is This DDoS?
CheckDDoS IndicatorsNot DDoS Indicators
Traffic volumeMassive spike in inbound trafficNormal or below normal
Traffic sourcesMany IPs, often geographically distributedNormal user distribution
Traffic patternUnusual protocols, ports, request patternsNormal protocol mix
Application errorsTimeouts, connection refusedApplication bugs, misconfig
Affected scopeAll users, external facingSpecific users or internal

KQL - Traffic Volume Analysis

// Identify traffic volume anomaly
AzureNetworkAnalytics_CL
| where TimeGenerated > ago(1h)
| summarize 
    InboundGB = sum(InboundBytes_d) / 1073741824,
    OutboundGB = sum(OutboundBytes_d) / 1073741824,
    FlowCount = count()
    by bin(TimeGenerated, 5m)
| render timechart

KQL - Identify Attack Type

// Classify DDoS attack type
AzureNetworkAnalytics_CL
| where TimeGenerated > ago(1h)
| summarize 
    PacketCount = sum(FlowCount_d),
    UniqueSourceIPs = dcount(SrcIP_s),
    TopPorts = make_set(DestPort_d, 10)
    by L4Protocol_s, bin(TimeGenerated, 5m)
| extend AttackType = case(
    L4Protocol_s == "U" and PacketCount > 1000000, "UDP Flood",
    L4Protocol_s == "T" and PacketCount > 1000000, "TCP Flood",
    L4Protocol_s == "I", "ICMP Flood",
    "Unknown"
)
| order by PacketCount desc

SPL - NetFlow Analysis (Splunk)

index=netflow
| stats sum(bytes) as TotalBytes dc(src_ip) as UniqueIPs by dest_port, protocol
| eval GB=round(TotalBytes/1073741824, 2)
| where GB > 1
| sort -TotalBytes

Step 2: Identify Attack Characteristics

KQL - Source IP Analysis

// Identify top attacking sources
AzureNetworkAnalytics_CL
| where TimeGenerated > ago(1h)
| where FlowDirection_s == "I"  // Inbound
| summarize 
    Bytes = sum(BytesSent_d),
    Flows = count()
    by SrcIP_s, SrcCountry_s
| top 100 by Bytes
| extend GeoDistribution = strcat(SrcCountry_s, ": ", Bytes)

KQL - HTTP Flood Detection (L7)

// Detect HTTP flood attacks
AzureDiagnostics
| where TimeGenerated > ago(1h)
| where ResourceType == "APPLICATIONGATEWAYS"
| summarize 
    RequestCount = count(),
    UniqueIPs = dcount(clientIp_s),
    AvgResponseTime = avg(toint(timeTaken_s))
    by requestUri_s, bin(TimeGenerated, 1m)
| where RequestCount > 1000
| order by RequestCount desc

SPL - L7 Attack Detection (Splunk)

index=web sourcetype=access_combined
| stats count as Requests dc(clientip) as UniqueIPs by uri_path
| where Requests > 10000
| eval RequestsPerIP = Requests / UniqueIPs
| where RequestsPerIP > 100
| sort -Requests

Step 3: Impact Assessment

Measure Attack Impact
  • Bandwidth consumption: What % of capacity is used?
  • Server resources: CPU, memory, connection table status
  • Service availability: Which services are affected?
  • User impact: Error rates, response times
  • Business impact: Revenue loss, SLA breach

KQL - Service Impact

// Check service availability during attack
AzureDiagnostics
| where TimeGenerated > ago(1h)
| where ResourceType == "APPLICATIONGATEWAYS"
| summarize 
    Total = count(),
    Success = countif(httpStatus_s startswith "2"),
    ClientError = countif(httpStatus_s startswith "4"),
    ServerError = countif(httpStatus_s startswith "5"),
    Timeout = countif(httpStatus_s == "504")
    by bin(TimeGenerated, 1m)
| extend SuccessRate = round(100.0 * Success / Total, 2)
| render timechart

Post-Attack Analysis

KQL - Attack Summary Report

// Generate attack summary
let AttackStart = datetime(2024-01-15T10:00:00Z);  // Adjust
let AttackEnd = datetime(2024-01-15T12:00:00Z);    // Adjust
AzureNetworkAnalytics_CL
| where TimeGenerated between (AttackStart .. AttackEnd)
| summarize 
    TotalFlows = count(),
    TotalGB = round(sum(BytesSent_d) / 1073741824, 2),
    UniqueSourceIPs = dcount(SrcIP_s),
    PeakFlowsPerMin = max(FlowCount_d),
    TopSourceCountries = make_set(SrcCountry_s, 10),
    TopDestPorts = make_set(DestPort_d, 10)
| extend AttackDuration = AttackEnd - AttackStart

Interview-Ready Answer

"How do you investigate and respond to a DDoS attack?"

My Answer:

"DDoS response is unique because it's as much about availability as security. My approach prioritizes mitigation first, then investigation - restore service while understanding the attack.

Identify the Attack Type:
First, I classify the attack: Volumetric (bandwidth exhaustion) - look for traffic spike, usually UDP flood or amplification. Protocol attacks (SYN floods, fragmentation) - overwhelm server resources. Application layer (HTTP floods, Slowloris) - target the application itself. The type determines mitigation strategy.

Mitigation Actions:
For volumetric attacks, I engage upstream DDoS protection - cloud scrubbing services or ISP-level mitigation. For application-layer attacks, I implement WAF rate limiting, CAPTCHA challenges, or geo-blocking if attack is from specific regions. I might fail over to backup infrastructure or enable emergency static content mode.

Investigation During Attack:
While mitigating, I gather information: What IPs are attacking? Is it a botnet or small number of sources? What's being targeted - the main site or specific endpoints? Is this covering for something else - DDoS is sometimes used as distraction while attackers do something more targeted elsewhere.

Post-Attack Analysis:
After mitigation, I document the attack profile for future protection. I analyze if there are patterns - is someone targeting us regularly? I review if any security events occurred during the DDoS that might have been masked by the noise. I work on improving resilience - CDN configuration, auto-scaling, DDoS protection services."

💡 Pro Tips for Interview:
  • Know the three DDoS types: volumetric, protocol, application layer
  • Emphasize service restoration as primary goal
  • Mention DDoS as potential distraction for other attacks
  • Know that SOC often can't stop volumetric attacks alone - need upstream help
