Encryption Explained Simply

Imagine you want to send a secret letter:

  • Symmetric encryption: You and your friend share the SAME key to a lockbox. Fast, but how do you share the key securely?
  • Asymmetric encryption: Your friend has a PUBLIC mailbox anyone can drop letters into, but only THEIR PRIVATE key opens it.
  • TLS/HTTPS: Uses asymmetric to securely exchange a symmetric key, then symmetric for speed.
  • Certificate: A trusted third party (CA) vouches "This public key really belongs to google.com"

Digital Signatures

Signature Analogy

A digital signature is like a wax seal on a letter:

  • Authenticity: Only the sender could create this seal
  • Integrity: If the letter is opened, the seal breaks
  • Non-repudiation: Sender can't deny they sent it
DIGITAL SIGNATURE PROCESS SIGNING (Sender): 1. Hash the message "Hello Bob" ──▶ [SHA-256] ──▶ "a591a6d40..." (fixed-size fingerprint) 2. Encrypt hash with PRIVATE key = SIGNATURE "a591a6d40..." ──▶ [Sign with 🔐] ──▶ "Rk9PQkFS..." 3. Send message + signature { message: "Hello Bob", signature: "Rk9PQkFS..." } VERIFYING (Receiver): 1. Hash the received message "Hello Bob" ──▶ [SHA-256] ──▶ "a591a6d40..." 2. Decrypt signature with sender's PUBLIC key "Rk9PQkFS..." ──▶ [Verify with 🔓] ──▶ "a591a6d40..." 3. Compare hashes "a591a6d40..." == "a591a6d40..." ✅ Valid signature! If message was tampered: "a591a6d40..." != "different..." ❌ Invalid!

Hashing

What is Hashing?

Hashing is a one-way function that converts any data into a fixed-size fingerprint. You CANNOT reverse a hash to get the original data.

SHA-256256 bits✅ StandardEverything - TLS, blockchain, integrity

# SHA-256 example
echo -n "Hello" | sha256sum
# 185f8db32271fe25f561a6fc938b2e264306ec304eda518007d1764826381969

# Small change = completely different hash
echo -n "hello" | sha256sum  
# 2cf24dba5fb0a30e26e83b2ac5b9e29e1b161e5c1fa7425e73043362938b9824

# Password hashing with bcrypt (via Python)
import bcrypt
hashed = bcrypt.hashpw(b"password", bcrypt.gensalt())
# $2b$12$LQv3c1yqBWVHxkd0LHAkCOYz6TtxMQJqhN8/X4.nfTqB.q5h3LqC.

Never Do This!

  • ❌ MD5 for anything security-related
  • ❌ SHA-1 for signatures or certificates
  • ❌ Plain SHA-256 for passwords (use bcrypt/Argon2)
  • ❌ Unsalted password hashes

Certificates & PKI

Certificate Analogy

A certificate is like a government-issued ID card:

  • The CA (Certificate Authority) is like the government
  • The certificate says "This public key belongs to google.com"
  • The CA's signature proves it's not forged
  • Your browser has a list of CAs it trusts (like accepting foreign passports)

TLS/SSL & HTTPS

TLS Version History

SSL 2.0 (1995) - ❌ BROKEN

First public version. Completely insecure, never use.

SSL 3.0 (1996) - ❌ BROKEN (POODLE)

Better but still vulnerable. Disabled everywhere.

TLS 1.0 (1999) - ❌ DEPRECATED

First TLS. Still vulnerable to BEAST. PCI DSS requires disabling.

TLS 1.1 (2006) - ❌ DEPRECATED

Minor improvements. Also being phased out.

TLS 1.2 (2008) - ✅ MINIMUM ACCEPTABLE

Still widely used. Supports modern ciphers. SHA-256.

TLS 1.3 (2018) - ✅ RECOMMENDED

Current best. Faster handshake, removed weak ciphers, forward secrecy required.

Recommended TLS Configuration

  • ✅ TLS 1.2 minimum, prefer TLS 1.3
  • ✅ ECDHE key exchange (forward secrecy)
  • ✅ AES-GCM or ChaCha20-Poly1305 ciphers
  • ✅ SHA-256 or SHA-384 hashing
  • ❌ Disable SSL 2.0, 3.0, TLS 1.0, 1.1
  • ❌ Disable RC4, 3DES, export ciphers

Common Commands

OpenSSL Commands

# Generate private key
openssl genrsa -out private.key 2048

# Generate CSR (Certificate Signing Request)
openssl req -new -key private.key -out request.csr

# Generate self-signed certificate
openssl req -x509 -new -key private.key -out cert.pem -days 365

# View certificate
openssl x509 -in cert.pem -text -noout

# Test TLS connection
openssl s_client -connect google.com:443 -tls1_3

# Check certificate expiration
openssl s_client -connect google.com:443 2>/dev/null | openssl x509 -noout -dates

# Verify certificate chain
openssl verify -CAfile ca-bundle.crt server.crt

Let's Encrypt (Free Certificates)

# Install certbot
sudo apt install certbot python3-certbot-nginx

# Get certificate
sudo certbot --nginx -d example.com -d www.example.com

# Auto-renewal (usually automatic)
sudo certbot renew --dry-run

# Certificates stored in:
# /etc/letsencrypt/live/example.com/fullchain.pem
# /etc/letsencrypt/live/example.com/privkey.pem

Modern Developments

Post-Quantum Cryptography

Quantum computers could break RSA and ECC. NIST has standardized new algorithms:

  • CRYSTALS-Kyber: Key encapsulation (replacement for DH)
  • CRYSTALS-Dilithium: Digital signatures
  • SPHINCS+: Hash-based signatures

Timeline: Start planning now, full transition by 2030s when quantum computers become practical.
