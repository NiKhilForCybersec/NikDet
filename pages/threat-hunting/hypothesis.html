Hypothesis Development

Learn to craft effective, testable hypotheses that drive successful threat hunts.

What Makes a Good Hypothesis?

A hunting hypothesis is your educated guess about what malicious activity might be happening in your environment. Good hypotheses are the foundation of effective threat hunting.

Specific

Clearly defines the threat behavior you're looking for

Testable

Can be validated with data you have access to

Threat-Based

Grounded in real attacker behaviors and TTPs

Scoped

Reasonable timeframe and data volume

Hypothesis Sources

Where do hunting ideas come from?

SourceDescriptionExample
Threat Intelligence Reports about threat actors, campaigns "APT29 report mentions WMI persistence"
ATT&CK Coverage Gaps Techniques you can't currently detect "We have no detection for T1055"
Industry Incidents Breaches at similar organizations "Healthcare breach used RDP tunneling"
Security News New vulnerabilities, attack trends "New Exchange exploit in the wild"
Anomaly Signals Unusual patterns in your data "Spike in PowerShell execution"
Red Team Findings What your red team got away with "Red team used DCSync undetected"
Past Incidents Variations of previous attacks "Similar phishing campaign possible"

Hypothesis Templates

Template 1: Basic Structure

"I believe [THREAT ACTOR/BEHAVIOR] may be occurring in our environment, which would leave evidence in [DATA SOURCE], detectable by looking for [OBSERVABLE PATTERN]."

Template 2: ATT&CK-Based

"Attackers may be using [TECHNIQUE ID: NAME] via [SPECIFIC METHOD], which I can detect by querying [LOG SOURCE] for [SPECIFIC INDICATORS]."

Template 3: Intel-Driven

"Based on [INTEL SOURCE/REPORT], I suspect [THREAT ACTOR] may have targeted us using [TTP], evidenced by [INDICATORS] in [DATA]."

Hypothesis Examples by Tactic

Initial Access (TA0001)

Phishing Detection

Hypothesis: Attackers delivered malware via spearphishing attachments that bypassed email security, resulting in macro execution from Office documents.

Data Sources: Sysmon Event ID 1, Office audit logs

Observable: Word.exe or Excel.exe spawning cmd.exe, powershell.exe, or wscript.exe

Execution (TA0002)

LOLBin Abuse

Hypothesis: Attackers are using living-off-the-land binaries (certutil, mshta, regsvr32) to download and execute malicious payloads.

Data Sources: Sysmon Event ID 1, Windows Security 4688

Observable: certutil.exe with "-urlcache", mshta.exe with http://, regsvr32.exe with /s /i:http

Persistence (TA0003)

Scheduled Task Persistence

Hypothesis: Attackers have established persistence by creating scheduled tasks that execute from suspicious locations or run encoded commands.

Data Sources: Windows Security 4698, Sysmon Event ID 1

Observable: Tasks with actions in Temp/AppData/ProgramData, tasks running PowerShell with -enc flag

Credential Access (TA0006)

LSASS Credential Dumping

Hypothesis: Attackers are accessing LSASS memory to extract credentials using tools like Mimikatz or ProcDump.

Data Sources: Sysmon Event ID 10

Observable: Non-system processes accessing lsass.exe with GrantedAccess 0x1010, 0x1410, or 0x1fffff

Lateral Movement (TA0008)

RDP Lateral Movement

Hypothesis: Attackers are using RDP to move laterally between systems using compromised credentials.

Data Sources: Windows Security 4624 (Type 10), RDP logs

Observable: RDP connections from workstations (not admin jump boxes), connections at unusual times, single user RDP to many systems

Validating Your Hypothesis

Pre-Hunt Checklist

QuestionWhy It Matters
Do I have the required data? Can't hunt without visibility
How much data will this query return? Avoid overwhelming results
What does "normal" look like? Need baseline to find anomalies
What's my initial query? Start with a concrete approach
How will I know if I found something? Define success criteria
What will I do with findings? Plan for escalation or detection creation

Hypothesis Refinement

1
Start Broad

Begin with a general hypothesis about attacker behavior.

"Attackers may be using PowerShell for malicious activity."

2
Add Specificity

Narrow down to specific techniques or tools.

"Attackers may be using encoded PowerShell commands to evade detection."

3
Define Observables

Specify exactly what you'll look for in the data.

"PowerShell.exe or pwsh.exe with '-enc' or '-encoded' in command line arguments."

4
Scope It

Limit to reasonable time range and systems.

"Look at last 30 days across all workstations."

From Hypothesis to Hunt

HYPOTHESIS:
Attackers may have established persistence via WMI event subscriptions,
which would appear in Sysmon WMI events (Event IDs 19-21).

DATA SOURCE:
Microsoft-Windows-Sysmon/Operational

INITIAL QUERY:
Sysmon
| where EventID in (19, 20, 21)
| where TimeGenerated > ago(30d)
| project TimeGenerated, Computer, EventID, User, 
    Consumer, Filter, Destination
| sort by TimeGenerated desc

SUCCESS CRITERIA:
- WMI subscriptions created by non-admin users
- Subscriptions executing scripts from unusual paths
- Consumer destinations containing encoded commands

PIVOT PLAN:
If suspicious WMI found:
1. Check what process created it (parent process)
2. Look for other activity from same user/host
3. Check if destination script exists and contents
