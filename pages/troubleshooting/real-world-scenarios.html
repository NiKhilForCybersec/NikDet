Real-World Investigation Scenarios

Learn from detailed walkthroughs of actual security investigations. Each scenario shows the full investigation process from alert to resolution.

Scenario 1: The Impossible Travel That Wasn't

Alert: Impossible Travel - User logged in from US and Germany within 30 minutes

Severity: High

User: john.smith@company.com (Finance department)

Investigation Steps

1
Initial Triage

Alert shows login from New York (10:15 AM EST) and Frankfurt (10:42 AM EST). User is based in New York office.

2
Check Login Details

New York login: IP 203.45.67.89, Browser: Chrome, MFA: Completed via authenticator app

Germany login: IP 185.23.45.67, Browser: Edge, MFA: Completed via SMS

Red flag: Different browsers and MFA methods

3
Check IP Reputation

New York IP: Registered to Verizon (ISP), matches user's previous logins

Germany IP: Registered to hosting provider. Red flag: VPS/hosting provider IP

4
Check Post-Login Activity

Germany session: Created inbox rule forwarding emails to external address. Accessed finance reports. Major red flag!

5
Contact User

Called user directly. User confirms only the New York login was them. Received SMS code but didn't request it.

Verdict: TRUE POSITIVE - Account Compromise

What happened: Attacker phished user's credentials. Used SIM swapping or SS7 attack to intercept SMS MFA code. Logged in from Germany VPS.

Response taken:

  • Reset user's password immediately
  • Revoked all active sessions
  • Removed malicious inbox rule
  • Blocked the Germany IP
  • Changed user's MFA to authenticator app only (no SMS)
  • Reviewed what data was accessed

Scenario 2: The PowerShell That Was OK

Alert: Suspicious PowerShell - Encoded command execution

Severity: High

Host: WKS-FINANCE-042

Command: powershell.exe -EncodedCommand UwB0AGEAcgB0AC0AUwBsAGUAZQBwACAALQBTAGUAYwBvAG4AZABzACAANQA=

Investigation Steps

1
Decode the Command

Base64 decoded: Start-Sleep -Seconds 5

Just a sleep command - not immediately malicious, but need context.

2
Check Parent Process

Parent: SCCM Agent (ccmexec.exe)

Grandparent: services.exe

This is the legitimate SCCM/MECM software deployment chain.

3
Check Timing

Executed at 2:00 AM on Tuesday - matches IT's software deployment window.

4
Verify with IT

IT confirms they deployed a software package that night. Sleep command is part of installation script.

Verdict: FALSE POSITIVE - Legitimate IT Activity

What happened: IT software deployment uses encoded PowerShell for compatibility. Detection rule needs tuning.

Action taken:

  • Documented as false positive
  • Created exception for SCCM-initiated encoded commands
  • Kept rule active for non-SCCM encoded commands

Scenario 3: The Phishing That Spread

Alert: User reported suspicious email

Reporter: sarah.jones@company.com

Subject: "Urgent: Your password expires today - Action Required"

Investigation Steps

1
Analyze the Email

From: IT-Support@c0mpany.com (note: zero instead of 'o' - typosquatting)

Link: hxxps://company-password[.]com/reset (lookalike domain)

Reply-To: Different from sender. Confirmed phishing.

2
Check Who Else Received It

Searched email logs: 47 users received the same email!

3
Check Who Clicked

Web proxy logs show 8 users visited the phishing URL.

4
Identify Credential Submission

3 users have POST requests to the phishing site - likely submitted credentials!

5
Check for Compromise

1 of the 3 users has new login from unusual IP after credential submission. Confirmed compromise.

Verdict: TRUE POSITIVE - Phishing Campaign with 1 Compromise

Response taken:

  • Blocked sender domain and phishing URL at email gateway and proxy
  • Deleted phishing email from all 47 mailboxes
  • Reset passwords for all 3 users who submitted credentials
  • Revoked sessions and investigated compromised account
  • Sent awareness notice to all recipients
  • Reported phishing domain for takedown

Scenario 4: The Ransomware Near-Miss

Alert: Multiple file encryption detected

Severity: Critical

Host: SRV-FILE-01 (File server)

Investigation Steps

1
Immediate Isolation

Given the criticality, isolated server via EDR immediately while investigating.

2
Check What's Happening

EDR shows: cmd.exe → powershell.exe → encrypting files with .locked extension

Ransom note being dropped in each folder.

3
Identify Source

Process started from user's mapped drive connection from WKS-ACCT-015.

User: mike.wilson@company.com

4
Check Origin Workstation

WKS-ACCT-015: User opened malicious Excel attachment 30 minutes ago. Macro executed Cobalt Strike beacon. Ransomware deployed.

5
Scope the Impact

Only one folder (500 files) encrypted before isolation. Backups from 1 hour ago available.

Verdict: TRUE POSITIVE - Ransomware Stopped Early

Response taken:

  • Kept both systems isolated
  • Blocked all identified C2 IPs and domains
  • Reset Mike's credentials
  • Reimaged Mike's workstation
  • Restored encrypted files from backup
  • Scanned all systems for Cobalt Strike beacon IOCs
  • Enhanced email filtering for Excel macros

Key Takeaways

  • Context is everything: Same alert can be malicious or benign depending on context
  • Don't trust single indicators: Build the full picture before deciding
  • Check for spread: One compromised account/system often means more
  • Speed matters: For ransomware, isolate first, investigate second
  • Document everything: Future analysts will thank you
