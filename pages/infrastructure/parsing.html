Log Parsing & Normalization

Transform raw logs into structured, searchable data for effective detection and analysis.

What is Log Parsing?

Log parsing is the process of extracting structured fields from raw log data. Without parsing, logs are just text strings that are difficult to search and analyze.

Why Parsing Matters

Without ParsingWith Parsing
Search entire log text with wildcards Query specific fields: src_ip = "192.168.1.100"
Slow, inefficient searches Fast, indexed field lookups
Can't aggregate or group data Easy aggregation: stats count by src_ip
Difficult to correlate across sources Normalized fields enable correlation

Parsing Methods

1. Regular Expressions (Regex)

Most flexible but complex. Extract fields by matching patterns.

# SSH Failed Login Regex
Pattern: Failed password for (?:invalid user )?(?P<user>\S+) from (?P<src_ip>\d+\.\d+\.\d+\.\d+) port (?P<src_port>\d+)

# Splunk rex command
| rex field=_raw "Failed password for (?:invalid user )?(?P<user>\S+) from (?P<src_ip>\d+\.\d+\.\d+\.\d+)"

# Sentinel KQL parse
| parse RawData with * "Failed password for " UserType:string " " User:string " from " SrcIP:string " port " *

2. Key-Value Extraction

For logs with key=value pairs.

# Sample log with key-value pairs
action=login user=admin src=192.168.1.100 result=failure reason="invalid password"

# Splunk automatic extraction
| extract auto=true

# Splunk spath for JSON
| spath input=_raw

# KQL parse_json
| extend parsed = parse_json(RawData)

3. Delimited Parsing

For CSV, TSV, or other delimited formats.

# CSV log
2025-01-15,10:23:45,webserver01,login,admin,192.168.1.100,failure

# Splunk - specify fields
| makemv delim="," _raw
| eval date=mvindex(_raw,0), time=mvindex(_raw,1), host=mvindex(_raw,2)

# KQL - split
| extend fields = split(RawData, ",")
| extend date = fields[0], time = fields[1], host = fields[2]

4. Grok Patterns (Logstash/Elastic)

Pre-built regex patterns for common log formats.

# Logstash grok filter
filter {
  grok {
    match => { "message" => "%{SYSLOGTIMESTAMP:timestamp} %{HOSTNAME:host} %{PROG:program}\[%{POSINT:pid}\]: %{GREEDYDATA:message}" }
  }
}

# Common grok patterns
%{IP:src_ip}              # IP address
%{HOSTNAME:hostname}      # Hostname
%{EMAILADDRESS:email}     # Email
%{URIPATH:path}           # URL path
%{NUMBER:bytes}           # Numeric value

Common Log Formats

Syslog (RFC 5424)

# Format:
<priority>version timestamp hostname app-name procid msgid structured-data msg

# Example:
<34>1 2025-01-15T10:23:45.123Z webserver01 nginx 12345 - - GET /index.html 200

# Fields:
priority = 34 (facility=4/auth, severity=2/critical)
version = 1
timestamp = 2025-01-15T10:23:45.123Z
hostname = webserver01
app-name = nginx
procid = 12345

CEF (Common Event Format)

# Format:
CEF:Version|Device Vendor|Device Product|Device Version|Signature ID|Name|Severity|Extension

# Example:
CEF:0|Palo Alto|NGFW|10.0|threat|Malware Detected|9|src=192.168.1.100 dst=10.0.0.5 act=blocked

# Common CEF extensions:
src = source IP
dst = destination IP
spt = source port
dpt = destination port
act = action taken
msg = message
cs1-cs6 = custom strings
cn1-cn3 = custom numbers

JSON Logs

# Native JSON is easiest to parse
{
  "timestamp": "2025-01-15T10:23:45Z",
  "level": "error",
  "service": "auth-service",
  "message": "Authentication failed",
  "user": "admin",
  "source_ip": "192.168.1.100",
  "error_code": "AUTH_001"
}

# Splunk - automatic JSON extraction
| spath

# KQL - parse_json
| extend data = parse_json(RawData)
| extend user = data.user, source_ip = data.source_ip

Splunk Parsing Configuration

props.conf - Field Extractions

# $SPLUNK_HOME/etc/apps/myapp/local/props.conf

[my_custom_sourcetype]
TIME_FORMAT = %Y-%m-%d %H:%M:%S
TIME_PREFIX = timestamp=
MAX_TIMESTAMP_LOOKAHEAD = 30
SHOULD_LINEMERGE = false
LINE_BREAKER = ([\r\n]+)

# Field extractions using regex
EXTRACT-user = user=(?P<user>[^\s]+)
EXTRACT-src_ip = src=(?P<src_ip>\d+\.\d+\.\d+\.\d+)
EXTRACT-action = action=(?P<action>[^\s]+)

# Field aliases (normalization)
FIELDALIAS-source = SourceIP AS src_ip
FIELDALIAS-dest = DestinationIP AS dst_ip

# Calculated fields
EVAL-bytes_kb = bytes / 1024

Troubleshooting Parsing Issues

ProblemCauseSolution
Fields not extracted Regex doesn't match log format Test regex against sample logs, check for variations
Wrong timestamp TIME_FORMAT doesn't match Verify timestamp format, use strptime format codes
Multi-line logs broken LINE_BREAKER incorrect Adjust line breaking, use SHOULD_LINEMERGE
Truncated fields Field length limits Increase TRUNCATE setting, check field limits
Special characters Encoding issues Verify UTF-8, escape special chars in regex

Best Practices

  • Parse at ingest time: Extract fields during indexing, not search time
  • Use standard formats: Prefer JSON or CEF over custom formats
  • Normalize field names: Use consistent names across all sources
  • Document your parsers: Explain what each extraction does
  • Test with variations: Logs change over time, test edge cases
  • Monitor parsing errors: Alert on logs that fail to parse
