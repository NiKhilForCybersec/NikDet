Month 1: BEC Prevention Detections

Priority after the $340,000 wire fraud incident

APEX-DET-001: Suspicious Email Forwarding Rule Created

T1564.008 T1114.003 High Severity

Why this detection: This is exactly what the attacker did - created an inbox rule to forward payment-related emails to an external address.

Sigma Rule

title: Suspicious Email Forwarding Rule to External Domain id: apex-det-001 status: production description: Detects creation of inbox rules that forward emails to external domains, especially with financial keywords author: Apex Detection Engineering date: 2024/04/15 references: - Internal incident INC-2024-0315-001 logsource: product: m365 service: exchange detection: selection: Operation: - 'New-InboxRule' - 'Set-InboxRule' - 'UpdateInboxRules' filter_internal: Parameters|contains: - 'apexfinancial.com' - 'apex-financial.com' condition: selection and not filter_internal fields: - UserId - Operation - Parameters - ClientIP falsepositives: - Legitimate forwarding to known partners - Marketing automation (HubSpot, etc.) level: high tags: - attack.collection - attack.t1114.003 - attack.defense_evasion - attack.t1564.008

Microsoft Sentinel KQL (Production)

// APEX-DET-001: Suspicious Email Forwarding Rule // Production query running every 15 minutes let trustedDomains = dynamic(["apexfinancial.com", "apex-financial.com", "hubspot.com", "servicenow.com"]); let suspiciousKeywords = dynamic(["payment", "wire", "transfer", "invoice", "bank", "ach", "routing"]); let highRiskDomains = dynamic(["protonmail.com", "tutanota.com", "guerrillamail.com", "tempmail.com"]); OfficeActivity | where TimeGenerated > ago(15m) | where Operation in ("New-InboxRule", "Set-InboxRule", "UpdateInboxRules") | extend RuleParams = tostring(Parameters) | where RuleParams contains "ForwardTo" or RuleParams contains "RedirectTo" or RuleParams contains "ForwardAsAttachmentTo" // Extract forwarding address | extend ForwardTo = extract(@'"ForwardTo":\s*\[?"?([^"\],]+)"?\]?', 1, RuleParams) | extend ForwardDomain = tostring(split(ForwardTo, "@")[1]) // Skip internal domains | where ForwardDomain != "" and not(ForwardDomain has_any (trustedDomains)) // Check for suspicious patterns | extend HasFinancialKeywords = RuleParams has_any (suspiciousKeywords) | extend IsHighRiskDomain = ForwardDomain has_any (highRiskDomains) | extend RuleName = extract(@'"Name":\s*"([^"]*)"', 1, RuleParams) // Calculate severity | extend Severity = case( IsHighRiskDomain and HasFinancialKeywords, "Critical", IsHighRiskDomain or HasFinancialKeywords, "High", "Medium" ) | project TimeGenerated, UserId, Operation, RuleName, ForwardTo, ForwardDomain, HasFinancialKeywords, IsHighRiskDomain, Severity, ClientIP, RuleParams

Investigation Steps (for SOC analysts)

1. CHECK USER LEGITIMACY - Is this the user's own mailbox or a shared mailbox? - Contact user: "Did you create a forwarding rule to [address]?" 2. CHECK RECENT SIGN-IN ACTIVITY SigninLogs | where UserPrincipalName == "[affected_user]" | where TimeGenerated > ago(7d) | project TimeGenerated, Location, IPAddress, AppDisplayName, ResultType 3. IF USER DIDN'T CREATE IT → ACCOUNT COMPROMISED - Reset password immediately - Revoke all sessions - Delete the malicious rule - Check for other indicators (OAuth apps, MFA changes) 4. IF USER DID CREATE IT - Medium severity: Personal email forwarding - policy violation, notify HR - Review if sensitive data could have been forwarded
APEX-DET-002: Impossible Travel Detection

T1078 High Severity

Why this detection: The attacker accessed the CFO's account from Russia while CFO was in Chicago. If we had this detection, we would have caught it on Day 1.

Microsoft Sentinel KQL

// APEX-DET-002: Impossible Travel Detection // Custom implementation (not using built-in, more control over tuning) let vpnRanges = dynamic(["10.255.0.0/16", "172.16.100.0/24"]); // Apex VPN ranges let trustedLocations = dynamic(["United States", "Canada"]); // Normal work locations let maxSpeedKmh = 900; // Faster than commercial flight = suspicious SigninLogs | where TimeGenerated > ago(24h) | where ResultType == 0 // Successful logins only | where IPAddress !startswith "10.255." // Exclude VPN | project TimeGenerated, UserPrincipalName, IPAddress, Location, Latitude = toreal(LocationDetails.geoCoordinates.latitude), Longitude = toreal(LocationDetails.geoCoordinates.longitude) | sort by UserPrincipalName, TimeGenerated asc | extend PrevTime = prev(TimeGenerated, 1), PrevLat = prev(Latitude, 1), PrevLong = prev(Longitude, 1), PrevLocation = prev(Location, 1), PrevUser = prev(UserPrincipalName, 1) | where UserPrincipalName == PrevUser // Same user | extend TimeDiffHours = datetime_diff('hour', TimeGenerated, PrevTime) | where TimeDiffHours > 0 and TimeDiffHours < 24 // Calculate distance (simplified) | extend DistanceKm = geo_distance_2points(Longitude, Latitude, PrevLong, PrevLat) / 1000 | extend RequiredSpeedKmh = DistanceKm / TimeDiffHours | where RequiredSpeedKmh > maxSpeedKmh // Exclude known travel patterns | where not(Location in (trustedLocations) and PrevLocation in (trustedLocations)) | project TimeGenerated, UserPrincipalName, CurrentLocation = Location, PreviousLocation = PrevLocation, TimeDiffHours, DistanceKm = round(DistanceKm, 0), RequiredSpeedKmh = round(RequiredSpeedKmh, 0), CurrentIP = IPAddress
APEX-DET-003: Suspicious OAuth App Consent

T1550.001 Medium Severity

Why this detection: After BEC, attackers often add OAuth apps for persistence. Even if password is reset, the malicious app retains access.

Microsoft Sentinel KQL

// APEX-DET-003: OAuth Application Consent // Detects when users consent to third-party applications let approvedApps = dynamic([ "Microsoft Teams", "Zoom", "Slack", "Salesforce", "Adobe Sign", "DocuSign", "Workday" ]); AuditLogs | where TimeGenerated > ago(1h) | where OperationName == "Consent to application" | extend AppName = tostring(TargetResources[0].displayName) | extend AppId = tostring(TargetResources[0].id) | extend UserPrincipalName = tostring(InitiatedBy.user.userPrincipalName) | extend Permissions = tostring(AdditionalDetails) | where AppName !in (approvedApps) // High risk: Mail.Read, Mail.Send, Files.ReadWrite | extend HasMailPermission = Permissions contains "Mail" | extend HasFilePermission = Permissions contains "Files" | extend Severity = case( HasMailPermission and HasFilePermission, "High", HasMailPermission or HasFilePermission, "Medium", "Low" ) | project TimeGenerated, UserPrincipalName, AppName, AppId, HasMailPermission, HasFilePermission, Severity, Permissions

Month 2: Identity & Credential Protection

Protecting against credential theft and lateral movement

APEX-DET-017: LSASS Memory Access Detection

T1003.001 High Severity

Why this detection: Mimikatz, procdump targeting LSASS - the most common credential dumping technique.

Microsoft Sentinel KQL (MDE)

// APEX-DET-017: LSASS Memory Access // Detects processes accessing LSASS memory (credential dumping) let trustedProcesses = dynamic([ "MsMpEng.exe", // Windows Defender "csrss.exe", // Windows subsystem "services.exe", // Service Control Manager "lsass.exe", // Self-access "svchost.exe", // Windows services "WerFault.exe", // Crash dumps (legitimate) "wininit.exe", // Windows init "MpCmdRun.exe" // Defender command line ]); let trustedPaths = dynamic([ "C:\\Program Files\\Windows Defender", "C:\\Program Files\\Microsoft Security Client", "C:\\Windows\\System32" ]); DeviceProcessEvents | where TimeGenerated > ago(1h) | where FileName =~ "lsass.exe" or ProcessCommandLine contains "lsass" | where ActionType == "ProcessAccessed" or ProcessCommandLine contains "-ma lsass" or // procdump ProcessCommandLine contains "sekurlsa" or // mimikatz ProcessCommandLine contains "minidump" // comsvcs.dll method | extend InitProcess = InitiatingProcessFileName | extend InitPath = InitiatingProcessFolderPath | where InitProcess !in (trustedProcesses) | where not(InitPath has_any (trustedPaths)) | project TimeGenerated, DeviceName, AccountName, InitiatingProcessFileName, InitiatingProcessCommandLine, InitiatingProcessFolderPath, ProcessCommandLine | extend AlertSeverity = "High" | extend AlertTitle = "Potential Credential Dumping - LSASS Access"

Sigma Rule

title: LSASS Memory Access for Credential Dumping id: apex-det-017 status: production description: Detects processes accessing LSASS memory which may indicate credential dumping author: Apex Detection Engineering logsource: category: process_access product: windows detection: selection: TargetImage|endswith: '\lsass.exe' GrantedAccess|contains: - '0x1010' # PROCESS_VM_READ + PROCESS_QUERY_INFORMATION - '0x1410' - '0x1F0FFF' # PROCESS_ALL_ACCESS - '0x1F1FFF' filter_legitimate: SourceImage|endswith: - '\MsMpEng.exe' - '\csrss.exe' - '\services.exe' - '\svchost.exe' condition: selection and not filter_legitimate level: high tags: - attack.credential_access - attack.t1003.001
APEX-DET-019: Kerberoasting Detection

T1558.003 High Severity

Why this detection: Apex has 47 service accounts. Kerberoasting could compromise all of them offline.

Microsoft Sentinel KQL

// APEX-DET-019: Kerberoasting Detection // Detects high volume TGS requests with RC4 encryption let excludedAccounts = dynamic([ "svc_monitoring", // Legitimate monitoring "APEX\\svc_scanner", // Vulnerability scanner "healthcheck" // Health check account ]); SecurityEvent | where TimeGenerated > ago(1h) | where EventID == 4769 // Kerberos Service Ticket Operation | where TicketEncryptionType == "0x17" // RC4 - weak, targeted by Kerberoasting | where ServiceName !endswith "$" // Exclude machine accounts | where TargetUserName !in (excludedAccounts) | summarize TicketCount = count(), UniqueServices = dcount(ServiceName), ServicesList = make_set(ServiceName, 20), SourceIPs = make_set(IpAddress) by TargetUserName, bin(TimeGenerated, 5m) | where TicketCount > 15 and UniqueServices > 5 // Threshold: more than 15 requests for 5+ different services | extend Severity = case( UniqueServices > 20, "Critical", UniqueServices > 10, "High", "Medium" ) | project TimeGenerated, SuspectedAttacker = TargetUserName, TicketCount, UniqueServicesTargeted = UniqueServices, ServicesList, SourceIPs, Severity

Month 3: Endpoint & Ransomware Protection

Detecting malicious execution and ransomware precursors

APEX-DET-011: Suspicious Encoded PowerShell

T1059.001 High Severity

Why this detection: Most malware uses encoded PowerShell to evade detection.

Microsoft Sentinel KQL

// APEX-DET-011: Suspicious Encoded PowerShell Execution let sccmServer = "SCCM-PROD-01.apexfinancial.com"; // Exclude SCCM deployments DeviceProcessEvents | where TimeGenerated > ago(1h) | where FileName in~ ("powershell.exe", "pwsh.exe") | where ProcessCommandLine contains "-enc" or ProcessCommandLine contains "-encodedcommand" or ProcessCommandLine contains "-e " or ProcessCommandLine contains "FromBase64String" // Exclude known legitimate sources | where DeviceName != sccmServer | where InitiatingProcessFileName !in~ ("CcmExec.exe", "svchost.exe") // Check for suspicious patterns | extend HasDownloadCradle = ProcessCommandLine has_any ("WebClient", "DownloadString", "DownloadFile", "Invoke-WebRequest", "IWR", "wget", "curl") | extend HasHiddenWindow = ProcessCommandLine has_any ("-w hidden", "-windowstyle hidden", "-nop", "-noprofile") | extend FromOfficeApp = InitiatingProcessFileName in~ ("WINWORD.EXE", "EXCEL.EXE", "POWERPNT.EXE", "OUTLOOK.EXE") // Calculate severity | extend Severity = case( FromOfficeApp, "Critical", // Office spawning encoded PS = very bad HasDownloadCradle and HasHiddenWindow, "High", HasDownloadCradle or HasHiddenWindow, "Medium", "Low" ) | where Severity in ("Critical", "High", "Medium") // Filter out Low | project TimeGenerated, DeviceName, AccountName, InitiatingProcessFileName, ProcessCommandLine, HasDownloadCradle, HasHiddenWindow, FromOfficeApp, Severity
APEX-DET-027: Ransomware Precursor - Shadow Copy Deletion

T1490 Critical Severity

Why this detection: Ransomware always deletes shadow copies before encrypting. This gives us early warning.

Microsoft Sentinel KQL

// APEX-DET-027: Shadow Copy Deletion (Ransomware Indicator) // This is a CRITICAL detection - shadow copy deletion almost always precedes ransomware DeviceProcessEvents | where TimeGenerated > ago(15m) // Check frequently | where FileName in~ ("vssadmin.exe", "wmic.exe", "wbadmin.exe", "bcdedit.exe", "powershell.exe") | where ProcessCommandLine has_any ( "delete shadows", // vssadmin delete shadows "shadowcopy delete", // wmic shadowcopy delete "delete catalog", // wbadmin delete catalog "recoveryenabled no", // bcdedit /set recoveryenabled no "Win32_ShadowCopy", // WMI shadow copy access "resize shadowstorage" // Resize to 0 ) | project TimeGenerated, DeviceName, AccountName, FileName, ProcessCommandLine, InitiatingProcessFileName, InitiatingProcessCommandLine | extend AlertTitle = "CRITICAL: Ransomware Precursor Detected - Shadow Copy Manipulation" | extend AlertSeverity = "Critical" | extend RecommendedAction = "IMMEDIATELY isolate device and investigate. Do NOT reboot."
