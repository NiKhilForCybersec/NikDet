Real Investigation Scenarios

These are actual investigations L2 handles, with step-by-step approach:

Investigation A: Phishing Compromise (L1 escalated PowerShell alert) 1-2 hours

L1 Escalation:

Escalating: Suspicious PowerShell on WKSTN-PC042
User: mike.wilson
Finding: Outlook spawned encoded PowerShell (download cradle)
Target URL: http://10.0.0.5/stager
Checked: Decoded command, confirmed malicious intent
Need: Full investigation, possible isolation

L2 Investigation Steps:

Step 1: Verify and expand timeline (15 min)

// Get full process tree around the event
DeviceProcessEvents
| where DeviceName == "WKSTN-PC042"
| where TimeGenerated between (datetime(2025-01-04 14:00) .. datetime(2025-01-04 15:00))
| project TimeGenerated, FileName, ProcessCommandLine, 
    InitiatingProcessFileName, InitiatingProcessCommandLine, AccountName
| order by TimeGenerated asc

What you find:

14:28:12 - outlook.exe opens attachment "Invoice_Jan.docm"

14:28:15 - WINWORD.EXE spawns from outlook.exe

14:28:22 - powershell.exe spawns from WINWORD.EXE (macro executed)

14:28:23 - PowerShell runs encoded download cradle

14:28:24 - Connection attempt to 10.0.0.5:80

Step 2: Did the download succeed? (10 min)

// Check network connections
DeviceNetworkEvents
| where DeviceName == "WKSTN-PC042"
| where TimeGenerated > datetime(2025-01-04 14:28)
| where RemoteIP == "10.0.0.5" or RemoteUrl contains "10.0.0.5"
| project TimeGenerated, ActionType, RemoteIP, RemotePort, RemoteUrl, InitiatingProcessFileName

Result: Connection was BLOCKED by proxy/firewall. No successful download. ✓

Step 3: Any persistence or lateral movement? (15 min)

// Check for persistence mechanisms
DeviceRegistryEvents
| where DeviceName == "WKSTN-PC042"
| where TimeGenerated > datetime(2025-01-04 14:28)
| where RegistryKey contains "Run" or RegistryKey contains "Services"
| project TimeGenerated, ActionType, RegistryKey, RegistryValueName, RegistryValueData

// Check for scheduled tasks
DeviceProcessEvents
| where DeviceName == "WKSTN-PC042"
| where FileName in ("schtasks.exe", "at.exe")
| project TimeGenerated, ProcessCommandLine

Result: No persistence found. Attack stopped at download stage. ✓

Step 4: Find the malicious email (10 min)

// Find the phishing email
EmailEvents
| where RecipientEmailAddress == "mike.wilson@company.com"
| where TimeGenerated between (datetime(2025-01-04 14:00) .. datetime(2025-01-04 14:30))
| where AttachmentCount > 0
| project TimeGenerated, SenderFromAddress, Subject, AttachmentCount, ThreatTypes

Result: Email from "invoices@legtimate-vendor.com" (typosquat) with Invoice_Jan.docm

Step 5: Check for other recipients (10 min)

// Did anyone else get this email?
EmailEvents
| where SenderFromAddress == "invoices@legtimate-vendor.com"
| where TimeGenerated > ago(7d)
| summarize Recipients=make_set(RecipientEmailAddress), Count=count() by Subject
| where Count > 1

Result: 5 other users received similar emails. Need to check if anyone else clicked.

🎯 L2 Decision Point

Finding: Attack was blocked. No persistence. But 5 other users received same phishing.

Actions:

  1. No need to isolate WKSTN-PC042 (attack blocked)
  2. Block sender domain at email gateway
  3. Search for clicks from other 5 recipients
  4. Send awareness reminder to targeted users
  5. Add 10.0.0.5 to blocklist (investigate if internal - could be compromised host)

Investigation Summary:

INVESTIGATION REPORT

Incident: Phishing attempt with malicious macro
Status: Contained - Attack blocked by network controls

Timeline:
- 14:28: mike.wilson received phishing email from typosquat domain
- 14:28: Opened Word attachment, macro executed PowerShell download cradle
- 14:28: Download attempt to 10.0.0.5 BLOCKED by proxy

Scope:
- Affected: mike.wilson (WKSTN-PC042) - no compromise
- Related: 5 additional users received similar phishing emails
- No persistence or lateral movement detected

Actions Taken:
- Blocked sender domain at email gateway
- Added 10.0.0.5 to network blocklist
- Verified other 5 recipients did not click
- User awareness email sent

Root Cause: Phishing email bypassed email security (new domain)
Recommendation: Review email filtering rules for attachment types

Investigation B: Compromised Account (Impossible Travel confirmed real) 2-4 hours

L1 Escalation:

Escalating: Impossible Travel for david.chen
Login 1: New York at 09:00 (normal location)
Login 2: Russia at 09:45
Checked: Not VPN, not cloud service
User confirms NOT in Russia
Possible account compromise

L2 Investigation Steps:

Step 1: Immediate containment (5 min)

🔒
Reset password + Revoke sessions

User confirmed not in Russia = confirmed compromise. Stop attacker access NOW.

Step 2: What did the attacker do? (30 min)

// All activity from the Russian IP
let attackerIP = "185.156.xxx.xxx";
union SigninLogs, AADNonInteractiveUserSignInLogs
| where IPAddress == attackerIP
| where TimeGenerated > ago(7d)
| project TimeGenerated, UserPrincipalName, AppDisplayName, ResultType, 
    Location, ClientAppUsed, DeviceDetail
| order by TimeGenerated asc

What you find:

09:45 - Login to Outlook Web (success)

09:46 - Login to SharePoint (success)

09:47 - Login to Azure Portal (success)

09:52 - Failed login to admin portal (MFA blocked)

Step 3: Check email activity (20 min)

// What did attacker do in email?
OfficeActivity
| where UserId == "david.chen@company.com"
| where ClientIP == "185.156.xxx.xxx"
| where TimeGenerated > ago(24h)
| project TimeGenerated, Operation, Item, ResultStatus
| order by TimeGenerated asc

Findings:

  • Created inbox rule to forward all emails to external address
  • Read 47 emails in 7 minutes (automated scraping)
  • Downloaded 3 attachments

Step 4: Check for persistence (15 min)

// Check for mailbox rules (persistence)
OfficeActivity
| where UserId == "david.chen@company.com"
| where Operation in ("New-InboxRule", "Set-InboxRule", "UpdateInboxRules")
| project TimeGenerated, Operation, Parameters, ClientIP

Found: Inbox rule forwarding to "david.chen.backup@protonmail.com" - DELETE THIS!

Step 5: Check SharePoint/OneDrive access (15 min)

// What files were accessed?
OfficeActivity
| where UserId == "david.chen@company.com"
| where ClientIP == "185.156.xxx.xxx"
| where Operation in ("FileDownloaded", "FileAccessed", "FileSyncDownloadedFull")
| project TimeGenerated, Operation, SourceFileName, Site_Url

Found: Downloaded "Q4 Financial Report.xlsx", "Customer List.xlsx", "Contract_ACME.pdf"

🎯 L2 Decision Point: This is a Data Breach

Escalate to L3/IR Team:

  • Confirmed data exfiltration (sensitive files downloaded)
  • Email forwarding rule = ongoing data leak
  • May require breach notification

Immediate Actions:

  1. ✓ Password reset + session revoke (done)
  2. ✓ Delete malicious inbox rule
  3. ✓ Enable MFA if not already
  4. Block the attacker IP at firewall
  5. Preserve email logs for legal
  6. Escalate for breach assessment

Investigation C: Internal Reconnaissance (Unusual AD queries) 1-2 hours

L1 Escalation:

Alert: Enumeration of domain admins
User: svc_backup (service account)
Activity: LDAP query for Domain Admins group members
Source: SERVER-DB01
Unusual: Service account shouldn't be querying AD groups

L2 Investigation:

Step 1: Is this normal for this service account? (10 min)

// Check historical behavior of svc_backup
IdentityQueryEvents
| where AccountName == "svc_backup"
| where TimeGenerated > ago(30d)
| summarize QueryTypes=make_set(QueryType), 
    QueryTargets=make_set(QueryTarget), 
    Count=count() by bin(TimeGenerated, 1d)
| order by TimeGenerated desc

Finding: This account has NEVER queried Domain Admins before. First time in 30 days. 🚨

Step 2: What else is this account doing? (15 min)

// Full activity timeline
union IdentityQueryEvents, IdentityLogonEvents, DeviceProcessEvents, DeviceNetworkEvents
| where AccountName == "svc_backup" or InitiatingProcessAccountName == "svc_backup"
| where TimeGenerated > ago(24h)
| project TimeGenerated, ActionType, DeviceName, ProcessCommandLine, 
    QueryType, QueryTarget, DestinationIPAddress
| order by TimeGenerated asc

Timeline found:

02:15 - Normal backup job ran on SERVER-DB01

03:45 - svc_backup logged into SERVER-WEB01 (unusual!)

03:46 - BloodHound-like LDAP queries started

03:47 - Queried Domain Admins, Enterprise Admins

03:48 - Queried all computers in domain

03:50 - Queried SPNs (Kerberoasting prep?)

Step 3: How did attacker get svc_backup credentials? (20 min)

// Check for credential access on servers where svc_backup runs
DeviceProcessEvents
| where DeviceName in ("SERVER-DB01", "SERVER-WEB01")
| where TimeGenerated > ago(7d)
| where FileName in ("mimikatz.exe", "procdump.exe", "secretsdump.py") 
    or ProcessCommandLine contains "sekurlsa" 
    or ProcessCommandLine contains "lsass"
| project TimeGenerated, DeviceName, FileName, ProcessCommandLine, AccountName

Found: procdump.exe ran on SERVER-DB01 targeting lsass.exe 2 days ago!

🎯 This is Active Compromise - Escalate Immediately

Attack chain identified:

  1. Attacker compromised SERVER-DB01 (how? need to investigate)
  2. Dumped credentials using procdump (got svc_backup creds)
  3. Used svc_backup to pivot and enumerate AD
  4. Likely preparing for privilege escalation (queried SPNs = Kerberoasting)

Immediate containment:

  • Disable svc_backup account
  • Isolate SERVER-DB01 and SERVER-WEB01
  • Reset all admin passwords (attacker may have harvested)
  • Engage IR team - this is a domain compromise in progress

Common L2 Inefficiencies

❌ Inefficiency #1: Repeating L1's Work

Problem: L2 receives escalation, ignores L1's findings, starts investigation from scratch. Wastes 20-30 minutes duplicating effort.

✓ Solution: Build on L1's Work

  • Read the escalation notes completely
  • Trust (but verify quickly) L1's findings
  • Start from where L1 stopped, not from zero
  • If L1 checked user legitimacy, don't recheck - expand the investigation

❌ Inefficiency #2: Tunnel Vision on Single Alert

Problem: L2 focuses only on the escalated alert, misses related activity that shows larger attack.

✓ Solution: Always Pivot

For every investigation, ask:

  • What happened BEFORE this alert? (How did attacker get here?)
  • What happened AFTER? (What's the impact?)
  • Are there other alerts for this user/host/IP?
  • Did this affect other systems?

❌ Inefficiency #3: Investigating Then Containing

Problem: Spending 2 hours investigating while attack is still active. Attacker continues to exfiltrate data.

✓ Solution: Contain First If Active Threat

Active threat (credentials stolen, C2 active)→ Contain FIRST, investigate after
Historical event (attack was days ago)→ Investigate first (attacker already finished)
Blocked attack (no successful execution)→ Investigate for scope, no urgent containment

❌ Inefficiency #4: Not Using Saved Queries

Problem: Writing the same investigation queries from scratch every time. "What processes ran on this host" query written 100 times.

✓ Solution: Build Query Library

  • Save common investigation queries with variables
  • Create investigation templates for common scenarios
  • Share with team - don't reinvent the wheel

Investigation Query Patterns

User Investigation (Sentinel/KQL)

// TEMPLATE: Full user activity investigation
let targetUser = "john.doe@company.com";
let investigationWindow = 24h;

// 1. Authentication activity
SigninLogs
| where TimeGenerated > ago(investigationWindow)
| where UserPrincipalName =~ targetUser
| project TimeGenerated, ResultType, ResultDescription, IPAddress, 
    Location, AppDisplayName, ClientAppUsed, DeviceDetail
| order by TimeGenerated desc;

// 2. Email activity
OfficeActivity
| where TimeGenerated > ago(investigationWindow)
| where UserId =~ targetUser
| where Operation in ("MailItemsAccessed", "Send", "Create", "UpdateInboxRules")
| project TimeGenerated, Operation, Item, ClientIP;

// 3. File activity
OfficeActivity
| where TimeGenerated > ago(investigationWindow)
| where UserId =~ targetUser
| where Operation contains "File"
| project TimeGenerated, Operation, SourceFileName, Site_Url, ClientIP;

// 4. Related alerts
SecurityAlert
| where TimeGenerated > ago(7d)
| where Entities contains targetUser
| project TimeGenerated, AlertName, Severity, Status

Host Investigation (Sentinel/KQL)

// TEMPLATE: Full host investigation
let targetHost = "WKSTN-PC042";
let investigationWindow = 24h;

// 1. Process execution
DeviceProcessEvents
| where TimeGenerated > ago(investigationWindow)
| where DeviceName =~ targetHost
| project TimeGenerated, FileName, ProcessCommandLine, 
    InitiatingProcessFileName, AccountName, SHA256
| order by TimeGenerated desc;

// 2. Network connections
DeviceNetworkEvents
| where TimeGenerated > ago(investigationWindow)
| where DeviceName =~ targetHost
| where ActionType == "ConnectionSuccess"
| project TimeGenerated, RemoteIP, RemotePort, RemoteUrl, 
    InitiatingProcessFileName, InitiatingProcessCommandLine
| order by TimeGenerated desc;

// 3. File activity
DeviceFileEvents
| where TimeGenerated > ago(investigationWindow)
| where DeviceName =~ targetHost
| where ActionType in ("FileCreated", "FileModified", "FileRenamed")
| project TimeGenerated, ActionType, FileName, FolderPath, 
    InitiatingProcessFileName, SHA256;

// 4. Logon activity
DeviceLogonEvents
| where TimeGenerated > ago(investigationWindow)
| where DeviceName =~ targetHost
| project TimeGenerated, ActionType, AccountName, LogonType, 
    RemoteIP, IsLocalAdmin

Splunk Equivalents

// User investigation
index=* user="john.doe@company.com" earliest=-24h
| stats count by sourcetype, action, src_ip, app
| sort -count

// Host investigation
index=* host="WKSTN-PC042" earliest=-24h
| stats count by sourcetype, EventCode, process_name, dest_ip
| sort -count

// Process execution
index=windows sourcetype="WinEventLog:Security" EventCode=4688 host="WKSTN-PC042"
| table _time, user, process_name, process, parent_process_name
| sort -_time

Containment Decisions

Containment Decision Matrix

SituationContainment ActionBusiness Impact
Confirmed account compromise Reset password + Revoke sessions User must re-login, low impact
Malware executing on endpoint Isolate device from network User offline, moderate impact
Ransomware detected Isolate segment, disable accounts HIGH - business disruption
Data exfiltration in progress Block destination IP/domain Low if attacker-controlled
Phishing - user clicked but attack blocked None required No impact
Suspicious but unconfirmed Monitor closely, prepare containment No impact

How to Isolate (MDE)

1. Microsoft 365 Defender Portal
2. Devices → Select device
3. "..." menu → Isolate Device
4. Select isolation type:
   - Full: No network access except to Defender service
   - Selective: Block specific IPs/ports
5. Add comment for audit trail
6. Click Isolate

To release: Same menu → "Release from isolation"

How to Reset/Revoke (Entra ID)

1. Entra ID → Users → Select user
2. Reset password: "Reset password" button
3. Revoke sessions: "Revoke sessions" button
4. Block sign-in (if needed): "Block sign-in" under properties

PowerShell method:
# Reset password
Set-AzureADUserPassword -ObjectId "user@company.com" -ForceChangePasswordNextLogin $true

# Revoke all sessions
Revoke-AzureADUserAllRefreshToken -ObjectId "user@company.com"

Handling L1 Escalations

Good vs Poor Escalations

Good EscalationPoor EscalationHow to Coach L1
Clear summary of alert Just forwarded raw alert "Include your assessment, not just the alert"
What they checked No indication of work done "Tell me what you looked at so I don't duplicate"
Their hypothesis "I don't know, you figure it out" "It's okay to be wrong, but tell me what you think"
Urgency level noted No priority indication "Let me know if this is time-sensitive"

When to Push Back to L1

  • Escalation has zero investigation done → "What did you check? Start with the 5-minute triage."
  • Known FP pattern → "Check the FP doc - this is documented as benign. But good catch asking!"
  • Missing basic info → "Can you add the relevant IOCs before I dig in?"
