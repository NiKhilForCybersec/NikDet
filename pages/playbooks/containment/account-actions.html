Account Containment Actions

Procedures for containing compromised accounts across Active Directory, Azure AD, and service accounts.

Active Directory Containment

User Account Actions

// Disable account (immediate)
Disable-ADAccount -Identity "compromised.user"

// Reset password
Set-ADAccountPassword -Identity "compromised.user" -Reset `
    -NewPassword (ConvertTo-SecureString "TempP@ss123!" -AsPlainText -Force)
Set-ADUser -Identity "compromised.user" -ChangePasswordAtLogon $true

// Remove from all groups (preserve list first)
$groups = Get-ADPrincipalGroupMembership -Identity "compromised.user"
$groups | Export-Csv "C:\IR\user-groups-backup.csv"
$groups | Where-Object {$_.Name -ne "Domain Users"} | ForEach-Object {
    Remove-ADGroupMember -Identity $_.Name -Members "compromised.user" -Confirm:$false
}

// Move to quarantine OU
Move-ADObject -Identity "CN=compromised.user,OU=Users,DC=company,DC=com" `
    -TargetPath "OU=Quarantine,DC=company,DC=com"

// Clear service principal names (if any)
Set-ADUser -Identity "compromised.user" -ServicePrincipalNames @{}

// Expire account immediately
Set-ADAccountExpiration -Identity "compromised.user" -DateTime (Get-Date)

Force Logoff Active Sessions

// Find active sessions
$computers = Get-ADComputer -Filter * -SearchBase "OU=Workstations,DC=company,DC=com"
foreach ($computer in $computers) {
    $sessions = query user /server:$computer.Name 2>$null
    if ($sessions -match "compromised.user") {
        Write-Host "User logged into: $($computer.Name)"
    }
}

// Force logoff remotely
Invoke-Command -ComputerName "WORKSTATION01" -ScriptBlock {
    $sessionId = ((quser | Where-Object {$_ -match "compromised.user"}) -split ' +')[2]
    logoff $sessionId
}

// Kill Kerberos tickets (on DC)
klist purge -li 0x3e7

Azure AD / Entra ID Containment

// Connect to Microsoft Graph
Connect-MgGraph -Scopes "User.ReadWrite.All", "Directory.AccessAsUser.All"

// Block sign-in
Update-MgUser -UserId "user@company.com" -AccountEnabled:$false

// Revoke all refresh tokens (invalidates all sessions)
Revoke-MgUserSignInSession -UserId "user@company.com"

// Reset password
$passwordProfile = @{
    Password = "NewTempP@ss456!"
    ForceChangePasswordNextSignIn = $true
    ForceChangePasswordNextSignInWithMfa = $true
}
Update-MgUser -UserId "user@company.com" -PasswordProfile $passwordProfile

// Remove all group memberships
$memberships = Get-MgUserMemberOf -UserId "user@company.com"
foreach ($group in $memberships) {
    if ($group.AdditionalProperties.'@odata.type' -eq '#microsoft.graph.group') {
        Remove-MgGroupMemberByRef -GroupId $group.Id -DirectoryObjectId (Get-MgUser -UserId "user@company.com").Id
    }
}

// Remove all app role assignments
$appRoles = Get-MgUserAppRoleAssignment -UserId "user@company.com"
foreach ($role in $appRoles) {
    Remove-MgUserAppRoleAssignment -UserId "user@company.com" -AppRoleAssignmentId $role.Id
}

// Revoke all OAuth consents
$consents = Get-MgUserOauth2PermissionGrant -UserId "user@company.com"
foreach ($consent in $consents) {
    Remove-MgOauth2PermissionGrant -OAuth2PermissionGrantId $consent.Id
}

// Remove registered devices
$devices = Get-MgUserRegisteredDevice -UserId "user@company.com"
foreach ($device in $devices) {
    Remove-MgDevice -DeviceId $device.Id
}

Service Account Password Rotation

// Find services using the account
Get-WmiObject Win32_Service | Where-Object {$_.StartName -like "*svc_account*"} | 
    Select-Object Name, DisplayName, StartName, State, SystemName

// Reset service account password in AD
$newPassword = ConvertTo-SecureString "NewServiceP@ss789!" -AsPlainText -Force
Set-ADAccountPassword -Identity "svc_account" -Reset -NewPassword $newPassword

// Update service on target servers
$servers = @("SERVER01", "SERVER02")
$credential = Get-Credential -UserName "DOMAIN\svc_account"
foreach ($server in $servers) {
    Invoke-Command -ComputerName $server -ScriptBlock {
        $service = Get-WmiObject Win32_Service -Filter "Name='ServiceName'"
        $service.Change($null,$null,$null,$null,$null,$null,$using:credential.UserName,$using:credential.GetNetworkCredential().Password)
        Restart-Service -Name "ServiceName"
    }
}

Domain Admin Compromise Response

// CRITICAL: Reset krbtgt password TWICE (24 hours apart)
# First reset
Set-ADAccountPassword -Identity krbtgt -Reset -NewPassword (ConvertTo-SecureString "RandomPass1!" -AsPlainText -Force)

# Wait 24 hours for replication, then:
Set-ADAccountPassword -Identity krbtgt -Reset -NewPassword (ConvertTo-SecureString "RandomPass2!" -AsPlainText -Force)

// Check for Golden Ticket indicators
# Look for TGTs with unusually long lifetimes
# Check for Kerberos events with encryption type mismatches

// Review AdminSDHolder ACL
Get-ACL "AD:CN=AdminSDHolder,CN=System,DC=company,DC=com" | Format-List

// Check for DCSync permissions
Get-ADPermission -Identity "DC=company,DC=com" | Where-Object {
    $_.ExtendedRights -like "*Replicating*"
}

Verification Checklist

  • ☐ Account disabled in all directories (AD, Azure AD)
  • ☐ Password reset with strong random password
  • ☐ All active sessions terminated
  • ☐ Group memberships removed/documented
  • ☐ OAuth app consents revoked
  • ☐ Registered devices removed
  • ☐ Inbox rules checked and removed
  • ☐ Email forwarding disabled
  • ☐ No VPN/remote access tokens active
  • ☐ Service dependencies identified and coordinated

Account Restoration Process

After investigation complete and cleared:

  1. Verify all persistence mechanisms removed
  2. Re-enable account with new password
  3. Re-enroll MFA on new device
  4. Restore necessary group memberships
  5. Brief user on incident and prevention
  6. Enhanced monitoring for 30 days

Interview-Ready Answer

"How do you handle account containment for a compromised user?"

My Answer:

"Account containment needs to be thorough - attackers maintain multiple persistence methods. My approach: terminate access, reset credentials, remove persistence, verify clean.

Terminate Active Sessions:
Password reset alone isn't enough - attackers have active tokens. I revoke all sessions and refresh tokens immediately. In Azure AD, that's Revoke-AzureADUserAllRefreshToken. In Okta, it's clearing sessions. The goal is kicking the attacker out right now, not waiting for tokens to expire.

Reset and Secure:
Reset password to a strong, random value. If this is a service account, coordinate with app owners first - breaking their app at 2 AM makes you unpopular. Review and potentially reset MFA - attackers may have registered their own device.

Remove Persistence:
Check for attacker persistence: inbox rules forwarding email, OAuth app consents, delegated permissions, administrative role assignments they may have added. Each of these gives them a way back in after password reset."

💡 Pro Tips for Interview:
  • Emphasize session revocation, not just password reset
  • Know about OAuth app and inbox rule persistence
  • Coordinate service account changes with app owners
  • Check for MFA manipulation
