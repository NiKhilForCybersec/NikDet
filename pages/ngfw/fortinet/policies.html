FortiGate Firewall Policies

Complete guide to firewall policy configuration, NAT, policy ordering, and best practices.

Policy Flow Analogy

Think of policies like a bouncer with a rulebook:

  1. Packet arrives → "Where are you coming from? Where going?"
  2. Bouncer checks rulebook from TOP to BOTTOM
  3. First matching rule applies (STOP checking)
  4. If no rules match → DENY by default

Rule order matters! A broad "allow all" rule at the top will match everything before specific rules are checked.

Before Policies: Create Objects

Address Objects

Define reusable network objects before creating policies:

# Single host
config firewall address
    edit "Server-Web01"
        set type ipmask
        set subnet 10.1.1.100 255.255.255.255
        set comment "Production web server"
    next
end

# Network/subnet
config firewall address
    edit "Net-Users"
        set type ipmask
        set subnet 10.100.0.0 255.255.0.0
        set comment "User network"
    next
end

# IP range
config firewall address
    edit "DHCP-Pool"
        set type iprange
        set start-ip 10.1.1.100
        set end-ip 10.1.1.200
    next
end

# FQDN (domain name - auto-resolves)
config firewall address
    edit "Office365"
        set type fqdn
        set fqdn "*.office365.com"
    next
end

# Geography-based
config firewall address
    edit "Geo-Russia"
        set type geography
        set country "RU"
    next
end

Address Groups

config firewall addrgrp
    edit "Grp-WebServers"
        set member "Server-Web01" "Server-Web02" "Server-Web03"
        set comment "All web servers"
    next
end

config firewall addrgrp
    edit "Grp-BlockedCountries"
        set member "Geo-Russia" "Geo-China" "Geo-NorthKorea"
        set comment "Blocked source countries"
    next
end

Service Objects

# Custom TCP service
config firewall service custom
    edit "TCP-8080"
        set tcp-portrange 8080
        set comment "Custom web port"
    next
end

# Custom UDP service
config firewall service custom
    edit "UDP-5060"
        set udp-portrange 5060
        set comment "SIP signaling"
    next
end

# Service range
config firewall service custom
    edit "HighPorts"
        set tcp-portrange 1024-65535
    next
end

# Multiple ports in one service
config firewall service custom
    edit "WebPorts"
        set tcp-portrange 80 443 8080 8443
    next
end

Service Groups

config firewall service group
    edit "Grp-WebServices"
        set member "HTTP" "HTTPS" "TCP-8080"
    next
end

config firewall service group
    edit "Grp-Microsoft"
        set member "DNS" "HTTP" "HTTPS" "MS-SQL" "SMB"
    next
end

Creating Firewall Policies

Basic Allow Policy

# Allow internal users to access internet
config firewall policy
    edit 0  # 0 = auto-assign ID
        set name "Users-to-Internet"
        set srcintf "VLAN100-Users"
        set dstintf "wan1"
        set srcaddr "all"
        set dstaddr "all"
        set action accept
        set schedule "always"
        set service "ALL"
        set logtraffic all
        set nat enable
        
        # Add UTM profiles (optional but recommended)
        set utm-status enable
        set av-profile "default"
        set webfilter-profile "default"
        set ips-sensor "default"
        set application-list "default"
        set ssl-ssh-profile "certificate-inspection"
    next
end

Restrictive Policy (Best Practice)

# Allow only specific services
config firewall policy
    edit 0
        set name "Users-Web-Only"
        set srcintf "Trust"
        set dstintf "Untrust"
        set srcaddr "Net-Users"
        set dstaddr "all"
        set action accept
        set schedule "always"
        set service "HTTP" "HTTPS" "DNS"  # Only web traffic
        set logtraffic all
        set nat enable
        
        # Security profiles
        set utm-status enable
        set av-profile "strict-av"
        set webfilter-profile "corporate-filter"
        set ips-sensor "protect-client"
        set application-list "allow-business-apps"
        set ssl-ssh-profile "deep-inspection"
    next
end

Deny Policy with Logging

# Block traffic from untrusted countries
config firewall policy
    edit 0
        set name "Block-BadCountries"
        set srcintf "wan1"
        set dstintf "any"
        set srcaddr "Grp-BlockedCountries"
        set dstaddr "all"
        set action deny
        set schedule "always"
        set service "ALL"
        set logtraffic all  # Log all blocked traffic
        set comments "Block known malicious source countries"
    next
end

DMZ Inbound Policy (For Public Servers)

# Allow internet to DMZ web server
config firewall policy
    edit 0
        set name "Internet-to-WebServer"
        set srcintf "wan1"
        set dstintf "DMZ"
        set srcaddr "all"
        set dstaddr "Server-Web01"  # VIP or actual server
        set action accept
        set schedule "always"
        set service "HTTP" "HTTPS"
        set logtraffic all
        
        # CRITICAL: Enable security on inbound!
        set utm-status enable
        set av-profile "default"
        set ips-sensor "protect-server"
        set waf-profile "web-server"  # Web Application Firewall
    next
end

User-Based Policy

# Allow only IT group to use SSH
config firewall policy
    edit 0
        set name "IT-SSH-Access"
        set srcintf "Trust"
        set dstintf "Trust"
        set srcaddr "all"
        set dstaddr "Grp-Servers"
        set action accept
        set schedule "always"
        set service "SSH"
        set groups "IT-Admins"  # AD group
        set logtraffic all
    next
end

NAT Configuration

Source NAT (Outbound)

Source NAT is typically enabled in the policy itself:

config firewall policy
    edit 10
        set name "Outbound-NAT"
        set srcintf "Trust"
        set dstintf "wan1"
        set srcaddr "all"
        set dstaddr "all"
        set action accept
        set nat enable  # Enables Source NAT using WAN interface IP
    next
end

NAT to Specific IP (IP Pool)

# Create IP Pool
config firewall ippool
    edit "Pool-PublicIPs"
        set startip 203.0.113.10
        set endip 203.0.113.20
        set type overload  # PAT (many-to-one)
        # set type one-to-one  # Static NAT
    next
end

# Use in policy
config firewall policy
    edit 10
        set nat enable
        set ippool enable
        set poolname "Pool-PublicIPs"
    next
end

Destination NAT (VIP - Port Forwarding)

# Create Virtual IP for web server
config firewall vip
    edit "VIP-WebServer"
        set extip 203.0.113.50  # Public IP
        set mappedip "10.100.1.50"  # Internal server IP
        set extintf "wan1"
        set portforward enable
        set extport 443
        set mappedport 443
        set comment "HTTPS to internal web server"
    next
end

# Create policy using VIP
config firewall policy
    edit 0
        set name "Inbound-HTTPS"
        set srcintf "wan1"
        set dstintf "DMZ"
        set srcaddr "all"
        set dstaddr "VIP-WebServer"  # Reference the VIP
        set action accept
        set service "HTTPS"
        set utm-status enable
        set ips-sensor "protect-server"
    next
end

Full NAT Hairpin (Internal to VIP)

When internal users need to access the public IP of an internal server:

# Enable hairpin NAT on VIP
config firewall vip
    edit "VIP-WebServer"
        set extip 203.0.113.50
        set mappedip "10.100.1.50"
        set extintf "any"  # Important: "any" not specific interface
        set nat-source-vip enable  # Enable hairpin
    next
end

# Create internal-to-VIP policy
config firewall policy
    edit 0
        set name "Internal-to-VIP"
        set srcintf "Trust"
        set dstintf "DMZ"
        set srcaddr "Net-Users"
        set dstaddr "VIP-WebServer"
        set action accept
        set service "HTTPS"
        set nat enable  # Source NAT needed for hairpin
    next
end

Policy Ordering

Move Policies

# Move policy 15 before policy 10
config firewall policy
    move 15 before 10
end

# Move policy 20 after policy 5
config firewall policy
    move 20 after 5
end

Policy Ordering Best Practices

  1. Most specific first: Narrow rules before broad rules
  2. Deny rules before allow: Block known bad before allowing good
  3. User-based before IP-based: More specific identification
  4. Application rules before service rules: App-ID is more specific

Policy Troubleshooting

Find Which Policy Matches

# Check which policy would match specific traffic
diagnose firewall iprope lookup      

# Example: Check HTTP from 10.1.1.50 to 8.8.8.8
diagnose firewall iprope lookup 10.1.1.50 12345 8.8.8.8 80 6 port2

# Protocol numbers: TCP=6, UDP=17, ICMP=1

View Active Sessions

# List all sessions
diagnose sys session list

# Filter sessions by IP
diagnose sys session filter dst 8.8.8.8
diagnose sys session list

# Clear session filter
diagnose sys session filter clear

# Kill specific sessions
diagnose sys session filter dst 10.1.1.100
diagnose sys session clear

Debug Policy Matching

# Enable debug for specific traffic
diagnose debug enable
diagnose debug flow filter addr 10.1.1.50
diagnose debug flow show function-name enable
diagnose debug flow trace start 100

# Generate traffic, then disable debug
diagnose debug flow trace stop
diagnose debug disable

# CLI:
get firewall policy

show firewall policy 10

Policy Best Practices

Security Best Practices

  • Default deny: Never create a policy with srcaddr=all, dstaddr=all, service=ALL, action=accept
  • Name policies clearly: "HR-to-HRIS" not "Policy_47"
  • Log everything: At minimum log denied traffic, ideally log all traffic
  • Use groups: Policies referencing groups are easier to maintain
  • Enable UTM: Every allow policy should have security profiles attached
  • Review regularly: Remove unused policies, check hit counts monthly
  • Comment everything: Document why each policy exists

Common Mistakes to Avoid

  • ❌ Allowing "ALL" services outbound
  • ❌ No UTM profiles on allow policies
  • ❌ Broad rules at top of policy list
  • ❌ Not logging denied traffic
  • ❌ Using IP addresses instead of objects
  • ❌ Forgetting to enable NAT on outbound policies
