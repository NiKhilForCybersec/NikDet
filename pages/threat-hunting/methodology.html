Threat Hunting Methodology

A structured approach to conducting effective threat hunts.

PEAK Hunting Framework

PEAK is a structured framework for organizing threat hunting activities:

P - Prepare

  • Define scope and objectives
  • Identify data sources
  • Develop hypothesis
  • Prepare queries and tools

E - Execute

  • Run queries
  • Analyze results
  • Pivot on findings
  • Iterate as needed

A - Act

  • Escalate if threat found
  • Create detections
  • Recommend improvements
  • Update threat intel

K - Knowledge

  • Document findings
  • Share with team
  • Update playbooks
  • Improve for next hunt

Phase 1: Prepare

1.1 Select Hunt Focus

Choose what you're hunting for based on:

SourceExampleWhen to Use
Threat IntelligenceNew APT report mentions techniqueActive threat campaign
ATT&CK GapsNo detection for T1055Coverage improvement
Recent IncidentsSimilar attack in industryProactive validation
High-Value AssetsDomain controllersRisk-based prioritization
Anomaly SignalsUnusual network traffic spikeSuspicious indicators

1.2 Form Hypothesis

Write a clear, testable hypothesis:

Template:

"I believe [THREAT ACTOR/MALWARE] may be [DOING WHAT] in our environment
using [TECHNIQUE/TOOL] which would leave evidence in [DATA SOURCE]
that I can find by [LOOKING FOR WHAT]."

Example:

"I believe attackers may be establishing persistence in our environment
using scheduled tasks which would leave evidence in Windows Event Logs (4698)
that I can find by looking for tasks created by non-admin users or from unusual paths."

1.3 Identify Data Sources

What logs/telemetry do you need?

  • Primary source: Most directly relevant (e.g., Sysmon for process creation)
  • Supporting sources: For context and correlation
  • Time range: How far back do you need to look?
  • Scope: All systems or specific segments?

1.4 Prepare Queries

Write your hunt queries before starting. Include:

  • Baseline query (what's normal?)
  • Detection query (what's suspicious?)
  • Pivot queries (where to go next?)

Phase 2: Execute

2.1 Run Initial Query

Execute your primary hunt query:

// Example: Hunt for suspicious scheduled tasks
SecurityEvent
| where TimeGenerated > ago(30d)
| where EventID == 4698
| extend TaskName = tostring(EventData.TaskName)
| extend TaskPath = tostring(EventData.TaskContent)
| where SubjectUserName !endswith "$"  // Exclude computer accounts
| where TaskName !has "Microsoft"       // Exclude known MS tasks
| project TimeGenerated, Computer, SubjectUserName, TaskName, TaskPath

2.2 Analyze Results

For each result, ask:

  • Is this expected? Known software, admin activity?
  • Is this anomalous? Rare user, unusual timing, strange path?
  • Is this suspicious? Matches known TTP, indicators of compromise?
  • What else should I check? Related events, other systems?

2.3 Pivot on Findings

When you find something interesting, expand your search:

FoundPivot ToWhy
Suspicious processParent process, child processesUnderstand execution chain
Suspicious userAll user activityFind other malicious actions
Suspicious hostAll host activityIdentify compromise scope
Malicious IP/domainAll connections to that IOCFind all affected systems
Malicious file hashAll systems with that fileIdentify spread

2.4 Pivoting Queries

// Found suspicious process? Look at what else it did
DeviceProcessEvents
| where InitiatingProcessFileName =~ "suspicious.exe" 
    or FileName =~ "suspicious.exe"
| project Timestamp, DeviceName, FileName, ProcessCommandLine, 
    InitiatingProcessFileName, InitiatingProcessCommandLine
| sort by Timestamp

// Found suspicious user? Get all their activity
union DeviceProcessEvents, DeviceNetworkEvents, DeviceLogonEvents
| where AccountName =~ "suspicious_user"
| project Timestamp, DeviceName, ActionType, FileName, 
    RemoteUrl, RemoteIP
| sort by Timestamp

// Found malicious hash? Find all occurrences
DeviceFileEvents
| where SHA256 == "abc123..."
| project Timestamp, DeviceName, FileName, FolderPath, ActionType

Phase 3: Act

3.1 If Threat Found

Active Threat Response
  1. STOP hunting - This is now an incident
  2. Document - Screenshot/save all findings
  3. Escalate - Follow IR procedures
  4. Preserve evidence - Don't modify affected systems
  5. Hand off - IR team takes over

3.2 If No Threat Found

A "clean" hunt is still valuable:

  • Document the absence: "No evidence of X in our environment"
  • Create detection: If you could hunt for it, you can detect it
  • Note limitations: "Could not detect if attacker used technique Y"
  • Improve data: Identify missing telemetry

3.3 Create Detections

Convert hunt queries to automated detections:

// Hunt query (manual)
SecurityEvent
| where EventID == 4698
| where TaskName !has "Microsoft"
| where SubjectUserName !endswith "$"

// Detection rule (automated)
name: Suspicious Scheduled Task Creation
description: Detects scheduled tasks created by non-admin users
severity: Medium
query: |
    SecurityEvent
    | where EventID == 4698
    | where TaskName !has "Microsoft"
    | where SubjectUserName !endswith "$"
    | where SubjectUserName !in ("admin_list")

Phase 4: Knowledge

4.1 Hunt Report Template

Hunt ID: HUNT-2025-001
Date: 2025-01-15
Hunter: Security Analyst
Duration: 4 hours

HYPOTHESIS:
Attackers may have established persistence via scheduled tasks
created from suspicious locations or by non-admin users.

DATA SOURCES:
- Windows Security Events (4698, 4699, 4702)
- Sysmon Event 1 (correlated)
- Time Range: 30 days

METHODOLOGY:
1. Queried for all scheduled task creation events
2. Filtered out known legitimate tasks
3. Analyzed remaining for suspicious patterns
4. Pivoted on suspicious findings

FINDINGS:
- Total tasks analyzed: 1,247
- Suspicious tasks identified: 3
- Confirmed malicious: 0
- False positives: 3 (documented below)

FALSE POSITIVES:
1. IT automation tool (added to allowlist)
2. Developer test script (user notified)
3. Legacy backup script (scheduled for removal)

ACTIONS TAKEN:
1. Created detection rule: "Suspicious Scheduled Task Creation"
2. Updated baseline with legitimate tasks
3. Documented findings in threat wiki

RECOMMENDATIONS:
1. Improve logging for task command line content
2. Review IT automation practices
3. Schedule follow-up hunt for services (T1543.003)

STATUS: Complete - No active threat

4.2 Share Knowledge

  • Team briefing: Share findings in team meeting
  • Wiki update: Add to threat hunting knowledge base
  • Playbook update: Improve hunt playbook for next time
  • Detection catalog: Add new rules created
