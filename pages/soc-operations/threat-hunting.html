Threat Hunting

Proactively search for threats that evade automated detection systems.

What is Threat Hunting?

Threat hunting is the proactive, human-driven search for threats that have bypassed your automated security controls. Unlike alert-driven SOC work, hunting assumes adversaries are already in your environment and actively searches for evidence of their presence.

Hunting vs. Alert Investigation
Alert InvestigationThreat Hunting
Reactive - triggered by alertsProactive - initiated by hunter
Known bad indicatorsUnknown or emerging threats
Follows playbooksCreative hypothesis testing
High volume, quick triageDeep dive, thorough analysis

The Hunting Loop

Effective hunting follows an iterative cycle:

1️⃣

Hypothesis

Form a theory about potential threats

2️⃣

Investigate

Query data, analyze patterns

3️⃣

Discover

Find evidence or rule out threat

4️⃣

Enrich

Create detections, document findings

Hypothesis Development

Every hunt starts with a hypothesis - an educated guess about what threat activity might look like.

Hypothesis Sources

SourceDescriptionExample Hypothesis
Threat Intelligence Reports about active threats, APT campaigns "APT29 is targeting our sector with spearphishing - look for their known TTPs"
ATT&CK Framework Techniques we haven't validated detection for "We have no detection for T1055 Process Injection - hunt for it manually"
Security News New vulnerabilities, emerging attack techniques "Log4Shell is being exploited - search for JNDI lookup patterns"
Internal Events Suspicious alerts, user reports, audit findings "Finance reported unusual emails - hunt for BEC indicators"
Anomalies Unusual patterns in baseline data "DNS queries spiked 300% - investigate the cause"

Good Hypothesis Format

Template:
"Adversaries may be using [TECHNIQUE] to [GOAL] in our environment.
Evidence would include [OBSERVABLE INDICATORS].
I will search [DATA SOURCES] for [SPECIFIC PATTERNS]."

Example:
"Adversaries may be using scheduled tasks for persistence in our environment.
Evidence would include tasks created by non-standard accounts or running unusual binaries.
I will search Windows Security logs for Event 4698 and filter for suspicious attributes."

Hunting Methodologies

1. Intelligence-Driven Hunting

Start with known threat intelligence and search for specific indicators or TTPs.

1
Collect Intelligence

Gather IOCs, TTPs from threat reports (APT reports, ISACs, vendor intel)

2
Translate to Queries

Convert IOCs to SIEM queries (hash, IP, domain searches)

3
Execute Search

Run queries against historical data (30-90 days typically)

4
Analyze Results

Review matches, eliminate false positives, investigate true hits

2. Hypothesis-Driven Hunting

Start with a theory about attacker behavior and test it against your data.

Example Hunt: Credential Dumping

Hypothesis: Attackers may be dumping credentials from LSASS
ATT&CK: T1003.001 - OS Credential Dumping: LSASS Memory
Data Source: Sysmon Event 10 (Process Access)
Search: Processes accessing lsass.exe with suspicious access masks
Expected Results: Mimikatz, procdump, or unknown tools accessing LSASS

3. Baseline/Anomaly Hunting

Establish what's normal, then search for deviations.

  • First: Establish baseline of normal activity
  • Then: Search for statistical outliers
  • Focus: Rare processes, unusual connections, abnormal volumes

Hunting Queries by Technique

Hunt: Rare Process Execution

// KQL - Find processes seen on <3 machines in 7 days
DeviceProcessEvents
| where Timestamp > ago(7d)
| summarize 
    MachineCount = dcount(DeviceName),
    Machines = make_set(DeviceName, 5),
    Users = make_set(AccountName, 5),
    SampleCommandLine = any(ProcessCommandLine)
    by FileName
| where MachineCount <= 3
| sort by MachineCount asc
Why This Works

Malware and attacker tools are often unique to compromised systems. A legitimate enterprise application appears on many machines; a backdoor appears on one or two.

Hunt: Suspicious PowerShell

// KQL - PowerShell with suspicious patterns
DeviceProcessEvents
| where Timestamp > ago(7d)
| where FileName in~ ("powershell.exe", "pwsh.exe")
| where ProcessCommandLine has_any (
    "-enc", "-encoded", "-e ",           // Encoded commands
    "downloadstring", "downloadfile",     // Downloads
    "invoke-expression", "iex",           // Execution
    "bypass", "-nop", "-w hidden",        // Evasion
    "frombase64", "decompress",           // Obfuscation
    "webclient", "net.webclient",         // Web access
    "reflection.assembly"                 // In-memory loading
)
| project Timestamp, DeviceName, AccountName, ProcessCommandLine, InitiatingProcessFileName

Hunt: Beaconing Activity

// KQL - Find regular interval connections (potential C2)
DeviceNetworkEvents
| where Timestamp > ago(24h)
| where RemoteIPType == "Public"
| summarize 
    ConnectionCount = count(),
    TimeStamps = make_list(Timestamp)
    by DeviceName, RemoteIP, RemotePort
| where ConnectionCount > 50
| extend TimeDiffs = array_sort_asc(TimeStamps)
| mv-expand TimeDiff = TimeDiffs
| extend PrevTime = prev(todatetime(TimeDiff))
| where isnotnull(PrevTime)
| extend Interval = datetime_diff('second', todatetime(TimeDiff), PrevTime)
| summarize 
    AvgInterval = avg(Interval),
    StdDev = stdev(Interval),
    Count = count()
    by DeviceName, RemoteIP
| where StdDev < 10 and AvgInterval between (30 .. 900)  // Low variance, 30s-15min interval
| extend CoeffOfVariation = StdDev / AvgInterval * 100
| where CoeffOfVariation < 15  // Very regular timing

Hunt: Lateral Movement via RDP

// KQL - RDP from unusual sources
DeviceLogonEvents
| where Timestamp > ago(7d)
| where LogonType == "RemoteInteractive"  // RDP
| where isnotempty(RemoteIP)
| summarize 
    FirstSeen = min(Timestamp),
    LastSeen = max(Timestamp),
    LogonCount = count(),
    TargetMachines = make_set(DeviceName)
    by RemoteIP, AccountName
| join kind=leftouter (
    // Historical baseline - who normally RDPs from where
    DeviceLogonEvents
    | where Timestamp between (ago(90d) .. ago(7d))
    | where LogonType == "RemoteInteractive"
    | summarize HistoricalLogons = count() by RemoteIP, AccountName
) on RemoteIP, AccountName
| where isnull(HistoricalLogons) or HistoricalLogons < 5  // New or rare

Hunt: Persistence via Scheduled Tasks

// KQL - Suspicious scheduled task creation
DeviceEvents
| where Timestamp > ago(7d)
| where ActionType == "ScheduledTaskCreated"
| extend TaskContent = parse_json(AdditionalFields)
| extend TaskCommand = tostring(TaskContent.TaskCommand)
| where TaskCommand has_any (
    "powershell", "cmd.exe", "wscript", "cscript",
    "mshta", "rundll32", "regsvr32", "certutil",
    "\\temp\\", "\\appdata\\", "\\public\\"
)
| project Timestamp, DeviceName, AccountName, TaskContent, TaskCommand

hunt_id: HUNT-2025-001
title: Credential Dumping via LSASS Access
date: 2025-01-15
hunter: Security Analyst
time_spent: 4 hours

hypothesis: |
  Attackers may be using credential dumping tools to access LSASS 
  memory and extract credentials for lateral movement.

mitre_attack:
  - T1003.001 - OS Credential Dumping: LSASS Memory

data_sources:
  - Sysmon Event 10 (Process Access)
  - Windows Security Event 4663

queries_used:
  - name: LSASS Access Detection
    query: |
      DeviceEvents | where ActionType == "ProcessAccess" 
      | where TargetFileName =~ "lsass.exe"

findings:
  - finding_id: F001
    description: Procdump.exe accessed LSASS on WORKSTATION-15
    severity: High
    action_taken: Escalated to IR team
    
outcome: |
  Found one true positive (procdump used by IT admin for legitimate 
  troubleshooting - verified). Created detection rule for future.

detections_created:
  - DET-087: LSASS Access by Suspicious Process

recommendations:
  - Implement Credential Guard on sensitive systems
  - Add LSASS protection via Windows Defender
