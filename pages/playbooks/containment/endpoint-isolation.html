PB-CON-001

Endpoint Isolation Procedures

Network isolation procedures for compromised or suspicious endpoints.

DO NOT Power Off

Unless specifically directed, do NOT power off the system. Memory contains valuable forensic evidence and possibly encryption keys.

When to Isolate

  • Confirmed ransomware activity
  • Active C2 communication
  • Credential theft in progress (LSASS access)
  • Lateral movement detected from the host
  • Data exfiltration in progress
  • Advanced persistent threat indicators

What EDR Isolation Provides

  • Network block: All traffic except EDR agent communication
  • Continued management: Can still run remote commands, queries
  • Evidence preservation: System stays running for forensics
  • Lateral movement prevention: Can't spread to other systems
  • C2 disruption: Attacker loses control of endpoint

Isolation Procedure

1
Document Current State

Note hostname, IP, user, reason for isolation, time.

2
Initiate Isolation

Use EDR console to isolate. Verify isolation status.

3
Notify User (If Appropriate)

Coordinate with management. User may need to know.

4
Begin Investigation

Use EDR to collect evidence, run queries, check persistence.

Release from Isolation

Only release after:

  • Threat is fully remediated
  • No persistence mechanisms remain
  • Full scan shows system clean
  • IR lead approves release
  • Enhanced monitoring in place
