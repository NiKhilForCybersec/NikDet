Identity & Access Management (IAM)

Complete guide to authentication, authorization, identity providers, SSO, OAuth, SAML, and Microsoft Entra ID. From fundamental concepts to advanced enterprise implementations.

IAM Explained Simply

Think of IAM like airport security:

  • Authentication (AuthN): "Who are you?" → Checking your passport/ID
  • Authorization (AuthZ): "What can you do?" → Checking if you have a boarding pass for this flight
  • Identity Provider (IdP): The government that issued your passport
  • SSO: Using one passport to board multiple connecting flights
  • MFA: Passport + fingerprint + face recognition

Evolution of Identity

1990s: Local Accounts

Each system had its own user database. Users had different passwords for every system. No centralized management.

2000: Active Directory

Microsoft introduced AD with Windows 2000. Centralized on-premises identity. Single domain login for Windows resources. Kerberos authentication.

2005: SAML 2.0

Federated identity becomes practical. Organizations can trust each other's identity assertions. SSO across different organizations.

2012: OAuth 2.0

Authorization framework for APIs. "Login with Google/Facebook" becomes common. Tokens instead of passwords for API access.

2014: OpenID Connect

Authentication layer on top of OAuth 2.0. Identity tokens (who you are) + access tokens (what you can do). Modern standard for SSO.

2020s: Zero Trust & Passwordless

Identity is the new perimeter. Continuous verification. Risk-based authentication. FIDO2, passkeys, biometrics replace passwords.

Core IAM Concepts

Authentication (AuthN)

Definition: Verifying that someone is who they claim to be.

Methods:

  • Something you know: Password, PIN, security questions
  • Something you have: Phone, hardware token, smart card
  • Something you are: Fingerprint, face, iris
  • Somewhere you are: Location, network
  • Something you do: Typing pattern, gait

Authorization (AuthZ)

Definition: Determining what an authenticated user is allowed to do.

Models:

  • RBAC (Role-Based): Permissions assigned to roles, users get roles
  • ABAC (Attribute-Based): Decisions based on user/resource/environment attributes
  • PBAC (Policy-Based): Rules define access (if X then allow Y)
  • DAC (Discretionary): Owner controls access to their resources
  • MAC (Mandatory): System-enforced labels (classified, secret, etc.)

Identity Provider (IdP)

Definition: The authoritative source that creates, maintains, and manages identity information.

Examples: Microsoft Entra ID, Okta, Active Directory, Google Workspace, Ping Identity

Responsibilities:

  • Store user credentials and attributes
  • Authenticate users
  • Issue tokens/assertions
  • Manage user lifecycle

Service Provider (SP)

Definition: The application or service that the user wants to access.

Examples: Salesforce, ServiceNow, your internal HR portal

Responsibilities:

  • Request authentication from IdP
  • Validate tokens/assertions
  • Authorize user actions based on identity
  • Trust the IdP
