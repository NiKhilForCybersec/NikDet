PB-INV-003

Account Compromise Investigation

Complete investigation procedure for suspected or confirmed account compromise. Covers authentication analysis, activity timeline reconstruction, impact assessment, and remediation.

SeverityHigh
TierL2 / L3
Time45-120 min
Last Updated2025-01-02
T1078 T1110 T1556 T1558 T1539

Overview

Account compromise occurs when an unauthorized party gains access to a legitimate user account. This can happen through credential theft (phishing, malware), brute force attacks, session hijacking, or exploitation of authentication mechanisms. Early detection and rapid response are critical to limit damage.

What This Playbook Covers
  • Credential theft (phishing, infostealers, database breaches)
  • Password spraying and brute force attacks
  • Session token theft and replay
  • MFA bypass and fatigue attacks
  • OAuth/consent phishing
  • Pass-the-Hash / Pass-the-Ticket attacks
  • Service account compromise

Why Account Compromise is Critical

  • Valid credentials bypass perimeter security - Attackers appear as legitimate users
  • Enables lateral movement - Access to resources, systems, and data
  • Hard to detect - Actions blend with normal user behavior
  • Gateway to bigger attacks - Ransomware, data theft, BEC fraud

Critical Account Compromised?

If Global Admin, Domain Admin, or any Tier 0 account is compromised: STOP and immediately escalate to IR team. Assume worst-case scenario and follow critical incident procedures.

1.3
Contact the User (If Possible)
Verify legitimate vs. malicious activity:
User Interview Questions
  1. Are you currently traveling or working remotely?
  2. Did you recently use a new device or browser?
  3. Did you receive any suspicious emails or calls?
  4. Did you enter your password anywhere unusual?
  5. Did you approve any unexpected MFA prompts?
  6. Have you noticed anything unusual in your account?
  7. Did you share your credentials with anyone?
Verification Warning

Do NOT contact user via email if account is compromised—attacker may intercept. Use phone, Teams/Slack (verified account), or in-person.

Step 2: Authentication Analysis (20 Minutes)

2.1
Review Recent Sign-in Activity
Analyze authentication patterns for anomalies:

Complete Sign-in History (KQL)

Sentinel
// Comprehensive sign-in analysis for user
let TargetUser = "user@company.com";
let TimeRange = 14d;
SigninLogs
| where TimeGenerated > ago(TimeRange)
| where UserPrincipalName =~ TargetUser
| extend 
    City = tostring(LocationDetails.city),
    State = tostring(LocationDetails.state),
    Country = tostring(LocationDetails.countryOrRegion),
    OS = tostring(DeviceDetail.operatingSystem),
    Browser = tostring(DeviceDetail.browser),
    DeviceId = tostring(DeviceDetail.deviceId),
    TrustType = tostring(DeviceDetail.trustType),
    IsCompliant = tostring(DeviceDetail.isCompliant)
| project
    TimeGenerated,
    AppDisplayName,
    IPAddress,
    Location = strcat(City, ", ", Country),
    OS,
    Browser,
    DeviceId,
    TrustType,
    IsCompliant,
    ResultType,
    ResultDescription,
    AuthenticationRequirement,
    MfaDetail = tostring(MfaDetail.authMethod),
    ConditionalAccessStatus,
    RiskLevelDuringSignIn,
    RiskState
| order by TimeGenerated desc

2.2
Identify Impossible Travel
Detect physically impossible location changes:
Sentinel
// Detect impossible travel (simplified)
let TargetUser = "user@company.com";
SigninLogs
| where TimeGenerated > ago(7d)
| where UserPrincipalName =~ TargetUser
| where ResultType == "0"  // Successful sign-ins only
| extend Country = tostring(LocationDetails.countryOrRegion)
| order by TimeGenerated asc
| extend PrevTime = prev(TimeGenerated), PrevCountry = prev(Country)
| extend TimeDiffMinutes = datetime_diff('minute', TimeGenerated, PrevTime)
| where Country != PrevCountry
| where TimeDiffMinutes < 120  // Less than 2 hours
| project 
    TimeGenerated,
    PrevTime,
    TimeDiffMinutes,
    FromCountry = PrevCountry,
    ToCountry = Country,
    IPAddress,
    AppDisplayName
2.3
Check for Failed Authentications
Failed sign-ins may indicate password guessing or spraying:
Sentinel
// Failed sign-ins followed by success (potential compromise)
let TargetUser = "user@company.com";
SigninLogs
| where TimeGenerated > ago(7d)
| where UserPrincipalName =~ TargetUser
| summarize
    FailedAttempts = countif(ResultType != "0"),
    SuccessfulAttempts = countif(ResultType == "0"),
    FirstFailed = minif(TimeGenerated, ResultType != "0"),
    FirstSuccess = minif(TimeGenerated, ResultType == "0"),
    FailedIPs = make_set_if(IPAddress, ResultType != "0"),
    SuccessIPs = make_set_if(IPAddress, ResultType == "0")
    by bin(TimeGenerated, 1h)
| where FailedAttempts > 0 and SuccessfulAttempts > 0

2.4
Check for MFA Bypass or Fatigue
Attackers may bypass or exhaust MFA:
Sentinel
// Detect MFA fatigue attack (multiple MFA prompts)
let TargetUser = "user@company.com";
SigninLogs
| where TimeGenerated > ago(24h)
| where UserPrincipalName =~ TargetUser
| where ResultType in ("50074", "50076", "0")
| summarize
    MfaPrompts = countif(ResultType in ("50074", "50076")),
    MfaSuccess = countif(ResultType == "0")
    by bin(TimeGenerated, 1h)
| where MfaPrompts > 5  // Many MFA attempts

MFA Bypass Techniques

TechniqueDetection Method

Legacy ProtocolSign-in via IMAP/POP3 which doesn't support MFA

Step 3: Activity Timeline (20 Minutes)

3.1
Build Complete Activity Timeline
Reconstruct what the attacker did after gaining access:
Sentinel
// Complete activity timeline from multiple sources
let TargetUser = "user@company.com";
let SuspiciousIP = "203.0.113.100";  // IP identified as attacker
let StartTime = datetime(2025-01-01T00:00:00Z);
let EndTime = datetime(2025-01-03T00:00:00Z);
// Sign-in events
let Signins = SigninLogs
| where TimeGenerated between (StartTime .. EndTime)
| where UserPrincipalName =~ TargetUser or IPAddress == SuspiciousIP
| extend Source = "SignIn", Details = strcat(AppDisplayName, " - ", ResultDescription);
// Azure AD audit events
let Audits = AuditLogs
| where TimeGenerated between (StartTime .. EndTime)
| where InitiatedBy.user.userPrincipalName =~ TargetUser
| extend Source = "AuditLog", Details = OperationName;
// Office 365 activity
let O365 = OfficeActivity
| where TimeGenerated between (StartTime .. EndTime)
| where UserId =~ TargetUser or ClientIP == SuspiciousIP
| extend Source = "O365Activity", Details = Operation;
// Union all sources
union Signins, Audits, O365
| project TimeGenerated, Source, Details, IPAddress = coalesce(IPAddress, ClientIP)
| order by TimeGenerated asc
3.2
Check for Persistence Mechanisms
Attackers establish persistence to maintain access:

Inbox Rules (Email Persistence)

Sentinel
// Check for inbox rules created
OfficeActivity
| where TimeGenerated > ago(30d)
| where UserId =~ "user@company.com"
| where Operation in ("New-InboxRule", "Set-InboxRule", "Enable-InboxRule")
| extend RuleParams = tostring(Parameters)
| project TimeGenerated, Operation, RuleParams, ClientIP

OAuth App Consent (API Persistence)

Sentinel
// Check for OAuth app consents
AuditLogs
| where TimeGenerated > ago(30d)
| where OperationName == "Consent to application"
| where InitiatedBy.user.userPrincipalName =~ "user@company.com"
| extend 
    AppName = tostring(TargetResources[0].displayName),
    AppId = tostring(TargetResources[0].id)
| project TimeGenerated, AppName, AppId, InitiatedBy

MFA Method Changes

Sentinel
// Check for MFA method changes
AuditLogs
| where TimeGenerated > ago(30d)
| where OperationName has_any ("User registered security info", "User deleted security info", "Admin registered security info")
| where TargetResources[0].userPrincipalName =~ "user@company.com"
| project TimeGenerated, OperationName, InitiatedBy, TargetResources
3.3
Check for Data Access
Determine what data the attacker accessed:

Email Access

Sentinel
// Email access from suspicious IP
OfficeActivity
| where TimeGenerated > ago(7d)
| where UserId =~ "user@company.com"
| where Operation in ("MailItemsAccessed", "Send", "SendAs", "SendOnBehalf")
| summarize
    ItemsAccessed = countif(Operation == "MailItemsAccessed"),
    EmailsSent = countif(Operation in ("Send", "SendAs"))
    by ClientIP, bin(TimeGenerated, 1h)

File Access (SharePoint/OneDrive)

Sentinel
// File operations from compromised account
OfficeActivity
| where TimeGenerated > ago(7d)
| where UserId =~ "user@company.com"
| where RecordType in ("SharePointFileOperation", "OneDrive")
| where Operation in ("FileDownloaded", "FileAccessed", "FileSyncDownloadedFull")
| summarize
    FilesDownloaded = count(),
    UniqueFiles = dcount(SourceFileName)
    by ClientIP, bin(TimeGenerated, 1h)

let AttackerIPs = dynamic(["203.0.113.100", "203.0.113.101"]);
SigninLogs
| where TimeGenerated > ago(7d)
| where IPAddress in (AttackerIPs)

Containment & Remediation

Immediate Containment (Execute Now)

ActionHow to ExecutePriority
Reset PasswordAzure AD → Users → Reset PasswordCritical
Revoke SessionsAzure AD → Users → Revoke SessionsCritical
Revoke Refresh TokensRevoke-AzureADUserAllRefreshTokenCritical
Block Sign-in (if severe)Azure AD → Users → Block Sign-inHigh
Remove Inbox RulesExchange Admin → Inbox RulesHigh
Remove ForwardingExchange Admin → Mail FlowHigh
Review OAuth AppsAzure AD → User → ApplicationsHigh
Review MFA MethodsAzure AD → User → Authentication MethodsHigh

Post-Containment (Within 24 Hours)

  • Re-enable account with new password and verified MFA
  • Brief user on what happened and security awareness
  • Monitor account for 30 days
  • Review other accounts accessed from attacker IP
  • Update threat intelligence with IOCs

Decision Tree

Q1: Is the suspicious activity confirmed unauthorized?
NO → User verified activity. Close as False Positive.
YES → Continue to Q2
Q2: Is this a privileged account?
NO → Standard response, continue investigation
YES → Escalate to IR immediately. Assume worst case.
Q3: Did attacker establish persistence?
NO → Reset creds, revoke sessions, monitor
YES → Full remediation required. Check for lateral movement.
Q4: Did attacker access sensitive data?
NO → Complete remediation, close incident
YES → Notify data privacy team. Potential breach notification required.
