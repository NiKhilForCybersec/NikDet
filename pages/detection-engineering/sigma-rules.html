Sigma Rules Complete Guide

Write once, convert anywhere. The universal detection rule format for sharing and portability.

What is Sigma?

Sigma is an open, vendor-agnostic format for writing detection rules. Think of it as "YARA for logs" - you write a rule once in Sigma format, then convert it to your SIEM's native query language (Splunk SPL, Microsoft KQL, Elastic Query DSL, etc.).

Why Sigma Matters
  • Portability: Rules work across different SIEM platforms
  • Community: Thousands of pre-built rules from the community
  • Standardization: Consistent format for documentation
  • Sharing: Easy to share rules between organizations
  • Version Control: YAML format works well with Git

Sigma Rule Structure

Every Sigma rule consists of these sections:

title: Rule Name Here
id: 12345678-1234-1234-1234-123456789012  # UUID
status: experimental | test | stable | deprecated | unsupported
description: |
    Detailed description of what this rule detects
    and why it matters.
references:
    - https://attack.mitre.org/techniques/T1059/001/
    - https://blog.example.com/analysis
author: Your Name
date: 2025/01/01
modified: 2025/01/15
tags:
    - attack.execution
    - attack.t1059.001
logsource:
    category: process_creation
    product: windows
detection:
    selection:
        field_name: value
    condition: selection
falsepositives:
    - Legitimate admin activity
    - Specific software that exhibits this behavior
level: low | medium | high | critical

Detection Section

The core logic of the rule. Consists of selections and a condition:

Selection Types

# Basic equality
selection:
    Image|endswith: '\powershell.exe'

# Multiple values (OR)
selection:
    Image|endswith:
        - '\powershell.exe'
        - '\pwsh.exe'
        - '\cmd.exe'

# Multiple fields (AND)
selection:
    Image|endswith: '\powershell.exe'
    CommandLine|contains: '-enc'

# Multiple selections
selection_process:
    Image|endswith: '\powershell.exe'
selection_args:
    CommandLine|contains:
        - '-enc'
        - '-nop'
        - '-w hidden'
condition: selection_process and selection_args

Complete Rule Examples

Example 1: Encoded PowerShell Detection

title: Encoded PowerShell Command Line
id: fb843269-508c-4b76-8b8d-88679db22ce7
status: stable
description: |
    Detects PowerShell commands with Base64 encoded arguments,
    commonly used by attackers to obfuscate malicious scripts.
references:
    - https://attack.mitre.org/techniques/T1059/001/
    - https://attack.mitre.org/techniques/T1027/
author: Security Team
date: 2025/01/01
tags:
    - attack.execution
    - attack.t1059.001
    - attack.defense_evasion
    - attack.t1027
logsource:
    category: process_creation
    product: windows
detection:
    selection_process:
        Image|endswith:
            - '\powershell.exe'
            - '\pwsh.exe'
    selection_encoded:
        CommandLine|contains:
            - ' -e '
            - ' -enc '
            - ' -encoded'
            - ' -encodedcommand'
    filter_legitimate:
        ParentImage|endswith:
            - '\sccm.exe'  # SCCM legitimate usage
    condition: selection_process and selection_encoded and not filter_legitimate
falsepositives:
    - SCCM scripts
    - Legitimate admin automation
level: medium

Example 2: Suspicious Parent Process

title: Suspicious Shell Spawned by Office Application
id: 438025f9-5856-4663-83f7-52f878a70a50
status: stable
description: |
    Detects Office applications spawning command line interpreters,
    which often indicates macro-based malware or exploits.
references:
    - https://attack.mitre.org/techniques/T1566/001/
author: Security Team
date: 2025/01/01
tags:
    - attack.initial_access
    - attack.t1566.001
    - attack.execution
    - attack.t1059
logsource:
    category: process_creation
    product: windows
detection:
    selection_parent:
        ParentImage|endswith:
            - '\winword.exe'
            - '\excel.exe'
            - '\powerpnt.exe'
            - '\outlook.exe'
            - '\msaccess.exe'
            - '\mspub.exe'
            - '\onenote.exe'
    selection_child:
        Image|endswith:
            - '\cmd.exe'
            - '\powershell.exe'
            - '\pwsh.exe'
            - '\wscript.exe'
            - '\cscript.exe'
            - '\mshta.exe'
            - '\regsvr32.exe'
            - '\rundll32.exe'
    condition: selection_parent and selection_child
falsepositives:
    - Legitimate Office automation (rare)
    - Some add-ins may trigger this
level: high

Example 3: LSASS Access Detection

title: LSASS Memory Access by Suspicious Process
id: 32d0d3e2-e58d-4d41-926b-18b520b2b32d
status: stable
description: |
    Detects processes accessing LSASS memory, which is the primary
    technique for credential dumping tools like Mimikatz.
references:
    - https://attack.mitre.org/techniques/T1003/001/
author: Security Team
date: 2025/01/01
tags:
    - attack.credential_access
    - attack.t1003.001
logsource:
    category: process_access
    product: windows
detection:
    selection:
        TargetImage|endswith: '\lsass.exe'
        GrantedAccess|contains:
            - '0x1010'  # PROCESS_QUERY_LIMITED_INFORMATION + PROCESS_VM_READ
            - '0x1038'
            - '0x1410'
            - '0x1438'
            - '0x143a'
            - '0x1fffff'  # PROCESS_ALL_ACCESS
    filter_legitimate:
        SourceImage|endswith:
            - '\csrss.exe'
            - '\wininit.exe'
            - '\wmiprvse.exe'
            - '\svchost.exe'
            - '\services.exe'
            - '\MsMpEng.exe'  # Windows Defender
    condition: selection and not filter_legitimate
falsepositives:
    - Legitimate security tools
    - EDR agents
level: critical

Converting Sigma Rules

Use sigma-cli or pySigma to convert rules to your SIEM format:

Installation

# Install sigma-cli
pip install sigma-cli

# Install backends for your SIEM
pip install pysigma-backend-splunk
pip install pysigma-backend-microsoft365defender
pip install pysigma-backend-elasticsearch

Conversion Examples

# Convert to Splunk SPL
sigma convert -t splunk rule.yml

# Convert to Microsoft Sentinel KQL
sigma convert -t microsoft365defender rule.yml

# Convert to Elasticsearch
sigma convert -t elasticsearch rule.yml

# Convert with specific pipeline (field mappings)
sigma convert -t splunk -p sysmon rule.yml

# Convert entire directory
sigma convert -t splunk rules/ -o converted/

Best Practices

Writing Good Sigma Rules
  1. Always include falsepositives: Document known legitimate triggers
  2. Use appropriate level: Reserve "critical" for high-fidelity detections
  3. Tag with ATT&CK: Always map to MITRE techniques
  4. Test before sharing: Validate converted queries work
  5. Be specific: Narrow conditions reduce false positives
  6. Use filters: Exclude known legitimate behavior
  7. Document thoroughly: Future you will thank present you
