GCP Integration Guide

Complete step-by-step guide to connect your Google Cloud Platform projects to Microsoft Defender for Cloud. No steps skipped.

Prerequisites

RequirementDetails
Azure SubscriptionWith Defender for Cloud enabled
Azure PermissionsSecurity Admin + Contributor on subscription
GCP ProjectWith Owner or Editor access
GCP APIs EnabledCloud Resource Manager, IAM, Compute Engine
Defender PlanFoundational CSPM (free) or Defender CSPM (paid)

What Gets Created in GCP

The integration creates these resources in your GCP project:

  • Service Account: microsoft-defender-for-cloud@[project].iam.gserviceaccount.com
  • Workload Identity Federation: Pool and provider for Azure authentication
  • IAM Bindings: Security Reviewer, Viewer roles
  • For CWPP: Additional service account for Arc agent deployment

Step-by-Step: Connect Single GCP Project

1

Enable Required GCP APIs

Before connecting, enable these APIs in your GCP project:

# Using gcloud CLI
gcloud services enable cloudresourcemanager.googleapis.com
gcloud services enable iam.googleapis.com
gcloud services enable compute.googleapis.com
gcloud services enable container.googleapis.com  # For GKE
gcloud services enable sqladmin.googleapis.com   # For Cloud SQL

# Verify enabled APIs
gcloud services list --enabled
2

Access Defender for Cloud in Azure

  1. Go to Azure Portal
  2. Search for "Microsoft Defender for Cloud"
  3. Click Environment settings in left menu
  4. Click + Add environment
  5. Select Google Cloud Platform
3

Configure Project Details

  1. Select Single project (or Organization for multiple projects)
  2. Enter Connector name: e.g., "GCP-Production"
  3. Select Azure Subscription
  4. Select or create Resource group
  5. Select Location: Choose region
  6. Enter your GCP Project ID (not project name)
  7. Click Next: Select plans
# Find your GCP Project ID
gcloud projects list --format="table(projectId,name)"

# Or in GCP Console: Dashboard → Project info → Project ID
4

Select Defender Plans

Choose which plans to enable for GCP:

PlanWhat It ProtectsCost
Foundational CSPMBasic security recommendationsFree
Defender CSPMAttack paths, agentless scanningPaid
ServersCompute Engine VMs via ArcPaid
ContainersGKE clustersPaid
DatabasesCloud SQL instancesPaid

Toggle desired plans On

Click Next: Configure access

5

Configure Access - Download Script

  1. Select deployment type: GCP Cloud Shell (recommended)
  2. Click Copy to copy the script, OR
  3. Click Download to get the shell script
  4. Note the script content - it creates:
    • Service account
    • Workload identity pool
    • Workload identity provider
    • IAM policy bindings
6

Run Script in GCP Cloud Shell

  1. Open GCP Console
  2. Click the Cloud Shell icon (top right)
  3. Wait for Cloud Shell to initialize
  4. Paste the copied script and press Enter
  5. Script will prompt for confirmation - type y
  6. Wait for completion (2-5 minutes)
# Example of what the script does (simplified):

# Set variables
PROJECT_ID="your-project-id"
POOL_ID="azure-defender-pool"
PROVIDER_ID="azure-defender-provider"
SERVICE_ACCOUNT="microsoft-defender-for-cloud"

# Create service account
gcloud iam service-accounts create $SERVICE_ACCOUNT \
    --display-name="Microsoft Defender for Cloud"

# Create workload identity pool
gcloud iam workload-identity-pools create $POOL_ID \
    --location="global" \
    --display-name="Azure Defender Pool"

# Create workload identity provider
gcloud iam workload-identity-pools providers create-oidc $PROVIDER_ID \
    --location="global" \
    --workload-identity-pool=$POOL_ID \
    --issuer-uri="https://sts.windows.net/YOUR-TENANT-ID/" \
    --allowed-audiences="api://YOUR-APP-ID" \
    --attribute-mapping="google.subject=assertion.sub"

# Grant service account permissions
gcloud projects add-iam-policy-binding $PROJECT_ID \
    --member="serviceAccount:$SERVICE_ACCOUNT@$PROJECT_ID.iam.gserviceaccount.com" \
    --role="roles/iam.securityReviewer"

gcloud projects add-iam-policy-binding $PROJECT_ID \
    --member="serviceAccount:$SERVICE_ACCOUNT@$PROJECT_ID.iam.gserviceaccount.com" \
    --role="roles/viewer"
7

Verify Script Output

After script completion, you should see:

  • Service account created successfully
  • Workload identity pool created
  • Workload identity provider created
  • IAM bindings updated
# Verify service account exists
gcloud iam service-accounts list --filter="email:microsoft-defender"

# Verify workload identity pool
gcloud iam workload-identity-pools list --location=global

# Verify IAM bindings
gcloud projects get-iam-policy $PROJECT_ID \
    --filter="bindings.members:microsoft-defender" \
    --format="table(bindings.role)"
8

Complete Azure Configuration

  1. Return to Azure portal tab
  2. Click Next: Review and generate
  3. Review your configuration
  4. Click Create
  5. Wait for connector creation (1-2 minutes)
  6. Status should show Connected

Data Sync Time

After connection, it takes up to 24 hours for full security assessment. Initial recommendations appear within 2-4 hours.

Connect GCP Organization (Multiple Projects)

For GCP Organizations

To connect all projects in a GCP organization:

Prerequisites

  • GCP Organization Administrator role
  • Organization ID (numeric)
  • All projects must have required APIs enabled
  1. In Azure, select Organization instead of Single project
  2. Enter your GCP Organization ID
  3. The script will apply at organization level
  4. All current and future projects are covered
# Find GCP Organization ID
gcloud organizations list

# Output example:
# DISPLAY_NAME     ID              DIRECTORY_CUSTOMER_ID
# My Organization  123456789012    C01234567

# List all projects in organization
gcloud projects list --filter="parent.id=123456789012"

Enable Defender for Servers (Compute Engine)

Protect GCE VMs with Azure Arc

To get full server protection, install Azure Arc agent on Compute Engine VMs.

Enable Auto-provisioning

  1. In Defender for Cloud, go to Environment settings
  2. Select your GCP connector
  3. Click Settings & monitoring
  4. Under Servers, enable Auto-provision Arc agent

Manual Arc Agent Installation on GCE

# SSH to your GCE VM first
gcloud compute ssh your-vm-name --zone=us-central1-a

# On Linux GCE instance
wget https://aka.ms/azcmagent -O install_linux_azcmagent.sh
sudo bash install_linux_azcmagent.sh

# Connect to Azure
sudo azcmagent connect \
    --tenant-id "YOUR-AZURE-TENANT-ID" \
    --subscription-id "YOUR-AZURE-SUBSCRIPTION-ID" \
    --resource-group "YOUR-RESOURCE-GROUP" \
    --location "eastus" \
    --cloud "AzureCloud"

# On Windows GCE instance (PowerShell as Admin)
Invoke-WebRequest -Uri https://aka.ms/AzureConnectedMachineAgent -OutFile AzureConnectedMachineAgent.msi
msiexec /i AzureConnectedMachineAgent.msi /l*v installationlog.txt /qn

& "$env:ProgramFiles\AzureConnectedMachineAgent\azcmagent.exe" connect `
    --tenant-id "YOUR-AZURE-TENANT-ID" `
    --subscription-id "YOUR-AZURE-SUBSCRIPTION-ID" `
    --resource-group "YOUR-RESOURCE-GROUP" `
    --location "eastus"

Enable Defender for Containers (GKE)

GKE Cluster Protection

Enable GKE Protection

  1. In connector settings, enable Containers plan
  2. Defender extension auto-deploys to GKE clusters
  3. Or manually install via Helm:
# Get GKE credentials
gcloud container clusters get-credentials your-cluster --zone us-central1-a

# Add Microsoft Helm repo
helm repo add microsoft https://raw.githubusercontent.com/microsoft/Defender-for-Cloud-Helm-Charts/main/repo/
helm repo update

# Install Defender extension
helm install defender-for-containers microsoft/defender-for-containers \
    --namespace mdc \
    --create-namespace \
    --set defender.subscriptionId="YOUR-AZURE-SUBSCRIPTION-ID" \
    --set defender.resourceGroup="YOUR-RESOURCE-GROUP" \
    --set defender.clusterName="your-gke-cluster"

# Verify deployment
kubectl get pods -n mdc

Verify Connection

Check Connector Status

# Azure CLI - Check connector
az security connector show --name "your-gcp-connector" --resource-group "your-rg"

# List all GCP connectors
az security connector list --query "[?environmentName=='GCP']" --output table

Verify in Portal

  1. Go to Defender for Cloud → Inventory
  2. Filter by Environment: GCP
  3. You should see:
    • Compute Engine instances
    • Cloud Storage buckets
    • GKE clusters (if Containers enabled)
    • Cloud SQL instances (if Databases enabled)
    • IAM service accounts

Check Recommendations

  1. Go to Defender for Cloud → Recommendations
  2. Filter by Environment: GCP
  3. Review GCP-specific recommendations like:
    • "GCP VM instances should not use default service account"
    • "GCP Cloud Storage buckets should not be publicly accessible"
    • "GCP Firewall rules should not allow unrestricted access"

Remove GCP Connection

Clean Removal Steps

Step 1: Remove from Azure

  1. Go to Defender for Cloud → Environment settings
  2. Find your GCP connector
  3. Click ... → Delete
  4. Confirm deletion

Step 2: Clean up GCP Resources

# Delete service account
gcloud iam service-accounts delete microsoft-defender-for-cloud@$PROJECT_ID.iam.gserviceaccount.com

# Delete workload identity pool (this deletes provider too)
gcloud iam workload-identity-pools delete azure-defender-pool --location=global

# Remove IAM bindings (if needed)
gcloud projects remove-iam-policy-binding $PROJECT_ID \
    --member="serviceAccount:microsoft-defender-for-cloud@$PROJECT_ID.iam.gserviceaccount.com" \
    --role="roles/iam.securityReviewer"

Troubleshooting

Common Issues

IssueSolution
Script fails with permission errorEnsure you have Owner role on GCP project
APIs not enabledRun: gcloud services enable [api-name]
Connector shows "Unhealthy"Verify service account and workload identity exist
No resources discoveredWait 24 hours; check service account permissions
VMs not protectedInstall Azure Arc agent on GCE instances

Debug Commands

# Check if APIs are enabled
gcloud services list --enabled | grep -E "cloudresourcemanager|iam|compute"

# Check service account permissions
gcloud projects get-iam-policy $PROJECT_ID \
    --flatten="bindings[].members" \
    --filter="bindings.members:microsoft-defender" \
    --format="table(bindings.role)"

# Test workload identity
gcloud iam workload-identity-pools describe azure-defender-pool --location=global

# Check for errors in GCP logging
gcloud logging read "resource.type=service_account AND severity>=ERROR" --limit=10
