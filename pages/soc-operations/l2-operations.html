L2 SOC Analyst Operations

Deep-dive investigation, incident handling, threat hunting, and mentoring L1 analysts.

L2 Analyst Role

L2 (Tier 2) analysts handle escalations from L1, perform deep-dive investigations, coordinate incident response, and develop detection content. You bridge the gap between front-line triage and advanced threat operations.

L2 Key Responsibilities
  • Investigate escalations from L1 with deep analysis
  • Coordinate incident response for confirmed incidents
  • Perform proactive threat hunting
  • Develop and tune detection rules
  • Mentor and train L1 analysts
  • Create investigation documentation and runbooks
  • Interface with IT teams for containment/remediation
  • Escalate complex threats to L3/IR team

Handling L1 Escalations

When you receive an escalation:

1
Review L1 Work (2-3 minutes)
  • Read the ticket documentation thoroughly
  • Understand what L1 already checked
  • Identify any gaps in the initial investigation
  • Note the reason for escalation
2
Expand the Scope (5-10 minutes)
  • Pivot on all IOCs (IPs, domains, hashes, users)
  • Search for related alerts across the environment
  • Check for activity on other systems by same user/account
  • Look for lateral movement indicators
  • Review historical data for this entity
3
Deep Analysis (10-30 minutes)
  • Analyze malware samples (if applicable)
  • Review full process trees and command lines
  • Examine network connections in detail
  • Check for persistence mechanisms
  • Correlate with threat intelligence
4
Determine Impact & Scope
  • How many systems/users affected?
  • What data could be accessed/exfiltrated?
  • Is this ongoing or contained?
  • Business criticality of affected assets?
5
Take Action
  • Execute containment if needed (isolate, disable, block)
  • Coordinate with IT for remediation
  • Document everything in the ticket
  • Escalate to L3/IR if major incident
  • Provide feedback to L1 for learning

Investigation Techniques

Pivoting Strategy

Start from your initial indicator and expand outward:

Starting PointPivot ToQuestions to Answer
Suspicious IPAll connections to/from that IPWhat else communicated with it? When did it start?
Malicious HashAll systems with that fileHow widespread? How did it get there?
Compromised UserAll activity by that accountWhat else did they access? Any lateral movement?
Suspicious ProcessParent/child processes, network activityWhat spawned it? What did it do? C2?
Malicious DomainDNS queries, connectionsWho queried it? Was it resolved? Data transferred?

Threat Hunting

L2 analysts should dedicate time to proactive hunting:

Hunt Workflow

  1. Hypothesis: What threat behavior are you looking for?
  2. Data Sources: Where would this activity appear?
  3. Query: Build and execute detection query
  4. Analyze: Review results, filter noise
  5. Document: Record findings (even if negative)
  6. Detection: Convert successful hunts to automated rules

Weekly Hunt Ideas

  • Rare processes executed across the environment
  • Unusual outbound connections by volume or destination
  • Service accounts with interactive logons
  • PowerShell with encoded commands
  • Scheduled tasks created in the past 7 days
  • New local admin accounts
  • DNS queries to newly registered domains

Detection Engineering

L2 analysts contribute to detection content:

  • Tune existing rules: Reduce false positives, add exclusions
  • Create new detections: Based on hunts and incidents
  • Document detections: Purpose, logic, expected FP rate
  • Test detections: Validate with atomic tests

Mentoring L1 Analysts

L1 Development Tips
  • Provide constructive feedback on escalations
  • Explain your investigation process, don't just give answers
  • Share interesting cases as learning opportunities
  • Create runbooks for common scenarios they struggle with
  • Shadow sessions - let them watch your investigations
  • Encourage questions; no question is too basic

When to Escalate to L3

Escalate to L3/IR When:
  • Evidence of APT/nation-state activity
  • Ransomware deployment (even if caught early)
  • Confirmed data breach requiring legal/compliance
  • Compromise of critical infrastructure
  • Attack scope exceeds your capacity to handle
  • Need for forensic imaging/preservation
  • Executive or VIP accounts compromised
  • Unknown malware requiring reverse engineering

Documentation Standards

L2 documentation should be comprehensive enough for legal/compliance review:

L2 INVESTIGATION REPORT

1. EXECUTIVE SUMMARY
- What happened in 2-3 sentences
- Business impact
- Current status

2. TIMELINE
- Chronological events with timestamps

3. TECHNICAL ANALYSIS
- IOCs discovered
- Attack chain / kill chain mapping
- MITRE ATT&CK techniques observed

4. SCOPE & IMPACT
- Systems affected
- Users affected
- Data potentially accessed

5. CONTAINMENT ACTIONS
- What was done, when, by whom

6. RECOMMENDATIONS
- Immediate actions needed
- Long-term improvements

7. EVIDENCE
- Screenshots, logs, queries used
