Ransomware Investigation Playbook

Critical investigation procedures for ransomware incidents. Time-sensitive - every minute counts.

CRITICAL: Time-Sensitive Response

Ransomware spreads in MINUTES. If you're reading this during an active incident:

  1. ISOLATE affected systems from network NOW
  2. DO NOT turn off affected systems (preserves evidence)
  3. IDENTIFY patient zero and stop lateral spread
  4. ESCALATE to incident commander immediately

How to Investigate

Step 1: Identify Patient Zero

// KQL - Find first ransomware execution
DeviceProcessEvents
| where Timestamp > ago(24h)
| where FileName in~ ("vssadmin.exe", "wmic.exe", "bcdedit.exe", "wbadmin.exe")
| where ProcessCommandLine has_any ("delete", "shadowcopy", "catalog", "recoveryenabled")
| summarize FirstSeen = min(Timestamp), Devices = make_set(DeviceName) by FileName, ProcessCommandLine
| order by FirstSeen asc

// KQL - Mass file modifications (encryption indicator)
DeviceFileEvents
| where Timestamp > ago(1h)
| where ActionType in ("FileModified", "FileRenamed")
| summarize FileCount = count(), Extensions = make_set(FileExtension) by DeviceName, bin(Timestamp, 1m)
| where FileCount > 100
| order by FileCount desc

// KQL - Ransomware note file creation
DeviceFileEvents
| where Timestamp > ago(24h)
| where FileName matches regex @"(?i)(readme|decrypt|restore|recover|ransom|locked).*\.(txt|html|hta)"
| project Timestamp, DeviceName, FileName, FolderPath, InitiatingProcessFileName

// KQL - Find initial access (work backwards from patient zero)
let patientZero = "DEVICE-NAME"; // Replace with actual device
DeviceLogonEvents
| where Timestamp > ago(7d)
| where DeviceName == patientZero
| where LogonType in ("RemoteInteractive", "Network")
| project Timestamp, AccountName, LogonType, RemoteIP, RemoteDeviceName
| order by Timestamp asc

What If Scenarios

What If...Then...Rationale
Backups are also encrypted?Check offline/air-gapped backups. Check cloud backups with versioning. Contact backup vendor for recovery options.Many attackers specifically target backups first
Domain controllers are compromised?Assume complete AD compromise. Plan for full AD rebuild. All credentials must be reset.DC compromise = total domain control
We pay ransom but don't get decryptor?Common outcome. Still need to rebuild. Consider this possibility before paying.~30% of ransom payments don't result in working decryptor
Ransomware is still spreading during investigation?STOP investigating, focus on containment. Disconnect network segments. Isolate is priority #1.Can't investigate while fire is still burning
Data was exfiltrated before encryption?This is now also a data breach. Different notification requirements. Expect leak threat.Double extortion is now standard practice
We're not sure if it's real ransomware?Treat as real until proven otherwise. Better to over-react than under-react.Cost of false alarm << cost of ignoring real attack

Containment Actions

Immediate Containment (Do Now)

PriorityActionHowWhy
1Isolate affected systemsEDR isolation, network disconnect, disable switch portStop lateral spread
2Protect backupsDisconnect backup systems from network immediatelyAttackers target backups
3Block C2 communicationBlock attacker IPs/domains at firewallCut attacker control
4Disable compromised accountsDisable AD accounts used by attackerRemove attacker credentials
5Segment networkBlock SMB, RDP between segmentsPrevent spread to clean segments
6Reset privileged passwordsReset all admin passwords, KRBTGT twiceInvalidate stolen credentials

Do NOT Do

  • Don't turn off systems - Preserves memory evidence, may have decryption keys
  • Don't restore from backup yet - Need to understand entry point first or you'll get reinfected
  • Don't contact attacker without executive/legal approval - Opens negotiation
  • Don't assume it's over - Attackers often maintain access after ransomware
  • Don't pay immediately - Verify backups first, understand full scope

Escalation

Ransomware = Automatic Escalation

Any confirmed ransomware incident requires immediate escalation to:

  • CISO / Security leadership
  • IT leadership (for infrastructure decisions)
  • Legal (for breach notification, ransom legality)
  • Executive leadership (for business decisions)
  • Consider: External IR firm, law enforcement, cyber insurance
