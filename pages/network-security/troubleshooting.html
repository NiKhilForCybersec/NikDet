SASE/ZTNA Troubleshooting Guide

Comprehensive troubleshooting guide for Zscaler ZIA, ZPA, and SASE deployments. Diagnose and resolve common issues quickly.

Quick Diagnostics

First Things to Check

1. Is traffic going through Zscaler?

Visit: http://ip.zscaler.com

✅ Should show: "You are accessing the Internet via Zscaler"

❌ If shows your real IP: Traffic not going through Zscaler

2. Is the Client Connector running?

Windows: Check system tray for Zscaler icon (should be blue/green)

macOS: Check menu bar for Zscaler icon

Click icon → "Open Zscaler" → Check status

3. Is the user authenticated?

Zscaler Client → More → Status

Should show: User email and "Authenticated" status

# Quick Diagnostic Commands # Check Zscaler connectivity curl -v http://ip.zscaler.com/ curl -v https://gateway.zscaler.net/ # Check SSL inspection (certificate issuer) openssl s_client -connect www.google.com:443 2>/dev/null | openssl x509 -noout -issuer # Should show Zscaler if SSL inspection is on # Check DNS resolution nslookup gateway.zscaler.net nslookup mobile.zscaler.net # Windows: Check Zscaler services Get-Service ZSATunnel, ZSAService # macOS: Check Zscaler process ps aux | grep -i zscaler # Check client logs Windows: %LOCALAPPDATA%\Zscaler\logs\ macOS: ~/Library/Logs/Zscaler/

ZIA (Internet Access) Issues

🔴 Issue: Website incorrectly blocked

Symptom: Legitimate business site shows Zscaler block page

✅ Resolution Steps
  1. Check the block reason:
    • Note the URL category shown on block page
    • Admin Portal → Analytics → Web Logs → Search for URL
  2. Verify categorization:
    • Administration → URL Lookup → Enter URL
    • Check if category is correct
  3. Quick fix: Add URL to custom allow list
    • Administration → URL Categories → Custom Categories
    • Add to "Allowed-Business-Sites" category
  4. Long-term fix: Submit URL for recategorization
    • Administration → URL Lookup → Submit for Review
    • Takes 24-48 hours
# Add URL to custom allow list Administration → URL Categories → Custom Categories → Add Name: Business-Allowed-Sites URLs: - example-business-site.com - *.partner-company.com # Create policy to allow custom category Policy → URL & Cloud App Control → Add Rule Name: Allow-Custom-Business Action: Allow URL Categories: Business-Allowed-Sites Rule Order: Before block rules

🔴 Issue: Certificate error on HTTPS site

Symptom: Browser shows "Your connection is not private" or certificate error

✅ Resolution Steps
  1. Check if Zscaler CA is installed:
    # Windows - Check certificate store certmgr.msc → Trusted Root Certification Authorities Look for "Zscaler Root CA" # macOS - Check Keychain Keychain Access → System → Certificates Look for "Zscaler Root CA" (should show "This certificate is trusted")
  2. If CA missing: Deploy via GPO/MDM or download from Zscaler admin portal
  3. If certificate pinning: Add to SSL bypass list
    Policy → SSL Inspection → Add Rule Name: Bypass-Pinned-Apps Action: Do Not Inspect URL Categories/Domains: - *.apple.com - *.windowsupdate.com - [problematic site]

🔴 Issue: Application not working through Zscaler

Symptom: Specific app fails, but browser works fine

✅ Resolution Steps
  1. Identify the app's traffic:
    • Check if app uses non-standard ports
    • Check if app has certificate pinning
  2. Check firewall policy:
    • Policy → Firewall → Check if app's ports are allowed
  3. Add SSL bypass if needed:
    # Common apps that need SSL bypass - Zoom (*.zoom.us) - Webex (*.webex.com) - Microsoft Teams (*.teams.microsoft.com) - Slack desktop (*.slack.com) - Banking apps - Healthcare portals
  4. If app uses VPN/tunnel: May need app-specific bypass

🔴 Issue: Slow browsing performance

Symptom: Web pages load slowly, latency is high

✅ Resolution Steps
  1. Check which Zscaler DC you're hitting:
    curl http://ip.zscaler.com/ # Note the data center location # Should be geographically close to user
  2. If distant DC:
    • Client Connector → Settings → Check DC selection
    • May need to configure preferred DCs
  3. Check SSL inspection overhead:
    • Test site with and without SSL inspection
    • Consider bypassing high-bandwidth sites (video)
  4. Check local network:
    • Run speed test without Zscaler
    • Check for local network issues

ZPA (Private Access) Issues

🔴 Issue: User can't access any private apps

Symptom: ZPA not working at all, all internal apps fail

Troubleshooting Flowchart

User reports ZPA not working │ ▼ ┌───────────────────────────────┐ │ Is Client Connector running? │ │ (Check system tray) │ └───────────────────────────────┘ │ ┌───┴───┐ No Yes │ │ ▼ ▼ Start ┌───────────────────────────────┐ Client │ Is user authenticated? │ │ (Client → More → Status) │ └───────────────────────────────┘ │ ┌───┴───┐ No Yes │ │ ▼ ▼ Re-auth ┌───────────────────────────────┐ via IdP │ Is ZPA enabled on client? │ │ (Settings → ZPA toggle) │ └───────────────────────────────┘ │ ┌───┴───┐ No Yes │ │ ▼ ▼ Enable ┌───────────────────────────────┐ ZPA │ Check connectivity to ZPA │ │ nslookup mobile.zscaler.net │ └───────────────────────────────┘ │ ┌───┴───┐ Fails Works │ │ ▼ ▼ Check App Connector network or Policy issue

🔴 Issue: Specific application not accessible

Symptom: Some ZPA apps work, but one specific app doesn't

✅ Resolution Steps
  1. Verify Application Segment:
    # Check in ZPA Admin Applications → Application Segments # Verify: ✓ App domain/IP is in a segment ✓ Correct ports included ✓ Correct Connector Group assigned ✓ Segment is enabled
  2. Check Access Policy:
    Access Policy → Access Policy # Verify: ✓ User's group has a policy for this app ✓ Policy action is "Allow" ✓ Policy is not disabled ✓ Check rule order (first match wins)
  3. Check App Connector:
    Administration → App Connectors # Verify: ✓ Connector is online (green status) ✓ Connector can reach the application ✓ SSH to connector and test: curl -v http://[app-ip]:[port]
  4. Check ZPA logs:
    Analytics → ZPA Logs → User Activity # Filter by: - User - Time range - Application # Look for: - Action: Denied → Check policy - Connector: None → App not in segment - Error messages

🔴 Issue: "Access Denied" error

Symptom: User sees "Access Denied" when accessing ZPA app

✅ Resolution Steps
  1. Check user's group membership:
    • Administration → Users → Search for user
    • Verify groups are synced from IdP
  2. Check access policy conditions:
    • Is user in correct group?
    • Does device meet posture requirements?
    • Is there a time restriction?
    • Is there a location restriction?
  3. Check device posture:
    # On user's device Zscaler Client → More → Device Posture # Check what's failing: ❌ Disk encryption: Not enabled ❌ Antivirus: Not running ❌ OS version: Too old ❌ Firewall: Disabled
  4. If all looks correct: Check for conflicting deny policy higher in rule order

🔴 Issue: App Connector shows unhealthy

Symptom: Connector status is red/unhealthy in admin portal

✅ Resolution Steps
  1. Check connector VM:
    # SSH to connector ssh admin@[connector-ip] # Check service status sudo systemctl status zpa-connector # Check logs sudo journalctl -u zpa-connector -f # Check health sudo /opt/zscaler/bin/health_check.sh
  2. Check network connectivity:
    # Can connector reach Zscaler cloud? curl -v https://connector.zscaler.net # Check DNS nslookup connector.zscaler.net # Check firewall allows outbound 443 nc -zv connector.zscaler.net 443
  3. Common causes:
    • Firewall blocking outbound 443
    • DNS resolution failing
    • Certificate issues (expired, wrong time)
    • VM resource constraints (CPU, memory)
  4. Restart connector service:
    sudo systemctl restart zpa-connector # Wait 2-3 minutes, check status in admin portal

Client Connector Issues

🔴 Issue: Client Connector won't install

Symptom: Installation fails or stuck

✅ Resolution Steps
# Windows 1. Run installer as Administrator 2. Check for conflicting software: - Other VPN clients - Antivirus blocking installation - Previous Zscaler installation # Uninstall previous version "C:\Program Files\Zscaler\Uninstall.exe" /S # Clear registry (if needed) reg delete "HKLM\SOFTWARE\Zscaler" /f # macOS 1. Check System Preferences → Security & Privacy 2. Allow system extension for Zscaler 3. Grant Full Disk Access for posture checks # MDM Deployment Issues - Verify package is signed - Check MDM deployment logs - Ensure required configurations are included

🔴 Issue: Client shows "Not Connected" or "Connecting..."

Symptom: Client stuck in connecting state

✅ Resolution Steps
  1. Check network connectivity:
    # Can you reach Zscaler? ping gateway.zscaler.net nslookup mobile.zscaler.net
  2. Check for network blocks:
    • Corporate firewall blocking Zscaler domains
    • Captive portal (hotel/airport WiFi)
    • Proxy interference
  3. Required Zscaler domains (whitelist on firewall):
    # Must be allowed outbound on port 443 *.zscaler.net *.zscalerone.net *.zscalertwo.net *.zscalerthree.net *.zscloud.net *.zpath.net
  4. Restart client:
    # Windows Restart-Service ZSATunnel, ZSAService # macOS sudo launchctl unload /Library/LaunchDaemons/com.zscaler.tunnel.plist sudo launchctl load /Library/LaunchDaemons/com.zscaler.tunnel.plist

Common Scenario Resolution

ScenarioLikely CauseQuick Fix
User traveling, can't connect Hotel/airport WiFi blocking ports Use mobile hotspot, or enable fallback ports in client
New employee can't authenticate User not synced from IdP Check SCIM sync, force manual sync
App worked yesterday, not today Policy change, certificate expired Check audit logs for recent changes
Specific department can't access app Group not in policy Verify IdP group membership, check policy
Browser works, but desktop app fails Certificate pinning Add app to SSL bypass list
VPN and Zscaler conflict Route collision Configure proper routing, or disable legacy VPN
File downloads blocked ATP file type policy Check ATP logs, whitelist source if legitimate

When to Escalate to Zscaler Support

# Escalate to Zscaler Support when: - App Connector consistently unhealthy despite local fixes - Zscaler service outage suspected (check trust.zscaler.com) - SSL inspection causing widespread certificate issues - Performance degradation across multiple users/locations - Bug in client connector behavior - SIEM integration not receiving logs # Information to Gather Before Opening Ticket: 1. Affected users: How many? Specific users or all? 2. Scope: One location or multiple? 3. Timeline: When did it start? Any changes? 4. Error messages: Exact text from block pages, logs 5. Client logs: Export from Zscaler Client 6. Admin logs: Export from ZIA/ZPA analytics 7. HAR file: Browser network capture (for web issues) 8. Reproduce steps: How to replicate the issue # Support Portal: https://help.zscaler.com # Status Page: https://trust.zscaler.com
