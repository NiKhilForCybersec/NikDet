Complete guide to configuring logging, FortiAnalyzer, syslog, and integrating with Microsoft Sentinel and Splunk.

Configure Logging Settings

Global Log Settings

config log setting
    set resolve-ip enable           # Resolve IPs to hostnames
    set resolve-port enable         # Resolve ports to service names
    set log-user-in-upper enable    # Consistent username format
    set fwpolicy-implicit-log enable # Log implicit denies
    set local-in-allow enable       # Log allowed local-in traffic
    set local-in-deny-unicast enable
    set local-in-deny-broadcast disable
    set local-out enable            # Log FortiGate-originated traffic
    set daemon-log enable
    set neighbor-log enable
    set brief-traffic-format disable # Full log format
    set user-anonymize disable
    set expolicy-implicit-log enable
    set log-policy-comment enable   # Include policy comments in logs
    set log-policy-name enable      # Include policy names
end

Enable Logging on Policies

config firewall policy
    edit 10
        set logtraffic all          # Log all traffic (allowed and denied)
        # Options: disable, utm, all
        
        set logtraffic-start enable # Log session start (not just end)
        # Useful for long-lived sessions
        
        set capture-packet enable   # Capture packet on UTM events
        # Warning: High storage impact
    next
end

# Log implicit deny (traffic that matches no policy)
config log setting
    set fwpolicy-implicit-log enable
end

Syslog Configuration

Configure Syslog Server

config log syslogd setting
    set status enable
    set server "10.1.1.100"         # SIEM/Syslog server IP
    set mode udp                     # udp, tcp, or reliable (TCP with TLS)
    set port 514                     # Standard syslog port
    set facility local7              # Syslog facility
    set source-ip 10.1.1.1          # FortiGate source IP
    set format default               # default, csv, or cef
    set max-log-rate 0              # 0 = unlimited
    set priority default
    set certificate ""              # For TLS mode
end

# For multiple syslog servers (up to 4)
config log syslogd2 setting
    set status enable
    set server "10.1.1.101"
    set mode udp
    set port 514
end

config log syslogd3 setting
    set status enable
    set server "10.1.1.102"
end

Configure Syslog Filters

config log syslogd filter
    set severity information        # Minimum severity
    # Options: emergency, alert, critical, error, warning, notification, information, debug
    
    set forward-traffic enable
    set local-traffic enable
    set multicast-traffic enable
    set sniffer-traffic enable
    set anomaly enable
    set voip enable
    set dns enable
    
    # UTM log types
    set filter "logid(0001000014,0419016384)"  # Specific log IDs
    set filter-type include                     # include or exclude
end

CEF Format for SIEM

# Enable CEF format (Common Event Format)
config log syslogd setting
    set format cef
end

# CEF Example Output:
# CEF:0|Fortinet|Fortigate|v7.4.3|00013|traffic:forward close|5|
# src=10.1.1.50 dst=8.8.8.8 spt=52341 dpt=443 proto=6 
# act=accept deviceDirection=0 ...

Reliable Syslog (TCP with TLS)

config log syslogd setting
    set status enable
    set server "siem.company.com"
    set mode reliable                # TCP with TLS
    set port 6514                    # Standard TLS syslog port
    set certificate "SIEM-CA-Cert"   # CA certificate for verification
    set enc-algorithm high           # AES256 encryption
end

FortiAnalyzer Integration

Configure FortiAnalyzer Connection

config log fortianalyzer setting
    set status enable
    set server "10.1.1.200"         # FortiAnalyzer IP
    set serial "FAZ-VM0000000000"   # FAZ serial (optional, for verification)
    set upload-option realtime      # realtime, 1-minute, 5-minute
    set reliable enable             # Reliable logging
    set enc-algorithm high          # Encryption
    
    # Source IP for logs
    set source-ip 10.1.1.1
    
    # High availability
    set ha-peer-ip "10.1.1.201"     # Secondary FortiAnalyzer
    set ha-peer-serial "FAZ-VM0000000001"
end

# Verify connection
diagnose log test
get log fortianalyzer setting
execute log fortianalyzer test-connectivity

FortiAnalyzer Filter

config log fortianalyzer filter
    set severity information
    set forward-traffic enable
    set local-traffic enable
    set anomaly enable
    
    # Include all UTM logs
    set dlp-archive enable
    set gtp enable
    set free-style enable
    set dns enable
end

Microsoft Sentinel Integration

Option 1: FortiGate Data Connector (Recommended)

Microsoft Sentinel has a native FortiGate connector that uses CEF over syslog.

Prerequisites

  • Azure Log Analytics workspace
  • Linux VM with Log Analytics agent (syslog forwarder)
  • FortiGate configured to send CEF logs

Step 1: Deploy Linux Syslog Forwarder

# On Linux VM (Ubuntu/RHEL)
# Install Log Analytics agent
wget https://raw.githubusercontent.com/Microsoft/OMS-Agent-for-Linux/master/installer/scripts/onboard_agent.sh
sudo sh onboard_agent.sh -w <workspace-id> -s <shared-key> -d opinsights.azure.com

# Configure rsyslog to receive logs
sudo nano /etc/rsyslog.d/security-config-omsagent.conf

# Add:
# if $rawmsg contains "CEF:" then @@127.0.0.1:25226
# & stop
# if $rawmsg contains "ASA-" then @@127.0.0.1:25226
# & stop

# Open firewall for syslog
sudo ufw allow 514/udp
sudo ufw allow 514/tcp

# Restart rsyslog
sudo systemctl restart rsyslog

Step 2: Configure FortiGate for CEF to Sentinel

config log syslogd setting
    set status enable
    set server "10.1.1.150"         # Linux forwarder IP
    set mode udp
    set port 514
    set format cef                   # MUST be CEF for Sentinel
    set facility local4
end

config log syslogd filter
    set severity information
    set forward-traffic enable
    set local-traffic enable
    set anomaly enable
    set dns enable
end

Step 3: Enable Sentinel Connector

  1. In Azure Portal → Microsoft Sentinel → Data connectors
  2. Search "Fortinet" → Select "Fortinet FortiGate"
  3. Click "Open connector page"
  4. Follow the configuration steps
  5. Verify data in: CommonSecurityLog table

Sentinel KQL Queries for FortiGate

// All FortiGate logs
CommonSecurityLog
| where DeviceVendor == "Fortinet"
| take 100

// Blocked traffic
CommonSecurityLog
| where DeviceVendor == "Fortinet"
| where DeviceAction == "deny"
| summarize count() by SourceIP, DestinationIP, DestinationPort
| top 10 by count_

// IPS/IDS detections
CommonSecurityLog
| where DeviceVendor == "Fortinet"
| where Activity contains "intrusion"
| project TimeGenerated, SourceIP, DestinationIP, Activity, Message

// Web filter blocks
CommonSecurityLog
| where DeviceVendor == "Fortinet"
| where Activity contains "webfilter"
| where DeviceAction == "blocked"
| summarize count() by SourceIP, RequestURL

// Failed logins
CommonSecurityLog
| where DeviceVendor == "Fortinet"
| where Activity contains "login" and DeviceAction == "failure"
| project TimeGenerated, SourceIP, SourceUserName, Message

// Top talkers
CommonSecurityLog
| where DeviceVendor == "Fortinet"
| where DeviceAction == "accept"
| summarize TotalBytes = sum(SentBytes + ReceivedBytes) by SourceIP
| top 10 by TotalBytes

Splunk Integration

Option 1: Syslog to Splunk

# Configure FortiGate to send syslog to Splunk
config log syslogd setting
    set status enable
    set server "splunk.company.com"
    set mode udp
    set port 514
    set format default              # Or csv for easier parsing
    set facility local0
end

# On Splunk:
# 1. Settings → Data Inputs → UDP → New Local UDP
# 2. Port: 514
# 3. Source type: fgt_log (or create custom)
# 4. Index: firewall (or your index)

Option 2: Fortinet App for Splunk

Install the Fortinet FortiGate App from Splunkbase for pre-built dashboards.

# Splunk searches for FortiGate
# All FortiGate logs
index=firewall sourcetype=fgt_log

# Blocked traffic
index=firewall sourcetype=fgt_log action=deny
| stats count by srcip, dstip, dstport

# IPS events
index=firewall sourcetype=fgt_log type=utm subtype=ips
| table _time, srcip, dstip, attack, severity, action

# Top applications
index=firewall sourcetype=fgt_log type=traffic
| stats sum(sentbyte) as bytes by app
| sort -bytes
| head 20

# Failed VPN logins
index=firewall sourcetype=fgt_log type=event subtype=vpn action=tunnel-down
| stats count by remip, user

Recommended Splunk Index Settings

# In indexes.conf
[firewall]
homePath = $SPLUNK_DB/firewall/db
coldPath = $SPLUNK_DB/firewall/colddb
thawedPath = $SPLUNK_DB/firewall/thaweddb
maxTotalDataSizeMB = 500000
frozenTimePeriodInSecs = 7776000  # 90 days

Local Disk Logging

Configure Local Logging

config log disk setting
    set status enable
    set max-log-file-size 100       # MB before rotation
    set roll-day sunday             # Weekly rotation
    set roll-schedule daily         # Or weekly
    set roll-time 00:00             # Rotation time
    set diskfull overwrite          # What to do when disk full
    # Options: overwrite, nolog
    set log-quota 0                 # 0 = unlimited (use available space)
    set maximum-log-age 365         # Days to keep logs
    set upload enable               # Upload to FortiAnalyzer when connected
    set upload-destination faz      # faz or fmg
end

config log disk filter
    set severity information
    set forward-traffic enable
    set local-traffic enable
    set anomaly enable
end

# Look for "send" messages

# Check log disk space
diagnose sys logdisk usage

# Real-time log viewing
execute log filter category traffic
execute log filter field srcip 10.1.1.50
execute log display

# Clear log filter
execute log filter reset

Logging Best Practices

Best Practices

  • Log everything: Storage is cheap, missing logs is expensive
  • Use reliable logging: TCP instead of UDP for critical deployments
  • Enable session start logs: Needed for long-lived sessions
  • Include policy names: Makes SIEM queries much easier
  • NTP is critical: Logs with wrong timestamps are useless
  • Multiple destinations: Local + FortiAnalyzer + SIEM
  • Monitor log rate: High rates indicate issues or attacks
  • Test regularly: Verify logs are reaching SIEM
