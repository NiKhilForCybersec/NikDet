Major Incident Scenarios

🚨 Scenario: Ransomware Attack in Progress CRITICAL

L2 Escalation:

CRITICAL ESCALATION - RANSOMWARE

Multiple file servers showing encryption activity
- SERVER-FS01, SERVER-FS02, SERVER-FS03
- Files being renamed to .encrypted extension
- Ransom notes appearing: README_RESTORE.txt
- Started ~15 minutes ago, spreading

Users reporting files inaccessible
Need immediate response

⏱️ First 15 Minutes - Containment Sprint

Every minute counts. Ransomware encrypts ~1000 files/second per host.

Minute 0-5: Immediate Containment

  1. Isolate affected servers - Network isolation NOW 
    # MDE isolation
Invoke-MgDeviceManagementManagedDeviceAction -DeviceId $deviceId -ActionName "isolate"

# Or network team: Disable switch ports / VLAN isolation
# Or firewall: Block all traffic from affected IPs
  2. Disable compromised accounts 
    # Find accounts used on affected servers
DeviceLogonEvents
| where DeviceName in ("SERVER-FS01", "SERVER-FS02", "SERVER-FS03")
| where TimeGenerated > ago(24h)
| summarize by AccountName, AccountDomain
| where AccountName !contains "$"  // Exclude machine accounts
  3. Block C2 indicators if known

Minute 5-15: Scope Assessment

// Find all hosts with encryption activity
DeviceFileEvents
| where TimeGenerated > ago(1h)
| where ActionType == "FileRenamed"
| where FileName endswith ".encrypted" or FileName endswith ".locked" or FileName endswith ".crypted"
| summarize EncryptedFiles=count() by DeviceName, bin(TimeGenerated, 1m)
| order by TimeGenerated desc

// Find the ransomware process
DeviceProcessEvents
| where DeviceName in ("SERVER-FS01", "SERVER-FS02", "SERVER-FS03")
| where TimeGenerated > ago(2h)
| where FileName in ("vssadmin.exe", "wmic.exe", "bcdedit.exe")  // Common ransomware prep
    or ProcessCommandLine contains "shadowcopy"
    or ProcessCommandLine contains "recoveryenabled"
| project TimeGenerated, DeviceName, FileName, ProcessCommandLine, InitiatingProcessFileName

What you find:

T-2h - RDP login to SERVER-FS01 from unusual IP (compromised VPN?)

T-1h - vssadmin.exe deleted shadow copies

T-45m - bcdedit disabled recovery mode

T-30m - PsExec copied ransomware to FS02, FS03

T-15m - Encryption started on all three servers

Minute 15-60: Full Investigation

  • Identify initial access (how did they get in?)
  • Identify all compromised systems
  • Determine if data was exfiltrated before encryption
  • Preserve evidence for forensics

🎯 Key Decisions

Pay ransom?Business/legal decision. Security provides impact assessment.
Rebuild vs restore?Depends on backup integrity, confidence in eradication
Report to authorities?Usually yes - FBI IC3, CISA. Required for some industries.
Notify customers?Legal/compliance decision based on data exposure

🚨 Scenario: Business Email Compromise (BEC) - Wire Fraud URGENT

Situation: Finance department wired $450,000 to "vendor" - turned out to be fraudulent account.

L3 Investigation:

Step 1: Identify the compromised account (30 min)

// Check for mailbox rule manipulation
OfficeActivity
| where TimeGenerated > ago(30d)
| where Operation in ("New-InboxRule", "Set-InboxRule", "UpdateInboxRules")
| where UserId contains "finance" or UserId contains "cfo" or UserId contains "controller"
| project TimeGenerated, UserId, Operation, Parameters, ClientIP

Finding: CFO account had inbox rule created 2 weeks ago forwarding emails containing "wire", "payment", "invoice" to external address.

Step 2: Reconstruct attacker activity

// All CFO account activity from suspicious IPs
let cfoUser = "cfo@company.com";
let suspiciousIPs = SigninLogs
    | where UserPrincipalName =~ cfoUser
    | where TimeGenerated > ago(30d)
    | where Location !in ("United States", "Canada")  // Normal locations
    | summarize by IPAddress;
OfficeActivity
| where UserId =~ cfoUser
| where ClientIP in (suspiciousIPs)
| project TimeGenerated, Operation, Item, ClientIP

Timeline reconstructed:

Day -14 - CFO received phishing email (fake O365 login)

Day -14 - CFO credentials harvested, attacker logged in

Day -14 - Inbox rule created (forward payment emails)

Day -14 to -1 - Attacker monitored email traffic, learned patterns

Day -1 - Attacker sent spoofed email as "vendor" with new bank details

Day 0 - Finance processed wire to fraudulent account

Immediate Actions:

  1. Contact bank IMMEDIATELY - attempt to recall wire
  2. Reset CFO credentials, revoke all sessions
  3. Delete malicious inbox rule
  4. Enable MFA if not already
  5. Review all recent wire transfers for similar fraud
  6. Notify FBI IC3, file SAR if required

Malware Analysis

Quick Triage Analysis (10-15 min)

Step 1: Static Analysis - Don't Execute!
# Get file hashes
Get-FileHash -Algorithm SHA256 suspicious.exe
Get-FileHash -Algorithm MD5 suspicious.exe

# Check VirusTotal
# https://www.virustotal.com/gui/file/[HASH]

# Strings analysis
strings suspicious.exe | findstr /i "http https .com .net cmd powershell"

# PE headers
pestudio suspicious.exe  # or PEView, CFF Explorer
Step 2: Quick Reputation Checks
  • VirusTotal - AV detection, behavioral info
  • Hybrid Analysis - Sandbox report
  • Any.Run - Interactive sandbox
  • Joe Sandbox - Detailed behavioral analysis
Step 3: Safe Behavioral Analysis (if needed)
# In isolated sandbox VM:
# 1. Take snapshot BEFORE execution
# 2. Start monitoring tools:
   - Procmon (process/file/registry activity)
   - Wireshark (network traffic)
   - Regshot (registry changes)

# 3. Execute malware
# 4. Wait 5-10 minutes
# 5. Stop monitoring, compare results

# Look for:
# - New processes spawned
# - Registry persistence added
# - Files dropped
# - Network connections made
# - C2 communication patterns

Threat Hunting Operations

Hunt: Detect Credential Dumping

// LSASS access detection
DeviceProcessEvents
| where TimeGenerated > ago(7d)
| where FileName in ("mimikatz.exe", "procdump.exe", "procdump64.exe", "nanodump.exe")
    or ProcessCommandLine contains "sekurlsa"
    or ProcessCommandLine contains "lsass"
| project TimeGenerated, DeviceName, AccountName, FileName, ProcessCommandLine
| order by TimeGenerated desc

// LSASS memory access via DeviceEvents
DeviceEvents
| where ActionType == "SensitiveFileRead"
| where FileName == "lsass.exe"
| project TimeGenerated, DeviceName, InitiatingProcessFileName, InitiatingProcessCommandLine

Hunt: Detect Kerberoasting

// High volume TGS requests for SPNs
SecurityEvent
| where EventID == 4769
| where ServiceName !endswith "$"  // Not machine accounts
| where TicketEncryptionType in ("0x17", "0x18")  // RC4 encryption (weak, targeted)
| summarize RequestCount=count() by Account, ServiceName, ClientAddress
| where RequestCount > 5
| order by RequestCount desc

Hunt: Detect Unusual Outbound Traffic

// Beaconing detection (regular intervals = C2)
DeviceNetworkEvents
| where TimeGenerated > ago(24h)
| where RemoteIPType == "Public"
| summarize 
    Connections=count(),
    FirstSeen=min(TimeGenerated),
    LastSeen=max(TimeGenerated)
    by DeviceName, RemoteIP, RemotePort, bin(TimeGenerated, 1h)
| where Connections > 10
| extend Duration = LastSeen - FirstSeen
| where Duration > 1h  // Persistent connection
| order by Connections desc

Hunt: Detect Living-off-the-Land

// Suspicious LOLBin usage
DeviceProcessEvents
| where TimeGenerated > ago(7d)
| where FileName in ("certutil.exe", "bitsadmin.exe", "mshta.exe", "regsvr32.exe", 
    "rundll32.exe", "wmic.exe", "msiexec.exe")
| where ProcessCommandLine contains "http" 
    or ProcessCommandLine contains "ftp"
    or ProcessCommandLine contains "-decode"
    or ProcessCommandLine contains "scrobj"
| project TimeGenerated, DeviceName, AccountName, FileName, ProcessCommandLine
| order by TimeGenerated desc

APT Investigation

Signs You're Dealing with APT

IndicatorWhy It Matters
Custom malware (0 VT detections)Not commodity - developed for this target
Long dwell time (months)Patience indicates nation-state or sophisticated actor
Targeting specific dataNot opportunistic - they know what they want
Multiple persistence mechanismsEnsuring they can come back
Living-off-the-land techniquesAvoiding detection, blending in
Sophisticated C2 (DNS tunneling, steganography)Evading network detection

APT Investigation Approach

  1. Assume they're still watching - Don't tip them off with obvious remediation
  2. Parallel investigation - Keep normal operations while investigating covertly
  3. Full scope before containment - Find ALL persistence before kicking them out
  4. Coordinate eradication - Remove all access simultaneously
  5. Monitor for return - They will try to come back
