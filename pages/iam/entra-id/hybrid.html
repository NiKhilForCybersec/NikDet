Entra ID Hybrid Identity

Synchronize on-premises Active Directory with Entra ID using Entra Connect, with authentication options including password hash sync, pass-through auth, and federation.

Hybrid Identity Components

ComponentPurposeLocation
Entra ConnectSyncs users/groups from AD to Entra IDOn-premises server
Entra Connect Cloud SyncLightweight agent-based sync (newer)On-premises (agent)
Password Hash Sync (PHS)Syncs password hashes to cloudPart of Entra Connect
Pass-through Auth (PTA)Validates passwords on-prem in real-timeOn-premises agents
AD FSFederation for SSO, claims-based authOn-premises farm
Seamless SSOAuto sign-in for domain-joined devicesKerberos-based

Authentication Methods Comparison

MethodHow It WorksProsCons
Password Hash Sync (PHS) Hash of password hash synced to cloud Simple, cloud-resilient, enables leaked credential detection Passwords technically in cloud (hashed)
Pass-through Auth (PTA) Auth request sent to on-prem agents Passwords never leave on-prem, honors AD policies Requires on-prem availability, more complex
Federation (AD FS) Redirect to on-prem AD FS for auth Full control, complex claims, smart cards Complex infrastructure, single point of failure
Microsoft Recommendation

Password Hash Sync is recommended for most organizations. It enables Identity Protection (leaked credential detection), works when on-prem is down, and is simplest to maintain. Use PTA only if regulatory/compliance requires passwords never leave on-prem.

Entra Connect Architecture

Sync Cycle

  • Initial sync: Full sync of all objects (can take hours for large directories)
  • Delta sync: Every 30 minutes, syncs only changes
  • Manual sync: Start-ADSyncSyncCycle -PolicyType Delta

Filtered Sync (Recommended)

Don't sync everything - filter by:

  • OU-based: Only sync specific OUs (e.g., "Cloud Users")
  • Group-based: Sync only members of a group
  • Attribute-based: Custom rules based on attributes

PowerShell: Entra Connect Management

# Run on Entra Connect server
Import-Module ADSync

# Check sync status
Get-ADSyncScheduler

# Force delta sync
Start-ADSyncSyncCycle -PolicyType Delta

# Force full sync (caution - slow for large directories)
Start-ADSyncSyncCycle -PolicyType Initial

# Check last sync time
Get-ADSyncScheduler | Select-Object LastSyncCycleStartTimeTicks, NextSyncCycleStartTimeTicks

# View sync errors
Get-ADSyncConnectorRunStatus

# Export sync errors to CSV
Get-ADSyncCSObject -ConnectorName "contoso.com" | 
    Where-Object { $_.Error } | 
    Export-Csv -Path "SyncErrors.csv"

# Check connector status
Get-ADSyncConnector | Select-Object Name, Type, State

# View password hash sync status
Get-ADSyncAADPasswordResetConfiguration
Get-ADSyncAADPasswordSyncConfiguration -SourceConnector "contoso.com"

# Enable PHS if not already
Set-ADSyncAADPasswordSyncConfiguration -SourceConnector "contoso.com" -TargetConnector "AAD" -Enable $true

Pass-through Authentication Setup

1
Enable PTA in Entra Connect

Run Entra Connect wizard → Change user sign-in → Select Pass-through authentication

2
Install Additional Agents

Download PTA agent from Entra Admin Center → Install on 2+ servers for HA

3
Verify Agents

Entra Admin Center → Entra Connect → Pass-through authentication → Check agent status

4
Enable PHS as Backup

Also enable PHS so Identity Protection works and users can still sign in if PTA fails

PTA Agent PowerShell

# Check PTA agent status (run on agent server)
Get-Service -Name "AzureADConnectAuthenticationAgent"

# View agent logs
Get-WinEvent -LogName "Microsoft-AzureADConnect-AuthenticationAgent/Admin" -MaxEvents 50

# Register new PTA agent
& "C:\Program Files\Microsoft Azure AD Connect Authentication Agent\RegisterConnector.ps1" -modulePath "C:\Program Files\Microsoft Azure AD Connect Authentication Agent\Modules\"

Seamless SSO Configuration

Enables automatic sign-in for domain-joined devices on corporate network.

  1. Enable in Entra Connect wizard or PowerShell
  2. Creates computer account AZUREADSSOACC in AD
  3. Configure browser settings via GPO for IE/Edge
  4. Add https://autologon.microsoftazuread-sso.com to Intranet zone
# Enable Seamless SSO
Set-ADSyncTenantConfiguration -SeamlessSso $true

# Roll over Kerberos decryption key (do this every 30 days)
Update-AzureADSSOForest -OnPremCredentials $creds -PreserveCustomPermissionsOnDesktopSsoAccount

Security Considerations

Hybrid Identity Attack Vectors
  • Entra Connect server compromise - Has sync credentials, can forge tokens
  • Silver ticket attacks - Seamless SSO computer account compromise
  • PTA agent compromise - Can intercept/manipulate auth requests
  • AD FS server compromise - Golden SAML attacks
  • Sync account compromise - Can reset any synced user's password

Hardening Recommendations

ComponentHardening
Entra Connect serverTier 0 asset, limit admin access, no internet browsing, enable audit logging
Sync service accountMinimal permissions, long complex password, monitor for suspicious use
PTA agentsRun on dedicated servers, multiple agents for HA, monitor health
Seamless SSORoll over Kerberos key every 30 days, monitor AZUREADSSOACC account
AD FS (if used)Protect token signing certificate, monitor for abnormal SAML assertions

Monitoring Hybrid Identity (KQL)

// Entra Connect sync errors
AADProvisioningLogs
| where TimeGenerated > ago(7d)
| where ResultType == "Failure"
| project TimeGenerated, SourceIdentity, TargetIdentity, Action, ResultDescription

// Pass-through auth failures
SigninLogs
| where TimeGenerated > ago(24h)
| where AuthenticationProtocol == "passthrough"
| where ResultType != 0
| project TimeGenerated, UserPrincipalName, IPAddress, ResultDescription

// Sign-ins using different auth methods
SigninLogs
| where TimeGenerated > ago(7d)
| summarize count() by AuthenticationProtocol
| render piechart

// Suspicious: Sign-in as sync account
SigninLogs
| where TimeGenerated > ago(30d)
| where UserPrincipalName has "sync" or UserPrincipalName has "MSOL_"
| project TimeGenerated, UserPrincipalName, IPAddress, AppDisplayName, ResultType

// AD FS sign-in anomalies (if using federation)
SigninLogs
| where TimeGenerated > ago(7d)
| where AuthenticationProtocol == "wsFed" or AuthenticationProtocol == "samlp"
| where ResultType != 0
| project TimeGenerated, UserPrincipalName, IPAddress, ResultDescription

Migration Path: AD FS to Cloud Auth

Microsoft recommends migrating from AD FS to PHS + Seamless SSO:

  1. Enable PHS in Entra Connect (runs alongside federation)
  2. Enable Seamless SSO for internal users
  3. Staged rollout: Move users in batches to managed auth
  4. Update DNS to remove AD FS dependency
  5. Decommission AD FS infrastructure

Best Practices Summary

  • Use PHS as primary - Simplest, enables Identity Protection
  • Enable PHS even with PTA/Federation - Backup and leaked credential detection
  • Filter sync scope - Don't sync service accounts, admin accounts to cloud
  • Protect Entra Connect - Tier 0, limited access, monitored
  • Multiple PTA agents - At least 3 for high availability
  • Roll Seamless SSO key - Every 30 days minimum
  • Plan for AD outage - Cloud-only break-glass accounts
