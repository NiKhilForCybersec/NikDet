Part 1: Why Detection Testing is Critical

The Problem with Untested Detections

An untested detection gives you false confidence. You believe you're protected, but you have no evidence. Here's what can go wrong:

RiskWhat HappensReal-World Impact
False Negatives Detection doesn't fire on actual attacks Breaches go undetected. You find out from the news.
False Positives Detection fires on legitimate activity Alert fatigue. Analysts ignore all alerts, including real ones.
Broken Syntax Rule has errors, fails silently Rule appears enabled but never runs. Zero coverage.
Environment Drift Rule worked before but not anymore Log source changed, fields renamed, rule stops matching.
Performance Issues Rule is too slow or resource-intensive SIEM degrades. Other detections affected.
Real Example

A Fortune 500 company had a detection for Mimikatz. It was enabled for 2 years. During a pen test, Mimikatz was run 47 times. Zero alerts. Investigation found: a log source configuration change 18 months prior broke the detection. Nobody noticed because nobody tested it.

Part 3: Unit Testing (Automated)

Unit tests are fast, automated, and run on every code change. They catch basic errors before code is merged.

3.1 YAML Syntax Validation

First, ensure your YAML files are syntactically correct:

# Install yamllint
pip install yamllint

# Create a configuration file: .yamllint.yml
cat > .yamllint.yml << 'EOF'
extends: default
rules:
  line-length:
    max: 200
  indentation:
    spaces: 4
  document-start: disable
EOF

# Run yamllint on all detection files
yamllint detections/

# Example output for a valid file:
detections/windows/encoded_powershell.yml: OK

# Example output for an invalid file:
detections/windows/broken_rule.yml
  4:1       error    wrong indentation: expected 4 but found 2  (indentation)
  7:10      error    trailing spaces  (trailing-spaces)

3.2 Sigma Rule Validation

Validate that rules conform to the Sigma specification:

# Install sigma-cli
pip install sigma-cli

# Validate a single rule
sigma check detections/windows/encoded_powershell.yml

# Validate all rules in a directory
sigma check detections/

# Validate with strict mode (catches more issues)
sigma check --validation-config strict detections/

# Example valid output:
Checking 47 rules...
All rules valid!

# Example invalid output:
Error in detections/windows/bad_rule.yml:
  - Missing required field: 'logsource'
  - Invalid detection condition: undefined identifier 'selectoin'

3.3 Schema Validation (Custom)

Enforce your organization's standards beyond Sigma requirements:

# File: scripts/validate_rules.py
#!/usr/bin/env python3
"""
Custom validation for organizational standards.
Run: python scripts/validate_rules.py detections/
"""

import sys
import yaml
import re
from pathlib import Path

# Your organization's required fields
REQUIRED_FIELDS = ['title', 'id', 'status', 'description', 'author', 
                   'date', 'logsource', 'detection', 'level', 'tags']

# Valid status values
VALID_STATUSES = ['experimental', 'test', 'production', 'deprecated']

# Valid severity levels
VALID_LEVELS = ['informational', 'low', 'medium', 'high', 'critical']

def validate_rule(filepath: Path) -> list:
    """Validate a single rule file. Returns list of errors."""
    errors = []
    
    try:
        with open(filepath) as f:
            rule = yaml.safe_load(f)
    except yaml.YAMLError as e:
        return [f"YAML parse error: {e}"]
    
    if not isinstance(rule, dict):
        return ["File does not contain a valid YAML dictionary"]
    
    # Check required fields
    for field in REQUIRED_FIELDS:
        if field not in rule:
            errors.append(f"Missing required field: '{field}'")
    
    # Validate UUID format
    if 'id' in rule:
        uuid_pattern = r'^[0-9a-f]{8}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{12}$'
        if not re.match(uuid_pattern, str(rule['id']).lower()):
            errors.append(f"Invalid UUID format: {rule['id']}")
    
    # Validate status
    if 'status' in rule and rule['status'] not in VALID_STATUSES:
        errors.append(f"Invalid status: {rule['status']}. Must be one of {VALID_STATUSES}")
    
    # Validate level
    if 'level' in rule and rule['level'] not in VALID_LEVELS:
        errors.append(f"Invalid level: {rule['level']}. Must be one of {VALID_LEVELS}")
    
    # Validate MITRE ATT&CK tags
    if 'tags' in rule:
        for tag in rule['tags']:
            if tag.startswith('attack.t'):
                if not re.match(r'^attack\.t\d{4}(\.\d{3})?$', tag):
                    errors.append(f"Invalid ATT&CK technique format: {tag}")
    
    # Validate description length
    if 'description' in rule:
        if len(str(rule['description'])) < 20:
            errors.append("Description too short (minimum 20 characters)")
    
    # Validate falsepositives field exists for production rules
    if rule.get('status') == 'production' and 'falsepositives' not in rule:
        errors.append("Production rules must document false positives")
    
    return errors

def main():
    if len(sys.argv) < 2:
        print("Usage: python validate_rules.py ")
        sys.exit(1)
    
    path = Path(sys.argv[1])
    
    if path.is_file():
        files = [path]
    else:
        files = list(path.rglob('*.yml')) + list(path.rglob('*.yaml'))
    
    total_errors = 0
    
    for filepath in files:
        errors = validate_rule(filepath)
        if errors:
            print(f"\n✗ {filepath}")
            for error in errors:
                print(f"  - {error}")
                total_errors += 1
        else:
            print(f"✓ {filepath}")
    
    print(f"\n{'='*50}")
    print(f"Files checked: {len(files)}")
    print(f"Errors found: {total_errors}")
    
    sys.exit(1 if total_errors > 0 else 0)

if __name__ == '__main__':
    main()

3.4 Conversion Testing

Verify rules convert to your target SIEM without errors:

# Install pySigma backends
pip install pysigma-backend-splunk
pip install pysigma-backend-microsoft365defender
pip install pysigma-backend-elasticsearch

# Test conversion to Splunk
sigma convert -t splunk detections/windows/encoded_powershell.yml

# Test conversion to Sentinel/Defender
sigma convert -t microsoft365defender detections/windows/encoded_powershell.yml

# Test all rules convert without errors
for file in $(find detections -name "*.yml"); do
    echo "Converting: $file"
    sigma convert -t splunk "$file" > /dev/null 2>&1
    if [ $? -ne 0 ]; then
        echo "  ERROR: Failed to convert $file"
        exit 1
    fi
done
echo "All rules convert successfully!"

Part 4: Integration Testing

Integration tests verify that rules work in your actual SIEM environment with real (or realistic) log data.

4.1 Test Environment Setup

What You Need
  • Test SIEM instance: Separate from production (could be free tier, dev license, or Docker)
  • Sample log data: Logs containing both malicious and benign activity
  • API access: To deploy rules and check for alerts programmatically
  • Automation: Scripts to run tests and report results

4.2 Creating Test Cases

For each detection, create test cases with known-good (should match) and known-bad (should not match) samples:

# File: tests/windows/encoded_powershell_test.yml

rule_file: detections/windows/process_creation/encoded_powershell.yml

test_cases:

  # Cases that SHOULD trigger the detection
  should_match:
  
    - name: "Basic encoded command with -enc flag"
      description: "Standard encoded PowerShell execution"
      log:
        EventID: 1
        Image: 'C:\Windows\System32\WindowsPowerShell\v1.0\powershell.exe'
        CommandLine: 'powershell.exe -enc SGVsbG8gV29ybGQh'
        ParentImage: 'C:\Windows\System32\cmd.exe'
        User: 'DOMAIN\user'
      expected_result: ALERT
      
    - name: "Encoded with -encodedcommand flag"
      description: "Full flag name variation"
      log:
        EventID: 1
        Image: 'C:\Windows\System32\WindowsPowerShell\v1.0\powershell.exe'
        CommandLine: 'powershell.exe -NoProfile -encodedcommand SGVsbG8='
        ParentImage: 'C:\Windows\explorer.exe'
        User: 'DOMAIN\admin'
      expected_result: ALERT
      
    - name: "PowerShell Core (pwsh.exe)"
      description: "PowerShell 7 uses pwsh.exe"
      log:
        EventID: 1
        Image: 'C:\Program Files\PowerShell\7\pwsh.exe'
        CommandLine: 'pwsh.exe -e SGVsbG8gV29ybGQh'
        ParentImage: 'C:\Windows\System32\cmd.exe'
        User: 'DOMAIN\user'
      expected_result: ALERT

  # Cases that should NOT trigger the detection
  should_not_match:
  
    - name: "Normal PowerShell without encoding"
      description: "Regular PowerShell execution - no encoding"
      log:
        EventID: 1
        Image: 'C:\Windows\System32\WindowsPowerShell\v1.0\powershell.exe'
        CommandLine: 'powershell.exe -ExecutionPolicy Bypass -File C:\Scripts\backup.ps1'
        ParentImage: 'C:\Windows\System32\services.exe'
        User: 'SYSTEM'
      expected_result: NO_ALERT
      
    - name: "Different executable entirely"
      description: "cmd.exe should not match PowerShell rule"
      log:
        EventID: 1
        Image: 'C:\Windows\System32\cmd.exe'
        CommandLine: 'cmd.exe /c echo hello'
        ParentImage: 'C:\Windows\explorer.exe'
        User: 'DOMAIN\user'
      expected_result: NO_ALERT
      
    - name: "Known good application (exclusion)"
      description: "SCCM uses encoded PowerShell legitimately"
      log:
        EventID: 1
        Image: 'C:\Windows\System32\WindowsPowerShell\v1.0\powershell.exe'
        CommandLine: 'powershell.exe -enc SGVsbG8= -InputFormat None'
        ParentImage: 'C:\Windows\CCM\CcmExec.exe'
        User: 'SYSTEM'
      expected_result: NO_ALERT  # Assuming SCCM is excluded

4.3 Running Integration Tests

# File: scripts/run_integration_tests.py
#!/usr/bin/env python3
"""
Run integration tests against a test SIEM.
Injects sample logs and verifies detection behavior.
"""

import yaml
import json
import time
import requests
from pathlib import Path

# Configuration
SPLUNK_URL = "https://test-splunk.company.com:8089"
SPLUNK_TOKEN = "your-token-here"

def inject_log(log_data: dict) -> bool:
    """Inject a log event into the test SIEM."""
    url = f"{SPLUNK_URL}/services/receivers/simple"
    headers = {"Authorization": f"Bearer {SPLUNK_TOKEN}"}
    
    response = requests.post(
        url,
        headers=headers,
        data=json.dumps(log_data),
        params={"sourcetype": "WinEventLog:Security"},
        verify=False
    )
    return response.status_code == 200

def check_for_alert(rule_name: str, timeout: int = 60) -> bool:
    """Check if an alert was generated within timeout seconds."""
    url = f"{SPLUNK_URL}/services/search/jobs"
    headers = {"Authorization": f"Bearer {SPLUNK_TOKEN}"}
    
    # Search for triggered alerts
    search_query = f'index=notable search_name="{rule_name}" | head 1'
    
    start_time = time.time()
    while time.time() - start_time < timeout:
        # Run search and check for results
        response = requests.post(url, headers=headers, data={"search": search_query})
        if response.json().get("resultCount", 0) > 0:
            return True
        time.sleep(5)
    
    return False

def run_test(test_file: Path) -> dict:
    """Run all tests in a test file."""
    with open(test_file) as f:
        tests = yaml.safe_load(f)
    
    results = {"passed": 0, "failed": 0, "details": []}
    
    # Test cases that should match
    for test_case in tests.get("should_match", []):
        print(f"  Testing: {test_case['name']}")
        
        # Inject the log
        inject_log(test_case["log"])
        
        # Wait and check for alert
        alert_fired = check_for_alert(tests["rule_file"], timeout=60)
        
        if alert_fired:
            print(f"    ✓ PASS - Alert fired as expected")
            results["passed"] += 1
        else:
            print(f"    ✗ FAIL - No alert fired (expected alert)")
            results["failed"] += 1
    
    # Test cases that should NOT match
    for test_case in tests.get("should_not_match", []):
        print(f"  Testing: {test_case['name']}")
        
        inject_log(test_case["log"])
        alert_fired = check_for_alert(tests["rule_file"], timeout=30)
        
        if not alert_fired:
            print(f"    ✓ PASS - No alert (as expected)")
            results["passed"] += 1
        else:
            print(f"    ✗ FAIL - Alert fired (should not have)")
            results["failed"] += 1
    
    return results

def main():
    test_files = Path("tests").rglob("*_test.yml")
    
    total_passed = 0
    total_failed = 0
    
    for test_file in test_files:
        print(f"\nRunning tests: {test_file}")
        results = run_test(test_file)
        total_passed += results["passed"]
        total_failed += results["failed"]
    
    print(f"\n{'='*50}")
    print(f"Total: {total_passed} passed, {total_failed} failed")
    
    return 0 if total_failed == 0 else 1

if __name__ == '__main__':
    exit(main())

Part 5: Atomic Red Team Testing (Step-by-Step)

Atomic Red Team executes real attack techniques in a controlled way, allowing you to verify detections against actual malicious behavior.

5.1 What is Atomic Red Team?

  • Library of attack tests: 1000+ tests mapped to MITRE ATT&CK
  • Atomic = small: Each test is self-contained, minimal, and reversible
  • Safe for testing: Designed to be run in lab environments
  • Open source: Free, community-maintained

5.2 Installing Atomic Red Team

# STEP 1: Open PowerShell as Administrator on your TEST machine
# WARNING: Only run on isolated test systems, never in production!

# STEP 2: Install the execution framework
Install-Module -Name invoke-atomicredteam -Scope CurrentUser -Force

# STEP 3: Import the module
Import-Module invoke-atomicredteam

# STEP 4: Download the atomic tests library
# This downloads all 1000+ test definitions
Invoke-AtomicTest -InstallAtomicTestsFromGitHub

# STEP 5: Verify installation
Get-AtomicTechnique -All | Measure-Object
# Should show 200+ techniques with 1000+ tests

# STEP 6: See what tests are available for a technique
Invoke-AtomicTest T1059.001 -ShowDetails

# Output shows available tests:
# T1059.001-1: Mimikatz
# T1059.001-2: BloodHound
# T1059.001-3: Obfuscation Tests
# ...

5.3 Running Your First Atomic Test

# EXAMPLE: Testing Encoded PowerShell Detection (T1059.001)

# Step 1: See what the test will do (don't run yet)
Invoke-AtomicTest T1059.001 -TestNumbers 7 -ShowDetails

# Output:
# Technique: Command and Scripting Interpreter: PowerShell
# Test Name: Encoded Command
# Description: Executes PowerShell with an encoded command
# Command: powershell.exe -enc SQBFAFgAIAAoAE4AZQB3AC0...

# Step 2: Check prerequisites
Invoke-AtomicTest T1059.001 -TestNumbers 7 -CheckPrereqs

# Output:
# Prerequisites met: True

# Step 3: Run the test
Invoke-AtomicTest T1059.001 -TestNumbers 7

# Output:
# Executing test: Encoded Command
# Done executing test

# Step 4: Wait for logs to be ingested (usually 1-5 minutes)

# Step 5: Check your SIEM for alerts!
# - Did the detection fire?
# - How long did it take?
# - Is the alert accurate?

# Step 6: Clean up (remove test artifacts)
Invoke-AtomicTest T1059.001 -TestNumbers 7 -Cleanup

# Output:
# Cleanup complete

5.4 Complete Atomic Testing Workflow

1
Identify Detection to Test

Pick a detection rule. Note its MITRE ATT&CK technique ID (e.g., T1059.001).

2
Find Relevant Atomic Tests

Run Invoke-AtomicTest TXXXX -ShowDetails to see available tests.

3
Review Test Details

Understand what the test does. Is it relevant to your detection logic?

4
Check Prerequisites

Run -CheckPrereqs. Install any missing requirements.

5
Execute the Test

Run the atomic test on your test machine.

6
Wait for Log Ingestion

Allow time for logs to flow to SIEM (1-5 minutes typically).

7
Check for Alert

Did your detection fire? If yes, note time-to-detection. If no, investigate why.

8
Run Cleanup

Execute -Cleanup to remove test artifacts.

9
Document Results

Record pass/fail, timing, and any issues found.

5.5 Useful Atomic Test Commands

# List all available techniques
Get-AtomicTechnique -All

# Search for techniques by name
Get-AtomicTechnique -All | Where-Object {$_.display_name -like "*PowerShell*"}

# Run all tests for a technique
Invoke-AtomicTest T1059.001

# Run specific test numbers
Invoke-AtomicTest T1059.001 -TestNumbers 1,3,5

# Run test and automatically clean up
Invoke-AtomicTest T1059.001 -TestNumbers 1 -Cleanup

# Run multiple techniques
Invoke-AtomicTest T1059.001,T1003.001,T1053.005

# Run tests for an entire tactic
Get-AtomicTechnique -All | Where-Object {$_.attack_technique.tactic -contains "persistence"} | 
    ForEach-Object { Invoke-AtomicTest $_.attack_technique_id -ShowDetails }

# Generate a test log for reporting
Invoke-AtomicTest T1059.001 -LoggingModule "Invoke-AtomicLogger"

Part 6: False Positive Analysis

A detection that fires on legitimate activity is sometimes worse than no detection at all. It creates noise, wastes analyst time, and leads to alert fatigue.

6.1 Historical Data Analysis

Before deploying a new detection, run it against historical data:

// KQL: Test detection against 30 days of data
DeviceProcessEvents
| where Timestamp > ago(30d)
| where FileName in~ ("powershell.exe", "pwsh.exe")
| where ProcessCommandLine has_any ("-enc", "-encoded", "-e ", "-ec ")
| summarize 
    Count = count(),
    Devices = dcount(DeviceName),
    Users = dcount(AccountName)
    by InitiatingProcessFileName
| sort by Count desc

// Results might show:
// InitiatingProcessFileName  Count   Devices   Users
// CcmExec.exe               1,247   500       1      ← SCCM - exclude this
// svchost.exe                 89    12        1      ← Investigate
// explorer.exe                23    20        18     ← Users - potential FPs

6.2 Calculating False Positive Rate

FP Rate = False Positives ÷ (True Positives + False Positives) × 100

FP RateAssessmentAction
< 5% Excellent Deploy to production
5-10% Good Deploy, monitor, tune if needed
10-20% Acceptable Add exclusions, then deploy
20-50% Poor Rework detection logic
> 50% Unusable Do not deploy, redesign
