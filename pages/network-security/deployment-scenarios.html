🤝 Scenario 2: M&A Integration

Situation: Acquire 800-person company. Need SAP access in 3 weeks. Network integration will take 6+ months.

Challenge: Traditional approach requires network connectivity (MPLS, site-to-site VPN), firewall rules, routing changes. Timeline: 3-6 months minimum.
ZTNA Solution: Deploy ZPA. No network changes required. Application-level access only to SAP. Timeline: 2 weeks.

Implementation

# Day 1-3: Preparation 1. Create Connector Group: "Acquired-Company" 2. Create Application Segment: "SAP-Acquired-Access" Domains: sap.company.com Ports: 443, 3200-3299, 8000-8100 Connector Group: Existing-DC-Connectors # Day 4-7: Identity Integration 3. Option A: Federate acquired company's Azure AD - Configure as additional IdP in ZPA - Map groups for policy Option B: Create accounts in corporate IdP - Bulk import users - Assign to "Acquired-Company-Users" group # Day 8-10: Policy & Testing 4. Create Access Policy: Name: Acquired-Users-SAP Users: Acquired-Company-Users Apps: SAP-Acquired-Access Posture: Basic (managed device preferred) 5. Test with 10 pilot users from acquired company # Day 11-14: Deployment 6. Deploy Zscaler Client Connector - Via acquired company's MDM if available - Or provide download link with enrollment 7. Go Live - All 800 users can access SAP

Security Benefits

  • ✅ Acquired users ONLY see SAP, not entire network
  • ✅ No firewall rules opened between networks
  • ✅ Full audit trail of all access
  • ✅ Easy to revoke if deal falls through
  • ✅ Can add more apps incrementally

🏢 Scenario 3: Branch Office Transformation

Situation: 50 branch offices on MPLS. Cost: $500K/year. Users complaining about cloud app performance.

Architecture Change

# Before: Hub-and-Spoke MPLS Branch → MPLS → Data Center → Internet - All traffic backhauled to DC - Cloud apps (O365, Salesforce) go through DC proxy - Latency: 150-300ms to cloud apps - Cost: $10K/month per branch for MPLS # After: Direct-to-Cloud with SASE Branch → Local Internet → Zscaler Cloud → Destination - Local internet breakout via SD-WAN - All traffic through Zscaler (GRE/IPSec tunnel) - Latency: 20-50ms to cloud apps - Cost: $2K/month per branch for broadband + Zscaler

Branch Configuration

# SD-WAN + Zscaler Integration # Step 1: Deploy SD-WAN at branch (Cisco Viptela example) Branch Router Config: WAN1: Primary broadband (100 Mbps) WAN2: Secondary LTE backup # Step 2: Create GRE tunnels to Zscaler Zscaler Admin: Administration → GRE Tunnels → Add Source IP: [Branch Public IP] Assign to: Chicago-Branch location SD-WAN Policy: Internet traffic → Zscaler GRE tunnel Internal DC traffic → MPLS (retain for DC access) Cloud apps → Direct via Zscaler (SaaS optimization) # Step 3: Create Location in ZIA Name: Chicago-Branch-Office IP Range: [Branch internal subnet] GRE Tunnel: Chicago-Branch-GRE Auth: Cookie-based (for users without client) # Step 4: Apply branch-specific policies Bandwidth Policy: - Video conferencing: High priority - Social media: Limited (2 Mbps) - Streaming: Block during business hours

👷 Scenario 4: Third-Party Contractor Access

Situation: 50 external contractors need access to project management system for 6-month engagement. Can't install software on their devices.

Solution: ZPA Browser Access

# Configure Browser Access Application Navigation: Applications → Browser Access → Add Name: Project-Management-Contractor Internal URL: https://jira.internal.company.com External URL: https://jira.contractors.company.zpa.com Authentication: SAML (via contractor IdP or company IdP) # Access Policy Name: Contractor-Project-Access Users: External-Contractors group Application: Project-Management-Contractor Time Restriction: Business hours only Expiration: 2025-06-30 (contract end date) # Security Controls Session Recording: Enabled Clipboard: Disabled (no copy/paste out) File Download: Disabled Print: Disabled Watermark: Enabled (shows user email)

Benefits

  • ✅ No software installation required on contractor devices
  • ✅ Access via any browser (Chrome, Firefox, Safari)
  • ✅ Contractors see only the one application
  • ✅ Session recorded for compliance audit
  • ✅ Automatic access revocation on contract end
  • ✅ Data protection (no copy/paste/download)

🔐 Scenario 5: Privileged Access Management

Situation: IT admins need SSH/RDP to production servers. Compliance requires session recording and MFA per session.

# Application Segments Name: Production-Linux-SSH IPs: 10.1.50.0/24 (prod Linux servers) Ports: 22 Name: Production-Windows-RDP IPs: 10.1.60.0/24 (prod Windows servers) Ports: 3389 # Privileged Access Policy Name: IT-Admin-Privileged-Access Users: IT-Administrators, DevOps-Team Apps: Production-Linux-SSH, Production-Windows-RDP Device Posture: High-Security (corporate managed only) # Additional Controls MFA: Required for EVERY session (step-up auth) Session Recording: Full video recording Idle Timeout: 15 minutes Max Session: 4 hours (re-authenticate after) # Approval Workflow (Optional) Just-in-Time Access: Enabled Approval Required: Manager approval via ServiceNow Access Duration: 4 hours (then auto-revoke) Notification: Alert security team on each access

SASE Migration Checklist

# Pre-Migration ☐ Inventory all applications (internal + SaaS) ☐ Document current VPN/proxy configuration ☐ Identify certificate-pinned applications ☐ Map user groups to applications ☐ Define device posture requirements ☐ Plan IdP integration (SAML/OIDC) ☐ Baseline current user experience (latency, complaints) # Infrastructure ☐ Deploy App Connectors (2+ per location) ☐ Verify App Connector health ☐ Configure IdP integration ☐ Test SCIM provisioning (user/group sync) ☐ Deploy Zscaler Root CA to devices # Policy Configuration ☐ Create Application Segments ☐ Define Access Policies ☐ Configure Device Posture profiles ☐ Set up SSL inspection (with bypass list) ☐ Configure URL filtering policies ☐ Enable DLP policies ☐ Set up SIEM integration # Testing ☐ Pilot with IT team (friendly users) ☐ Test all critical applications ☐ Verify SSL inspection doesn't break apps ☐ Test from multiple locations (office, home, mobile) ☐ Document workarounds for issues ☐ Train help desk on common issues # Deployment ☐ Deploy Client Connector via MDM ☐ Staggered rollout by department ☐ Monitor for issues (check logs daily) ☐ Communicate to users (FAQ, support channel) ☐ Track adoption metrics # Post-Migration ☐ Decommission legacy VPN (after parallel run) ☐ Remove old proxy appliances ☐ Update disaster recovery procedures ☐ Conduct security assessment ☐ Document final architecture
