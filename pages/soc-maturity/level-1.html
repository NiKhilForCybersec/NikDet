Level 1: Initial

Ad-hoc security operations with minimal process and reactive response. This is the starting point for most organizations building security capabilities.

Level 1 Characteristics

DomainTypical State
BusinessNo formal SOC strategy, security is IT's side responsibility
PeopleIT staff handling security part-time, no dedicated analysts
ProcessNo documented procedures, response is ad-hoc
TechnologyBasic antivirus, firewall logs ignored or uncollected
ServicesReactive only—respond when something breaks

Common Level 1 Challenges

  • No visibility into what's happening on the network
  • Alerts go to email and get ignored
  • Incidents discovered by users or external parties
  • No log retention or centralization
  • Cannot determine scope when incidents occur
  • Response depends on who's available

Priority Improvements to Reach Level 2

PriorityActionWhy It Matters
1Deploy basic SIEM or log aggregationYou can't protect what you can't see
2Collect critical logs (AD, firewall, endpoints)Foundation for detection
3Assign dedicated security responsibilitySomeone owns the problem
4Document basic incident response stepsConsistent response regardless of who
5Enable built-in security alertsQuick wins from existing tools

Quick Wins for Level 1 Organizations

  • Enable M365 security defaults - Free MFA and basic protections
  • Turn on Windows Defender - Built-in endpoint protection
  • Forward firewall logs to central location - Start collecting data
  • Document your critical assets - Know what matters most
  • Create an incident contact list - Know who to call

Signs You're Ready for Level 2

  • Logs are being collected centrally
  • Someone reviews security alerts regularly
  • Basic incident response procedure exists
  • You know your critical assets
  • Security is someone's primary job (or managed service)
