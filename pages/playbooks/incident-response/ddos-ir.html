PB-IR-004

DDoS Incident Response

Response procedures for Distributed Denial of Service attacks, from detection through mitigation and recovery.

DDoS Attack Types

TypeLayerMethodMitigation
VolumetricL3/L4Flood bandwidth (UDP, ICMP)Upstream filtering, scrubbing
ProtocolL3/L4Exhaust resources (SYN flood, Ping of Death)SYN cookies, rate limiting
ApplicationL7Exhaust application (HTTP flood, Slowloris)WAF, bot detection
AmplificationL3/L4Reflected traffic (DNS, NTP, Memcached)Source validation, filtering

Phase 1: Detection & Triage

// Check current traffic patterns
CommonSecurityLog
| where TimeGenerated > ago(1h)
| where DeviceVendor == "Firewall"
| summarize Connections=count(), 
    UniqueIPs=dcount(SourceIP),
    TotalBytes=sum(ReceivedBytes + SentBytes)
    by bin(TimeGenerated, 1m)
| render timechart

// Identify top source IPs
CommonSecurityLog
| where TimeGenerated > ago(15m)
| summarize Count=count() by SourceIP
| top 100 by Count
| extend GeoInfo = geo_info_from_ip_address(SourceIP)

Triage Checklist

  • ☐ Confirm attack (not legitimate traffic spike)
  • ☐ Identify attack type (volumetric, protocol, application)
  • ☐ Determine affected services
  • ☐ Assess current impact level
  • ☐ Identify attack vectors and sources
  • ☐ Notify stakeholders

Mitigation Commands

// Cloudflare - Enable Under Attack Mode
curl -X PATCH "https://api.cloudflare.com/client/v4/zones/{zone_id}/settings/security_level" \
     -H "Authorization: Bearer {token}" \
     -H "Content-Type: application/json" \
     --data '{"value":"under_attack"}'

// iptables - Rate limit connections
iptables -A INPUT -p tcp --dport 80 -m state --state NEW -m limit --limit 50/minute --limit-burst 200 -j ACCEPT
iptables -A INPUT -p tcp --dport 80 -m state --state NEW -j DROP

// Block specific IP range
iptables -A INPUT -s 192.0.2.0/24 -j DROP

// nginx - Rate limiting
limit_req_zone $binary_remote_addr zone=one:10m rate=30r/s;
limit_req zone=one burst=50 nodelay;

Phase 3: Escalation

Suspected targeted attackLaw enforcementReport, preserve evidence

Phase 4: Recovery

  • ☐ Confirm attack has stopped or is controlled
  • ☐ Gradually restore normal operations
  • ☐ Monitor for follow-up attacks
  • ☐ Verify all services functioning
  • ☐ Document attack characteristics
  • ☐ Update protection rules if needed
