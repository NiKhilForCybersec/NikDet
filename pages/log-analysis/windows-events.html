Windows Event Log Analysis

Essential Windows Event IDs for security monitoring, investigation, and threat detection.

Why Windows Events Matter

The Foundation of Windows Security Monitoring

Windows Event Logs are the primary source of security telemetry for Windows systems. Understanding them is non-negotiable for any SOC analyst.

Without Windows Event KnowledgeWith Windows Event Knowledge
Can't investigate Windows-based attacksFull visibility into Windows activity
Miss critical security indicatorsDetect logons, process execution, privilege use
Rely entirely on EDR (single point of failure)Multiple detection layers
Can't build custom detectionsCreate precise, tailored alerts

Investigation Queries

// KQL - Failed logons by account (brute force detection)
SecurityEvent
| where TimeGenerated > ago(24h)
| where EventID == 4625
| summarize FailedCount = count(), 
    SourceIPs = make_set(IpAddress),
    FailureCodes = make_set(FailureReason)
    by TargetUserName
| where FailedCount > 10
| order by FailedCount desc

// KQL - Successful RDP logons
SecurityEvent
| where TimeGenerated > ago(7d)
| where EventID == 4624
| where LogonType == 10
| project TimeGenerated, Computer, TargetUserName, IpAddress
| order by TimeGenerated desc

// KQL - New service installations
Event
| where TimeGenerated > ago(24h)
| where EventLog == "System" and EventID == 7045
| parse EventData with * '' ServiceName '' *
| parse EventData with * '' ImagePath '' *
| project TimeGenerated, Computer, ServiceName, ImagePath

// KQL - Account added to privileged group
SecurityEvent
| where TimeGenerated > ago(7d)
| where EventID in (4728, 4732, 4756)
| where TargetUserName has_any ("Admin", "Domain Admins", "Enterprise Admins")
| project TimeGenerated, Computer, SubjectUserName, MemberName, TargetUserName
