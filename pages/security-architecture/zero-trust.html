Zero Trust Architecture

Never trust, always verify. Assume breach and verify explicitly.

Zero Trust Principles

Zero Trust (NIST SP 800-207) shifts from "trust but verify" to "never trust, always verify."

Verify Explicitly

Always authenticate and authorize based on all available data points

Least Privilege

Limit access with just-in-time and just-enough-access (JIT/JEA)

Assume Breach

Minimize blast radius and segment access. Verify end-to-end encryption.

Traditional vs. Zero Trust

Zero Trust Pillars

PillarDescriptionKey Controls
Identity Verify user identity strongly MFA, SSO, risk-based auth, PAM
Device Verify device health and compliance MDM, EDR, device trust, attestation
Network Segment and encrypt all traffic Microsegmentation, encryption, SDP
Application Secure app access and behavior App proxy, API security, CASB
Data Classify and protect data Classification, encryption, DLP, rights management

Conditional Access

Conditional Access is a key Zero Trust component. Example policies:

Policy 1: Require MFA for all users
IF: All users
    Accessing: All cloud apps
THEN: Require MFA

Policy 2: Block risky sign-ins
IF: All users
    Sign-in risk: High
THEN: Block access

Policy 3: Require compliant device for sensitive apps
IF: All users
    Accessing: Finance apps
    Device: Not compliant
THEN: Block access

Policy 4: Block legacy authentication
IF: All users
    Client apps: Legacy auth clients
THEN: Block access

SOC Implications

Zero Trust Detection Opportunities
  • More signals: Every access request generates logs
  • Identity focus: Monitor Conditional Access, sign-in logs closely
  • Device health: Alert on non-compliant devices accessing resources
  • Anomalies: Detect unusual access patterns with more context
  • Lateral movement: Microsegmentation makes this more detectable

Implementation Phases

  1. Phase 1: Strong identity (MFA, SSO, Conditional Access)
  2. Phase 2: Device compliance and health
  3. Phase 3: Network microsegmentation
  4. Phase 4: Application protection and visibility
  5. Phase 5: Data classification and protection
