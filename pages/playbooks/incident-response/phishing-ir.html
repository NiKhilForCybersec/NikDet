PB-IR-002

Phishing Incident Response

Response procedures when users click phishing links or submit credentials.

SeverityHIGH
TierL2/L3

Response by Interaction Level

User ActionRisk LevelResponse
Received only (no click)LowDelete email, no further action
Clicked link (no input)MediumCheck for drive-by download, scan endpoint
Submitted credentialsHighReset password, revoke sessions, monitor
Downloaded/executed fileCriticalIsolate endpoint, full investigation

Credential Submission Response

1
Reset Password Immediately

Force password change. Don't wait for user to do it.

2
Revoke All Sessions

Revoke-AzureADUserAllRefreshToken to kill active sessions.

3
Check for Mailbox Rules

Look for forwarding rules or inbox rules hiding emails.

4
Review Recent Activity

Check sign-in logs, email sent, files accessed since compromise.

5
Check OAuth Apps

Look for malicious app consent grants.

Campaign Response

  • Block sender: Add to block list
  • Block URLs: Add to proxy/DNS block
  • Delete from all mailboxes: Search and purge
  • Identify all recipients: Check who received
  • Identify all clickers: Check URL click logs
  • Notify affected users: Communication template

Remediation Commands

# Reset password
Set-AzureADUserPassword -ObjectId "user" -Password "TempP@ss" -ForceChangePasswordNextLogin $true

# Revoke sessions
Revoke-AzureADUserAllRefreshToken -ObjectId "user@domain.com"

# Check inbox rules
Get-InboxRule -Mailbox user@domain.com | Select Name, Enabled, ForwardTo, DeleteMessage

# Remove forwarding
Set-Mailbox user@domain.com -ForwardingAddress $null -ForwardingSmtpAddress $null

# Search and delete phishing email
New-ComplianceSearch -Name "PhishPurge" -ExchangeLocation All -ContentMatchQuery 'subject:"Phishing Subject"'
Start-ComplianceSearch -Identity "PhishPurge"
New-ComplianceSearchAction -SearchName "PhishPurge" -Purge -PurgeType SoftDelete
