KQL Fundamentals

Complete introduction to Kusto Query Language (KQL) for security analysts. Learn the syntax, operators, and patterns you will use every day.

What is KQL?

Kusto Query Language (KQL) is a read-only query language used to query large datasets in Azure services including Microsoft Sentinel, Azure Data Explorer, and Microsoft 365 Defender. As a security analyst, mastering KQL is essential for threat hunting, investigation, and detection engineering.

Why KQL Matters for Security
  • Query security logs across your entire environment
  • Build detection rules (Analytics Rules)
  • Perform threat hunting
  • Create dashboards and workbooks
  • Automate response with playbooks

Basic Query Structure

KQL queries follow a pipeline model where data flows through a series of operators:

Basic Structure
// Basic KQL query structure
TableName                           // 1. Start with a table
| where Condition                   // 2. Filter rows
| project Column1, Column2          // 3. Select columns
| order by Column1 desc            // 4. Sort results
| take 100                          // 5. Limit results

The where Operator

The where operator filters rows based on conditions. This is the most important operator for security queries.

where Examples
// Filter by time (ALWAYS start with time filter for performance)
SigninLogs
| where TimeGenerated > ago(24h)

// Filter by specific value (case-insensitive)
SigninLogs
| where UserPrincipalName =~ "user@company.com"

// Filter by multiple values
SecurityEvent
| where EventID in (4624, 4625, 4648)

// Filter with contains (partial match)
DeviceProcessEvents
| where ProcessCommandLine contains "powershell"

// Filter with has (word boundary match - faster)
DeviceProcessEvents
| where ProcessCommandLine has "encoded"

// Combine conditions with and/or
SigninLogs
| where TimeGenerated > ago(7d)
| where ResultType != "0" and IPAddress != ""

Performance Tip

Use has instead of contains when possible. has uses indexed word boundaries and is much faster on large datasets.

The project Operator

The project operator selects which columns to include in the output.

project Examples
// Select specific columns
SigninLogs
| where TimeGenerated > ago(24h)
| project TimeGenerated, UserPrincipalName, IPAddress, ResultType

// Rename columns
SigninLogs
| project Time = TimeGenerated, User = UserPrincipalName, IP = IPAddress

// Create calculated columns
SigninLogs
| project TimeGenerated, UserPrincipalName, 
    IsSuccess = (ResultType == "0")

// project-away removes columns (keep all others)
SigninLogs
| project-away TenantId, OperationName

The extend Operator

The extend operator adds new columns while keeping existing ones.

extend Examples
// Add a calculated column
SigninLogs
| where TimeGenerated > ago(24h)
| extend IsSuccess = (ResultType == "0")

// Extract nested JSON properties
SigninLogs
| extend 
    City = tostring(LocationDetails.city),
    Country = tostring(LocationDetails.countryOrRegion),
    OS = tostring(DeviceDetail.operatingSystem)

// String manipulation
SigninLogs
| extend Domain = tostring(split(UserPrincipalName, "@")[1])

The summarize Operator

The summarize operator aggregates data, similar to GROUP BY in SQL.

summarize Examples
// Count events
SigninLogs
| where TimeGenerated > ago(24h)
| summarize TotalSignins = count()

// Count by group
SigninLogs
| where TimeGenerated > ago(24h)
| summarize SigninCount = count() by UserPrincipalName
| order by SigninCount desc

// Multiple aggregations
SigninLogs
| where TimeGenerated > ago(7d)
| summarize 
    TotalAttempts = count(),
    SuccessCount = countif(ResultType == "0"),
    FailCount = countif(ResultType != "0"),
    UniqueIPs = dcount(IPAddress),
    Countries = make_set(tostring(LocationDetails.countryOrRegion))
    by UserPrincipalName

// Time-based aggregation (bin)
SigninLogs
| where TimeGenerated > ago(7d)
| summarize Count = count() by bin(TimeGenerated, 1h)
| render timechart

Time Functions

Working with time is critical for security queries. Always filter by time first for performance.

Time Examples
// Relative time with ago()
| where TimeGenerated > ago(24h)    // Last 24 hours
| where TimeGenerated > ago(7d)     // Last 7 days
| where TimeGenerated > ago(1h)     // Last hour

// Time range with between
| where TimeGenerated between (ago(7d) .. ago(1d))

// Specific datetime
| where TimeGenerated > datetime(2025-01-01)

// Extract time components
| extend Hour = hourofday(TimeGenerated)
| extend DayOfWeek = dayofweek(TimeGenerated)

// Time difference
| extend TimeSinceEvent = datetime_diff('minute', now(), TimeGenerated)

Practice Queries

Try these queries to practice the fundamentals:

Practice: Failed Sign-ins by User
// Find users with most failed sign-ins
SigninLogs
| where TimeGenerated > ago(7d)
| where ResultType != "0"
| summarize FailedAttempts = count() by UserPrincipalName
| where FailedAttempts > 10
| order by FailedAttempts desc
Practice: Sign-ins by Country
// Successful sign-ins by country
SigninLogs
| where TimeGenerated > ago(24h)
| where ResultType == "0"
| extend Country = tostring(LocationDetails.countryOrRegion)
| summarize Count = count(), Users = dcount(UserPrincipalName) by Country
| order by Count desc
