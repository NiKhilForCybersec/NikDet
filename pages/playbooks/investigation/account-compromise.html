PB-INV-003

Account Compromise Investigation Playbook

Complete investigation procedure for suspected or confirmed account compromise. Covers identity-based attacks, credential theft, session hijacking, and unauthorized access across cloud and on-premises environments.

SeverityCritical
TierL2 / L3
Time60-180 min
Last Updated2025-01-02
T1078 T1110 T1539 T1550 T1556 T1528 T1606 T1621

Overview

Account compromise is one of the most damaging attack vectors, providing attackers with legitimate credentials to move laterally, access sensitive data, and maintain persistence. This playbook provides a systematic approach to investigating compromised accounts in hybrid environments.

What This Playbook Covers
  • Cloud identity compromise (Azure AD/Entra ID, AWS IAM, GCP)
  • On-premises Active Directory compromise
  • Service account compromise
  • Privileged account compromise
  • Session hijacking and token theft
  • OAuth/consent phishing
  • MFA bypass attacks
  • Password spray and credential stuffing
  • Adversary-in-the-Middle (AiTM) attacks

Investigation Objectives

  1. Confirm Compromise - Is this account actually compromised or false positive?
  2. Determine Entry Point - How were credentials obtained?
  3. Assess Scope - What did the attacker access? Other accounts compromised?
  4. Identify Persistence - Did attacker establish backdoor access?
  5. Evaluate Data Impact - Was sensitive data accessed or exfiltrated?
  6. Enable Recovery - Secure the account and prevent re-compromise
  7. Extract IOCs - IPs, user agents, OAuth apps for blocking

Do NOT Use This Playbook For
  • Legitimate travel - User confirms they were actually traveling
  • VPN usage - User using corporate or personal VPN
  • Shared accounts - Known shared account with expected multi-location access
  • Service accounts with expected behavior - Automated processes from multiple locations
STOP - Escalate Immediately If
  • ✅ Global Admin or Privileged Role Administrator compromised
  • ✅ Domain Admin or Enterprise Admin compromised
  • ✅ Service account with broad permissions compromised
  • ✅ Multiple executives compromised simultaneously
  • ✅ Evidence of data exfiltration (large downloads, forwarding rules)
  • ✅ Attacker has modified authentication infrastructure
  • ✅ New federation trust or external identity provider added
  • ✅ Conditional Access policies modified or disabled

Escalation Path: SOC Lead → IR Team → CISO → Legal (if data breach)

Quickly assess the alert to determine if this is a true compromise requiring immediate action.

1.2
Check User's Normal Behavior
Compare suspicious activity to user's baseline:
// KQL - User's typical sign-in locations (last 30 days)
let targetUser = "user@domain.com";
SigninLogs
| where TimeGenerated > ago(30d)
| where UserPrincipalName =~ targetUser
| where ResultType == 0 // Successful only
| summarize SignInCount=count(), 
    FirstSeen=min(TimeGenerated),
    LastSeen=max(TimeGenerated)
    by Location, IPAddress
| order by SignInCount desc

// KQL - User's typical devices and browsers
SigninLogs
| where TimeGenerated > ago(30d)
| where UserPrincipalName =~ targetUser
| where ResultType == 0
| extend DeviceOS = tostring(DeviceDetail.operatingSystem)
| extend Browser = tostring(DeviceDetail.browser)
| summarize Count=count() by DeviceOS, Browser
| order by Count desc

// KQL - User's typical applications
SigninLogs
| where TimeGenerated > ago(30d)
| where UserPrincipalName =~ targetUser
| where ResultType == 0
| summarize Count=count() by AppDisplayName
| order by Count desc

Step 2: Sign-In Analysis (20 Minutes)

Deep dive into authentication events to understand the full scope of the compromise.

2.1
Analyze All Recent Sign-Ins
// KQL - Comprehensive sign-in analysis
let targetUser = "user@domain.com";
let investigationWindow = 7d; // Adjust as needed
SigninLogs
| where TimeGenerated > ago(investigationWindow)
| where UserPrincipalName =~ targetUser
| extend DeviceOS = tostring(DeviceDetail.operatingSystem)
| extend Browser = tostring(DeviceDetail.browser)
| extend DeviceTrust = tostring(DeviceDetail.trustType)
| extend City = tostring(LocationDetails.city)
| extend Country = tostring(LocationDetails.countryOrRegion)
| project TimeGenerated, 
    ResultType,
    ResultDescription,
    IPAddress,
    Location,
    City,
    Country,
    AppDisplayName,
    ClientAppUsed,
    DeviceOS,
    Browser,
    DeviceTrust,
    ConditionalAccessStatus,
    AuthenticationRequirement,
    MfaDetail=tostring(MfaDetail.authMethod),
    RiskLevelDuringSignIn,
    RiskState,
    CorrelationId
| order by TimeGenerated desc
2.2
Identify the Initial Compromise
Find the first suspicious sign-in to establish the compromise timeline:
// KQL - Find first sign-in from suspicious IPs
let targetUser = "user@domain.com";
let suspiciousIPs = dynamic(["IP1", "IP2"]); // Add suspicious IPs
SigninLogs
| where UserPrincipalName =~ targetUser
| where IPAddress in (suspiciousIPs)
| where ResultType == 0
| summarize FirstCompromisedAccess=min(TimeGenerated),
    AccessCount=count(),
    AppsAccessed=make_set(AppDisplayName)
| extend CompromiseDuration = now() - FirstCompromisedAccess

// KQL - Sign-ins just before compromise (find attack vector)
let targetUser = "user@domain.com";
let compromiseTime = datetime(2025-01-02T12:00:00Z);
SigninLogs
| where UserPrincipalName =~ targetUser
| where TimeGenerated between ((compromiseTime - 1h) .. compromiseTime)
| project TimeGenerated, IPAddress, Location, AppDisplayName,
    ResultType, ResultDescription, UserAgent
| order by TimeGenerated asc
2.3
Analyze Authentication Methods
Understand how the attacker authenticated:
Auth MethodAttack VectorInvestigation Focus
Password only (no MFA)Credential theft, password sprayCheck for phishing, credential dumps
MFA - Phone callSIM swap, call forwardingCheck phone number changes
MFA - SMSSIM swap, SS7 attackCheck phone number changes
MFA - Push notificationMFA fatigue, social engineeringCheck for repeated prompts
MFA - TOTPToken theft, AiTMCheck for proxy indicators
FIDO2/PasskeyToken theft post-authCheck for token replay
Primary Refresh TokenPRT theft from deviceCheck device compromise
No MFA requiredLegacy auth, CA bypassCheck Conditional Access gaps
 
// KQL - MFA analysis for user
let targetUser = "user@domain.com";
SigninLogs
| where UserPrincipalName =~ targetUser
| where TimeGenerated > ago(7d)
| where ResultType == 0
| extend MFAMethod = tostring(MfaDetail.authMethod)
| extend MFAResult = tostring(MfaDetail.authDetail)
| summarize Count=count() by MFAMethod, AuthenticationRequirement
| order by Count desc

// KQL - Find MFA fatigue attempts
SigninLogs
| where UserPrincipalName =~ targetUser
| where TimeGenerated > ago(24h)
| where ResultType == 50074 // MFA required but not completed
| summarize MFAPrompts=count() by bin(TimeGenerated, 5m), IPAddress
| where MFAPrompts > 3 // Multiple prompts in short window
| order by TimeGenerated desc
2.4
Check for AiTM/Proxy Indicators
Adversary-in-the-Middle attacks intercept credentials and tokens:
// KQL - Indicators of AiTM attack
let targetUser = "user@domain.com";
SigninLogs
| where UserPrincipalName =~ targetUser
| where TimeGenerated > ago(7d)
| where ResultType == 0
| extend SessionId = tostring(AuthenticationDetails[0].authenticationStepResultDetail)
| project TimeGenerated, IPAddress, Location, UserAgent,
    SessionId, AuthenticationProcessingDetails
| join kind=inner (
    SigninLogs
    | where UserPrincipalName =~ targetUser
    | where TimeGenerated > ago(7d)
    | where ResultType == 0
    | project TimeGenerated, IPAddress, SessionId
) on SessionId
| where IPAddress != IPAddress1 // Same session, different IPs = proxy
| project TimeGenerated, OriginalIP=IPAddress, ProxyIP=IPAddress1

// Check for known AiTM infrastructure user agents
SigninLogs
| where UserPrincipalName =~ targetUser
| where UserAgent has_any ("python", "curl", "Go-http-client", 
    "axios", "node-fetch", "evilginx")
| project TimeGenerated, IPAddress, UserAgent, AppDisplayName
2.5
Check Non-Interactive Sign-Ins
Token refreshes can reveal ongoing attacker access:
// KQL - Non-interactive sign-ins (token usage)
let targetUser = "user@domain.com";
let suspiciousIPs = dynamic(["IP1", "IP2"]);
AADNonInteractiveUserSignInLogs
| where UserPrincipalName =~ targetUser
| where TimeGenerated > ago(7d)
| where IPAddress in (suspiciousIPs)
| project TimeGenerated, IPAddress, AppDisplayName, 
    ResourceDisplayName, ClientAppUsed
| summarize TokenUsage=count(), 
    Apps=make_set(AppDisplayName),
    Resources=make_set(ResourceDisplayName)
    by IPAddress, bin(TimeGenerated, 1h)
| order by TimeGenerated desc

Step 3: Activity Analysis (30 Minutes)

Determine what the attacker did after gaining access.

3.1
Check Email Activity
// KQL - Check for malicious inbox rules
let targetUser = "user@domain.com";
OfficeActivity
| where UserId =~ targetUser
| where Operation in ("New-InboxRule", "Set-InboxRule", "Enable-InboxRule")
| project TimeGenerated, Operation, Parameters=tostring(Parameters),
    ClientIP
| extend RuleDetails = parse_json(Parameters)

// KQL - Check for email forwarding
OfficeActivity
| where UserId =~ targetUser
| where Operation == "Set-Mailbox"
| where Parameters has "ForwardingSmtpAddress" or 
    Parameters has "ForwardingAddress"
| project TimeGenerated, Parameters, ClientIP

// KQL - Emails sent by compromised account
EmailEvents
| where SenderFromAddress =~ targetUser
| where TimeGenerated > ago(7d)
| project TimeGenerated, Subject, RecipientEmailAddress,
    SenderIPv4, EmailDirection
| summarize EmailsSent=count(), 
    Recipients=make_set(RecipientEmailAddress)
    by bin(TimeGenerated, 1h)
| order by TimeGenerated desc

// KQL - Check for mass email access
CloudAppEvents
| where AccountId =~ targetUser
| where ActionType == "MailItemsAccessed"
| where TimeGenerated > ago(7d)
| summarize ItemsAccessed=count() by bin(TimeGenerated, 1h), IPAddress
| where ItemsAccessed > 100 // Unusual volume
| order by TimeGenerated desc
3.2
Check File Access (SharePoint/OneDrive)
// KQL - File downloads by user
let targetUser = "user@domain.com";
OfficeActivity
| where UserId =~ targetUser
| where Operation in ("FileDownloaded", "FileSyncDownloadedFull")
| where TimeGenerated > ago(7d)
| project TimeGenerated, Operation, SourceFileName, 
    Site_Url, ClientIP
| summarize FilesDownloaded=count(),
    Files=make_set(SourceFileName)
    by bin(TimeGenerated, 1h), ClientIP
| order by TimeGenerated desc

// KQL - Bulk file access (potential exfiltration)
OfficeActivity
| where UserId =~ targetUser
| where Operation in ("FileDownloaded", "FileAccessed", "FileModified")
| where TimeGenerated > ago(7d)
| summarize FileActions=count() by bin(TimeGenerated, 15m), ClientIP
| where FileActions > 50 // High volume in short time
| order by TimeGenerated desc

// KQL - Sensitive file access
OfficeActivity
| where UserId =~ targetUser
| where Operation == "FileDownloaded"
| where SourceFileName has_any ("confidential", "password", 
    "secret", "financial", "salary", "ssn", "pii", "budget")
| project TimeGenerated, SourceFileName, Site_Url, ClientIP
3.3
Check Azure AD/Entra ID Changes
// KQL - Directory changes by user
let targetUser = "user@domain.com";
AuditLogs
| where InitiatedBy.user.userPrincipalName =~ targetUser
| where TimeGenerated > ago(7d)
| project TimeGenerated, OperationName, Result,
    TargetResources, Category
| order by TimeGenerated desc

// KQL - Critical changes (privilege escalation, persistence)
AuditLogs
| where InitiatedBy.user.userPrincipalName =~ targetUser
| where OperationName in (
    "Add member to role",
    "Add owner to application", 
    "Add owner to service principal",
    "Add app role assignment to service principal",
    "Add delegated permission grant",
    "Consent to application",
    "Add service principal credentials",
    "Update application – Certificates and secrets management"
)
| project TimeGenerated, OperationName, 
    Target=tostring(TargetResources[0].displayName),
    Result

// KQL - OAuth app consents
AuditLogs
| where OperationName == "Consent to application"
| where InitiatedBy.user.userPrincipalName =~ targetUser
| extend AppName = tostring(TargetResources[0].displayName)
| extend Permissions = tostring(TargetResources[0].modifiedProperties)
| project TimeGenerated, AppName, Permissions
3.4
Check for OAuth/Consent Grant Abuse
Attackers often register malicious OAuth apps for persistence:
// KQL - All OAuth apps user consented to
let targetUser = "user@domain.com";
AuditLogs
| where OperationName == "Consent to application"
| where InitiatedBy.user.userPrincipalName =~ targetUser
| extend AppName = tostring(TargetResources[0].displayName)
| extend AppId = tostring(TargetResources[0].id)
| project TimeGenerated, AppName, AppId, Result

// KQL - Check for high-risk permissions
AuditLogs
| where OperationName == "Consent to application"
| where TargetResources[0].modifiedProperties has_any (
    "Mail.Read", "Mail.ReadWrite", "Mail.Send",
    "Files.Read.All", "Files.ReadWrite.All",
    "User.Read.All", "Directory.Read.All",
    "full_access_as_user"
)
| project TimeGenerated, 
    AppName=tostring(TargetResources[0].displayName),
    Permissions=tostring(TargetResources[0].modifiedProperties),
    User=tostring(InitiatedBy.user.userPrincipalName)
High-Risk OAuth Permissions
  • Mail.ReadWrite - Read and modify all mail
  • Mail.Send - Send mail as user
  • Files.ReadWrite.All - Access all files
  • Directory.ReadWrite.All - Modify directory
  • Application.ReadWrite.All - Modify apps
  • full_access_as_user - Exchange full access

Step 4: Scope Assessment (15 Minutes)

Determine if other accounts or systems were affected.

4.1
Check for Lateral Movement to Other Accounts
// KQL - Other accounts from same attacker IP
let attackerIPs = dynamic(["IP1", "IP2"]);
SigninLogs
| where TimeGenerated > ago(7d)
| where IPAddress in (attackerIPs)
| where ResultType == 0
| summarize Users=make_set(UserPrincipalName),
    UserCount=dcount(UserPrincipalName),
    SignInCount=count()
    by IPAddress
| where UserCount > 1 // Multiple accounts from same IP

// KQL - Check for password spray across org
SigninLogs
| where TimeGenerated > ago(24h)
| where ResultType in (50126, 50053, 50055) // Invalid password codes
| summarize FailedAttempts=count(),
    UsersTargeted=dcount(UserPrincipalName),
    Users=make_set(UserPrincipalName, 20)
    by IPAddress
| where UsersTargeted > 10 // Many users targeted
| order by UsersTargeted desc
4.2
Check for Internal Phishing
// KQL - Emails sent from compromised account
let targetUser = "user@domain.com";
let compromiseTime = datetime(2025-01-02T12:00:00Z);
EmailEvents
| where TimeGenerated > compromiseTime
| where SenderFromAddress =~ targetUser
| where EmailDirection == "Outbound"
| project TimeGenerated, Subject, RecipientEmailAddress,
    UrlCount, AttachmentCount
| summarize EmailCount=count(),
    Recipients=make_set(RecipientEmailAddress, 50),
    Subjects=make_set(Subject, 20)

// KQL - Check if recipients clicked links in these emails
let compromisedSender = "user@domain.com";
UrlClickEvents
| where TimeGenerated > ago(7d)
| where NetworkMessageId in (
    EmailEvents
    | where SenderFromAddress =~ compromisedSender
    | project NetworkMessageId
)
| project TimeGenerated, AccountUpn, Url, ActionType, UrlChain

Step 5: Containment (Immediate)

Once compromise is confirmed, take immediate containment actions.

5.1
Revoke Sessions and Reset Credentials
# PowerShell - Revoke all refresh tokens
Connect-MgGraph -Scopes "User.ReadWrite.All"
Revoke-MgUserSignInSession -UserId "user@domain.com"

# PowerShell - Force password reset
$newPassword = [System.Web.Security.Membership]::GeneratePassword(16, 4)
Update-MgUser -UserId "user@domain.com" `
    -PasswordProfile @{
        Password = $newPassword
        ForceChangePasswordNextSignIn = $true
    }

# PowerShell - Disable account (if severe)
Update-MgUser -UserId "user@domain.com" -AccountEnabled:$false

# Azure Portal steps:
# 1. Azure AD > Users > Select user > Revoke sessions
# 2. Reset password
# 3. Require MFA re-registration if MFA compromised
5.2
Remove Malicious Persistence
# PowerShell - Remove malicious inbox rules
Connect-ExchangeOnline
Get-InboxRule -Mailbox "user@domain.com" | 
    Where-Object {$_.ForwardTo -or $_.ForwardAsAttachmentTo -or 
        $_.RedirectTo -or $_.DeleteMessage} |
    Remove-InboxRule -Confirm:$false

# PowerShell - Remove email forwarding
Set-Mailbox -Identity "user@domain.com" `
    -ForwardingSmtpAddress $null `
    -ForwardingAddress $null `
    -DeliverToMailboxAndForward $false

# PowerShell - Revoke OAuth app consents
# In Azure AD > Enterprise applications > 
# Find app > Properties > Delete

# PowerShell - Remove MFA methods if compromised
# Azure AD > Users > User > Authentication methods > 
# Remove suspicious methods
5.3
Block Attacker Infrastructure
  • IPs: Block in Conditional Access named locations, firewall
  • Domains: Block in email gateway, web proxy
  • OAuth Apps: Block app IDs in Azure AD
  • User Agents: Block in Conditional Access (if distinctive)
