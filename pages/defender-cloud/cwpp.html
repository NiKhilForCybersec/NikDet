Defender for Servers

  • ✅ Microsoft Defender for Endpoint integration
  • ✅ Security alerts

  • ✅ Regulatory compliance
  • ❌ No vulnerability assessment
  • ❌ No JIT VM access

  • ✅ Everything in Plan 1

Enable Defender for Servers

# Azure CLI
az security pricing create --name VirtualMachines --tier Standard --subplan P2

# PowerShell
Set-AzSecurityPricing -Name "VirtualMachines" -PricingTier "Standard" -SubPlan "P2"

# Check current plan
az security pricing show --name VirtualMachines

Just-In-Time (JIT) VM Access

JIT closes management ports (RDP/SSH) by default and opens them on-demand.

Enable JIT on a VM

  1. Go to Defender for Cloud → Workload protections
  2. Click Just-in-time VM access
  3. Select Not configured tab
  4. Select VM(s) and click Enable JIT on VM
  5. Configure ports (default: 22, 3389, 5985, 5986)
  6. Set max request time (e.g., 3 hours)

Request JIT Access

  1. Go to Virtual Machine → Connect
  2. Click Request access
  3. Select ports and duration
  4. Add justification
  5. Click Open port
# Request JIT via PowerShell
$JitPolicy = @{
    id = "/subscriptions/{sub}/resourceGroups/{rg}/providers/Microsoft.Compute/virtualMachines/{vm}"
    ports = @{
        number = 3389
        endTimeUtc = (Get-Date).AddHours(3).ToUniversalTime().ToString("yyyy-MM-ddTHH:mm:ssZ")
        allowedSourceAddressPrefix = @("*")
    }
}
Start-AzJitNetworkAccessPolicy -ResourceGroupName "Security" -Name "default" -VirtualMachine $JitPolicy

# Azure CLI
az security jit-policy initiate --resource-group "rg" --name "default" \
    --virtual-machines '[{"id":"/subscriptions/.../vm","ports":[{"number":3389,"duration":"PT3H"}]}]'

File Integrity Monitoring (FIM)

Tracks changes to critical system files, registry keys, and configurations.

Enable FIM

  1. Go to Defender for Cloud → Workload protections
  2. Click File Integrity Monitoring
  3. Select workspace
  4. Click Enable
  5. Configure monitored paths (Windows registry, Linux files)

Defender for Containers

Capabilities

FeatureDescription
Runtime protectionThreat detection for running containers
Image scanningVulnerability scanning in ACR, ECR, GCR
Policy enforcementBlock vulnerable images from deploying
Kubernetes hardeningSecurity recommendations for K8s config

Supported Platforms

  • Azure: AKS, ACR
  • AWS: EKS, ECR
  • GCP: GKE, GCR
  • On-premises: Azure Arc-enabled Kubernetes
# Enable Defender for Containers
az security pricing create --name Containers --tier Standard

# View container recommendations
az security assessment list --query "[?contains(name,'container')]"

# Scan image in ACR
az acr task create --registry myregistry --name scanOnPush \
    --image-names myimage:latest --file Dockerfile \
    --context https://github.com/... --platform linux

Container Alerts Examples

  • Container running with high privileges
  • Crypto mining activity detected
  • SSH server running in container
  • New container in kube-system namespace
  • Container with sensitive mount

# Enable vulnerability assessment on SQL server
az sql server va enable --server-name myserver --resource-group rg \

Defender for Storage

Capabilities

  • Malware scanning - Scan uploaded blobs for malware
  • Sensitive data discovery - Find PII, credentials, secrets
  • Activity monitoring - Detect unusual access patterns

Alerts Examples

  • Access from Tor exit node
  • Access from unusual location
  • Unusual amount of data extracted
  • Malware uploaded to storage
  • Unusual access pattern
# Enable Defender for Storage (with malware scanning)
az security pricing create --name StorageAccounts --tier Standard \
    --extension name=OnUploadMalwareScanning isEnabled=true

# Check scanned blobs
az storage blob list --account-name mystorageaccount --container-name mycontainer \
    --query "[?tags.malwareScanResult!=null]"

Alert Investigation

Investigate an Alert

  1. Go to Defender for Cloud → Security alerts
  2. Click on alert to see details
  3. Review: Description, affected resource, attack chain
  4. Check Related entities for context
  5. Click Take action for remediation steps
  6. Update status: Active → In Progress → Resolved

Send Alerts to SIEM

# Stream to Sentinel
az security automation create --name "ExportToSentinel" \
    --resource-group "Security" \
    --scopes "/subscriptions/{subscription-id}" \
    --sources AlertsEventTypes \
    --actions actionType=LogicApp logicAppResourceId="/subscriptions/.../logicapp"

# Stream to Event Hub (for Splunk, etc.)
az security automation create --name "ExportToEventHub" \
    --resource-group "Security" \
    --scopes "/subscriptions/{subscription-id}" \
    --sources AlertsEventTypes \
    --actions actionType=EventHub eventHubResourceId="/subscriptions/.../eventhub"

Best Practices

  • Enable Defender for Servers P2 for full protection including JIT and vulnerability assessment
  • Use JIT for all management access - Never leave RDP/SSH open
  • Enable malware scanning for Storage - Especially user-facing uploads
  • Integrate alerts with Sentinel - For correlation and automation
  • Review alerts daily - High severity alerts need immediate attention
  • Tune noisy alerts - Create suppression rules for false positives
