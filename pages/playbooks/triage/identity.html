PB-TRI-007

Identity Alert Triage

Procedures for triaging identity-related alerts including risky users, privilege escalation, and account changes.

Common Identity Alert Types

Alert TypeSeverityTypical Cause
Risky User DetectedMedium-HighAzure AD Identity Protection risk signals
Privilege EscalationHighUser added to privileged group
Service Account AnomalyMedium-HighUnusual service account behavior
Account CreatedMediumNew user account creation
Password ResetMediumAdmin or self-service reset
MFA Method ChangedHighNew authenticator registered

Step 1: Initial Assessment

QuestionWhere to Look
What changed?Account created, modified, or privileged
Who made the change?Admin user, service account, or unknown
Was it authorized?Change request, expected process
What's the impact?What access was granted?

Step 2: Context Queries

// Get user risk details (Azure AD)
AADRiskyUsers
| where UserPrincipalName == "user@company.com"
| project TimeGenerated, RiskLevel, RiskDetail, RiskState

// Recent privilege changes
AuditLogs
| where TimeGenerated > ago(24h)
| where OperationName has_any ("Add member", "role", "group")
| project TimeGenerated, OperationName, InitiatedBy.user.userPrincipalName, TargetResources

// MFA registration changes
AuditLogs
| where TimeGenerated > ago(7d)
| where OperationName has_any ("User registered", "authentication method")
| project TimeGenerated, OperationName, InitiatedBy.user.userPrincipalName, TargetResources

Step 3: Decision Tree

QuestionIf YESIf NO
Was this an authorized change?Verify with ticket → CloseContinue investigation
Does user/admin have authority?May be policy violation if no ticketUnauthorized → Escalate
Does it grant sensitive access?Admin/sensitive groups → Verify immediatelyLower priority

High-Risk Identity Events

EventRiskAction
User added to Domain AdminsFull domain controlImmediate verification
MFA method added by unknownPersistence mechanismVerify with user
Service account interactive loginNot normal behaviorCheck if compromised
Password reset + new MFAAccount takeover patternVerify with user
Admin account from new locationPotential compromiseVerify legitimacy

Sensitive Groups to Monitor

  • Domain Admins / Enterprise Admins
  • Schema Admins / Account Operators
  • Global Administrators (Azure AD)
  • Exchange Admins / SharePoint Admins
  • Security Administrators
  • Any custom admin groups

Escalation Criteria

  • Unauthorized addition to privileged groups
  • MFA manipulation on high-value account
  • Service account abuse or interactive login
  • Account creation outside HR process
  • Multiple identity events for same user in short time
  • Admin activity from unexpected location
