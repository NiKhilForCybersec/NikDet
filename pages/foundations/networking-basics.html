Networking Basics - Visual Guide

As a SOC analyst, you'll analyze network traffic every day. This guide visualizes core networking concepts and shows exactly why they matter for security.

Why Networking Knowledge is Essential

WHAT YOU'LL ANALYZE DAILY AS A SOC ANALYST ═══════════════════════════════════════════════════════════════════════════════ Firewall Log: src_ip=10.50.100.42 dst_ip=185.220.101.34 dst_port=443 action=ALLOW Questions you need to answer IMMEDIATELY: ───────────────────────────────────────────────────────────────────────────── • 10.50.100.42 - Is this internal or external? (Internal - private range) • 185.220.101.34 - Is this internal or external? (External - public IP) • Port 443 - What service? (HTTPS - encrypted web) • What does this mean? (Internal host connecting to external server) • Is this suspicious? (Depends on context!) Without networking knowledge: "I don't know what any of this means" With networking knowledge: "Internal workstation making HTTPS connection to external server - let me check if that IP is malicious" DNS Log: query=evil-domain.com type=A response=185.220.101.34 Questions: • What's an A record? (Domain → IP address mapping) • Why would malware use DNS? (C2 communication, data exfil) • What's suspicious here? (Unknown domain resolving to suspicious IP) Network Alert: "SYN flood detected from 203.0.113.50 targeting 10.1.1.100:80" Questions: • What's a SYN flood? (TCP handshake abuse - denial of service) • Why is this bad? (Overwhelming the server) • What's the attacker's goal? (Take the service offline)

The OSI Model - How Networks Are Built

Network communication happens in layers. Each layer does one job and talks to the layers above and below it.

THE OSI MODEL - VISUALIZED ═══════════════════════════════════════════════════════════════════════════════ Think of it like sending a letter: YOU WRITE A LETTER │ ▼ ┌─────────────────────────────────────────────────────────────────────────────┐ │ LAYER 7 - APPLICATION │ │ "What do you want to say?" │ │ │ │ This is where you interact. Web browsers, email, file transfers. │ │ Protocols: HTTP, HTTPS, DNS, SMTP, FTP, SSH │ │ │ │ Security: Application attacks, malware C2, data exfiltration │ └─────────────────────────────────────────────────────────────────────────────┘ │ ▼ ┌─────────────────────────────────────────────────────────────────────────────┐ │ LAYER 6 - PRESENTATION │ │ "How should the data look?" │ │ │ │ Formats data, handles encryption. Think: translator. │ │ Functions: SSL/TLS encryption, compression, encoding │ │ │ │ Security: SSL/TLS attacks, certificate issues │ └─────────────────────────────────────────────────────────────────────────────┘ │ ▼ ┌─────────────────────────────────────────────────────────────────────────────┐ │ LAYER 5 - SESSION │ │ "Keep the conversation going" │ │ │ │ Manages connections between applications. Start, maintain, end. │ │ Functions: Session establishment, synchronization │ │ │ │ Security: Session hijacking, token theft │ └─────────────────────────────────────────────────────────────────────────────┘ │ ▼ ┌─────────────────────────────────────────────────────────────────────────────┐ │ LAYER 4 - TRANSPORT │ │ "Make sure it gets there correctly" │ │ │ │ Reliable delivery (TCP) or fast delivery (UDP). Ports live here. │ │ Protocols: TCP (reliable), UDP (fast) │ │ │ │ Security: Port scanning, SYN floods, service enumeration │ └─────────────────────────────────────────────────────────────────────────────┘ │ ▼ ┌─────────────────────────────────────────────────────────────────────────────┐ │ LAYER 3 - NETWORK │ │ "Find the best route" │ │ │ │ Routing between networks. IP addresses live here. │ │ Protocols: IP, ICMP (ping), routing protocols │ │ │ │ Security: IP spoofing, ICMP attacks, routing manipulation │ └─────────────────────────────────────────────────────────────────────────────┘ │ ▼ ┌─────────────────────────────────────────────────────────────────────────────┐ │ LAYER 2 - DATA LINK │ │ "Talk to neighbors" │ │ │ │ Communication within local network. MAC addresses live here. │ │ Protocols: Ethernet, Wi-Fi, ARP │ │ │ │ Security: ARP spoofing, MAC flooding, VLAN hopping │ └─────────────────────────────────────────────────────────────────────────────┘ │ ▼ ┌─────────────────────────────────────────────────────────────────────────────┐ │ LAYER 1 - PHYSICAL │ │ "The actual wires and signals" │ │ │ │ Cables, wireless signals, electrical/optical transmission. │ │ Components: Cables, hubs, wireless signals │ │ │ │ Security: Physical access, wiretapping, jamming │ └─────────────────────────────────────────────────────────────────────────────┘ MEMORY TRICK: "Please Do Not Throw Sausage Pizza Away" Physical → Data Link → Network → Transport → Session → Presentation → Application

🏠 Analogy: The Postal System

  • Layer 7 (Application): You write the letter content
  • Layer 6 (Presentation): You translate it if needed
  • Layer 5 (Session): The ongoing correspondence
  • Layer 4 (Transport): Registered mail vs regular (reliable vs fast)
  • Layer 3 (Network): The address on the envelope (routing)
  • Layer 2 (Data Link): The local mail carrier
  • Layer 1 (Physical): The mail truck and roads

Ports - The Application Addresses

HOW PORTS WORK ═══════════════════════════════════════════════════════════════════════════════ IP address = which computer Port = which application on that computer Think of it like an apartment building: IP Address: 192.168.1.100 = The building address Port: 443 = Apartment number SERVER: 192.168.1.100 ┌────────────────────────────────────────────────────────────────────────────┐ │ │ │ Port 22 ──► SSH Service "Knock on door 22 for remote access" │ │ Port 80 ──► Web Server (HTTP) "Knock on door 80 for website" │ │ Port 443 ──► Web Server (HTTPS) "Knock on door 443 for secure website"│ │ Port 3389 ──► RDP Service "Knock on door 3389 for remote desktop"│ │ │ └────────────────────────────────────────────────────────────────────────────┘ When you see: 192.168.1.100:443 └─── IP ───┘ └port PORT RANGES: ──────────────────────────────────────────────────────────────────────────────── 0 - 1023 Well-known ports Reserved for common services 1024 - 49151 Registered ports Assigned to specific applications 49152 - 65535 Dynamic/Private Temporary connections (ephemeral)

Critical Ports for SOC Analysts

PORTS YOU MUST KNOW ═══════════════════════════════════════════════════════════════════════════════ FILE TRANSFER & REMOTE ACCESS: ──────────────────────────────────────────────────────────────────────────────── Port 20,21 FTP File Transfer (UNENCRYPTED - legacy, risky) Port 22 SSH Secure Shell (encrypted remote access, file transfer) Port 23 Telnet Remote access (UNENCRYPTED - NEVER use!) Port 3389 RDP Remote Desktop Protocol (Windows remote access) 🔴 Security note: SSH and RDP are brute force targets! Alert on: Failed login attempts to these ports WEB: ──────────────────────────────────────────────────────────────────────────────── Port 80 HTTP Web traffic (unencrypted) Port 443 HTTPS Web traffic (encrypted) Port 8080 HTTP-Alt Alternative web (often proxies, development) Port 8443 HTTPS-Alt Alternative HTTPS 🔴 Security note: Most C2 traffic uses 80/443 to blend in! Alert on: Beaconing patterns, connections to suspicious domains EMAIL: ──────────────────────────────────────────────────────────────────────────────── Port 25 SMTP Send email (server to server) Port 587 SMTP Send email (client to server, modern) Port 110 POP3 Receive email (download and delete) Port 143 IMAP Receive email (synchronized) Port 993 IMAPS IMAP over SSL Port 995 POP3S POP3 over SSL 🔴 Security note: Port 25 outbound from workstations = suspicious Normal users use 587, not 25 WINDOWS/ACTIVE DIRECTORY: ──────────────────────────────────────────────────────────────────────────────── Port 53 DNS Domain name resolution Port 88 Kerberos Windows authentication Port 135 RPC Remote Procedure Call Port 137-139 NetBIOS Windows networking (legacy) Port 389 LDAP Directory services (Active Directory) Port 445 SMB File shares, lateral movement risk! Port 636 LDAPS LDAP over SSL Port 3268 GC Global Catalog (AD) 🔴 Security note: - SMB (445) = EternalBlue, lateral movement - Kerberos (88) = Kerberoasting, Golden Ticket - LDAP (389) = AD enumeration DATABASE: ──────────────────────────────────────────────────────────────────────────────── Port 1433 MSSQL Microsoft SQL Server Port 1521 Oracle Oracle Database Port 3306 MySQL MySQL Database Port 5432 PostgreSQL PostgreSQL Database Port 27017 MongoDB MongoDB 🔴 Security note: Databases should NEVER be exposed to internet Alert on: External IPs connecting to database ports

🔒 Port Security Rules of Thumb

  • Workstation → Port 445 → Another Workstation: Suspicious! Lateral movement.
  • External → Any internal port except 443: Why? Should be blocked by firewall.
  • Internal → External Port 22, 3389: Someone remoting OUT. Legitimate or C2?
  • High port numbers (>10000) as destinations: Often C2 trying to evade detection.

TCP vs UDP - Two Ways to Talk

TCP vs UDP - THE KEY DIFFERENCE ═══════════════════════════════════════════════════════════════════════════════ TCP (Transmission Control Protocol) - "Reliable Phone Call" ──────────────────────────────────────────────────────────────────────────────── Before sending data, TCP establishes a connection (the "3-way handshake"): CLIENT SERVER │ │ │ ─────── SYN ──────────────────────► │ "Can we talk?" │ │ │ ◄────── SYN-ACK ─────────────────── │ "Yes, I'm ready" │ │ │ ─────── ACK ──────────────────────► │ "Great, let's go" │ │ │ ═══════ DATA ═════════════════════► │ Now data flows │ ◄═════════════════════════════════ │ │ │ Features: ✓ Guaranteed delivery (retransmits lost packets) ✓ Ordered (packets arrive in sequence) ✓ Error checking ✗ Slower (overhead from acknowledgments) Used for: Web (HTTP/HTTPS), Email, File Transfer, SSH "I need to make sure you got everything correctly" UDP (User Datagram Protocol) - "Fast Shouting" ──────────────────────────────────────────────────────────────────────────────── No connection - just send and hope: CLIENT SERVER │ │ │ ─────── DATA ─────────────────────► │ "Here's data!" │ ─────── DATA ─────────────────────► │ "More data!" │ ─────── DATA ─────────────────────► │ "Even more!" │ │ │ (No response needed, no checking) │ Features: ✓ Fast (no handshake, no waiting) ✓ Low overhead ✗ No guarantee of delivery ✗ No order guarantee Used for: DNS, Video streaming, VoIP, Gaming "Speed matters more than perfection" SECURITY IMPLICATIONS: ═══════════════════════════════════════════════════════════════════════════════ TCP SYN FLOOD ATTACK: ──────────────────────────────────────────────────────────────────────────────── Attacker sends thousands of SYN packets but never completes handshake: ATTACKER TARGET │ │ │ ─────── SYN ──────────────────────► │ Server allocates memory │ ─────── SYN ──────────────────────► │ Server allocates memory │ ─────── SYN ──────────────────────► │ Server allocates memory │ ─────── SYN ──────────────────────► │ Server allocates memory │ ...thousands more... │ │ │ Server runs out of memory! │ │ DENIAL OF SERVICE Detection: Many half-open connections from same source UDP AMPLIFICATION ATTACK: ──────────────────────────────────────────────────────────────────────────────── Attacker spoofs victim's IP, asks servers for large responses: ATTACKER DNS SERVER VICTIM │ │ │ │ "Send big response │ │ │ to VICTIM's IP" │ │ │ ───────────────────► │ │ │ │ HUGE RESPONSE │ │ │ ─────────────────► │ Overwhelmed! Small request → Large response → Multiply effect × thousands of servers Detection: Large UDP responses to hosts that didn't request them

DNS - The Internet's Phone Book

HOW DNS WORKS ═══════════════════════════════════════════════════════════════════════════════ You type: www.google.com Your computer needs: 142.250.80.46 (the IP address) How it gets resolved: YOUR COMPUTER DNS SERVERS │ │ │ "What's the IP for www.google.com?" │ │ ──────────────────────────────────────► │ Local DNS (ISP) │ │ │ (If not cached, asks root servers) │ │ │ │ ◄────────────────────────────────────── │ │ "It's 142.250.80.46" │ │ │ │ Now your browser connects to that IP │ DNS RECORD TYPES (You'll see these in logs): ═══════════════════════════════════════════════════════════════════════════════ TYPE MEANING EXAMPLE ──────────────────────────────────────────────────────────────────────────────── A Domain → IPv4 google.com → 142.250.80.46 AAAA Domain → IPv6 google.com → 2607:f8b0:4004:800::200e CNAME Alias to another name www.google.com → google.com MX Mail server google.com mail → smtp.google.com TXT Text record SPF, DKIM, verification strings NS Name server Who handles DNS for this domain PTR Reverse lookup 142.250.80.46 → google.com WHY DNS IS CRITICAL FOR SECURITY: ═══════════════════════════════════════════════════════════════════════════════ MALWARE USES DNS FOR: ──────────────────────────────────────────────────────────────────────────────── 1. COMMAND & CONTROL Malware queries: evil-c2-server.com Gets back: IP of current C2 server Detection: Queries to suspicious/newly-registered domains 2. DOMAIN GENERATION ALGORITHMS (DGA) Malware generates random domain names: - asd7f8g9h.com - jk3l4m5n6.com - qw7er8ty9.com One of them is the real C2 - hard to block all Detection: High volume of NXDOMAIN (not found) responses 3. DNS TUNNELING Hide data in DNS queries: Query: c2VjcmV0ZGF0YQ.evil.com └── base64 encoded data! Exfiltrate data right through the firewall (port 53 usually allowed) Detection: Unusually long subdomain strings, high query volume 4. DNS HIJACKING Attacker changes DNS response: Victim asks: "Where is bankofamerica.com?" Attacker answers: "It's at 185.220.101.34" (attacker's server) Victim goes to fake site, enters credentials Detection: Unexpected DNS responses, certificate warnings SUSPICIOUS DNS PATTERNS TO WATCH: ═══════════════════════════════════════════════════════════════════════════════ 🔴 High volume queries from single host 🔴 Queries to newly registered domains 🔴 Many NXDOMAIN responses (DGA indicator) 🔴 Very long subdomain strings (tunneling) 🔴 Queries to TXT records for non-email domains 🔴 Direct DNS to external servers (bypassing internal DNS)
