CRYPTOGRAPHIC HASH FUNCTIONS ═══════════════════════════════════════════════════════════════════════════════ WHAT A HASH DOES: ───────────────────────────────────────────────────────────────────────────── ┌─────────────────────────────────────────────────────────────────────────┐ │ ANY INPUT FIXED OUTPUT │ │ (any size) (always same length) │ │ │ │ "Hi" ──► [SHA-256] ──► "8f434346648f6b96df89dda901c..." │ │ "Hello World" ──► [SHA-256] ──► "a591a6d40bf420404a011733cfb..." │ │ [10 GB file] ──► [SHA-256] ──► "9f86d081884c7d659a2feaa0c55..." │ │ "Hi" (again) ──► [SHA-256] ──► "8f434346648f6b96df89dda901c..." │ │ │ │ │ └─► Same input = Same output │ │ (deterministic) │ │ │ │ CANNOT reverse: Hash → Original input (computationally impossible) │ └─────────────────────────────────────────────────────────────────────────┘ THE AVALANCHE EFFECT: ───────────────────────────────────────────────────────────────────────────── Tiny change in input → Completely different hash "Hello" ──► SHA-256 ──► 185f8db32271fe25f561a6fc938b2e264306ec304eda5180... "hello" ──► SHA-256 ──► 2cf24dba5fb0a30e26e83b2ac5b9e29e1b161e5c1fa74255... ▲▲▲▲▲▲▲▲▲▲▲▲▲▲▲▲▲▲▲▲▲▲▲▲▲▲▲▲▲▲▲▲▲▲▲▲▲▲▲▲▲▲▲▲▲▲ COMPLETELY DIFFERENT (one capital letter change) This is critical for: • Detecting file tampering (change 1 bit → hash changes completely) • Password verification (similar passwords have unrelated hashes) HASH ALGORITHM STATUS: ═══════════════════════════════════════════════════════════════════════════════ Algorithm Output Speed Status When to Use ───────────────────────────────────────────────────────────────────────────── MD5 128 bits Very Fast ❌ BROKEN NEVER for security (OK for checksums) SHA-1 160 bits Fast ❌ BROKEN NEVER (collisions found 2017: SHAttered) SHA-256 256 bits Fast ✅ STANDARD TLS, certificates, digital signatures, blockchain SHA-384 384 bits Fast ✅ STRONG Government, high security SHA-512 512 bits Fast ✅ STRONG When you need longer hash SHA-3 Variable Medium ✅ MODERN Post-quantum ready, backup if SHA-2 broken BLAKE2 Variable Very Fast ✅ MODERN Performance-critical (faster than SHA-256) BLAKE3 Variable Extremely ✅ NEWEST Parallel, very fast Fast PASSWORD HASHING - DIFFERENT FROM REGULAR HASHING! ═══════════════════════════════════════════════════════════════════════════════ ❌ WRONG: Store SHA-256(password) Why it fails: • SHA-256 is FAST (~1 billion hashes/second on GPU) • Attacker downloads database, runs dictionary attack • "password123" → SHA-256 → Compare against database • Crack millions of passwords in hours ✅ RIGHT: Store bcrypt/Argon2(password, salt) Password Hash Functions are INTENTIONALLY SLOW: ┌─────────────────────────────────────────────────────────────────────┐ │ │ │ PASSWORD + SALT + PARAMETERS │ │ │ │ │ ▼ │ │ ┌───────────────────────────────────────────────────────────┐ │ │ │ SLOW HASH FUNCTION │ │ │ │ │ │ │ │ • bcrypt: CPU-hard, ~100ms per hash │ │ │ │ • scrypt: CPU + Memory hard │ │ │ │ • Argon2id: CPU + Memory hard (BEST) │ │ │ │ │ │ │ │ Time cost: How many iterations │ │ │ │ Memory cost: How much RAM required │ │ │ │ Parallelism: How many threads │ │ │ └───────────────────────────────────────────────────────────┘ │ │ │ │ │ ▼ │ │ $argon2id$v=19$m=65536,t=3,p=4$c2FsdDEyMzQ$hash... │ │ │ │ │ │ │ │ │ │ │ │ │ │ │ │ │ └─ The actual hash │ │ │ │ │ │ │ └───────────── Base64 salt │ │ │ │ │ │ └─────────────── Parallelism │ │ │ │ │ └─────────────────── Time cost │ │ │ │ └─────────────────────────── Memory (64 MB) │ │ │ └────────────────────────────────── Version │ │ └─────────────────────────────────────────── Algorithm │ │ │ │ LOGIN CHECK: │ │ User enters password → Hash with stored salt → Compare │ │ Match = Login success, No match = Login fail │ │ │ │ ATTACKER'S PROBLEM: │ │ • 100ms per guess instead of 0.000001ms │ │ • 1 million guesses = 27 hours (vs 1 second with SHA-256) │ │ • Memory-hard = GPUs can't parallelize effectively │ │ │ └─────────────────────────────────────────────────────────────────────┘ SALT EXPLAINED: ───────────────────────────────────────────────────────────────────────────── Without salt: User1: "password123" → Hash("password123") → "abc123..." User2: "password123" → Hash("password123") → "abc123..." Same password = Same hash! Attacker cracks one, gets both. Rainbow tables: Pre-computed hash lookups work. With salt (random per-user): User1: "password123" + "randomsalt1" → Hash → "xyz789..." User2: "password123" + "randomsalt2" → Hash → "def456..." Same password = Different hashes! Rainbow tables useless (would need table per salt)

Practical Commands

# ═══════════════════════════════════════════════════════════════════════════
# KEY GENERATION
# ═══════════════════════════════════════════════════════════════════════════

# Generate RSA 4096-bit key pair
openssl genrsa -out private.pem 4096
openssl rsa -in private.pem -pubout -out public.pem

# Generate ECDSA P-256 key pair (recommended)
openssl ecparam -genkey -name prime256v1 -out ec-private.pem
openssl ec -in ec-private.pem -pubout -out ec-public.pem

# Generate Ed25519 SSH key (modern, secure)
ssh-keygen -t ed25519 -C "your_email@example.com"

# ═══════════════════════════════════════════════════════════════════════════
# CERTIFICATES
# ═══════════════════════════════════════════════════════════════════════════

# Create CSR (Certificate Signing Request)
openssl req -new -key private.pem -out request.csr

# Self-signed certificate (testing only!)
openssl req -x509 -nodes -days 365 -newkey rsa:2048 \
    -keyout key.pem -out cert.pem

# View certificate details
openssl x509 -in certificate.pem -text -noout

# Check certificate expiration
echo | openssl s_client -connect google.com:443 2>/dev/null | \
    openssl x509 -noout -dates

# Verify certificate chain
openssl verify -CAfile ca-bundle.crt certificate.pem

# ═══════════════════════════════════════════════════════════════════════════
# TLS TESTING
# ═══════════════════════════════════════════════════════════════════════════

# Test TLS connection and show certificate
openssl s_client -connect google.com:443 -tls1_3

# Show supported cipher suites
openssl s_client -connect google.com:443 -cipher 'ALL' 2>/dev/null | \
    grep "Cipher"

# Test specific TLS version
openssl s_client -connect example.com:443 -tls1_2
openssl s_client -connect example.com:443 -tls1_3

# ═══════════════════════════════════════════════════════════════════════════
# HASHING
# ═══════════════════════════════════════════════════════════════════════════

# Hash a string
echo -n "Hello" | sha256sum

# Hash a file
sha256sum filename.txt
openssl dgst -sha256 filename.txt

# ═══════════════════════════════════════════════════════════════════════════
# ENCRYPTION
# ═══════════════════════════════════════════════════════════════════════════

# Encrypt file with AES-256-GCM
openssl enc -aes-256-gcm -salt -in plain.txt -out encrypted.bin -pass pass:MyPassword

# Decrypt
openssl enc -d -aes-256-gcm -in encrypted.bin -out decrypted.txt -pass pass:MyPassword

# Encrypt with RSA public key (small data only)
openssl rsautl -encrypt -pubin -inkey public.pem -in secret.txt -out encrypted.txt

# Decrypt with RSA private key
openssl rsautl -decrypt -inkey private.pem -in encrypted.txt -out decrypted.txt
