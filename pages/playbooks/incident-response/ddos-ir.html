IR-005

DDoS Incident Response

Comprehensive incident response playbook for Distributed Denial of Service attacks. Covers volumetric, protocol, and application layer attacks with mitigation strategies.

SeverityHigh
TimeMinutes to Hours
TeamSOC + Network + Cloud
Business Impact Alert

DDoS attacks directly impact service availability and customer experience. Rapid response is critical. Engage your DDoS protection provider early. Consider whether the DDoS is a distraction for another attack.

1.2 Determine Attack Type

// Volumetric Attack Indicators:
- Bandwidth saturation (>80% capacity)
- High packets per second
- Traffic from many sources
- Protocol: UDP, ICMP dominant

// Protocol Attack Indicators:
- SYN flood: High SYN rate, half-open connections
- ACK flood: Unexpected ACK packets
- Connection exhaustion: Max connections reached

// Application Layer Indicators:
- High HTTP request rate
- Specific URL targeted
- Normal packet counts, high request rate
- Server CPU/memory spike

2.3 Emergency Mitigation Commands

// iptables - Rate limiting (Linux)
# Limit incoming connections per IP
iptables -A INPUT -p tcp --dport 80 -m connlimit --connlimit-above 50 -j DROP

# SYN flood protection
iptables -A INPUT -p tcp --syn -m limit --limit 1/s --limit-burst 3 -j ACCEPT

# Block specific attacking IP
iptables -A INPUT -s ATTACKER_IP -j DROP

// nginx - Rate limiting
# In http block:
limit_req_zone $binary_remote_addr zone=one:10m rate=10r/s;

# In server block:
limit_req zone=one burst=20 nodelay;

// Apache - Connection limits
# mod_reqtimeout
RequestReadTimeout header=20-40,MinRate=500 body=20,MinRate=500

// Cloud WAF rule example (pseudo-code)
IF request_rate > 100/min per IP
AND country NOT IN (allowed_countries)
THEN block OR challenge

Phase 3: Analysis and Tuning (During Attack)

3.1 Traffic Analysis

// KQL - Traffic volume analysis
AzureNetworkAnalytics_CL
| where TimeGenerated > ago(1h)
| summarize 
    TotalBytes = sum(BytesSent_d + BytesReceived_d),
    Packets = sum(PacketsSent_d + PacketsReceived_d)
    by bin(TimeGenerated, 1m)
| render timechart

// KQL - Top source IPs
CommonSecurityLog
| where TimeGenerated > ago(1h)
| where DeviceAction == "Deny" or Activity has "DROP"
| summarize Count = count() by SourceIP
| top 50 by Count
| order by Count desc

// KQL - Geographic distribution
CommonSecurityLog
| where TimeGenerated > ago(1h)
| extend GeoInfo = geo_info_from_ip_address(SourceIP)
| extend Country = tostring(GeoInfo.country)
| summarize Count = count() by Country
| order by Count desc

// SPL - DDoS traffic analysis
index=firewall action=blocked
| timechart span=1m count by src_ip limit=20

Escalation Criteria

Escalate Immediately If:
  • Service is completely unavailable
  • Attack exceeds protection capacity
  • Revenue-impacting services affected
  • Customer-facing systems down
  • DDoS appears to be covering another attack
  • Ransom demand received
  • Attack persists beyond 30 minutes

Interview-Ready Answer

"Walk through your DDoS incident response process"

My Answer:

"DDoS IR prioritizes availability restoration. Unlike most incidents where we investigate then contain, here we mitigate first to restore service, then investigate.

Detection & Classification:
DDoS often comes from monitoring alerts - service down, high latency, bandwidth saturation. I quickly classify: Is it volumetric (bandwidth exhaustion), protocol-based (SYN flood), or application layer (HTTP flood)? This determines mitigation approach. I also verify it's actually DDoS and not infrastructure failure.

Immediate Mitigation:
For volumetric attacks, I engage our DDoS protection - cloud scrubbing service, ISP mitigation, or CDN protection. The SOC can't stop a 100 Gbps attack at the firewall. For application-layer attacks, I implement emergency WAF rules: rate limiting, geo-blocking if attack sources are concentrated, CAPTCHA challenges. Goal is restoring service, even partially.

Communication:
During active DDoS, communication is critical. I keep stakeholders updated on status and ETA. I coordinate with NOC/infrastructure team on network-level mitigation. If customer-facing, I work with communications team on status page updates. DDoS response is a team effort.

Investigation & Follow-up:
Once mitigated, I analyze the attack: profile, duration, sources. Was it targeted or opportunistic? Is this part of an extortion campaign? I check if the DDoS was cover for another attack - sometimes attackers use DDoS as distraction. Finally, I document lessons learned and improvements needed - better auto-scaling, improved DDoS protection, faster response procedures."

💡 Pro Tips for Interview:
  • Emphasize mitigation before investigation - availability is priority
  • Know you need upstream help for volumetric attacks
  • Mention DDoS as potential distraction for other attacks
  • Show awareness of DDoS extortion campaigns
