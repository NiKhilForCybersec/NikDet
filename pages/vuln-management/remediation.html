Vulnerability Remediation

Strategies and processes for effectively addressing identified vulnerabilities.

Remediation Options

OptionDescriptionWhen to Use
Patch Apply vendor security update Preferred when patch available
Upgrade Move to newer version When patch requires new version
Configuration Change Disable vulnerable feature When feature not needed
Compensating Control Add mitigating control When patching not possible
Network Segmentation Isolate vulnerable system Reduce exposure while planning fix
Virtual Patching WAF/IPS rule to block exploit Emergency mitigation
Decommission Remove the vulnerable system When system no longer needed
Accept Risk Document and accept the risk When remediation cost > risk

1

Emergency Patching Process

Emergency Criteria
  • Vulnerability in CISA KEV (actively exploited)
  • CVSS 9.0+ on internet-facing systems
  • Wormable vulnerability (e.g., WannaCry)
  • Active exploitation detected in your environment

Emergency Process

  1. Activate emergency change: Bypass normal change window
  2. Implement temporary mitigation: Virtual patch, isolate, disable service
  3. Rapid testing: Limited testing in staging
  4. Deploy patch: Push to production ASAP
  5. Verify: Confirm vulnerability resolved
  6. Post-mortem: Document lessons learned

Compensating Controls

When immediate patching isn't possible, implement compensating controls:

Control TypeExamples
Network Firewall rules, network segmentation, VPN only access
Application WAF rules, disable vulnerable feature, input validation
Host EDR rules, application whitelisting, enhanced logging
Access Restrict access, require MFA, limit privileges
Monitoring Enhanced alerting, specific detection rules

Risk Acceptance

When accepting risk, document:

  • Vulnerability details: CVE, CVSS, affected systems
  • Business justification: Why remediation isn't feasible
  • Compensating controls: What's in place to mitigate
  • Expiration date: When to review again
  • Approval: Business owner and security sign-off
