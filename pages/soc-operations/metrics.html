SOC Metrics & KPIs

Measure what matters. Comprehensive guide to SOC performance metrics, KPIs, and reporting.

Why Metrics Matter

Metrics serve multiple purposes in a SOC:

  • Demonstrate value to leadership and stakeholders
  • Identify improvement areas in processes and tools
  • Track team performance and workload distribution
  • Justify resource requests with data
  • Benchmark against industry standards
  • Drive accountability across the team

Metric Dashboards

Executive Dashboard (CISO/Leadership)

Focus on business impact and trends:

  • Security incidents by severity (monthly trend)
  • MTTD and MTTR trends
  • Top threat categories
  • Detection coverage heatmap (ATT&CK)
  • Comparison to industry benchmarks

Operations Dashboard (SOC Manager)

Focus on team performance and capacity:

  • Alert volume by hour/day/week
  • SLA compliance by severity
  • Alerts per analyst distribution
  • Queue age (oldest open alerts)
  • False positive rate by detection rule
  • Escalation rate trends

Analyst Dashboard

Focus on individual workload and queues:

  • My open alerts/incidents
  • My average triage time
  • Alerts by severity in queue
  • Recent closures needing review

Calculating Key Metrics

MTTD Example

Incident 1: Attack started 10:00, detected 14:00 = 4 hours
Incident 2: Attack started 08:00, detected 09:30 = 1.5 hours
Incident 3: Attack started 15:00, detected 16:00 = 1 hour

MTTD = (4 + 1.5 + 1) / 3 = 2.17 hours

False Positive Rate Query (KQL)

Sentinel
SecurityIncident
| where TimeGenerated > ago(30d)
| summarize 
    TruePositives = countif(Classification == "TruePositive"),
    FalsePositives = countif(Classification == "FalsePositive"),
    BenignPositives = countif(Classification == "BenignPositive")
| extend 
    Total = TruePositives + FalsePositives + BenignPositives,
    FPRate = round(FalsePositives * 100.0 / (TruePositives + FalsePositives + BenignPositives), 2)

Avoiding Bad Metrics

Metrics Pitfalls
  • Vanity metrics: "We blocked 1 million attacks!" (meaningless without context)
  • Gaming: Closing alerts quickly without investigation to hit SLA
  • Counting wrong things: Alert count instead of incident count
  • No baseline: Metrics without historical comparison
  • Too many metrics: Information overload loses focus

Continuous Improvement

Use metrics to drive improvements:

  1. Identify: Which metric is underperforming?
  2. Analyze: What's causing the issue?
  3. Plan: What changes could improve it?
  4. Implement: Make the changes
  5. Measure: Did the metric improve?
  6. Iterate: Repeat the cycle
Pro Tips
  • Start with 5-7 key metrics, not 50
  • Automate metric collection where possible
  • Review metrics monthly to ensure they're still relevant
  • Combine metrics with qualitative feedback
  • Celebrate improvements, not just flag issues
