DNS Logs

DNS logs are incredibly valuable for threat detection. Every network connection starts with DNS.

Common Fields

timestamp:     2025-01-15T14:23:45Z
src_ip:        192.168.1.100
query:         malware.bad
query_type:    A
response:      45.33.32.156
response_code: NOERROR

DNS Detection Techniques

TechniqueWhat to Look ForIndicates
Known Bad Domains Match against threat intel feeds Known malware/C2
DGA Detection High entropy domain names Domain Generation Algorithm
DNS Tunneling Long subdomains, many TXT queries Data exfiltration via DNS
NXDOMAIN Spikes Many failed lookups DGA or scanning
New Domains Query to newly registered domain Phishing, malware

Beaconing Detection

C2 malware often "beacons" at regular intervals:

// Look for consistent intervals between connections

192.168.1.100 → 45.33.32.156:443  @ 14:00:00
192.168.1.100 → 45.33.32.156:443  @ 14:05:00  (+5 min)
192.168.1.100 → 45.33.32.156:443  @ 14:10:00  (+5 min)
192.168.1.100 → 45.33.32.156:443  @ 14:15:00  (+5 min)

⚠ Regular 5-minute intervals = likely beaconing

Investigation Queries

// KQL: Find potential beaconing
NetworkEvents
| where TimeGenerated > ago(24h)
| summarize 
    count(),
    make_list(TimeGenerated)
    by SourceIP, DestinationIP, DestinationPort
| where array_length(list_TimeGenerated) > 10
| extend intervals = array_sort_asc(list_TimeGenerated)

// SPL: Large data transfers
index=firewall 
| stats sum(bytes_out) as total_bytes by src_ip, dst_ip
| where total_bytes > 100000000
| sort -total_bytes

// KQL: DNS to rare TLDs
DnsEvents
| where Name endswith ".xyz" or Name endswith ".top" or Name endswith ".tk"
| summarize count() by Name, ClientIP
| sort by count_ desc

Network Detection Checklist

  • Firewall: Denied connections, unusual ports, internal scanning
  • Proxy: Direct IP access, rare TLDs, suspicious downloads
  • DNS: DGA patterns, tunneling, known bad domains
  • Flow: Beaconing, large transfers, unusual destinations
  • Time: Activity outside business hours
