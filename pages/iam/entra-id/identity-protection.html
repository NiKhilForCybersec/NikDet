Entra ID Identity Protection

Risk-based Conditional Access using machine learning to detect compromised identities and suspicious sign-in behavior.

Configuring Risk Policies

Path: Entra Admin Center → Protection → Identity Protection → Policies

User Risk Policy

Recommended Configuration:

  • Users: All users (exclude break-glass accounts)
  • User risk: High
  • Access: Allow access + Require password change
  • Enforce policy: On

Sign-in Risk Policy

Recommended Configuration:

  • Users: All users (exclude break-glass accounts)
  • Sign-in risk: Medium and above
  • Access: Allow access + Require MFA
  • Enforce policy: On

Using Conditional Access (Recommended)

For more control, create CA policies instead of the built-in risk policies:

1
Create CA Policy

Conditional Access → New policy → Name: "Block High Risk Sign-ins"

2
Assignments

Users: All users (exclude break-glass) | Apps: All cloud apps

3
Conditions

Sign-in risk: High | User risk: High

4
Grant

Block access (for High) OR Require MFA + password change

PowerShell & Graph API

# Connect to Graph
Connect-MgGraph -Scopes "IdentityRiskyUser.Read.All","IdentityRiskEvent.Read.All"

# Get all risky users
Get-MgRiskyUser -Filter "riskLevel eq 'high'" | 
    Select-Object UserDisplayName, UserPrincipalName, RiskLevel, RiskState, RiskLastUpdatedDateTime

# Get risky users with details
Get-MgRiskyUser -All | Where-Object { $_.RiskState -eq "atRisk" } |
    Select-Object UserDisplayName, UserPrincipalName, RiskLevel, RiskDetail

# Get risk detections (events)
Get-MgRiskDetection -Filter "riskLevel eq 'high'" -Top 50 |
    Select-Object UserDisplayName, RiskEventType, RiskLevel, DetectedDateTime, IpAddress, Location

# Dismiss user risk (after investigation)
Invoke-MgDismissRiskyUser -UserIds @("user-id-1", "user-id-2")

# Confirm user compromised (force password reset)
Invoke-MgConfirmRiskyUserCompromised -UserIds @("user-id-here")

Monitoring & KQL Queries

// All risky sign-ins
SigninLogs
| where TimeGenerated > ago(7d)
| where RiskLevelDuringSignIn != "none" and RiskLevelDuringSignIn != ""
| project TimeGenerated, UserPrincipalName, RiskLevelDuringSignIn, RiskEventTypes, 
          IPAddress, Location, AppDisplayName, ResultType
| order by TimeGenerated desc

// High-risk sign-ins requiring investigation
SigninLogs
| where TimeGenerated > ago(24h)
| where RiskLevelDuringSignIn == "high"
| project TimeGenerated, UserPrincipalName, IPAddress, 
          Location=strcat(LocationDetails.city, ", ", LocationDetails.countryOrRegion),
          RiskEventTypes, DeviceDetail, AppDisplayName

// Leaked credentials detections
AADUserRiskEvents
| where TimeGenerated > ago(30d)
| where RiskEventType == "leakedCredentials"
| project TimeGenerated, UserPrincipalName, RiskLevel, RiskDetail, DetectedDateTime

// Users with elevated risk over time
AADUserRiskEvents
| where TimeGenerated > ago(30d)
| summarize RiskEvents = count(), HighRiskCount = countif(RiskLevel == "high") 
    by UserPrincipalName
| where HighRiskCount > 0
| order by HighRiskCount desc

// Impossible travel detections
SigninLogs
| where TimeGenerated > ago(7d)
| where RiskEventTypes has "impossibleTravel"
| project TimeGenerated, UserPrincipalName, IPAddress, 
          Location=strcat(LocationDetails.city, ", ", LocationDetails.countryOrRegion)

Best Practices

  • Use CA policies instead of built-in risk policies for more granular control
  • Block high sign-in risk - don't just require MFA
  • Integrate with SIEM - stream risk events to Sentinel for correlation
  • Enable self-service password reset (SSPR) - users can remediate user risk themselves
  • Review risky users weekly - investigate and dismiss/confirm
  • Alert on leaked credentials - immediate investigation required
  • Exclude break-glass accounts - prevent lockout scenarios
