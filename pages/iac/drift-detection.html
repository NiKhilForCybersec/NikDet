Configuration Drift Detection

Detect when actual infrastructure state diverges from desired state defined in code.

What is Drift?

Configuration drift occurs when the actual state of infrastructure differs from the desired state defined in IaC. This happens due to: manual changes via console/CLI, emergency fixes not committed to code, or automated processes modifying resources.

Why Drift is a Security Problem

Drift TypeSecurity ImpactExample
Security group changesUnauthorized access pathsPort 22 opened to 0.0.0.0/0 for "quick troubleshooting"
IAM policy changesPrivilege escalationAdmin added * permissions for testing
Encryption disabledData exposureS3 bucket encryption turned off
Logging disabledLoss of visibilityCloudTrail logging disabled
Public access enabledData breachS3 bucket made public

Terraform Drift Detection

# Manual drift check
terraform plan -detailed-exitcode
# Exit codes: 0=no changes, 1=error, 2=changes detected

# Refresh state and detect drift
terraform refresh
terraform plan

# Run terraform plan on schedule, alert if exit code = 2

GitHub Actions Scheduled Drift Check

# .github/workflows/drift-detection.yml
name: Drift Detection

on:
  schedule:
    - cron: '0 */6 * * *'  # Every 6 hours
  workflow_dispatch:

jobs:
  detect-drift:
    runs-on: ubuntu-latest
    strategy:
      matrix:
        environment: [dev, staging, prod]
    
    steps:
      - uses: actions/checkout@v4
      
      - name: Configure AWS Credentials
        uses: aws-actions/configure-aws-credentials@v4
        with:
          role-to-assume: ${{ secrets.AWS_ROLE_ARN }}
          aws-region: us-east-1
      
      - name: Setup Terraform
        uses: hashicorp/setup-terraform@v3
      
      - name: Terraform Init
        run: terraform init
        working-directory: environments/${{ matrix.environment }}
      
      - name: Terraform Plan (Drift Check)
        id: plan
        run: |
          terraform plan -detailed-exitcode -out=tfplan 2>&1 | tee plan.txt
          echo "exitcode=$?" >> $GITHUB_OUTPUT
        working-directory: environments/${{ matrix.environment }}
        continue-on-error: true
      
      - name: Alert on Drift
        if: steps.plan.outputs.exitcode == '2'
        uses: slackapi/slack-github-action@v1
        with:
          payload: |
            {
              "text": "⚠️ Drift detected in ${{ matrix.environment }}!",
              "attachments": [
                {
                  "color": "warning",
                  "text": "Terraform detected configuration drift. Review and remediate."
                }
              ]
            }
        env:
          SLACK_WEBHOOK_URL: ${{ secrets.SLACK_WEBHOOK }}

Cloud-Native Drift Detection

AWS Config Rules

# Terraform: AWS Config rule for S3 public access
resource "aws_config_config_rule" "s3_public_access" {
  name = "s3-bucket-public-read-prohibited"
  
  source {
    owner             = "AWS"
    source_identifier = "S3_BUCKET_PUBLIC_READ_PROHIBITED"
  }
}

resource "aws_config_config_rule" "security_group_open" {
  name = "restricted-ssh"
  
  source {
    owner             = "AWS"
    source_identifier = "INCOMING_SSH_DISABLED"
  }
}

# Auto-remediation with SSM
resource "aws_config_remediation_configuration" "s3_remediation" {
  config_rule_name = aws_config_config_rule.s3_public_access.name
  target_type      = "SSM_DOCUMENT"
  target_id        = "AWSConfigRemediation-ConfigureS3BucketPublicAccessBlock"
  automatic        = true
  
  parameter {
    name         = "BucketName"
    resource_value = "RESOURCE_ID"
  }
}

Remediation Strategies

StrategyWhen to UseHow
Auto-remediateClear security violationsAWS Config auto-remediation, ArgoCD self-heal
Alert and reviewMost drift scenariosNotify team, investigate, update IaC or revert
Import to IaCLegitimate manual changeterraform import, update code to match
Revert to IaCUnauthorized changeterraform apply to restore desired state

Prevention: Reducing Drift

  • Restrict console access: Limit who can make manual changes
  • Read-only roles: Most users should have read-only cloud console access
  • Service Control Policies: Prevent specific actions outside IaC
  • GitOps with self-heal: ArgoCD automatically reverts manual changes
  • Break-glass procedures: Document process for emergency manual changes
  • Mandatory PR for all changes: Even emergency fixes go through code review

Monitoring KQL (Azure)

// Detect manual Azure portal/CLI changes
AzureActivity
| where TimeGenerated > ago(24h)
| where OperationNameValue has "write" or OperationNameValue has "delete"
| where Caller !has "terraform" and Caller !has "pipeline" and Caller !has "github"
| project TimeGenerated, Caller, OperationNameValue, ResourceGroup, Resource
| order by TimeGenerated desc

// Security group changes
AzureActivity
| where TimeGenerated > ago(7d)
| where OperationNameValue has "networkSecurityGroups"
| where ActivityStatusValue == "Success"
| project TimeGenerated, Caller, OperationNameValue, Properties
