Password Hashing

Critical: Password Hashing is DIFFERENT!

Regular hash functions (SHA-256, etc.) are designed to be FAST. For passwords, you need functions designed to be SLOW. Using SHA-256 for passwords is a critical security mistake!

PASSWORD HASHING - WHY REGULAR HASHES FAIL ═══════════════════════════════════════════════════════════════════════════════ THE PROBLEM WITH FAST HASHES: ───────────────────────────────────────────────────────────────────────────── ❌ WRONG: Store SHA-256(password) in database ┌─────────────────────────────────────────────────────────────────────────┐ │ │ │ User registers: │ │ password: "password123" │ │ stored: SHA256("password123") = ef92b778bafe771e89245b89ecbc08a44a808│ │ │ │ ATTACK SCENARIO: │ │ │ │ 1. Attacker steals database │ │ 2. Has list of hashed passwords │ │ 3. Runs dictionary/brute force attack: │ │ │ │ Modern GPU: ~10 BILLION SHA-256 hashes per second │ │ │ │ Dictionary attack (10 million common passwords): │ │ Time: 10,000,000 / 10,000,000,000 = 0.001 seconds │ │ │ │ Brute force 8-char lowercase: │ │ 26^8 = 208 billion combinations │ │ Time: 208,000,000,000 / 10,000,000,000 = 20 seconds │ │ │ │ RESULT: Most passwords cracked in minutes to hours │ │ │ └─────────────────────────────────────────────────────────────────────────┘ THE SOLUTION: PASSWORD HASHING FUNCTIONS ═══════════════════════════════════════════════════════════════════════════════ ✅ RIGHT: Store bcrypt/Argon2(password, salt, parameters) ┌─────────────────────────────────────────────────────────────────────────┐ │ │ │ PASSWORD HASH FUNCTIONS ARE INTENTIONALLY SLOW │ │ │ │ Password + Salt + Parameters │ │ │ │ │ ▼ │ │ ┌───────────────────────────────────────────────────────────┐ │ │ │ SLOW HASH FUNCTION │ │ │ │ │ │ │ │ • Iterations: Run algorithm many times (stretching) │ │ │ │ • Memory: Require significant RAM (memory-hard) │ │ │ │ • Time: Each hash takes 100ms - 1 second │ │ │ │ │ │ │ └───────────────────────────────────────────────────────────┘ │ │ │ │ │ ▼ │ │ $argon2id$v=19$m=65536,t=3,p=4$salt$hash │ │ │ │ │ │ ATTACK SCENARIO WITH SLOW HASH: │ │ │ │ Each hash: 100ms (100 milliseconds) │ │ Rate: 10 hashes per second (vs 10 billion!) │ │ │ │ Dictionary attack (10 million passwords): │ │ Time: 10,000,000 / 10 = 1,000,000 seconds = 11.5 DAYS │ │ │ │ Brute force 8-char lowercase: │ │ Time: 208,000,000,000 / 10 = 20.8 billion seconds = 660 YEARS │ │ │ └─────────────────────────────────────────────────────────────────────────┘ SALT - PREVENTING RAINBOW TABLES: ═══════════════════════════════════════════════════════════════════════════════ WITHOUT SALT (BAD): ───────────────────────────────────────────────────────────────────────────── User1: password123 → Hash("password123") → abc123... User2: password123 → Hash("password123") → abc123... ← SAME! User3: password123 → Hash("password123") → abc123... ← SAME! PROBLEM 1: Same password = Same hash Crack one, get all users with that password PROBLEM 2: Rainbow tables Pre-compute Hash(common_password) for millions of passwords Instant lookup: hash → password WITH SALT (GOOD): ───────────────────────────────────────────────────────────────────────────── Salt = Random bytes, unique per user, stored with hash User1: password123 + "x7Km9p2L" → Hash → abc123... User2: password123 + "Qr4nT8bZ" → Hash → def456... ← DIFFERENT! User3: password123 + "Wv6jY3cN" → Hash → ghi789... ← DIFFERENT! BENEFITS: ✅ Same password → Different hashes ✅ Rainbow tables useless (would need table per salt) ✅ Each user must be attacked individually PASSWORD HASH ALGORITHM COMPARISON: ═══════════════════════════════════════════════════════════════════════════════ Algorithm Design Hardware Resistance Status ───────────────────────────────────────────────────────────────────────────── bcrypt 1999 CPU-hard ✅ GOOD Blowfish-based Good GPU resistance Widely deployed Max 72 chars Still recommended scrypt 2009 Memory-hard ✅ GOOD CPU + RAM Better GPU resistance Good alternative Tunable memory Argon2id 2015 Memory + CPU hard ✅ BEST PHC winner Best GPU resistance Use for new systems Hybrid mode Most configurable PBKDF2 2000 CPU-hard only ⚠️ LEGACY SHA-based NO memory hardness Still compliant GPUs can attack (NIST, FIPS) RECOMMENDATION: Argon2id > bcrypt > scrypt > PBKDF2

Argon2 Deep Dive

ARGON2 - THE CURRENT BEST PRACTICE ═══════════════════════════════════════════════════════════════════════════════ ARGON2 VARIANTS: ───────────────────────────────────────────────────────────────────────────── Argon2d Data-dependent memory access Maximum GPU/ASIC resistance Vulnerable to side-channel attacks Use for: Cryptocurrency mining Argon2i Data-independent memory access Side-channel resistant Less GPU resistance Use for: Password hashing in hostile environments Argon2id HYBRID - Best of both! Set memory as high as your system allows 2. Set time so login takes ~0.5-1 second 3. Set parallelism to number of CPU cores

Password Attacks

PASSWORD ATTACK METHODS ═══════════════════════════════════════════════════════════════════════════════ DICTIONARY ATTACK: ───────────────────────────────────────────────────────────────────────────── Try common passwords from wordlists: password, 123456, qwerty, admin, letmein, welcome, monkey... + Variations: Password, PASSWORD, p@ssword, Password1, Password123! Defense: Password complexity requirements, breach databases check BRUTE FORCE: ───────────────────────────────────────────────────────────────────────────── Try all possible combinations: 8 chars lowercase: 26^8 = 208 billion 8 chars + uppercase: 52^8 = 53 trillion 8 chars + digits: 62^8 = 218 trillion 8 chars + symbols: 95^8 = 6.6 quadrillion 12 chars full: 95^12 = 540 septillion Defense: Long passwords (12+ chars), slow hash functions RAINBOW TABLES: ───────────────────────────────────────────────────────────────────────────── Pre-computed hash → password lookup tables Trade storage for computation time Table for 8-char alphanumeric: ~100 GB Defense: SALT (makes rainbow tables useless) CREDENTIAL STUFFING: ───────────────────────────────────────────────────────────────────────────── Use breached username/password from Site A to try on Site B Works because: People reuse passwords! Defense: Unique passwords per site, MFA, breach monitoring PASS-THE-HASH: ───────────────────────────────────────────────────────────────────────────── Windows/NTLM: Use stolen hash directly without cracking Network auth accepts hash, not plaintext password Defense: Credential Guard, disable NTLM, privileged access management GPU CRACKING SPEEDS (2024 approximate): ═══════════════════════════════════════════════════════════════════════════════ Algorithm Speed (per GPU) With 8x GPUs ───────────────────────────────────────────────────────────────────────────── MD5 ~60 billion/sec 480 billion/sec SHA-1 ~20 billion/sec 160 billion/sec SHA-256 ~10 billion/sec 80 billion/sec NTLM ~100 billion/sec 800 billion/sec bcrypt (cost 10) ~30,000/sec 240,000/sec Argon2 (64MB) ~10/sec 80/sec THIS IS WHY SLOW HASHES MATTER!

Implementation Examples

# ═══════════════════════════════════════════════════════════════════════════
# PYTHON - ARGON2 (RECOMMENDED)
# ═══════════════════════════════════════════════════════════════════════════

# pip install argon2-cffi

from argon2 import PasswordHasher
from argon2.exceptions import VerifyMismatchError

# Create hasher with secure parameters
ph = PasswordHasher(
    time_cost=3,           # Iterations
    memory_cost=65536,     # 64 MB
    parallelism=4,         # Threads
    hash_len=32,           # Output length
    salt_len=16            # Salt length
)

# Hash password (salt automatically generated and included)
hash = ph.hash("user_password")
# Returns: $argon2id$v=19$m=65536,t=3,p=4$salt$hash

# Verify password
try:
    ph.verify(hash, "user_password")
    print("Password correct!")
except VerifyMismatchError:
    print("Invalid password!")

# Check if rehash needed (parameters changed)
if ph.check_needs_rehash(hash):
    new_hash = ph.hash("user_password")


# ═══════════════════════════════════════════════════════════════════════════
# PYTHON - BCRYPT
# ═══════════════════════════════════════════════════════════════════════════

# pip install bcrypt

import bcrypt

# Hash password
password = b"user_password"
salt = bcrypt.gensalt(rounds=12)  # Cost factor 12 (~250ms)
hash = bcrypt.hashpw(password, salt)

# Verify password
if bcrypt.checkpw(password, hash):
    print("Password correct!")


# ═══════════════════════════════════════════════════════════════════════════
# NODE.JS - ARGON2
# ═══════════════════════════════════════════════════════════════════════════

// npm install argon2

const argon2 = require('argon2');

// Hash password
const hash = await argon2.hash("user_password", {
    type: argon2.argon2id,
    memoryCost: 65536,  // 64 MB
    timeCost: 3,
    parallelism: 4
});

// Verify password
if (await argon2.verify(hash, "user_password")) {
    console.log("Password correct!");
}
