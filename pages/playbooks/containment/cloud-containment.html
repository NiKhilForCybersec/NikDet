Cloud Containment Playbook

Containment procedures for Azure, AWS, GCP, and M365 security incidents.

Cloud Containment Actions Overview

Azure/Entra ID Containment

User Account Actions

// Disable user account (blocks all sign-ins)
Update-MgUser -UserId "user@company.com" -AccountEnabled:$false

// Revoke all refresh tokens (forces re-auth)
Revoke-MgUserSignInSession -UserId "user@company.com"

// Reset password
$NewPassword = @{
    Password = "NewRandomP@ss123!"
    ForceChangePasswordNextSignIn = $true
}
Update-MgUser -UserId "user@company.com" -PasswordProfile $NewPassword

// Remove from all groups
$groups = Get-MgUserMemberOf -UserId "user@company.com"
foreach ($group in $groups) {
    Remove-MgGroupMember -GroupId $group.Id -DirectoryObjectId "user-id"
}

// Block sign-in via Conditional Access (recommended for investigation)
# Create CA policy targeting specific user with Block access

Remove Malicious OAuth Apps

// List user's OAuth app consents
Get-MgUserOauth2PermissionGrant -UserId "user@company.com"

// Remove specific app consent
Remove-MgOauth2PermissionGrant -OAuth2PermissionGrantId "grant-id"

// Disable enterprise app tenant-wide
Update-MgServicePrincipal -ServicePrincipalId "app-id" -AccountEnabled:$false

// Check for app credentials that may have been added
Get-MgServicePrincipal -ServicePrincipalId "app-id" | Select -Expand PasswordCredentials
Get-MgServicePrincipal -ServicePrincipalId "app-id" | Select -Expand KeyCredentials

Azure Resource Containment

// Isolate VM - remove from network (preserve for forensics)
$nic = Get-AzNetworkInterface -Name "vm-nic"
$nic.NetworkSecurityGroup = $null  # Remove NSG
$nic | Set-AzNetworkInterface

// Or apply deny-all NSG
$nsg = New-AzNetworkSecurityGroup -Name "Quarantine-NSG" -ResourceGroupName "RG" -Location "eastus"
$nsg | Add-AzNetworkSecurityRuleConfig -Name "DenyAll" -Priority 100 `
    -Access Deny -Direction Inbound -SourceAddressPrefix * `
    -SourcePortRange * -DestinationAddressPrefix * -DestinationPortRange * -Protocol *
$nic.NetworkSecurityGroup = $nsg
$nic | Set-AzNetworkInterface

// Stop VM (if service disruption acceptable)
Stop-AzVM -ResourceGroupName "RG" -Name "VM-Name" -Force

// Take snapshot before any changes
$vm = Get-AzVM -ResourceGroupName "RG" -Name "VM-Name"
$snapshot = New-AzSnapshotConfig -SourceUri $vm.StorageProfile.OsDisk.ManagedDisk.Id `
    -Location "eastus" -CreateOption Copy
New-AzSnapshot -ResourceGroupName "RG" -SnapshotName "Forensic-Snapshot" -Snapshot $snapshot

// Remove public IP
$pip = Get-AzPublicIpAddress -Name "public-ip-name"
Remove-AzPublicIpAddress -Name $pip.Name -ResourceGroupName "RG" -Force

AWS Containment

IAM User/Role Actions

// Deactivate access keys
aws iam update-access-key --user-name compromised-user --access-key-id AKIA... --status Inactive

// Delete access keys
aws iam delete-access-key --user-name compromised-user --access-key-id AKIA...

// Attach deny-all policy to user
aws iam put-user-policy --user-name compromised-user --policy-name DenyAll --policy-document '{
    "Version": "2012-10-17",
    "Statement": [{
        "Effect": "Deny",
        "Action": "*",
        "Resource": "*"
    }]
}'

// Detach all managed policies from user
aws iam list-attached-user-policies --user-name compromised-user
aws iam detach-user-policy --user-name compromised-user --policy-arn arn:aws:iam::aws:policy/...

// Remove from all groups
aws iam list-groups-for-user --user-name compromised-user
aws iam remove-user-from-group --user-name compromised-user --group-name ...

// Delete console password (prevents console login)
aws iam delete-login-profile --user-name compromised-user

// Revoke role session (for compromised role)
aws iam put-role-policy --role-name compromised-role --policy-name RevokeOldSessions --policy-document '{
    "Version": "2012-10-17",
    "Statement": [{
        "Effect": "Deny",
        "Action": "*",
        "Resource": "*",
        "Condition": {"DateLessThan": {"aws:TokenIssueTime": "2025-01-01T00:00:00Z"}}
    }]
}'

EC2 Instance Containment

// Create forensic snapshot
aws ec2 create-snapshot --volume-id vol-xxx --description "Forensic-2025-001"

// Create quarantine security group (deny all)
aws ec2 create-security-group --group-name Quarantine --description "IR Quarantine" --vpc-id vpc-xxx
# Default SG has no inbound rules, add explicit deny outbound
aws ec2 revoke-security-group-egress --group-id sg-quarantine --protocol all --cidr 0.0.0.0/0

// Apply quarantine SG to instance
aws ec2 modify-instance-attribute --instance-id i-xxx --groups sg-quarantine

// Stop instance (if acceptable)
aws ec2 stop-instances --instance-ids i-xxx

// Remove from auto-scaling group (prevent replacement)
aws autoscaling detach-instances --instance-ids i-xxx --auto-scaling-group-name ASG --should-decrement-desired-capacity

// Disable termination protection (if needed for cleanup)
aws ec2 modify-instance-attribute --instance-id i-xxx --no-disable-api-termination

M365/Office 365 Containment

// Remove malicious inbox rules
Get-InboxRule -Mailbox user@company.com | Where-Object {
    $_.ForwardTo -or $_.ForwardAsAttachmentTo -or $_.RedirectTo -or $_.DeleteMessage
} | Remove-InboxRule -Confirm:$false

// Disable mailbox forwarding
Set-Mailbox -Identity user@company.com -ForwardingSMTPAddress $null -DeliverToMailboxAndForward $false

// Remove delegates
Remove-MailboxPermission -Identity user@company.com -User malicious@attacker.com -AccessRights FullAccess
Remove-RecipientPermission -Identity user@company.com -Trustee malicious@attacker.com -AccessRights SendAs

// Revoke SharePoint/OneDrive sharing
# Via SharePoint Admin Center or:
Remove-SPOExternalUser -UniqueIDs "external-user-id"

// Disable external sharing for site
Set-SPOSite -Identity "https://company.sharepoint.com/sites/sensitive" -SharingCapability Disabled

GCP Containment

// Disable service account
gcloud iam service-accounts disable SA@project.iam.gserviceaccount.com

// Delete service account keys
gcloud iam service-accounts keys list --iam-account=SA@project.iam.gserviceaccount.com
gcloud iam service-accounts keys delete KEY_ID --iam-account=SA@project.iam.gserviceaccount.com

// Remove IAM bindings
gcloud projects remove-iam-policy-binding PROJECT_ID --member='user:compromised@company.com' --role='roles/editor'

// Isolate VM instance
gcloud compute instances remove-tags INSTANCE --tags=allow-external --zone=us-central1-a
gcloud compute instances add-tags INSTANCE --tags=quarantine --zone=us-central1-a

// Create snapshot
gcloud compute disks snapshot DISK --snapshot-names=forensic-snapshot --zone=us-central1-a

// Stop instance
gcloud compute instances stop INSTANCE --zone=us-central1-a

Interview-Ready Answer

"How do you contain threats in cloud environments?"

My Answer:

"Cloud containment differs from on-prem because of IAM-centric access and rapid scalability. My approach: revoke access, isolate resources, preserve evidence.

Revoke IAM Access:
In cloud, identity is the perimeter. I revoke compromised IAM credentials immediately - access keys, service account keys, temporary credentials. I review what roles and policies the compromised identity had to understand what they could have accessed.

Isolate Resources:
I isolate compromised resources using security groups, network ACLs, or VPC policies. Unlike physical networks, I can surgically isolate specific resources while keeping others operational. For compute resources, I might stop instances but preserve the disks for forensics.

Preserve Evidence:
Cloud evidence is volatile - instances can be terminated, logs can be deleted. I snapshot affected resources before making changes, ensure CloudTrail/audit logs are protected, and export logs to secure storage. Evidence preservation happens alongside containment."

💡 Pro Tips for Interview:
  • Understand IAM is the primary containment vector in cloud
  • Know how to isolate with security groups and network policies
  • Preserve evidence before making changes - snapshot instances
  • Remember attackers can delete logs if they have access
