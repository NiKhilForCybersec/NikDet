Security Fundamentals - Visual Guide

These principles are the foundation of everything in cybersecurity. Master these concepts and everything else will make sense. This guide uses visuals and real-world examples to make them stick.

The CIA Triad - The Three Pillars

Every security control, every attack, every risk assessment comes back to these three concepts:

THE CIA TRIAD - VISUALIZED ═══════════════════════════════════════════════════════════════════════════════ Every security control protects one or more of these: CONFIDENTIALITY "Keep secrets secret" /\ / \ / \ / \ / 🔒 \ / \ / \ /______________\ / \ / \ / \ / \ / \ /__________________________\ INTEGRITY AVAILABILITY "Don't let them "Keep it running" change things" WHAT EACH MEANS: ═══════════════════════════════════════════════════════════════════════════════ CONFIDENTIALITY 🔒 ───────────────────────────────────────────────────────────────────────────── "Only authorized people can see the data" Protected by: Attacked by: • Encryption • Data breaches • Access controls • Eavesdropping • DLP (Data Loss Prevention) • Phishing for credentials • MFA • Insider threats Example breach: Attacker steals customer database → Confidentiality FAILED INTEGRITY ✓ ───────────────────────────────────────────────────────────────────────────── "Data hasn't been tampered with" Protected by: Attacked by: • Hashing (checksums) • Man-in-the-middle • Digital signatures • SQL injection • Audit logs • Ransomware (encrypts = modifies) • Version control • Website defacement Example breach: Attacker modifies wire transfer amount → Integrity FAILED AVAILABILITY ⚡ ───────────────────────────────────────────────────────────────────────────── "Systems work when you need them" Protected by: Attacked by: • Redundancy • DDoS attacks • Backups • Ransomware (can't access files) • Load balancing • System destruction • Disaster recovery • Resource exhaustion Example breach: DDoS takes e-commerce site offline during Black Friday → Availability FAILED

🏠 Analogy: Your House

  • Confidentiality: Curtains on windows (people can't see inside)
  • Integrity: Locks on doors (people can't change what's inside)
  • Availability: Working plumbing and electricity (you can use your house)

A break-in affects all three: They saw your stuff (confidentiality), moved things around (integrity), and you can't feel safe using the house (availability).

Authentication Factors - The MFA Deep Dive

AUTHENTICATION FACTORS ═══════════════════════════════════════════════════════════════════════════════ THREE MAIN FACTORS: ┌───────────────────────────────────────────────────────────────────────────────┐ │ │ │ SOMETHING YOU KNOW SOMETHING YOU HAVE SOMETHING YOU ARE │ │ ════════════════ ══════════════════ ═════════════════ │ │ │ │ 🧠 Knowledge 📱 Possession 👤 Inherence │ │ │ │ • Password • Phone (for SMS/app) • Fingerprint │ │ • PIN • Hardware token • Face │ │ • Security question • Smart card • Iris │ │ • Pattern • USB security key • Voice │ │ │ │ Weakness: Weakness: Weakness: │ │ Can be guessed, Can be stolen, Can be spoofed │ │ phished, or leaked cloned, or lost (with effort) │ │ │ └───────────────────────────────────────────────────────────────────────────────┘ MFA = COMBINING DIFFERENT FACTORS: ───────────────────────────────────────────────────────────────────────────── Single Factor (WEAK): Password only └─► Attacker gets password → Game over Two Factor (STRONG): Password + Phone code └─► Attacker gets password → Still needs your phone └─► Attacker gets phone → Still needs your password True MFA requires DIFFERENT factor types: Password + PIN = NOT MFA (both are "something you know") Password + Phone = MFA ✓ (know + have) Password + Fingerprint = MFA ✓ (know + are) WHY MFA MATTERS: ───────────────────────────────────────────────────────────────────────────── Microsoft data: MFA blocks 99.9% of account compromise attacks Without MFA: Phishing email → User enters password → Attacker has access With MFA: Phishing email → User enters password → Attacker needs 2nd factor → Attack fails (usually)

⚠️ MFA Bypass Techniques (What Attackers Try)

  • MFA Fatigue: Spam push notifications until user approves one by accident
  • Real-time Phishing: Tools like Evilginx capture MFA codes as user enters them
  • SIM Swapping: Social engineer carrier to transfer phone number
  • Session Hijacking: Steal cookies AFTER user authenticates

As a SOC analyst: Watch for these patterns - multiple MFA prompts, logins from unexpected locations after successful MFA, etc.

Least Privilege - Only What You Need

LEAST PRIVILEGE PRINCIPLE ═══════════════════════════════════════════════════════════════════════════════ Users should have ONLY the minimum access required to do their job. BAD: Everyone is admin GOOD: Role-based access ────────────────────────── ───────────────────────── ┌─────────────────────┐ ┌─────────────────────┐ │ ALL USERS │ │ STANDARD USERS │ │ │ │ │ │ • Local admin │ │ • Can run apps │ │ • Install anything │ │ • Can save files │ │ • Access all shares │ │ • Can access email │ │ • Modify system │ │ • NO admin rights │ │ │ │ │ └─────────────────────┘ └─────────────────────┘ If ONE user gets ┌─────────────────────┐ compromised → Attacker │ ADMINS (separate) │ has FULL access │ │ │ • Install software │ │ • Modify system │ │ • Time-limited │ │ • Heavily audited │ └─────────────────────┘ REAL EXAMPLE - RANSOMWARE IMPACT: ═══════════════════════════════════════════════════════════════════════════════ WITHOUT least privilege: User: john.doe (has access to ALL file shares) Ransomware runs as john.doe │ ▼ Encrypts EVERYTHING john.doe can access │ ├─► Finance share (encrypted) ├─► HR share (encrypted) ├─► Engineering share (encrypted) └─► Backups share (encrypted) ← Even backups! Encryption - Protecting Data

ENCRYPTION TYPES VISUALIZED ═══════════════════════════════════════════════════════════════════════════════ SYMMETRIC ENCRYPTION - Same key for both ───────────────────────────────────────────────────────────────────────────── Original: "Secret message" │ │ + 🔑 (Key: "password123") ▼ Encrypted: "Xk9#mP2$vL..." │ │ + 🔑 (Same key: "password123") ▼ Decrypted: "Secret message" Use case: Encrypting files, disk encryption, VPN tunnels Examples: AES-256, ChaCha20 Speed: FAST (good for large amounts of data) Challenge: How do you share the key securely? ASYMMETRIC ENCRYPTION - Different keys ───────────────────────────────────────────────────────────────────────────── Two keys: 🔑 Public (share with everyone) 🗝️ Private (keep SECRET) SENDING A MESSAGE: Original: "Secret message" │ │ + 🔑 (Recipient's PUBLIC key) ▼ Encrypted: "Xk9#mP2$vL..." │ │ + 🗝️ (Recipient's PRIVATE key) ▼ Decrypted: "Secret message" Use case: Key exchange, digital signatures, HTTPS Examples: RSA, ECC Speed: SLOW (only for small data) Benefit: No need to share secret key! HASHING - One-way transformation ───────────────────────────────────────────────────────────────────────────── Original: "password123" │ │ Hash function (SHA-256) ▼ Hash: "ef92b778bafe771e89245b89ecbc08a44a4e166c..." KEY POINT: Cannot reverse! You can't get "password123" from the hash. Use case: Password storage, file integrity verification Examples: SHA-256, bcrypt, Argon2 How password checking works: 1. User creates password "MyP@ss123" 2. System stores hash: "a1b2c3..." 3. User logs in, enters "MyP@ss123" 4. System hashes input: "a1b2c3..." 5. Compare hashes: Match! ✓ Access granted Attacker steals database → Gets hashes, not passwords (Still need to crack them)

Understanding Risk

THE RISK EQUATION ═══════════════════════════════════════════════════════════════════════════════ ┌─────────────────────────────────────────────────────────────────┐ │ │ │ RISK = THREAT × VULNERABILITY × IMPACT │ │ │ └─────────────────────────────────────────────────────────────────┘ THREAT: Someone/something that could exploit a weakness VULNERABILITY: A weakness that could be exploited IMPACT: The damage if exploitation succeeds EXAMPLE CALCULATION: ═══════════════════════════════════════════════════════════════════════════════ Scenario: Unpatched web server THREAT: Ransomware groups scanning for this vulnerability (High - active exploitation in the wild) VULNERABILITY: Known CVE with public exploit (High - easy to exploit) IMPACT: Server hosts customer payment data (Critical - regulatory fines, reputation damage) RISK = High × High × Critical = CRITICAL RISK Action: Patch IMMEDIATELY REDUCING RISK: ═══════════════════════════════════════════════════════════════════════════════ You can reduce any component: Reduce THREAT: • Threat doesn't exist or isn't targeting you • Example: Air-gapped system (no internet = fewer threats) Reduce VULNERABILITY: • Patch systems • Secure configuration • Example: Apply the security update Reduce IMPACT: • Backups (ransomware impact reduced) • Encryption (stolen data is useless) • Example: Move sensitive data to more secure system If ANY component is ZERO, risk is ZERO: • No threat targeting you? Risk = 0 • Vulnerability patched? Risk = 0 • No impact if exploited? Risk = 0
