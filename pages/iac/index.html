Infrastructure as Code (IaC)

Learn how to manage infrastructure through code - what it is, why it matters for security, and how to use it effectively.

What is Infrastructure as Code?

Infrastructure as Code (IaC) means writing code (text files) that describe what infrastructure you want, and then using tools to automatically create that infrastructure for you.

Instead of:

  • Clicking through Azure/AWS console to create a VM
  • Manually configuring firewall rules one by one
  • Remembering what settings you used last time

You write code like this:

# This creates a virtual machine in Azure
resource "azurerm_virtual_machine" "web_server" {
  name                = "web-server-01"
  location            = "East US"
  vm_size             = "Standard_D2s_v3"
  
  # Security: Only allow SSH from specific IP
  network_security_group = azurerm_network_security_group.web_nsg.id
}

Then run one command, and the infrastructure is created exactly as specified.

Think of it like this

Without IaC: Building a house by telling workers verbally what to do each day. If something goes wrong, you have to remember what you said and re-explain everything.

With IaC: Building a house from detailed blueprints. Anyone can look at the blueprints to see exactly what was built. If the house burns down, you can rebuild it exactly the same from the blueprints.

Why Security Teams Should Care About IaC

As a security professional, IaC affects your work in several important ways:

1 You Can Review Changes BEFORE Deployment

When infrastructure is defined as code, security can review proposed changes in a pull request - just like reviewing application code. You can catch misconfigurations before they reach production.

Example: Developer creates PR to add new VM. You see they forgot to enable encryption. You comment, they fix it, then it deploys correctly.

2 Complete Audit Trail

Every infrastructure change is recorded in Git with who made it, when, and why. No more "who opened that firewall port?" mysteries.

git log --oneline
a1b2c3d - John: Add web server firewall rules (2024-01-15)
d4e5f6g - Sarah: Enable storage encryption (2024-01-14)
g7h8i9j - Mike: Create production VNet (2024-01-13)

3 Automated Security Scanning

Tools can automatically scan IaC files for security issues before deployment. This catches problems like:

  • Storage buckets set to public
  • Databases without encryption
  • Overly permissive security groups
  • Missing logging configuration

4 Consistent Security Baseline

When you define infrastructure as code, every environment (dev, staging, prod) is built the same way. No more "prod has different firewall rules than staging" problems.

Before vs After IaC

ScenarioWithout IaC (Manual)With IaC
Creating new server Click through console, might forget security settings Copy existing template, security built-in
Investigating incident "What were the firewall rules on Jan 15?" - Nobody knows Check git history for that date - exact rules documented
Disaster recovery Rebuild everything manually from memory Run terraform apply - rebuilt in minutes
Security review Log into each system, check settings manually Search code: "find all public storage buckets"

Types of IaC Tools (Simplified)

Two Main Categories You Need to Know

CategoryWhat It DoesMain ToolsExample Use
Provisioning
"Creating infrastructure"		 Creates cloud resources: VMs, networks, databases, storage Terraform, Pulumi, CloudFormation Create a new Azure VM with network and storage
Configuration
"Setting up servers"		 Configures what's ON a server: packages, settings, files Ansible, Puppet, Chef Install and configure nginx on all web servers
Key Insight: You often use both together! Terraform creates the VMs, then Ansible configures what's on them.

Common IaC Security Issues to Look For

IssueWhat It Looks Like in CodeRisk
Hardcoded Secrets password = "MyP@ssw0rd123" Credentials exposed in source control
Public Storage acl = "public-read" Anyone on internet can read your data
Open Security Groups cidr_blocks = ["0.0.0.0/0"] Database/admin ports open to internet
No Encryption encrypted = false Data at rest not protected
No Logging Missing logging configuration blocks Can't investigate incidents
