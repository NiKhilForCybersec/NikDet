Network Containment

Procedures for network-level containment including IP blocks, DNS sinkhole, and firewall rules.

SeverityHigh
TierAll Tiers

N/A

Overview

Procedures for network-level containment including IP blocks, DNS sinkhole, and firewall rules. This playbook provides systematic procedures applicable across any security environment.

When to Use This Playbook

Use this playbook when you encounter alerts or incidents matching the description above. It provides step-by-step guidance for efficient handling.

Prerequisites

Required Access

  • SIEM - Microsoft Sentinel or Splunk for log analysis
  • EDR - Endpoint detection and response platform
  • Identity - Azure AD / Active Directory access
  • Network - Firewall, proxy, DNS logs

Procedure

1
Initial Assessment
Gather context about the alert or incident:
  • Review alert details and severity
  • Identify affected users, hosts, or systems
  • Determine timeline of events
  • Check for related alerts
2
Evidence Collection
Gather relevant data for analysis:
  • Query SIEM for related events
  • Pull endpoint telemetry from EDR
  • Collect network flow data if applicable
  • Preserve volatile evidence if needed
3
Analysis
Analyze collected evidence to determine:
  • Is this a true positive or false positive?
  • What is the full scope of impact?
  • What was the attack vector/technique?
  • Are there additional indicators of compromise?
4
Containment
If confirmed malicious, execute containment:
  • Isolate affected systems if needed
  • Block malicious indicators
  • Disable compromised accounts
  • Prevent further spread
5
Documentation & Closure
Complete the investigation:
  • Document all findings
  • Record IOCs for threat intel
  • Update ticket with timeline
  • Determine final classification

Decision Tree

Is this a confirmed security incident?
NO → Close as False Positive with documentation
YES → Execute containment, continue investigation
Is escalation required?
NO → Complete remediation, close incident
YES → Escalate to IR team with all findings

Investigation Queries

KQL Example

Sentinel
// Investigate related events
let TimeRange = ago(24h);
let Target = "entity-to-investigate";
search in (SecurityEvent, SigninLogs, DeviceEvents)
| where TimeGenerated > TimeRange
| where * contains Target
| project TimeGenerated, Type, Activity
| order by TimeGenerated desc

SPL Example

Splunk
index=* earliest=-24h "entity-to-investigate"
| stats count by index sourcetype _time
| sort - _time
