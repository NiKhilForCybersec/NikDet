Defense in Depth

Layer security controls so that failure of one doesn't mean total compromise.

The Castle Model

Defense in depth is inspired by medieval castle design: multiple walls, moats, guards, and inner keeps. If attackers breach one layer, they face another.

Layer 1: Perimeter - Firewall, WAF, Email Gateway
Layer 2: Network - Segmentation, IDS/IPS, NDR
Layer 3: Endpoint - EDR, AV, DLP, Hardening
Layer 4: Application - WAF, Input Validation, Auth
Layer 5: Data - Encryption, Access Controls, DLP

Example Attack Path

ATTACK SCENARIO: Phishing to Data Exfiltration
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

1. Initial Access (Email)
   Attack: Phishing email with malicious attachment
   Defense: Email gateway blocks known malware
   ✓ Blocked or → Bypassed (new malware)

2. Execution (Endpoint)
   Attack: User opens attachment, macro executes
   Defense: EDR detects suspicious process behavior
   ✓ Detected or → Bypassed (obfuscation)

3. Persistence (Endpoint)
   Attack: Scheduled task created
   Defense: EDR alerts on persistence mechanism
   ✓ Detected or → Bypassed (LOLBin)

4. Lateral Movement (Network)
   Attack: Move to server via RDP
   Defense: Network segmentation blocks access
   ✓ Blocked or → Bypassed (compromised admin)

5. Collection (Data)
   Attack: Access sensitive database
   Defense: DLP detects bulk data access
   ✓ Detected or → Bypassed (encryption)

6. Exfiltration (Network)
   Attack: Upload data to cloud storage
   Defense: Web proxy blocks unauthorized upload
   ✓ Blocked

With multiple layers, even if some are bypassed,
others provide detection and prevention opportunities.

Key Principles

  • Diversity: Use controls from different vendors to avoid single point of failure
  • Redundancy: Multiple controls for the same risk
  • Visibility: Each layer provides detection opportunities
  • Fail-safe: If one layer fails, others continue to protect
