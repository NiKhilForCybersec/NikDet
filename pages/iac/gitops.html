GitOps & CI/CD for Infrastructure

Git as the single source of truth for infrastructure: declarative, versioned, automated, and auditable.

What is GitOps?

GitOps Principles
  • Declarative: Entire system described declaratively in Git
  • Versioned: All changes tracked with full audit trail
  • Automated: Approved changes automatically applied
  • Reconciled: System continuously ensures actual = desired state

GitOps Models

ModelHow It WorksTools
Push-basedCI/CD pushes changes to cluster after mergeGitHub Actions, GitLab CI, Jenkins
Pull-basedAgent in cluster pulls changes from GitArgoCD, Flux, Rancher Fleet

ArgoCD Application Definition

# argocd-application.yaml
apiVersion: argoproj.io/v1alpha1
kind: Application
metadata:
  name: my-application
  namespace: argocd
spec:
  project: default
  
  source:
    repoURL: https://github.com/company/k8s-manifests.git
    targetRevision: main
    path: applications/my-app
    
    # For Helm charts
    helm:
      valueFiles:
        - values-prod.yaml
      parameters:
        - name: image.tag
          value: "1.2.3"
  
  destination:
    server: https://kubernetes.default.svc
    namespace: production
  
  syncPolicy:
    automated:
      prune: true       # Delete resources not in Git
      selfHeal: true    # Revert manual changes
    syncOptions:
      - CreateNamespace=true
    retry:
      limit: 5
      backoff:
        duration: 5s
        factor: 2
        maxDuration: 3m

Security Considerations

GitOps Security
  • No secrets in Git: Use Sealed Secrets, External Secrets, or Vault
  • Branch protection: Require PR reviews for main/prod branches
  • Signed commits: GPG/SSH signing for auditability
  • RBAC: Limit who can approve changes to production
  • Audit logs: All Git operations and ArgoCD syncs logged

Sealed Secrets Example

# Install sealed-secrets controller
kubectl apply -f https://github.com/bitnami-labs/sealed-secrets/releases/download/v0.24.0/controller.yaml

# Create a regular secret (locally, don't commit!)
kubectl create secret generic db-creds \
  --from-literal=username=admin \
  --from-literal=password=supersecret \
  --dry-run=client -o yaml > secret.yaml

# Seal the secret (safe to commit)
kubeseal --format yaml < secret.yaml > sealed-secret.yaml

# sealed-secret.yaml (safe to commit to Git)
apiVersion: bitnami.com/v1alpha1
kind: SealedSecret
metadata:
  name: db-creds
spec:
  encryptedData:
    username: AgBQx5T...  # Encrypted with cluster's public key
    password: AgCMk9p...

CI/CD Pipeline Stages

1
Lint & Validate

terraform fmt, terraform validate, yamllint, kubeval

2
Security Scan

Checkov, tfsec, Trivy for misconfigurations

3
Plan/Diff

terraform plan, argocd app diff

4
Review

Human review of plan output in PR

5
Apply

terraform apply, ArgoCD sync (auto or manual)

6
Verify

Smoke tests, health checks, rollback if needed
