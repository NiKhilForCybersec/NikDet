It's critical because most attacks come through the web - phishing links, malware downloads, and data exfiltration. The key capability is SSL inspection, which lets you see inside encrypted traffic where 95% of threats now hide. Without SSL inspection, you're essentially blind to most web-based attacks." Q: "How does SSL inspection work and what are the challenges?" ───────────────────────────────────────────────────────────────────────────── A: "SSL inspection works by terminating the TLS connection at the SWG, decrypting the traffic, inspecting it, then re-encrypting with a certificate signed by a CA the user trusts. You deploy the SWG's root CA to all endpoints so they trust these re-signed certificates. Challenges include: certificate-pinned applications that break, privacy concerns for categories like banking and healthcare, performance impact, and ensuring proper certificate deployment. You need a clear exception policy for apps that can't be inspected." Q: "What traffic forwarding method would you use for remote users?" ───────────────────────────────────────────────────────────────────────────── A: "For remote users, I'd use the Client Connector agent. It creates an encrypted tunnel to the nearest Zscaler data center regardless of what network the user is on - home, coffee shop, or airport WiFi. This gives consistent protection everywhere without requiring VPN. For deployment, I'd use MDM for managed devices with silent install, and optionally a PAC file as backup for devices that can't run the connector." Q: "How would you roll out a cloud SWG to an enterprise?" ───────────────────────────────────────────────────────────────────────────── A: "I'd take a phased approach. Phase 1: Configure IdP integration and deploy the client connector to a pilot group - usually IT. Start with logging only, no blocking. Phase 2: Deploy the SSL inspection certificate and enable inspection with proper exceptions. Phase 3: Enable URL filtering with baseline policies - block security risks first, then unacceptable content. Phase 4: Enable advanced threat protection and DLP. Throughout, use report-only mode before blocking, and have a clear process for handling exception requests."

Secure Web Gateway Overview

💡 Interview Answer: What is a Secure Web Gateway?

"A Secure Web Gateway is a security solution that sits between users and the internet, inspecting all web traffic to protect against threats and enforce policies. Key functions include URL filtering, SSL/TLS inspection, malware scanning, application control, and data loss prevention. Cloud-based SWGs like Zscaler ZIA can protect users regardless of location."

SSL Inspection Configuration

💡 Interview Answer: How does SSL inspection work?

"SSL inspection performs a man-in-the-middle operation on HTTPS traffic. When a user connects to an HTTPS site, the proxy intercepts and terminates the connection. It establishes a new encrypted session with the destination, decrypts the traffic, inspects it for threats/policy violations, then re-encrypts using its own certificate before sending to the user. The user's device must trust the proxy's CA certificate."

SSL Inspection Setup

# Step 1: Download Zscaler Root CA Administration → SSL Inspection → Intermediate CA Certificate → Download Zscaler Root CA # Step 2: Deploy CA to Devices Windows (GPO): Computer Configuration → Policies → Windows Settings → Security Settings → Public Key Policies → Trusted Root Certification Authorities → Import Zscaler Root CA macOS (MDM/Jamf): Configuration Profile → Certificate Upload Zscaler Root CA Trust Settings: SSL, Always Trust iOS/Android (MDM): Push CA certificate via MDM profile Device automatically trusts for SSL # Step 3: Enable SSL Inspection Policy Policy → SSL Inspection → Add Rule Rule 1: Inspect All (except bypass list) Name: Inspect-All-Traffic Action: Inspect URL Categories: All Users: All Rule 2: Do Not Inspect (bypass) Name: SSL-Bypass-List Action: Do Not Inspect URL Categories: - Financial Services - Health - Government Custom URLs: - *.bankofamerica.com - *.chase.com - *.healthcare.gov

SSL Bypass Best Practices

# DO NOT INSPECT (Add to Bypass List) Certificate Pinning Apps: - Windows Update (*.windowsupdate.com) - Apple services (*.apple.com) - Microsoft Office (*.office.com, *.office365.com) - Zoom (*.zoom.us) - Webex (*.webex.com) Compliance/Privacy: - Banking sites (*.bankofamerica.com, *.chase.com) - Healthcare portals (HIPAA compliance) - Government sites (*.gov) - HR/Benefits (employee privacy) Performance: - Video conferencing (already encrypted, adds latency) - Large software downloads (Windows ISO, etc.) # ALWAYS INSPECT (Never bypass) - Social media - Webmail - Cloud storage - Unknown/uncategorized sites - High-risk categories
⚠️ Common SSL Inspection Issues:
  • Certificate errors: Zscaler CA not trusted on device
  • App failures: Certificate pinning (add to bypass)
  • Performance: Decrypt/re-encrypt adds latency
  • Mobile apps: Some apps don't work with inspection
