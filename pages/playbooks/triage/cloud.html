Cloud Alert Triage

Procedures for triaging cloud security alerts from Azure, AWS, GCP, and M365 environments.

Common Cloud Alert Types

Alert TypeSeverityPlatforms
Unusual API ActivityMedium-HighAll clouds
Resource ExposureHighStorage, databases public
Privilege EscalationHighIAM changes
Suspicious LoginMediumConsole/CLI access
Resource CreationMediumNew compute, storage
Security Group ChangeMedium-HighNetwork rules modified
Cryptomining DetectedHighCompute abuse

Step 1: Identify the Activity

QuestionWhat It Tells You
What resource was affected?VM, storage, IAM, networking
Who performed the action?User, service principal, root
What action was taken?Create, modify, delete, access
From where?Console, CLI, API, unusual IP

Step 2: Context Queries

// Azure: Activity for specific user
AzureActivity
| where TimeGenerated > ago(24h)
| where Caller == "user@company.com"
| project TimeGenerated, OperationName, ResourceGroup, Resource, ActivityStatus, CallerIpAddress

// Azure: Role assignment changes
AzureActivity
| where OperationName has "role"
| project TimeGenerated, InitiatedBy=Caller, OperationName, TargetResources=Resource

// Azure: Storage account exposure
AzureActivity
| where ResourceProvider == "Microsoft.Storage"
| where OperationName has_any ("networkRules", "publicAccess", "anonymousAccess")
| project TimeGenerated, Caller, OperationName, Resource

Step 3: Decision Tree

QuestionIf YESIf NO
Is this known/expected change?Verify with change ticket → CloseContinue
Was it performed by expected identity?May be legitimate → Verify with ownerUnexpected user → Escalate
Does it expose data/resources?High priority → Revert immediatelyAssess other impact

Platform-Specific Checks

PlatformKey Areas
AzureRole assignments, Storage public access, NSG rules, Key Vault access
AWSIAM policies, S3 bucket policies, Security Groups, CloudTrail
GCPIAM bindings, GCS permissions, Firewall rules, Audit logs
M365SharePoint sharing, Teams external access, App permissions

High-Risk Cloud Events

  • Root/Owner account used unexpectedly
  • Resource exposed to public internet (0.0.0.0/0)
  • Privilege escalation to admin role
  • Unusual resource creation (especially compute)
  • Security group/firewall opened wide
  • API keys or secrets accessed unusually
  • Cross-account/tenant access changes

Escalation Criteria

  • Data or resource exposed to public internet
  • Unauthorized privilege escalation
  • Root/global admin account compromise suspected
  • Unusual resource creation (cryptomining)
  • Large-scale changes across multiple resources
