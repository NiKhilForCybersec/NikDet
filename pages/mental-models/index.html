Security Mental Models

Frameworks for thinking about security architecture, strategy, and decisions. These models help you make better decisions faster.

What Are Mental Models?

Mental models are simplified frameworks for understanding complex systems. Instead of thinking through every detail from scratch, you apply a proven pattern.

Why they matter in security:

  • Security decisions are complex with many trade-offs
  • Good models help you avoid common mistakes
  • They give you a shared language with other professionals
  • They help you explain decisions to non-security people

Example: Instead of listing 50 security controls, you can say "we're applying defense in depth" - and security people immediately understand the strategy.

Essential Mental Models

Defense in Depth

"Multiple layers of security so one failure doesn't mean total compromise"

The Concept: Don't rely on a single security control. Stack multiple controls so if one fails, others still protect you.

Perimeter (Firewall, WAF)
Network (Segmentation, IDS)
Host (EDR, Hardening)
Application (Auth, Input Validation)
Data (Encryption, DLP)
Use this model when:
  • Designing security architecture
  • Justifying multiple security tools
  • Explaining why single points of failure are bad

Assume Breach

"Design your defenses assuming attackers are already inside"

The Concept: Traditional security focuses on keeping attackers OUT. Modern security accepts that breaches happen and focuses on detecting/containing attackers who get IN.

Old Mindset (Perimeter Only)Assume Breach Mindset
"Our firewall will keep them out""When they get past the firewall, what then?"
Trust everything inside the networkVerify everything, trust nothing
Detect attacks at the perimeterDetect lateral movement inside
Incident response is rareDetection and response is continuous
Use this model when:
  • Prioritizing detection investments
  • Designing internal network security
  • Building incident response capabilities

Zero Trust

"Never trust, always verify - regardless of network location"

The Concept: Being on the "corporate network" doesn't make you trusted. Every access request must be verified based on identity, device health, and context.

Core Principles:

  1. Verify explicitly: Authenticate and authorize based on all available data points
  2. Least privilege access: Limit access to only what's needed, only when needed
  3. Assume breach: Minimize blast radius, segment access, encrypt everything
Use this model when:
  • Designing access control for cloud resources
  • Planning remote work security
  • Modernizing legacy network security

Three Planes Model

"Separate your data plane, control plane, and management plane"

The Concept: Complex systems have three distinct "planes" that need different security approaches:

PlaneWhat It DoesSecurity Focus
Data Plane Where actual data flows (user traffic) Encryption, DLP, access controls
Control Plane What makes routing/policy decisions Authentication, integrity, availability
Management Plane Where admins configure the system Strong auth, audit logging, least privilege
Use this model when:
  • Securing cloud infrastructure
  • Designing network architecture
  • Threat modeling complex systems

Crown Jewels

"Identify and prioritize protection of your most critical assets"

The Concept: You can't protect everything equally. Identify your "crown jewels" (most critical assets) and focus your best security there.

How to Identify Crown Jewels:

  • What data would cause the most damage if stolen?
  • What systems would halt operations if unavailable?
  • What would regulators/customers care most about?
  • What would attackers specifically target?

Examples: Customer PII, financial data, trade secrets, production databases, domain controllers, authentication systems.

Use this model when:
  • Prioritizing security investments
  • Designing monitoring strategies
  • Planning incident response priorities

How to Use Mental Models

Practical Application
  1. Learn the vocabulary: Know the key models so you can communicate efficiently
  2. Apply during design: When building something new, ask "which models apply here?"
  3. Use to explain: Models help justify decisions to leadership
  4. Challenge your thinking: If a decision violates a model, make sure you know why
  5. Combine models: Real situations often need multiple models together
