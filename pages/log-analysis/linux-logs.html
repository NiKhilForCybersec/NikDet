Linux Log Analysis

Master Linux logging for server and cloud infrastructure security monitoring.

Linux Logging Overview

Linux systems use multiple logging mechanisms. Understanding where to find logs and what they contain is critical for investigating Linux-based attacks.

Log Locations

Authentication Logs (auth.log/secure)

Primary source for SSH, sudo, and authentication events.

SSH Events

# Successful SSH login
Jan 15 14:23:45 server sshd[12345]: Accepted publickey for admin from 192.168.1.100 port 52341 ssh2

# Failed SSH login
Jan 15 14:23:50 server sshd[12346]: Failed password for admin from 10.0.0.50 port 43210 ssh2

# Invalid user attempt
Jan 15 14:24:01 server sshd[12347]: Invalid user hacker from 45.33.32.156 port 38472

# SSH session closed
Jan 15 15:30:00 server sshd[12345]: Disconnected from user admin 192.168.1.100 port 52341

Sudo Events

# Successful sudo
Jan 15 14:30:00 server sudo: admin : TTY=pts/0 ; PWD=/home/admin ; USER=root ; COMMAND=/bin/cat /etc/shadow

# Failed sudo (wrong password)
Jan 15 14:30:15 server sudo: admin : 3 incorrect password attempts ; TTY=pts/0 ; PWD=/home/admin ; USER=root ; COMMAND=/bin/bash

# User not in sudoers
Jan 15 14:30:30 server sudo: attacker : user NOT in sudoers ; TTY=pts/1 ; PWD=/tmp ; USER=root ; COMMAND=/bin/bash

Auditd - Linux Audit System

Auditd provides detailed, configurable system auditing. Far more comprehensive than syslog.

Audit Log Format

type=SYSCALL msg=audit(1705330800.123:456): arch=c000003e syscall=59 success=yes exit=0 
  a0=7fff12345678 a1=7fff12345680 a2=7fff12345700 a3=0 items=2 ppid=1234 pid=5678 
  auid=1000 uid=0 gid=0 euid=0 suid=0 fsuid=0 egid=0 sgid=0 fsgid=0 tty=pts0 
  ses=1 comm="bash" exe="/bin/bash" key="shell_execution"

Key Fields:
type:     Event type (SYSCALL, EXECVE, PATH, etc.)
syscall:  System call number (59 = execve)
auid:     Audit UID (original login UID - survives sudo)
uid:      Effective UID at time of event
exe:      Executable that made the call
key:      Custom rule tag

Critical Audit Rules

# /etc/audit/rules.d/security.rules

# Monitor user/group changes
-w /etc/passwd -p wa -k identity
-w /etc/shadow -p wa -k identity
-w /etc/group -p wa -k identity
-w /etc/sudoers -p wa -k sudoers

# Monitor privilege escalation
-a always,exit -F arch=b64 -S setuid -S setgid -k priv_escalation

# Monitor process execution
-a always,exit -F arch=b64 -S execve -k exec

# Monitor network connections
-a always,exit -F arch=b64 -S connect -k network

# Monitor file deletions
-a always,exit -F arch=b64 -S unlink -S unlinkat -k delete

# Monitor cron
-w /etc/crontab -p wa -k cron
-w /etc/cron.d/ -p wa -k cron
-w /var/spool/cron/ -p wa -k cron

Parsing Audit Logs

# Search for specific key
ausearch -k identity

# Search by time range
ausearch --start today --end now

# Search for failed events
ausearch --success no

# Search by user (auid)
ausearch -ua 1000

# Generate report
aureport --summary
aureport --auth
aureport --login

Journald (systemd)

Modern Linux systems use journald for centralized logging.

# View all logs
journalctl

# View SSH logs
journalctl -u sshd

# View logs since boot
journalctl -b

# View logs in time range
journalctl --since "2025-01-15 14:00" --until "2025-01-15 16:00"

# Follow logs (like tail -f)
journalctl -f

# View kernel messages
journalctl -k

# Output as JSON
journalctl -o json-pretty

Useful Commands for Investigation

# Last logins
last -a

# Failed logins
lastb -a

# Currently logged in users
w
who

# User's last login
lastlog

# Search auth logs for IP
grep "192.168.1.100" /var/log/auth.log

# Count failed SSH attempts by IP
grep "Failed password" /var/log/auth.log | awk '{print $(NF-3)}' | sort | uniq -c | sort -rn | head

# Find all SSH accepted logins
grep "Accepted" /var/log/auth.log

# Check cron logs
grep CRON /var/log/syslog

Attack Indicators in Linux Logs

Attack TypeLog SourceWhat to Look For
SSH Brute Force auth.log Many "Failed password" from same IP
Credential Stuffing auth.log Failed logins for multiple users from same IP
Privilege Escalation auth.log, audit "NOT in sudoers", setuid syscalls
Persistence audit, cron crontab modifications, new services
Lateral Movement auth.log SSH from internal IPs, unusual times
Data Access audit Access to /etc/shadow, sensitive files

Log Forwarding

Forward Linux logs to your SIEM using rsyslog or Elastic Agent:

# /etc/rsyslog.d/50-siem.conf
*.* @@siem.company.com:514    # TCP
*.* @siem.company.com:514     # UDP
