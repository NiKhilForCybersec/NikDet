Investigation Decision Trees

Step-by-step decision guides for common alert types. Follow the questions to reach the right conclusion.

Authentication Alert Decision Tree

Start: You received an authentication alert (failed logins, unusual location, etc.)

Q1: Is the user account a service account or automated process?

  • YES → Check if there's a known issue with the service. Check with service owner. If expected, tune the alert. If unexpected, investigate as potential credential compromise.
  • NO → Continue to Q2

Q2: Did the authentication succeed?

  • NO (Failed) → Go to Failed Auth Tree (below)
  • YES (Succeeded) → Continue to Q3

Q3: Is the source IP/location normal for this user?

  • YES → Check if behavior after login is normal. If yes, likely false positive. Document and close.
  • NO → Continue to Q4

Q4: Could the unusual location be explained by VPN, travel, or mobile carrier?

  • YES → Verify with user if possible. If confirmed legitimate, document and close.
  • NO → Continue to Q5

Q5: Was MFA completed successfully?

  • NO (MFA failed or bypassed) → HIGH RISK - Likely compromise. Reset password, revoke sessions, investigate.
  • YES → Continue to Q6

Q6: Is there suspicious post-login activity?

(Inbox rules, mass file access, privilege changes, unusual applications)

  • YES → CONFIRMED COMPROMISE - Escalate immediately. Contain and investigate.
  • NO → Contact user to verify. If user confirms it was them, document and close. If user denies, treat as compromise.

Failed Authentication Tree

Start: Multiple failed authentication attempts detected

Q1: How many failed attempts?

  • 1-5 attempts → Likely user typo or forgot password. Low priority unless pattern continues.
  • 6-20 attempts → Suspicious. Continue to Q2.
  • 20+ attempts → Likely automated attack. Continue to Q2 with high priority.

Q2: Is it one account from one source, one account from many sources, or many accounts from one source?

  • One account, one source → Targeted brute force. Check if source is internal or external. Block source if external.
  • One account, many sources → Distributed brute force or credential stuffing. High priority. Consider disabling account temporarily.
  • Many accounts, one source → Password spray attack. HIGH PRIORITY - Check if any succeeded. Block source.

Q3: Did any attempt eventually succeed?

  • YES → POTENTIAL COMPROMISE - Go back to Authentication Alert Tree Q3
  • NO → Attack was unsuccessful. Block source, document, and monitor for retry.

Malware Detection Decision Tree

Start: AV/EDR detected malware on endpoint

Q1: What type of malware was detected?

  • Ransomware → CRITICAL - Isolate immediately. Do not wait. Then continue investigation.
  • RAT/Backdoor → HIGH - Isolate. Check for C2 communication. Continue investigation.
  • Trojan/Infostealer → HIGH - May need credential reset. Continue to Q2.
  • Worm → HIGH - Check for spread to other systems. Continue to Q2.
  • PUA/Adware → LOW - Usually low risk. Verify cleaned. Document and close.

Q2: Was the malware blocked/quarantined or did it execute?

  • Blocked before execution → Lower risk. Continue to Q3 to check for other indicators.
  • Executed before detection → Higher risk. Assume compromise. Continue to Q4.
  • Unknown → Check process creation logs. Assume executed if uncertain.

Q3: How did the malware arrive?

  • Email attachment → Check who else received. Search for same attachment hash across mailboxes.
  • Web download → Check what site. Was it categorized? Should it be blocked?
  • USB/Removable media → Check USB policy. Who plugged in the device?
  • Network share/Lateral movement → HIGH - There's already a compromised system. Find it.
  • Unknown → Need more investigation. Check parent process, file creation time.

Q4: Is there evidence of C2 communication?

  • YES → CONFIRMED COMPROMISE - Full IR response. Block C2 IOCs. Check all systems.
  • NO → Check for persistence mechanisms. If none found, may have been caught early. Still verify cleaned.

Q5: Are other systems affected?

  • YES → Scope is larger. Escalate. Need coordinated response.
  • NO → Contained to single system. Clean, verify, document.

Phishing Email Decision Tree

Start: User reported suspicious email or email gateway flagged potential phishing

Q1: Is the email actually phishing?

Check: Sender domain (typosquatting?), Reply-to mismatch, Urgent language, Suspicious links, Attachment type

  • Not phishing → Thank user for reporting. Explain why it's legitimate. Close.
  • Confirmed phishing → Continue to Q2
  • Uncertain → Check URL in sandbox. Check attachment in sandbox. Then decide.

Q2: What type of phishing is it?

  • Credential harvesting (fake login page) → Focus on who clicked and who submitted credentials
  • Malware delivery (attachment or link to download) → Focus on who opened attachment or downloaded file
  • BEC (no link/attachment, just asking for action) → Focus on whether anyone took the requested action

Q3: How many people received this email?

  • Just the reporter → Targeted spear phishing. Higher sophistication. Continue to Q4.
  • Multiple users → Campaign. Need to check all recipients. Continue to Q4.

Q4: Did anyone click the link or open the attachment?

  • NO → Good! Block IOCs. Delete from mailboxes. Notify recipients. Close.
  • YES → Continue to Q5

Q5: Did anyone submit credentials or execute malware?

  • NO (clicked but didn't submit/execute) → Users who clicked need awareness reminder. Block IOCs. Close.
  • YES, credentials submitted → COMPROMISE - Reset passwords. Revoke sessions. Check for abuse.
  • YES, malware executed → COMPROMISE - Go to Malware Detection Tree.

Suspicious Process Decision Tree

Start: Alert on suspicious process execution (unusual parent-child, suspicious command line, etc.)

Q1: Is the process a known legitimate tool?

(PowerShell, cmd, certutil, mshta, regsvr32, etc.)

  • YES, known tool → These are dual-use (legitimate and attack tool). Continue to Q2.
  • NO, unknown executable → Check hash reputation. If malicious, go to Malware Tree. If unknown, continue to Q2.

Q2: What is the parent process?

  • explorer.exe → User initiated. Check if user action makes sense.
  • Office application (WINWORD, EXCEL, OUTLOOK) → SUSPICIOUS - May be macro malware. Check for document.
  • Browser (chrome, firefox, edge) → May be download and execute. Check what was downloaded.
  • IT management tool (SCCM, Intune, etc.) → Likely IT activity. Verify with IT.
  • Script host (wscript, cscript) → Check what script ran. Often malicious.
  • Unusual parent → SUSPICIOUS - May indicate injection or unusual execution chain.

Q3: What does the command line contain?

  • Encoded/obfuscated content → SUSPICIOUS - Decode and analyze. Often malicious.
  • Downloads from internet → SUSPICIOUS - Check what's being downloaded.
  • Accesses sensitive paths → Check if accessing LSASS, SAM, or other sensitive files.
  • Normal-looking commands → May still be suspicious based on context. Continue to Q4.

Q4: What happened after this process ran?

  • Nothing notable → May have been blocked or benign. Document and monitor.
  • Network connections to unusual IPs → Check for C2. May be compromise.
  • File creation in unusual locations → Check files. May be malware dropping payload.
  • Child processes spawned → Follow the process tree. Attack chains have multiple steps.

Data Exfiltration Decision Tree

Start: Alert on potential data exfiltration (DLP, large transfer, unusual destination)

Q1: What type of data is involved?

  • PII (SSN, personal info) → Regulatory implications. Higher priority.
  • Financial data → High business impact. Higher priority.
  • Source code/IP → Competitive impact. Higher priority.
  • General business data → Assess sensitivity. May be lower priority.

Q2: Where is the data going?

  • Personal email (Gmail, Yahoo) → SUSPICIOUS - Why not use corporate email?
  • Personal cloud storage (Dropbox, GDrive personal) → SUSPICIOUS - Policy violation at minimum.
  • Known partner/vendor → May be legitimate. Verify with data owner.
  • Unknown external destination → HIGH RISK - Investigate immediately.
  • USB/Removable media → Check if user has business need. Often policy violation.

Q3: Who is the user and what is their role?

  • Role requires data access → May be legitimate but improper method. Verify with manager.
  • Role doesn't require this data → SUSPICIOUS - Why do they have it?
  • Departing employee → HIGH RISK - Possible data theft. Escalate to HR/Legal.
  • New employee → SUSPICIOUS - May not understand policies, or may be malicious.

Q4: Was the transfer blocked or allowed?

  • Blocked → Data protected. Still investigate intent. May need user education or HR involvement.
  • Allowed → Assess impact. May need to notify data owners, legal, or regulators depending on data type.
