SIEM & XDR Architecture

Q: What's your view on SIEM vs. XDR? 60 sec

SIEM vs XDR - VISUAL COMPARISON ═══════════════════════════════════════════════════════════════════════════════ XDR = DEPTH (within its ecosystem) SIEM = BREADTH (across everything) ──────────────────────────────── ───────────────────────────────── Microsoft Defender XDR Microsoft Sentinel ┌─────────────────────────────────┐ ┌─────────────────────────────────┐ │ │ │ │ │ ┌─────┐ ┌─────┐ ┌─────┐ │ │ ┌─────┐ ┌─────┐ ┌─────┐ │ │ │Email│ │Endpt│ │Ident│ │ │ │ XDR │ │Fire-│ │Cloud│ │ │ │ │ │ │ │ │ │ │ │Alert│ │wall │ │Logs │ │ │ └──┬──┘ └──┬──┘ └──┬──┘ │ │ └──┬──┘ └──┬──┘ └──┬──┘ │ │ │ │ │ │ │ │ │ │ │ │ └───────┴───────┘ │ │ └───────┴───────┘ │ │ │ │ │ │ │ │ ▼ │ │ ▼ │ │ ┌────────────────┐ │ │ ┌────────────────┐ │ │ │ CORRELATION │ │ │ │ CORRELATION │ │ │ │ (ML-powered) │ │ │ │ (Rule-based) │ │ │ └────────────────┘ │ │ └────────────────┘ │ │ │ │ │ │ STRENGTH: Deep correlation │ │ STRENGTH: See everything │ │ within Microsoft ecosystem │ │ across all vendors │ │ │ │ │ └─────────────────────────────────┘ └─────────────────────────────────┘ KEY INSIGHT: They're COMPLEMENTARY, not competing! ───────────────────────────────────────────────────────────────────────────── • Use XDR for what it's good at: Endpoint + Identity + Email correlation • Use SIEM for what XDR can't see: Firewall, custom apps, third-party SaaS THE MISTAKE: Trying to recreate XDR detections in SIEM We retired 780 rules doing exactly that — poorly.

Answer structure:

"They're complementary. XDR is depth — it correlates endpoint, identity, and email better than any SIEM rule. SIEM is breadth — it sees firewall logs, custom apps, third-party SaaS that XDR doesn't.

In our transformation, we designed for this. XDR handles Microsoft ecosystem threats. SIEM handles cross-platform correlation and what XDR can't see. The mistake is duplicating XDR detections in SIEM — we retired 780 rules doing exactly that."

Q: What experience do you have with KQL? Show me an example. 60 sec

// Detect unusual SharePoint download volume - Real production rule
let threshold = 100; // files
let timeWindow = 1h;

// Step 1: Build baseline of normal behavior (last 30 days)
let userBaseline = OfficeActivity
| where TimeGenerated between (ago(30d) .. ago(1d))
| where Operation == "FileDownloaded"
| summarize AvgDailyDownloads = count() / 30 by UserId;

// Step 2: Check recent activity
OfficeActivity
| where TimeGenerated > ago(timeWindow)
| where Operation == "FileDownloaded"
| summarize
    DownloadCount = count(),
    Files = make_set(OfficeObjectId, 10),
    SourceIPs = make_set(ClientIP)
    by UserId

// Step 3: Compare to baseline
| join kind=leftouter userBaseline on UserId
| where DownloadCount > threshold
    or DownloadCount > (AvgDailyDownloads * 5)

// Step 4: Classify the anomaly
| extend Anomaly = iff(DownloadCount > (AvgDailyDownloads * 5),
    "Baseline Deviation", "Threshold Exceeded")

Why this query is good: Combines threshold-based AND behavioral detection. Pure threshold misses low-and-slow exfil. Pure baseline misses new users. Both together = better coverage.

Q: Explain the difference between EDR and XDR 45 sec

EDR vs XDR - VISUAL EXPLANATION ═══════════════════════════════════════════════════════════════════════════════ EDR = Endpoint Detection & Response (SINGLE domain) ───────────────────────────────────────────────────────────────────────────── ┌─────────────────────────────────────┐ │ ENDPOINT │ │ │ │ • Processes │ │ • Files │ │ • Registry │ │ • Network connections │ │ │ │ [Detection] [Response] │ └─────────────────────────────────────┘ Examples: MDE, CrowdStrike, SentinelOne XDR = Extended Detection & Response (MULTIPLE domains) ───────────────────────────────────────────────────────────────────────────── ┌──────────┐ ┌──────────┐ ┌──────────┐ ┌──────────┐ │ ENDPOINT │ │ IDENTITY │ │ EMAIL │ │ CLOUD │ │ │ │ │ │ │ │ │ │ Processes│ │ Sign-ins │ │ Phishing │ │ Cloud │ │ Files │ │ MFA │ │ Malware │ │ Apps │ └────┬─────┘ └────┬─────┘ └────┬─────┘ └────┬─────┘ │ │ │ │ └─────────────┴─────────────┴─────────────┘ │ ▼ ┌───────────────────────┐ │ UNIFIED CORRELATION │ │ │ │ "User got phishing │ │ email, clicked link, │ │ malware ran on │ │ endpoint, stole │ │ credentials" │ │ │ │ ONE incident, not 4 │ └───────────────────────┘ Examples: Microsoft Defender XDR, Palo Alto Cortex XDR THE KEY DIFFERENCE: ───────────────────────────────────────────────────────────────────────────── With EDR alone: You see endpoint alerts. Miss the email that started it. With XDR: Phishing email + credential theft + lateral movement = ONE incident
