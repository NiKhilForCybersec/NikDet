PB-TRI-003

Network Alert Triage

Triage network security alerts including IDS/IPS, firewall, proxy, and network anomaly detections.

TierL1
Time5-15 min

Step 1: Alert Context

  • Source IP: Internal or external? What asset?
  • Destination IP: Known bad? Cloud service? Unknown?
  • Port/Protocol: Standard (80/443) or unusual?
  • Direction: Inbound (attack) or outbound (C2/exfil)?
  • Action: Allowed or blocked?

Step 2: Quick Lookups

// KQL: Investigate destination IP
let TargetIP = "1.2.3.4";
DeviceNetworkEvents
| where TimeGenerated > ago(7d)
| where RemoteIP == TargetIP
| summarize 
    Connections = count(),
    UniqueHosts = dcount(DeviceName),
    Hosts = make_set(DeviceName, 10),
    Ports = make_set(RemotePort),
    FirstSeen = min(TimeGenerated),
    LastSeen = max(TimeGenerated)

// KQL: What process is making the connection?
DeviceNetworkEvents
| where RemoteIP == "1.2.3.4"
| project TimeGenerated, DeviceName, InitiatingProcessFileName, 
    InitiatingProcessCommandLine, LocalPort, RemotePort
| order by TimeGenerated desc

Check IP reputation:
• VirusTotal: https://www.virustotal.com/gui/ip-address/{IP}
• AbuseIPDB: https://www.abuseipdb.com/check/{IP}
• Shodan: https://www.shodan.io/host/{IP}
• GreyNoise: https://viz.greynoise.io/ip/{IP}

Step 3: Decision Tree

Q1: Was the connection blocked?

  • YES → Lower risk. Document, may close if isolated.
  • NO (Allowed) → Continue investigation.

Q2: Is the destination known malicious?

  • YES (TI match, known C2) → HIGH PRIORITY. Identify source host, isolate if needed.
  • NO/Unknown → Continue to Q3.

Q3: Is this expected traffic for the source?

  • YES (Normal browsing, approved app) → Likely benign. Close.
  • NO (Unusual destination, weird port) → Investigate process on endpoint.

Q4: Is it a single connection or persistent?

  • Single → Lower risk. May be incidental.
  • Persistent/Beaconing → Potential C2. Escalate.

Escalation Criteria

  • Connection to known C2 infrastructure (allowed)
  • Multiple hosts connecting to same suspicious destination
  • Large outbound data transfer to unusual destination
  • Beaconing pattern detected
  • IDS signature for active exploit/shellcode
  • Connection from server to unexpected external IP
