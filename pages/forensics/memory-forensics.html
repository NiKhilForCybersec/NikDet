Memory Forensics

Analyze RAM to uncover malware, credentials, and attacker activity invisible to disk forensics.

Why Memory Forensics?

Memory forensics reveals what disk forensics cannot - running processes, network connections, injected code, and encryption keys that exist only in RAM.

What Memory Contains
  • Running processes and their command lines
  • Loaded DLLs and injected code
  • Network connections (including closed ones)
  • Registry hives in memory
  • Decrypted data and credentials
  • Malware that never touches disk (fileless)

DumpIt.exe

# Linux - AVML
./avml memory.lime

# Linux - LiME
insmod lime.ko "path=/tmp/memory.lime format=lime"

Volatility 3 Analysis

Volatility is the industry standard for memory analysis.

Basic Usage

# Identify OS profile
vol -f memory.raw windows.info

# List processes
vol -f memory.raw windows.pslist

# Process tree (parent-child)
vol -f memory.raw windows.pstree

# Hidden processes
vol -f memory.raw windows.psscan

# Network connections
vol -f memory.raw windows.netscan

# Command history
vol -f memory.raw windows.cmdline

Detection Techniques

1. Process Anomalies

# Look for suspicious parent-child relationships
vol -f memory.raw windows.pstree

Suspicious patterns:
- Word.exe → cmd.exe → powershell.exe
- svchost.exe with wrong parent (not services.exe)
- explorer.exe spawning cmd.exe
- lsass.exe spawning anything

2. Process Injection Detection

# Scan for injected code
vol -f memory.raw windows.malfind

What malfind detects:
- Memory regions with PAGE_EXECUTE_READWRITE
- Injected shellcode (often starts with MZ header or shellcode stubs)
- Process hollowing
- Reflective DLL injection

3. Network Analysis

# Get all network connections
vol -f memory.raw windows.netscan

Look for:
- Connections from suspicious processes
- Connections to unusual ports (4444, 5555, 8080, 9001)
- Multiple connections to same external IP
- ESTABLISHED connections during incident timeframe

4. DLL Analysis

# List DLLs for specific process
vol -f memory.raw windows.dlllist --pid 1234

Suspicious indicators:
- DLLs loaded from Temp or AppData
- DLLs with random names
- Missing or inconsistent file paths
- DLLs not matching expected signatures

Investigation Workflow

1
Identify OS and Profile

Run windows.info to identify the operating system and ensure correct analysis.

2
Process Analysis

Run pslist, pstree, and psscan to identify suspicious processes.

3
Network Connections

Use netscan to find C2 connections and lateral movement.

4
Injection Detection

Run malfind to detect code injection and shellcode.

5
Deep Dive

Use dlllist, handles, cmdline on suspicious processes.

6
Extract Evidence

Dump suspicious processes, DLLs, or memory regions for further analysis.

Common Findings

FindingIndicatesNext Steps
Process with no parent Parent terminated or DKOM Check psscan for hidden parent
svchost without services.exe parent Malware impersonating svchost Dump process, analyze binary
malfind hits with MZ header Reflective DLL injection Dump region, analyze as PE
ESTABLISHED connections to unusual IPs Active C2 communication Check process, block IP, hunt
PowerShell with encoded command Script-based attack Decode command, trace origin

Extracting Evidence

# Dump a suspicious process
vol -f memory.raw windows.pslist --pid 1234 --dump

# Dump memory region from malfind
vol -f memory.raw windows.malfind --pid 1234 --dump

# Extract a file from memory
vol -f memory.raw windows.filescan | grep "suspicious.exe"
vol -f memory.raw windows.dumpfiles --physaddr 0x12345678
