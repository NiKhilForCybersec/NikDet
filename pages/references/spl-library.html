SPL Query Library

100+ production-ready Splunk SPL queries for detection, investigation, and threat hunting.

How to Use This Library

These queries are designed for Splunk Enterprise and Splunk Cloud. Adjust index names, sourcetypes, and field names to match your environment. All queries include comments explaining the logic.

SPL Fundamentals

Essential SPL syntax and operators

Basic Search Structure
Basics
Understanding the fundamental structure of SPL queries. Searches flow left-to-right through a pipeline.
| Base search (retrieves events) | Command 1 (transforms data) | Command 2 (further transforms) | ... and so on Example: index=windows sourcetype=WinEventLog:Security EventCode=4625 | stats count by src_ip, user | sort - count | head 10
Key Concept: Data flows through the pipeline. Each command receives input from the previous command and passes output to the next. The first line (before any pipe) is the "base search" that retrieves raw events.
Essential Search Commands
Reference
The most commonly used SPL commands every analyst must know.
| search - Filter events (usually implicit in base search) | where - Filter using eval expressions (more powerful than search) | stats - Aggregate data (count, sum, avg, values, dc) | table - Display specific fields in tabular format | fields - Include (+) or exclude (-) fields | eval - Create or modify fields | rex - Extract fields using regex | rename - Rename fields | sort - Sort results (- for descending) | head/tail - Limit results to first/last N | dedup - Remove duplicate events | transaction - Group related events | join - Combine results from subsearches | lookup - Enrich with lookup tables | timechart - Time-based statistics | tstats - Fast statistics on indexed fields
Common Eval Functions
Reference
Eval functions for data manipulation and transformation.
| String Functions: | eval lower_user=lower(user) ` Convert to lowercase | eval domain=split(email, "@") ` Split string into multivalue | eval combined=user." - ".src_ip ` Concatenate strings | eval length=len(command) ` String length | eval has_enc=if(match(cmd, "-enc"), 1, 0) ` Regex match | Numeric Functions: | eval total=bytes_in + bytes_out ` Math operations | eval rounded=round(percentage, 2) ` Round to decimal places | eval abs_val=abs(difference) ` Absolute value | Time Functions: | eval hour=strftime(_time, "%H") ` Extract hour from timestamp | eval epoch=strptime(date, "%Y-%m-%d") ` Convert string to epoch | eval age=now() - _time ` Calculate age in seconds | Conditional Functions: | eval status=if(count>100, "High", "Low") ` If-then-else | eval category=case( count>1000, "Critical", count>100, "High", count>10, "Medium", true(), "Low") ` Multiple conditions | eval value=coalesce(field1, field2, "N/A") ` First non-null value

Authentication Queries

Failed logins, brute force, password spray, impossible travel

Failed Login Summary by User
T1110Brute Force
Identify users with excessive failed login attempts. Useful for detecting brute force attacks and compromised accounts.
` Failed Windows logon attempts - EventCode 4625 index=windows sourcetype=WinEventLog:Security EventCode=4625 | stats count as FailedAttempts, dc(src_ip) as UniqueSourceIPs, values(src_ip) as SourceIPs, earliest(_time) as FirstAttempt, latest(_time) as LastAttempt by user | where FailedAttempts > 10 | eval FirstAttempt=strftime(FirstAttempt, "%Y-%m-%d %H:%M:%S") | eval LastAttempt=strftime(LastAttempt, "%Y-%m-%d %H:%M:%S") | eval Duration=tostring(LastAttempt-FirstAttempt, "duration") | sort - FailedAttempts | table user, FailedAttempts, UniqueSourceIPs, SourceIPs, FirstAttempt, LastAttempt
Tuning: Adjust the threshold (>10) based on your environment. Service accounts may have higher legitimate failure rates. Consider excluding known service accounts or adding time constraints.
Password Spray Detection
T1110.003Critical
Detect password spray attacks: many users targeted with few attempts each from the same source. Attackers use this to avoid account lockouts.
` Password spray: Many users, few attempts per user, same source index=windows sourcetype=WinEventLog:Security EventCode=4625 | bucket _time span=15m | stats dc(user) as TargetedUsers, count as TotalAttempts, values(user) as Users by _time, src_ip | where TargetedUsers > 10 AND TotalAttempts/TargetedUsers < 3 ` Low attempts per user but many users = spray pattern | eval AttemptsPerUser=round(TotalAttempts/TargetedUsers, 2) | sort - TargetedUsers | table _time, src_ip, TargetedUsers, TotalAttempts, AttemptsPerUser, Users
Detection Logic: Password spraying shows a pattern of one source IP trying against many accounts (>10) with very few attempts per account (<3). This evades lockout policies while testing common passwords across many accounts.
Impossible Travel Detection
T1078High
Detect when a user authenticates from geographically distant locations in an impossibly short time frame, indicating credential theft.
` Requires GeoIP lookup configured index=authentication sourcetype=your_auth_logs action=success | iplocation src_ip | sort 0 user, _time | streamstats current=f last(Country) as prev_country, last(City) as prev_city, last(_time) as prev_time, last(src_ip) as prev_ip by user | eval time_diff_hours=round((_time - prev_time)/3600, 2) | where isnotnull(prev_country) AND Country!=prev_country AND time_diff_hours < 2 ` Different country within 2 hours = impossible travel | eval prev_time_formatted=strftime(prev_time, "%Y-%m-%d %H:%M:%S") | table _time, user, prev_city, prev_country, prev_ip, City, Country, src_ip, time_diff_hours
Considerations: VPN usage can cause false positives. Consider maintaining an allowlist of known VPN exit nodes. Also watch for cases where prev_country is null (first login of the day).
Successful Login After Multiple Failures
T1110Medium
Detect successful authentication that follows multiple failed attempts - potential indicator of successful brute force.
` Find successful logins preceded by failures index=windows sourcetype=WinEventLog:Security (EventCode=4625 OR EventCode=4624) | sort 0 user, _time | streamstats count(eval(EventCode=4625)) as FailuresBefore reset_after="EventCode=4624" by user | where EventCode=4624 AND FailuresBefore >= 5 | stats count as SuccessfulLogins, sum(FailuresBefore) as TotalFailuresBefore, values(src_ip) as SourceIPs, latest(_time) as LastSuccess by user | eval LastSuccess=strftime(LastSuccess, "%Y-%m-%d %H:%M:%S") | sort - TotalFailuresBefore | table user, SuccessfulLogins, TotalFailuresBefore, SourceIPs, LastSuccess
Why This Matters: A successful login after many failures could indicate a successful brute force attack. Investigate immediately - verify with the user if the activity was legitimate.

Endpoint Detection

Process execution, PowerShell, suspicious commands

Encoded PowerShell Commands
T1059.001T1027High
Detect PowerShell execution with Base64 encoded commands, commonly used to obfuscate malicious scripts.
` Encoded PowerShell - Sysmon EventCode 1 (Process Creation) index=windows sourcetype=XmlWinEventLog:Microsoft-Windows-Sysmon/Operational EventCode=1 (Image="*\\powershell.exe" OR Image="*\\pwsh.exe") (CommandLine="*-enc*" OR CommandLine="*-encoded*" OR CommandLine="*-e *" OR CommandLine="*-encodedcommand*") | rex field=CommandLine "(?i)-e[ncodedcommand]*\s+(?[A-Za-z0-9+/=]{20,})" | eval DecodedCommand=if(isnotnull(EncodedPayload), base64decode(EncodedPayload), "Unable to decode") | table _time, ComputerName, User, ParentImage, Image, CommandLine, DecodedCommand | sort - _time
Detection Logic: Legitimate encoded PowerShell exists (SCCM, etc.) but should be rare. Examine the decoded content for suspicious patterns: downloadstring, IEX, invoke-expression, webclient, etc.
Suspicious Parent-Child Process Relationships
T1059High
Detect when Office applications, browsers, or other programs spawn suspicious child processes like cmd.exe or PowerShell - common malware behavior.
` Suspicious parent spawning cmd/PowerShell/etc. index=windows sourcetype=XmlWinEventLog:Microsoft-Windows-Sysmon/Operational EventCode=1 | eval ParentProcess=lower(mvindex(split(ParentImage, "\\"), -1)) | eval ChildProcess=lower(mvindex(split(Image, "\\"), -1)) | where (ParentProcess IN ("winword.exe", "excel.exe", "powerpnt.exe", "outlook.exe", "msaccess.exe", "mspub.exe", "visio.exe", "onenote.exe", "chrome.exe", "firefox.exe", "iexplore.exe", "msedge.exe", "acrobat.exe", "acrord32.exe")) AND (ChildProcess IN ("cmd.exe", "powershell.exe", "pwsh.exe", "wscript.exe", "cscript.exe", "mshta.exe", "regsvr32.exe", "rundll32.exe", "certutil.exe", "bitsadmin.exe")) | table _time, ComputerName, User, ParentImage, Image, CommandLine | sort - _time
Why This Matters: Office applications and browsers should rarely spawn command interpreters. When they do, it often indicates macro malware, exploit kits, or phishing payloads executing.
LSASS Access Detection (Credential Dumping)
T1003.001Critical
Detect processes accessing LSASS memory - the primary method for credential theft tools like Mimikatz.
` Sysmon EventCode 10 = Process Access index=windows sourcetype=XmlWinEventLog:Microsoft-Windows-Sysmon/Operational EventCode=10 TargetImage="*\\lsass.exe" | eval SourceProcess=lower(mvindex(split(SourceImage, "\\"), -1)) ` Exclude known legitimate LSASS accessors | where NOT SourceProcess IN ("csrss.exe", "wininit.exe", "wmiprvse.exe", "svchost.exe", "services.exe", "lsm.exe", "mrt.exe", "vmtoolsd.exe", "taskmgr.exe", "procexp64.exe", "procexp.exe") ` Check for suspicious access masks | where GrantedAccess IN ("0x1010", "0x1038", "0x1410", "0x1438", "0x143a", "0x1fffff") | table _time, ComputerName, SourceImage, SourceProcessGUID, GrantedAccess, CallTrace | sort - _time
Critical Alert: LSASS access with suspicious access masks is a strong indicator of credential dumping. Common tools: Mimikatz, procdump, comsvcs.dll. Investigate immediately and consider isolating the endpoint.
Certutil Download Detection
T1105High
Detect certutil.exe being used to download files - a common LOLBin technique for malware delivery.
` Certutil used for downloading files index=windows sourcetype=XmlWinEventLog:Microsoft-Windows-Sysmon/Operational EventCode=1 Image="*\\certutil.exe" (CommandLine="*-urlcache*" OR CommandLine="*-verifyctl*" OR CommandLine="*-encode*" OR CommandLine="*-decode*") | rex field=CommandLine "(?i)(https?://[^\s\"']+)" max_match=0 | rex field=CommandLine "(?i)-f\s+[\"']?(?[^\s\"']+)" | table _time, ComputerName, User, ParentImage, CommandLine, OutputFile | sort - _time
LOLBin Alert: Certutil is a legitimate Windows utility for certificate management, but attackers abuse it to download payloads. Look for -urlcache -split -f patterns. Also watch for encode/decode used to obfuscate files.

Persistence Detection

Registry, scheduled tasks, services, startup

Registry Run Key Modifications
T1547.001High
Detect modifications to registry Run keys, a classic persistence mechanism that executes programs at user logon.
` Sysmon EventCode 13 = Registry value set index=windows sourcetype=XmlWinEventLog:Microsoft-Windows-Sysmon/Operational EventCode=13 (TargetObject="*\\CurrentVersion\\Run*" OR TargetObject="*\\CurrentVersion\\RunOnce*" OR TargetObject="*\\CurrentVersion\\RunServices*" OR TargetObject="*\\CurrentVersion\\Policies\\Explorer\\Run*") | eval RegistryPath=TargetObject | eval RegistryValue=Details | eval ProcessName=mvindex(split(Image, "\\"), -1) ` Filter known legitimate software (customize for your environment) | where NOT (ProcessName IN ("msiexec.exe", "chrome.exe", "teams.exe") AND match(RegistryValue, "(?i)(microsoft|google|zoom)")) | table _time, ComputerName, User, ProcessName, Image, RegistryPath, RegistryValue | sort - _time
Persistence Mechanism: Run keys execute programs every time a user logs in. Attackers commonly use this for persistence. Legitimate software also uses these keys, so establish a baseline of normal entries in your environment.
Scheduled Task Creation
T1053.005Medium
Monitor scheduled task creation for persistence and execution mechanisms.
` Windows Security Event 4698 = Scheduled task created index=windows sourcetype=WinEventLog:Security EventCode=4698 | rex field=TaskContent "(?[^<]+)" | rex field=TaskContent "(?[^<]+)" | rex field=TaskContent "(?[^<]+)" | eval FullCommand=TaskCommand." ".TaskArguments ` Look for suspicious patterns in the command | eval Suspicious=case( match(FullCommand, "(?i)(powershell|cmd\.exe|wscript|cscript|mshta|certutil|bitsadmin)"), "High", match(FullCommand, "(?i)(http|https|ftp)://"), "High", match(FullCommand, "(?i)(\\temp\\|\\appdata\\|\\public\\)"), "Medium", true(), "Low") | where Suspicious IN ("High", "Medium") | table _time, ComputerName, SubjectUserName, TaskName, FullCommand, TaskUser, Suspicious | sort - _time
Common Attack Pattern: Attackers create scheduled tasks for persistence and recurring execution. Watch for tasks running from unusual locations (Temp, AppData) or invoking script interpreters.
New Service Installation
T1543.003Medium
Detect new Windows service installations, commonly used for persistence and privilege escalation.
` System Event 7045 = New service installed index=windows sourcetype=WinEventLog:System EventCode=7045 | eval ServicePath=lower(Service_File_Name) ` Flag suspicious service paths | eval Suspicious=case( match(ServicePath, "(?i)(\\temp\\|\\appdata\\|\\public\\|\\programdata\\)"), "High - Suspicious Path", match(ServicePath, "(?i)(cmd\.exe|powershell|mshta|wscript|cscript)"), "High - Script Interpreter", match(ServicePath, "(?i)(psexe|winexe|remcom)"), "High - Remote Execution Tool", NOT match(ServicePath, "(?i)(windows|program files|microsoft)"), "Medium - Non-standard", true(), "Low") | where Suspicious!="Low" | table _time, ComputerName, Service_Name, Service_File_Name, Service_Type, Service_Start_Type, Service_Account, Suspicious | sort - _time
Why Services Matter: Services run with SYSTEM privileges by default and start automatically. Attackers install malicious services for persistent, elevated access. Monitor for services with unusual paths or names.

Lateral Movement

RDP, SMB, PsExec, remote execution

RDP Connections Tracking
T1021.001Medium
Track Remote Desktop connections for lateral movement detection.
` RDP logons (Type 10 = RemoteInteractive) index=windows sourcetype=WinEventLog:Security EventCode=4624 Logon_Type=10 | stats count as Connections, dc(dest) as UniqueDestinations, values(dest) as Destinations, earliest(_time) as FirstConnection, latest(_time) as LastConnection by src_ip, user | eval FirstConnection=strftime(FirstConnection, "%Y-%m-%d %H:%M:%S") | eval LastConnection=strftime(LastConnection, "%Y-%m-%d %H:%M:%S") | sort - Connections | table user, src_ip, Connections, UniqueDestinations, Destinations, FirstConnection, LastConnection
Lateral Movement Indicator: RDP from unusual sources or to unusual destinations warrants investigation. Create a baseline of normal RDP patterns and alert on deviations.
PsExec / Remote Service Execution
T1021.002T1569.002High
Detect PsExec-style remote execution through service installation on remote systems.
` Detect PsExec-like service installation index=windows sourcetype=WinEventLog:System EventCode=7045 (Service_File_Name="*PSEXESVC*" OR Service_File_Name="*\\ADMIN$\\*" OR Service_File_Name="*\\C$\\*" OR Service_Name="PSEXESVC" OR Service_File_Name="*remcom*" OR Service_File_Name="*csexec*" OR Service_File_Name="*paexec*") | table _time, ComputerName, Service_Name, Service_File_Name, Service_Account | sort - _time ` Alternative: Network logon (Type 3) followed by service creation index=windows sourcetype=WinEventLog:Security (EventCode=4624 Logon_Type=3) OR EventCode=4697 | transaction src_ip, dest maxspan=5m | where eventcount > 1 AND EventCode=4697 | table _time, src_ip, dest, user, Service_Name
Remote Execution: PsExec and similar tools create a service on the remote system to execute commands. This is a common lateral movement technique. Also watch for variations like csexec, paexec, remcom.
SMB/Network Share Access Patterns
T1021.002Medium
Track network share access patterns to identify lateral movement and data staging.
` Windows Security Event 5140 = Network share accessed index=windows sourcetype=WinEventLog:Security EventCode=5140 | stats count as AccessCount, dc(Share_Name) as UniqueShares, values(Share_Name) as Shares, dc(dest) as UniqueHosts by src_ip, user | where UniqueHosts > 5 OR AccessCount > 100 ` High access count or many different hosts = potential lateral movement | sort - UniqueHosts | table user, src_ip, AccessCount, UniqueShares, UniqueHosts, Shares
Pattern Analysis: Users typically access a limited set of shares. Sudden access to many hosts or shares may indicate an attacker enumerating the network or staging data for exfiltration.

Data Exfiltration

Large transfers, cloud uploads, archiving

Large Outbound Data Transfers
T1048High
Detect unusually large outbound data transfers that may indicate data exfiltration.
` Requires network traffic data (firewall, proxy, etc.) index=network sourcetype=your_firewall_logs direction=outbound | stats sum(bytes_out) as TotalBytes by src_ip, dest_ip, dest_port | eval TotalMB=round(TotalBytes/1024/1024, 2) | where TotalMB > 500 ` Over 500MB to single destination | lookup dnslookup clientip as dest_ip OUTPUT clienthost as dest_hostname | sort - TotalMB | table src_ip, dest_ip, dest_hostname, dest_port, TotalMB ` Daily baseline comparison index=network sourcetype=your_firewall_logs direction=outbound earliest=-1d | stats sum(bytes_out) as TodayBytes by src_ip | appendcols [search index=network sourcetype=your_firewall_logs direction=outbound earliest=-8d latest=-1d | stats avg(bytes_out) as AvgDailyBytes by src_ip] | eval Anomaly=if(TodayBytes > AvgDailyBytes*3, "High", "Normal") | where Anomaly="High" | eval TodayMB=round(TodayBytes/1024/1024, 2) | eval AvgMB=round(AvgDailyBytes/1024/1024, 2) | table src_ip, TodayMB, AvgMB, Anomaly
Exfiltration Detection: Attackers often exfiltrate data in bulk. Look for transfers exceeding baseline or going to unusual destinations (cloud storage providers, foreign IPs, etc.).
Archive Creation Before Transfer
T1560Medium
Detect archive tool usage (7z, rar, zip) that may precede data exfiltration.
` Archive tool execution index=windows sourcetype=XmlWinEventLog:Microsoft-Windows-Sysmon/Operational EventCode=1 (Image="*\\7z.exe" OR Image="*\\7za.exe" OR Image="*\\rar.exe" OR Image="*\\WinRAR.exe" OR Image="*\\zip.exe" OR Image="*tar.exe") | rex field=CommandLine "(?[^\s]+\.(zip|rar|7z|tar|gz))" ` Look for password-protected archives (common exfil technique) | eval PasswordProtected=if(match(CommandLine, "(?i)(-p|-hp|--password)"), "Yes", "No") ` Look for targeting sensitive directories | eval SensitiveTarget=case( match(CommandLine, "(?i)(documents|desktop|confidential|finance|hr|legal|passwords)"), "Yes", true(), "No") | where PasswordProtected="Yes" OR SensitiveTarget="Yes" | table _time, ComputerName, User, Image, CommandLine, ArchiveFile, PasswordProtected, SensitiveTarget | sort - _time
Pre-Exfiltration Staging: Attackers often compress and password-protect data before exfiltration. This makes the transfer faster and evades DLP inspection. Watch for archive creation from sensitive directories.

Threat Hunting

Anomaly detection, beaconing, rare processes

Rare Process Execution
Hunting
Find processes that have executed on very few systems - potential indicator of targeted malware or attacker tools.
` Find processes seen on very few endpoints index=windows sourcetype=XmlWinEventLog:Microsoft-Windows-Sysmon/Operational EventCode=1 earliest=-7d | eval ProcessName=lower(mvindex(split(Image, "\\"), -1)) | stats dc(ComputerName) as EndpointCount, values(ComputerName) as Endpoints, values(User) as Users, count as ExecutionCount, values(CommandLine) as CommandLines by ProcessName | where EndpointCount <= 3 AND EndpointCount > 0 ` Executed on 3 or fewer endpoints in 7 days | sort EndpointCount | table ProcessName, EndpointCount, ExecutionCount, Endpoints, Users, CommandLines
Hunting Hypothesis: Malware and attacker tools are often unique or rare in an environment. Finding processes that appear on very few systems can reveal targeted attacks that signature-based detection missed.
Beaconing Detection (C2)
T1071Hunting
Detect regular interval network connections characteristic of command-and-control beaconing behavior.
` Find connections with regular timing intervals (beaconing) index=network sourcetype=your_proxy_logs | bucket _time span=1m | stats count as ConnectionsPerMinute by _time, src_ip, dest_ip | streamstats current=f last(_time) as prev_time by src_ip, dest_ip | eval interval=_time - prev_time | where isnotnull(prev_time) AND interval > 0 | stats count as DataPoints, avg(interval) as AvgInterval, stdev(interval) as StdDevInterval, min(interval) as MinInterval, max(interval) as MaxInterval by src_ip, dest_ip | where DataPoints > 20 ` Calculate coefficient of variation (lower = more regular) | eval CoeffVar=round((StdDevInterval/AvgInterval)*100, 2) | where CoeffVar < 15 AND AvgInterval > 30 AND AvgInterval < 900 ` Low variance (CV < 15%) in 30s-15min range = potential beacon | sort CoeffVar | table src_ip, dest_ip, DataPoints, AvgInterval, StdDevInterval, CoeffVar
Beaconing Patterns: C2 malware often "beacons" home at regular intervals (e.g., every 60 seconds). Low coefficient of variation indicates very regular timing, which is suspicious for network traffic. Legitimate traffic is typically more variable.
First-Time Process Execution
Hunting
Identify processes running for the first time in the last 24 hours that haven't been seen in the prior 30 days.
` Find new processes in last 24h not seen in prior 30 days index=windows sourcetype=XmlWinEventLog:Microsoft-Windows-Sysmon/Operational EventCode=1 earliest=-1d | eval ProcessName=lower(mvindex(split(Image, "\\"), -1)) | dedup ProcessName | fields ProcessName | join type=left ProcessName [search index=windows sourcetype=XmlWinEventLog:Microsoft-Windows-Sysmon/Operational EventCode=1 earliest=-31d latest=-1d | eval ProcessName=lower(mvindex(split(Image, "\\"), -1)) | dedup ProcessName | eval SeenBefore="Yes" | fields ProcessName, SeenBefore] | where isnull(SeenBefore) ` These processes are new - never seen in past 30 days | table ProcessName ` Get details on the new processes | join ProcessName [search index=windows sourcetype=XmlWinEventLog:Microsoft-Windows-Sysmon/Operational EventCode=1 earliest=-1d | eval ProcessName=lower(mvindex(split(Image, "\\"), -1)) | stats values(ComputerName) as Hosts, values(User) as Users, values(CommandLine) as CommandLines by ProcessName] | table ProcessName, Hosts, Users, CommandLines
First Seen Analysis: New processes appearing suddenly could indicate malware introduction or attacker tools being deployed. Requires a baseline period (30 days in this example) to identify truly "new" processes.

Statistics & Reporting

Dashboards, metrics, summaries

Security Event Summary Dashboard
Reporting
Create a summary of key security events for SOC dashboards.
` Daily security event summary index=windows sourcetype=WinEventLog:Security earliest=-24h | eval EventCategory=case( EventCode IN (4624, 4625, 4634, 4647, 4648), "Authentication", EventCode IN (4720, 4722, 4723, 4724, 4725, 4726, 4738, 4740), "Account Management", EventCode IN (4728, 4729, 4732, 4733, 4756, 4757), "Group Management", EventCode IN (4688, 4689), "Process Execution", EventCode IN (4697, 4698, 4699, 4700, 4701, 4702), "Scheduled Tasks/Services", EventCode IN (5140, 5145), "File Share Access", EventCode=1102, "Audit Log Cleared", true(), "Other") | stats count by EventCategory | sort - count ` Timechart version for trends index=windows sourcetype=WinEventLog:Security earliest=-7d | eval EventCategory=case( EventCode IN (4624, 4625), "Logon Events", EventCode IN (4720, 4726), "Account Changes", EventCode IN (4688), "Process Creation", true(), "Other") | timechart span=1h count by EventCategory
Top Talkers (Network)
Reporting
Identify the highest bandwidth users and destinations on your network.
` Top internal hosts by outbound traffic index=network sourcetype=your_firewall direction=outbound earliest=-24h | stats sum(bytes_out) as TotalBytes, dc(dest_ip) as UniqueDestinations by src_ip | eval TotalGB=round(TotalBytes/1024/1024/1024, 2) | sort - TotalBytes | head 20 | table src_ip, TotalGB, UniqueDestinations ` Top external destinations index=network sourcetype=your_firewall direction=outbound earliest=-24h | stats sum(bytes_out) as TotalBytes, dc(src_ip) as UniqueSourcesIPs by dest_ip | eval TotalGB=round(TotalBytes/1024/1024/1024, 2) | lookup dnslookup clientip as dest_ip OUTPUT clienthost as dest_hostname | iplocation dest_ip | sort - TotalBytes | head 20 | table dest_ip, dest_hostname, Country, TotalGB, UniqueSourcesIPs
Failed Login Heatmap
Visualization
Create a time-based heatmap of failed login attempts to identify attack patterns.
` Failed logins by hour and day of week index=windows sourcetype=WinEventLog:Security EventCode=4625 earliest=-7d | eval HourOfDay=strftime(_time, "%H") | eval DayOfWeek=strftime(_time, "%A") | stats count by DayOfWeek, HourOfDay | xyseries DayOfWeek HourOfDay count ` This creates a matrix perfect for heatmap visualization ` In Splunk dashboard, use "Choropleth Map" or "Heat Map" visualization
Pattern Recognition: Heatmaps reveal temporal patterns in attacks. Brute force attempts often spike during off-hours or weekends when response may be slower. Business hours attacks may indicate insider threats.
