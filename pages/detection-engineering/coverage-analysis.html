Remaining Gaps & Next Quarter Priorities

Critical Gaps to Address

Gap 1: Linux Server Monitoring

45 Linux servers with minimal visibility. Trading platform backend runs on Linux.

Risk: Attacker could compromise trading system undetected

Plan: Deploy Defender for Linux, create Linux-specific detections

Gap 2: AWS Cloud Coverage

Growing AWS footprint with no SIEM integration. S3 buckets, Lambda functions unmonitored.

Risk: Cloud misconfiguration or compromise undetected

Plan: Integrate CloudTrail, create AWS-specific detections

Gap 3: Web Shell Detection

Customer portal runs on IIS with no web shell detection capability.

Risk: Attacker persistence on web server

Plan: IIS log analysis, file integrity monitoring

Gap 4: Advanced Exfiltration

Only basic exfiltration detection. No DNS tunneling, steganography, or encrypted channel detection.

Risk: Data theft via covert channels

Plan: Network traffic analysis, DNS analytics

Lessons Learned: The Apex Journey

🏢 Key Takeaways from Apex's Detection Journey

1. Incidents drive priorities

The BEC incident wasn't just a loss - it was a catalyst for change. Use incidents to justify investment and set priorities.

2. Prioritize based on threat model, not MITRE coverage

Apex didn't try to cover all 200+ MITRE techniques. They focused on the threats most likely to target them (financial criminals, insiders).

3. Test before deploying

Every detection was tested against 30 days of historical data. This prevented alert fatigue and built SOC trust.

4. Document everything

Each detection has investigation steps, FP guidance, and response actions. Analysts can use them effectively.

5. Measure and report

Regular coverage analysis shows progress and justifies continued investment. The board can see ROI.

6. It's a journey, not a destination

68% coverage is good, but gaps remain. Detection engineering is ongoing, not a one-time project.
