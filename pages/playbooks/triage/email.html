Email Security Alert Triage

Comprehensive triage procedure for email security alerts including phishing, malicious attachments, spam, spoofing, and business email compromise indicators.

TierL1 / L2
Time5-15 min
ToolsEmail Gateway, SIEM, Sandbox

Triage Decision Flow

1
Assess Email Threat Type
IndicatorLikely ThreatInitial Priority
Malware detected in attachmentMalicious attachmentHigh
URL to known phishing siteCredential phishingHigh
Spoofed executive nameBEC/CEO fraudHigh
SPF/DKIM failureSpoofingMedium
Bulk sender, low reputationSpamLow
2
Check Delivery Status
  • Blocked/Quarantined: Email never reached user - lower urgency
  • Delivered to inbox: User may have interacted - check for clicks
  • User reported: User aware but may have already clicked
  • Link clicked: Elevated priority - check for compromise
  • Attachment opened: High priority - check for malware execution
3
Verify Sender Legitimacy
CheckMethodRed Flag
SPFHeader analysisFail = not authorized sender
DKIMHeader analysisFail = message modified
DMARCHeader analysisFail = policy violation
Display vs FromCompare addressesMismatch = deception
Reply-ToHeader analysisDifferent = redirect attempt
Domain ageWHOIS lookupNew domain = suspicious
4
Analyze Content
  • URLs: Check reputation, look for typosquatting, redirects
  • Attachments: File type, macro presence, sandbox results
  • Language: Urgency, threats, unusual requests
  • Branding: Logo quality, formatting, legitimate sender?
5
Make Triage Decision
ScenarioDecisionAction
Spam, blockedCloseNo action needed
Phishing, blockedMonitorCheck for other recipients
Phishing, deliveredRemediateRemove from mailboxes
Malware, clickedEscalateFull endpoint investigation
BEC attemptEscalateAlert finance, investigate

Email Triage Queries

// KQL - Find all recipients of suspicious email
let suspiciousSender = "attacker@phishing-domain.com";
let suspiciousSubject = "Urgent: Update your account";
EmailEvents
| where TimeGenerated > ago(24h)
| where SenderFromAddress =~ suspiciousSender 
    or Subject has suspiciousSubject
| project TimeGenerated, RecipientEmailAddress, DeliveryAction,
    DeliveryLocation, Subject, NetworkMessageId
| summarize Recipients = make_set(RecipientEmailAddress),
    Count = count() by DeliveryAction

// KQL - Check for link clicks
let messageId = "NetworkMessageId_HERE";
EmailUrlInfo
| where NetworkMessageId == messageId
| join kind=inner (
    UrlClickEvents
    | where TimeGenerated > ago(24h)
) on Url
| project TimeGenerated, AccountUpn, Url, ActionType, IsClickedThrough

// KQL - Authentication results analysis
EmailEvents
| where TimeGenerated > ago(24h)
| where SenderFromAddress =~ "suspicious@domain.com"
| extend AuthDetails = parse_json(AuthenticationDetails)
| project TimeGenerated, SenderFromAddress, 
    SPF = AuthDetails.SPF,
    DKIM = AuthDetails.DKIM,
    DMARC = AuthDetails.DMARC,
    CompAuth = AuthDetails.CompAuth

// KQL - Attachment analysis
EmailAttachmentInfo
| where TimeGenerated > ago(24h)
| where NetworkMessageId == "MessageId_HERE"
| project FileName, FileType, SHA256, FileSize,
    MalwareFilterVerdict, DetectionMethods

// KQL - Similar emails (campaign detection)
EmailEvents
| where TimeGenerated > ago(7d)
| where Subject has "Invoice" and Subject has "Urgent"
| summarize 
    Recipients = dcount(RecipientEmailAddress),
    Senders = make_set(SenderFromAddress, 5)
    by Subject
| where Recipients > 5

// SPL - Email threat summary
index=email action=blocked
| stats count by threat_type, sender_domain
| sort -count

Escalation Criteria

Escalate Immediately If:
  • Malware attachment was opened/executed
  • User entered credentials on phishing page
  • Multiple users affected by same campaign
  • Executive targeted (whaling/BEC)
  • Finance team targeted with payment request
  • Sensitive data sent externally
  • Account compromise indicators present
  • Targeted attack (spear phishing) detected
