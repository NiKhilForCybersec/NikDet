PB-IR-001

Ransomware Incident Response

Time-critical response procedures for active ransomware incidents. Speed is essential - every minute matters.

CRITICAL: Time-Sensitive Response

Ransomware spreads rapidly. Do NOT wait to gather more information before containing. Isolate first, investigate second.

Immediate Actions (First 15 Minutes)

PriorityActionHowWho
1Isolate affected systemsEDR isolation or network disconnectSOC Analyst
2Notify IR lead/managerPhone call, not emailSOC Analyst
3Preserve evidenceDo NOT reboot or wipe systemsAll
4Identify patient zeroFirst system with encryption activitySOC Analyst
5Check backup statusAre backups intact and accessible?IT/Backup Admin
6Isolate backup systemsDisconnect to protect from encryptionIT/Backup Admin

DO NOT

  • ❌ Reboot infected systems (destroys memory evidence)
  • ❌ Run antivirus scans on infected systems (can corrupt encrypted files)
  • ❌ Delete ransom notes (needed for identification)
  • ❌ Communicate using potentially compromised email
  • ❌ Attempt to negotiate or pay without proper authorization
  • ❌ Publicly disclose the incident prematurely

Containment Phase (15-60 Minutes)

Network Containment

ActionCommand/MethodPurpose
Block lateral movement portsBlock TCP 445, 135, 139, 3389 between segmentsStop SMB/RDP spread
Block known C2Add IOCs to firewall block listsCut attacker communication
Disable compromised accountsAD: Disable-ADAccountStop credential abuse
Consider network segmentationIsolate affected VLANsContain spread

Scope Assessment

Rapidly determine how far the infection has spread:

// KQL: Find systems with ransomware file extensions
DeviceFileEvents
| where TimeGenerated > ago(24h)
| where FileName endswith ".locked" or FileName endswith ".encrypted" 
    or FileName endswith ".crypted" or FileName contains "readme"
| summarize Count=count() by DeviceName
| order by Count desc

// KQL: Find lateral movement using compromised account
SigninLogs
| where TimeGenerated > ago(24h)
| where UserPrincipalName == "compromised_user@company.com"
| summarize Logins=count() by IPAddress, AppDisplayName

// KQL: Find process execution patterns
DeviceProcessEvents
| where TimeGenerated > ago(24h)
| where ProcessCommandLine has_any ("vssadmin", "wmic", "shadowcopy", "bcdedit", "wbadmin")
| project TimeGenerated, DeviceName, ProcessCommandLine, InitiatingProcessFileName

Investigation Phase (1-4 Hours)

Determine Attack Vector

VectorEvidence to Look For
PhishingEmail with attachment or link before first encryption
RDP Brute ForceMultiple failed logins followed by success, external IP
VPN CompromiseLogin from unusual location, credential theft
Supply ChainCompromised software update, MSP access
ExploitVulnerability exploitation, public-facing system

Ransomware Identification

  • Collect ransom note text
  • Note encrypted file extension
  • Use ID Ransomware (id-ransomware.malwarehunterteam.com) to identify variant
  • Check for known decryptors (nomoreransom.org)

Timeline Construction

Build a timeline of attacker activity:

  • When did initial access occur?
  • What was the dwell time before ransomware?
  • What systems did the attacker access?
  • Was data exfiltrated before encryption?
  • How did lateral movement occur?

Recovery Phase

Recovery Options

OptionWhen to UseConsiderations
Restore from backupBackups are intact and recentPreferred option. Verify backups aren't encrypted.
Decryptor toolKnown ransomware with available decryptorCheck nomoreransom.org first
Rebuild systemsNo backups, can rebuild from scratchTime-consuming but clean
Pay ransomLast resort, business decisionNo guarantee of decryption. May be illegal. Funds criminals.

Recovery Steps

  1. Confirm containment: Ensure no active attacker presence
  2. Validate backups: Confirm backups are clean and complete
  3. Rebuild infrastructure: AD, critical servers first
  4. Reset all credentials: Assume all passwords compromised
  5. Restore data: From validated backups
  6. Enhanced monitoring: Watch for return activity
  7. Remediate root cause: Fix the vulnerability that allowed entry

Post-Incident

  • Conduct lessons learned within 1-2 weeks
  • Document complete timeline and actions
  • Implement recommendations to prevent recurrence
  • Update incident response plan based on lessons
  • Brief leadership on root cause and improvements
