INV-008

Business Email Compromise Investigation

Comprehensive investigation procedure for BEC attacks including CEO fraud, invoice fraud, vendor impersonation, account takeover, W-2 scams, and gift card fraud scenarios.

SeverityCritical
MITRE TacticTA0001, TA0009
Time2-4 hours
T1566.001 T1566.002 T1534 T1114 T1078 T1585
Financial Impact Alert

BEC attacks result in the highest financial losses of any cybercrime category. The FBI IC3 reports over $2.7 billion in losses annually. Time is critical - funds transferred fraudulently may be unrecoverable within 24-72 hours. If funds have been transferred, initiate financial recovery procedures IMMEDIATELY before continuing investigation.

Step 1: Initial Assessment (15 min)

1.1 Determine BEC Type and Status

1
Critical First Questions
  • Was money transferred? If YES → Initiate financial recovery IMMEDIATELY
  • Was data sent? W-2s, PII, customer data → Breach notification may be required
  • Is an account compromised? Internal email involved → Check for ATO indicators
  • External impersonation or internal account? Different investigation paths
  • Who is being impersonated? Executive, vendor, attorney, HR
  • What was requested? Wire transfer, gift cards, data, bank change
  • Did the target comply? Attempted vs successful fraud

1.2 Financial Recovery (If Funds Transferred)

Time Critical - Act Within Hours

Wire transfers can be recalled within 24-72 hours in many cases. After that, recovery becomes extremely difficult.

Step 2: Email Analysis (30 min)

2.1 External Impersonation Analysis

// Email Header Analysis Checklist
Key Header Fields to Examine:
┌─────────────────────┬──────────────────────────────────────────────┐
│ Header Field        │ What to Check                                │
├─────────────────────┼──────────────────────────────────────────────┤
│ From                │ Display name vs actual email address         │
│ Reply-To            │ Does it differ from From? (RED FLAG)         │
│ Return-Path         │ Original sender - should match From          │
│ X-Originating-IP    │ Source IP - check geolocation                │
│ Received            │ Trace the email path                         │
│ Authentication      │ SPF, DKIM, DMARC results                     │
│ Message-ID          │ Domain should match sender                   │
└─────────────────────┴──────────────────────────────────────────────┘

// Common Domain Spoofing Patterns
Legitimate: ceo@company.com
Spoofed variations:
- ceo@c0mpany.com         (zero instead of 'o')
- ceo@cornpany.com        (rn looks like 'm')
- ceo@company-inc.com     (added suffix)
- ceo@compamy.com         (transposed letters)
- ceo@company.co          (wrong TLD)
- ceo@company.com.ru      (added domain)
- ceo-urgent@gmail.com    (free email service)
- company.ceo@gmail.com   (reversed format)

// Check Authentication Results
Authentication-Results header should show:
- spf=pass (sender IP authorized)
- dkim=pass (signature valid)
- dmarc=pass (policy compliance)

If ANY fail for supposedly internal email = SUSPICIOUS

2.2 Spoofing Detection Queries

// KQL - Find executive impersonation attempts
let executiveNames = dynamic(["CEO Name", "CFO Name", "CTO Name"]);
EmailEvents
| where TimeGenerated > ago(30d)
| where SenderFromAddress !endswith "@yourdomain.com"
| where SenderDisplayName has_any (executiveNames)
| project TimeGenerated, RecipientEmailAddress, SenderFromAddress,
    SenderDisplayName, Subject, DeliveryAction, 
    AuthenticationDetails
| order by TimeGenerated desc

// KQL - Lookalike domain detection
let legitDomain = "yourdomain.com";
EmailEvents
| where TimeGenerated > ago(30d)
| extend SenderDomain = tostring(split(SenderFromAddress, "@")[1])
| where SenderDomain != legitDomain
| where SenderDomain has "yourdomain" or SenderDomain has "y0urdomain"
    or SenderDomain has "yourd0main" or SenderDomain has "yourdornain"
| project TimeGenerated, SenderFromAddress, SenderDomain, Subject

// KQL - Reply-To mismatch (strong BEC indicator)
EmailEvents
| where TimeGenerated > ago(30d)
| where SenderFromAddress != ReplyToAddress
| where isnotempty(ReplyToAddress)
| project TimeGenerated, SenderFromAddress, ReplyToAddress, 
    RecipientEmailAddress, Subject
| order by TimeGenerated desc

// KQL - BEC keyword detection in subjects
EmailEvents
| where TimeGenerated > ago(7d)
| where Subject has_any ("wire transfer", "urgent payment", 
    "confidential", "wire instructions", "bank details",
    "ACH", "routing number", "invoice attached",
    "payment required", "past due", "immediate attention")
| where SenderFromAddress !endswith "@yourdomain.com"
| project TimeGenerated, SenderFromAddress, RecipientEmailAddress, Subject

// SPL - Executive impersonation
index=email 
| search sender_display_name IN ("CEO Name", "CFO Name")
| where NOT match(sender_address, "@yourdomain\.com$")
| table _time, sender_address, sender_display_name, recipient, subject

2.3 Account Takeover Analysis

// KQL - Suspicious inbox rule creation
CloudAppEvents
| where TimeGenerated > ago(30d)
| where ActionType in ("New-InboxRule", "Set-InboxRule", "Set-Mailbox")
| extend RuleData = tostring(RawEventData)
| where RuleData has_any ("DeleteMessage", "ForwardTo", 
    "ForwardAsAttachmentTo", "RedirectTo", "MoveToFolder",
    "MarkAsRead")
| project TimeGenerated, AccountDisplayName, ActionType,
    RuleData, IPAddress
| order by TimeGenerated desc

// KQL - Rules targeting financial keywords
let financialKeywords = dynamic(["invoice", "payment", "wire", 
    "transfer", "bank", "ach", "routing", "swift", "remittance"]);
CloudAppEvents
| where ActionType == "New-InboxRule"
| extend RuleData = tostring(RawEventData)
| where RuleData has_any (financialKeywords)
| project TimeGenerated, AccountDisplayName, RuleData

// KQL - External forwarding configured
CloudAppEvents
| where ActionType == "Set-Mailbox"
| where RawEventData has "ForwardingSmtpAddress"
| extend ForwardTo = extract("ForwardingSmtpAddress\":\"([^\"]+)", 1, 
    tostring(RawEventData))
| where isnotempty(ForwardTo)
| project TimeGenerated, AccountDisplayName, ForwardTo

// KQL - Sent items analysis for fraud emails
EmailEvents
| where TimeGenerated > ago(14d)
| where SenderFromAddress == "compromised.user@company.com"
| where Subject has_any ("invoice", "payment", "wire", "bank details",
    "account change", "new account", "updated banking")
| project TimeGenerated, RecipientEmailAddress, Subject, 
    NetworkMessageId

// KQL - Mailbox delegation changes
CloudAppEvents
| where ActionType in ("Add-MailboxPermission", "Add-RecipientPermission",
    "Set-MailboxFolderPermission")
| where RawEventData has_any ("FullAccess", "SendAs", "SendOnBehalf")
| project TimeGenerated, AccountDisplayName, ActionType, 
    RawEventData, IPAddress

Step 3: Account Compromise Investigation (45 min)

3.1 Sign-in Analysis

// KQL - Complete sign-in timeline
SigninLogs
| where TimeGenerated > ago(30d)
| where UserPrincipalName =~ "suspected.user@company.com"
| project TimeGenerated, 
    Location,
    IPAddress,
    DeviceDetail,
    AppDisplayName,
    ClientAppUsed,
    ResultType,
    ResultDescription,
    AuthenticationRequirement,
    ConditionalAccessStatus,
    RiskLevelDuringSignIn,
    RiskState
| order by TimeGenerated desc

// KQL - Impossible travel detection
let targetUser = "suspected.user@company.com";
SigninLogs
| where TimeGenerated > ago(14d)
| where UserPrincipalName =~ targetUser
| where ResultType == 0  // Successful only
| project TimeGenerated, Location, IPAddress, City = 
    tostring(LocationDetails.city)
| order by TimeGenerated asc
| extend PrevTime = prev(TimeGenerated), 
    PrevLocation = prev(Location),
    PrevCity = prev(City)
| extend TimeDiffMinutes = datetime_diff('minute', TimeGenerated, PrevTime)
| where PrevLocation != Location and TimeDiffMinutes < 120
| project TimeGenerated, Location, City, PrevLocation, PrevCity, 
    TimeDiffMinutes

// KQL - Sign-ins from suspicious countries
let allowedCountries = dynamic(["United States", "Canada"]);
SigninLogs
| where TimeGenerated > ago(30d)
| where UserPrincipalName =~ "suspected.user@company.com"
| where ResultType == 0
| where Location !in (allowedCountries)
| project TimeGenerated, Location, IPAddress, AppDisplayName,
    DeviceDetail

// KQL - Legacy authentication (often abused)
SigninLogs
| where TimeGenerated > ago(30d)
| where UserPrincipalName =~ "suspected.user@company.com"
| where ClientAppUsed in ("Exchange ActiveSync", "IMAP4", "POP3", 
    "SMTP", "Authenticated SMTP", "Other clients")
| project TimeGenerated, ClientAppUsed, IPAddress, ResultType

// KQL - MFA bypass or failure patterns
SigninLogs
| where TimeGenerated > ago(30d)
| where UserPrincipalName =~ "suspected.user@company.com"
| where AuthenticationRequirement == "singleFactorAuthentication"
    or ResultType in ("50074", "50076", "53003")
| project TimeGenerated, IPAddress, AppDisplayName, 
    AuthenticationRequirement, ResultType, ResultDescription

// KQL - First-time applications accessed
let recentApps = SigninLogs
| where TimeGenerated > ago(7d)
| where UserPrincipalName =~ "suspected.user@company.com"
| where ResultType == 0
| distinct AppDisplayName;
let historicalApps = SigninLogs
| where TimeGenerated between (ago(90d) .. ago(7d))
| where UserPrincipalName =~ "suspected.user@company.com"
| where ResultType == 0
| distinct AppDisplayName;
recentApps
| join kind=leftanti historicalApps on AppDisplayName

3.2 OAuth Application Analysis

// KQL - OAuth app consents by user
CloudAppEvents
| where TimeGenerated > ago(90d)
| where ActionType == "Consent to application"
| where AccountDisplayName contains "suspected.user"
| extend AppName = tostring(RawEventData.ApplicationName)
| extend Permissions = tostring(RawEventData.Permissions)
| project TimeGenerated, AccountDisplayName, AppName, Permissions

// Suspicious OAuth permissions to look for:
// - Mail.ReadWrite (read/write all mail)
// - Mail.Send (send as user)
// - MailboxSettings.ReadWrite (create rules)
// - Files.ReadWrite.All (OneDrive access)
// - User.ReadWrite.All (modify user profiles)

// KQL - Illicit consent grant detection
AuditLogs
| where TimeGenerated > ago(30d)
| where OperationName == "Consent to application"
| extend AppName = tostring(TargetResources[0].displayName)
| extend UserUPN = tostring(InitiatedBy.user.userPrincipalName)
| project TimeGenerated, UserUPN, AppName, TargetResources

Step 4: Scope and Impact Assessment (30 min)

4.1 Identify All Affected Parties

// KQL - All recipients of fraudulent emails
let fraudulentSender = "attacker@spoofed-domain.com";
let compromisedSender = "compromised.user@company.com";
EmailEvents
| where TimeGenerated > ago(30d)
| where SenderFromAddress in (fraudulentSender, compromisedSender)
| summarize 
    EmailCount=count(),
    FirstEmail=min(TimeGenerated),
    LastEmail=max(TimeGenerated),
    Subjects=make_set(Subject, 5)
    by RecipientEmailAddress
| order by EmailCount desc

// KQL - Track email reply chains
EmailEvents
| where TimeGenerated > ago(30d)
| where Subject startswith "Re:" 
| where Subject has_any ("invoice", "payment", "wire", "transfer")
| where RecipientEmailAddress == "compromised.user@company.com"
| project TimeGenerated, SenderFromAddress, Subject,
    NetworkMessageId

// KQL - External recipients contacted
EmailEvents
| where TimeGenerated > ago(30d)
| where SenderFromAddress == "compromised.user@company.com"
| where RecipientEmailAddress !endswith "@company.com"
| summarize ExternalEmails=count() by RecipientEmailAddress
| order by ExternalEmails desc

// KQL - Check for vendor/customer notifications
EmailEvents
| where SenderFromAddress == "compromised.user@company.com"
| where Subject has_any ("bank", "account", "payment", "invoice",
    "routing", "wire")
| where RecipientEmailAddress !endswith "@company.com"
| project TimeGenerated, RecipientEmailAddress, Subject

Containment Commands

// PowerShell - Complete account remediation

# 1. Reset password and force change
Set-MsolUserPassword -UserPrincipalName "user@company.com" `
    -NewPassword "TempP@ssw0rd!" -ForceChangePassword $true

# 2. Revoke all sessions (Azure AD)
Revoke-AzureADUserAllRefreshToken -ObjectId "user@company.com"

# 3. Block sign-in temporarily if needed
Set-MsolUser -UserPrincipalName "user@company.com" -BlockCredential $true

# 4. List all inbox rules
Get-InboxRule -Mailbox "user@company.com" | 
    Select Name, Description, Enabled, ForwardTo, 
    ForwardAsAttachmentTo, RedirectTo, DeleteMessage, MoveToFolder

# 5. Remove suspicious rules
Remove-InboxRule -Mailbox "user@company.com" -Identity "RuleName" -Confirm:$false

# 6. Check and remove forwarding
Get-Mailbox "user@company.com" | 
    Select ForwardingAddress, ForwardingSmtpAddress, DeliverToMailboxAndForward

Set-Mailbox "user@company.com" -ForwardingSmtpAddress $null `
    -ForwardingAddress $null -DeliverToMailboxAndForward $false

# 7. Check mailbox delegates
Get-MailboxPermission "user@company.com" | 
    Where {$_.User -ne "NT AUTHORITY\SELF"}

# 8. Remove unauthorized delegates
Remove-MailboxPermission -Identity "user@company.com" `
    -User "unauthorized@company.com" -AccessRights FullAccess -Confirm:$false

# 9. Block sender domain (transport rule)
New-TransportRule -Name "Block spoofed domain" `
    -FromAddressMatchesPatterns "@spoofed-domain\.com$" `
    -RejectMessageReasonText "Blocked due to security policy"

Escalation Criteria

Escalate Immediately If:
  • Funds have been transferred (any amount)
  • Multiple accounts are compromised
  • Executive accounts involved (CEO, CFO, etc.)
  • Customers or vendors received fraudulent emails
  • Sensitive data (W-2, PII, financials) was sent externally
  • Ongoing active attacker access confirmed
  • Attack spans multiple days or victims
  • Evidence of persistence mechanisms (OAuth apps, forwarding)

Initial Triage Checklist

First 5 Minutes - Quick Assessment
  • Check email headers - Is this spoofed? Check SPF/DKIM/DMARC
  • Verify sender identity - Is this really from who it claims?
  • Has money moved? - If yes, this is urgent financial recovery
  • Did recipient click/respond? - Check for engagement
  • Are there other victims? - Search for same sender/subject
