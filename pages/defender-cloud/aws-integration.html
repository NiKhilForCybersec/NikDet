AWS Integration Guide

Complete step-by-step guide to connect your AWS accounts to Microsoft Defender for Cloud. No steps skipped.

Prerequisites

RequirementDetails
Azure SubscriptionWith Defender for Cloud enabled
Azure PermissionsSecurity Admin + Contributor on subscription
AWS AccountWith administrator access
AWS PermissionsIAM:CreateRole, CloudFormation:CreateStack, etc.
Defender PlanFoundational CSPM (free) or Defender CSPM (paid)

What Gets Deployed

When you connect AWS to Defender for Cloud, the following is created in AWS:

  • IAM Role: Cross-account role trusted by Microsoft
  • IAM Policies: Read permissions for security assessment
  • CloudFormation Stack: Deploys the above resources
  • For CWPP: Additional roles for Arc agent deployment

Step-by-Step: Connect Single AWS Account

1

Access Defender for Cloud

  1. Go to Azure Portal
  2. Search for "Microsoft Defender for Cloud"
  3. Click to open Defender for Cloud
2

Navigate to Environment Settings

  1. In the left menu, click Environment settings
  2. Click + Add environment
  3. Select Amazon Web Services
3

Configure Account Details

  1. Select Single account (or Management account for Organizations)
  2. Enter a Connector name: e.g., "AWS-Production"
  3. Select Subscription where connector will be created
  4. Select Resource group or create new
  5. Select Location: Choose region closest to your AWS region
  6. Click Next: Select plans
4

Select Defender Plans

Choose which plans to enable for AWS:

PlanWhat It DoesCost
Foundational CSPMBasic recommendationsFree
Defender CSPMAttack paths, agentless scanPaid
Servers (Plan 1/2)EC2 protection via ArcPaid
ContainersEKS protectionPaid
DatabasesRDS protectionPaid

Toggle desired plans On

Click Next: Configure access

5

Configure Access Method

Select deployment type:

  • Azure (Recommended) - Uses CloudFormation
  • AWS CloudFormation - Manual deployment

For automated setup, select Azure

Click Next: Review and generate

6

Deploy CloudFormation Stack (Automated)

  1. Review your configuration
  2. Click Download CloudFormation template
  3. Note the Stack name shown
  4. Click Go to AWS - This opens AWS Console
7

In AWS Console - Create Stack

  1. You should be in CloudFormation → Create stack
  2. If not automatically populated:
    • Select "Template is ready"
    • Select "Upload a template file"
    • Upload the downloaded template
  3. Click Next
8

Specify Stack Details

  1. Stack name: Use the name from Azure (e.g., "DefenderForCloud-xxxxxxxx")
  2. Leave parameters as default (pre-filled by template)
  3. Click Next
9

Configure Stack Options

  1. Tags: Optional - add tags for tracking
  2. Permissions: Leave default
  3. Stack failure options: Leave default (Rollback)
  4. Click Next
10

Review and Create

  1. Review all settings
  2. IMPORTANT: Check the box: "I acknowledge that AWS CloudFormation might create IAM resources with custom names"
  3. Click Submit
  4. Wait for stack status: CREATE_COMPLETE (2-5 minutes)
11

Complete Azure Configuration

  1. Return to the Azure portal tab
  2. Click Create
  3. Wait for connector creation (1-2 minutes)
  4. Connector status should show Connected

Data Sync Time

After connection, it takes up to 24 hours for full security assessment. Initial recommendations appear within 2-4 hours.

Connect AWS Organization (Multiple Accounts)

For AWS Organizations

If you have multiple AWS accounts managed by AWS Organizations:

Prerequisites for Organization Connection

  • Access to AWS Management Account
  • AWS Organizations enabled
  • CloudFormation StackSets permissions
  1. In Azure, select Management account instead of Single account
  2. Enter your AWS Organization ID (found in AWS Organizations console)
  3. The CloudFormation template creates a StackSet that deploys to all member accounts
  4. Optionally exclude specific accounts or OUs
# Find AWS Organization ID via CLI
aws organizations describe-organization --query 'Organization.Id' --output text

# List all accounts in organization
aws organizations list-accounts --output table

Enable Defender for Servers on EC2

Auto-provisioning with Azure Arc

To protect EC2 instances with Defender for Servers, they need the Azure Arc agent.

Enable Auto-provisioning

  1. In Defender for Cloud, go to Environment settings
  2. Select your AWS connector
  3. Click Settings & monitoring
  4. Under Servers, click Configuration
  5. Enable Auto-provision Arc agent
  6. Select tags to scope which EC2 instances to onboard

Manual Arc Agent Installation

For instances not auto-provisioned:

# On EC2 Linux instance
wget https://aka.ms/azcmagent -O install_linux_azcmagent.sh
sudo bash install_linux_azcmagent.sh

# Connect to Azure
sudo azcmagent connect \
    --tenant-id "YOUR-TENANT-ID" \
    --subscription-id "YOUR-SUBSCRIPTION-ID" \
    --resource-group "YOUR-RG" \
    --location "eastus" \
    --service-principal-id "YOUR-SP-ID" \
    --service-principal-secret "YOUR-SP-SECRET"

# On EC2 Windows instance (PowerShell)
Invoke-WebRequest -Uri https://aka.ms/AzureConnectedMachineAgent -OutFile AzureConnectedMachineAgent.msi
msiexec /i AzureConnectedMachineAgent.msi /l*v installationlog.txt /qn

# Connect
& "$env:ProgramFiles\AzureConnectedMachineAgent\azcmagent.exe" connect `
    --tenant-id "YOUR-TENANT-ID" `
    --subscription-id "YOUR-SUBSCRIPTION-ID" `
    --resource-group "YOUR-RG" `
    --location "eastus"

Enable Defender for Containers (EKS)

EKS Protection

Enable EKS Protection

  1. Go to AWS connector settings
  2. Enable Containers plan
  3. The Defender extension deploys automatically to EKS clusters
  4. Alternatively, deploy manually via Helm:
# Manual Defender extension for EKS
# Add Microsoft Helm repo
helm repo add microsoft https://raw.githubusercontent.com/microsoft/Defender-for-Cloud-Helm-Charts/main/repo/
helm repo update

# Install Defender extension
helm install defender-for-containers microsoft/defender-for-containers \
    --namespace mdc \
    --create-namespace \
    --set defender.subscriptionId="YOUR-SUBSCRIPTION-ID" \
    --set defender.resourceGroup="YOUR-RG" \
    --set defender.clusterName="YOUR-EKS-CLUSTER"

Verify Connection

# Check connector status in Azure
az security connector show --name "your-connector-name" --resource-group "your-rg"

# List all AWS connectors
az security connector list --query "[?environmentName=='AWS']" --output table

# Check AWS resources discovered
# Go to: Defender for Cloud → Inventory → Filter by Environment: AWS

Expected Resources

After successful connection, you should see:

  • EC2 instances in Inventory
  • S3 buckets with security recommendations
  • IAM users and roles
  • RDS instances (if Defender for Databases enabled)
  • EKS clusters (if Defender for Containers enabled)
  • Security recommendations specific to AWS

Remove AWS Connection

Clean Removal Steps

Step 1: Remove from Azure

  1. Go to Defender for Cloud → Environment settings
  2. Find your AWS connector
  3. Click ... → Delete
  4. Confirm deletion

Step 2: Delete CloudFormation Stack in AWS

  1. Go to AWS Console → CloudFormation
  2. Find the Defender for Cloud stack
  3. Select it and click Delete
  4. Confirm deletion

No resources discoveredWait 24 hours; check AWS role permissions
EC2 not protectedVerify Arc agent installed and connected
