DLP Alert Triage

Rapid triage procedures for Data Loss Prevention alerts. Balance data protection with business operations.

Investigation Queries

Microsoft Purview DLP

// DLP incidents in last 24 hours
DLPAlerts
| where TimeGenerated > ago(24h)
| project TimeGenerated, User, PolicyName, SensitiveInfoType, 
    Action, Destination, FileName, FileSize
| order by TimeGenerated desc

// User's DLP history (pattern analysis)
DLPAlerts
| where TimeGenerated > ago(90d)
| where User == "user@company.com"
| summarize TotalIncidents=count(), Blocked=countif(Action=="Block"),
    Allowed=countif(Action=="Allow") by PolicyName
| order by TotalIncidents desc

// Bulk data movement detection
OfficeActivity
| where TimeGenerated > ago(24h)
| where UserId == "user@company.com"
| where Operation in ("FileDownloaded", "FileSyncDownloadedFull")
| summarize FileCount=count(), TotalSize=sum(FileSize) by bin(TimeGenerated, 1h)
| where FileCount > 50 or TotalSize > 100000000

// External sharing events
OfficeActivity
| where TimeGenerated > ago(24h)
| where Operation in ("AnonymousLinkCreated", "SharingInvitationCreated", 
    "AddedToSecureLink", "SecureLinkCreated")
| where TargetUserOrGroupType == "Guest" or TargetUserOrGroupName contains "@"
| project TimeGenerated, UserId, FileName, TargetUserOrGroupName, Site_Url

Symantec/Broadcom DLP

// User incident history
index=dlp user="jsmith" earliest=-30d
| stats count by policy_name, severity, action
| sort -count

// High severity incidents today

Triage Workflow

1
Assess Data Sensitivity

What type of data triggered the alert? Is it actually sensitive? Check classification and content.

2
Identify Destination

Where was the data going? Internal, authorized external, or unauthorized destination?

3
Check User Context

User's role, department, history, and whether action aligns with job function.

4
Determine Action Taken

Was data blocked, warned, or allowed? If allowed, assess exposure and containment need.

5
Escalate or Close

Based on risk assessment, either close as FP/low risk or escalate to IR/management.

Documentation Requirements

  • ☐ Data type and sensitivity level
  • ☐ Volume of data involved
  • ☐ Destination (internal/external, specific recipient)
  • ☐ DLP action (blocked/warned/allowed)
  • ☐ User and their role/department
  • ☐ Business justification (if any)
  • ☐ Investigation findings
  • ☐ Containment actions taken
  • ☐ Follow-up required (policy tuning, user training)
